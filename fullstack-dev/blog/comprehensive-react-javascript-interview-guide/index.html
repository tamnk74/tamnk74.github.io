The Complete React & Advanced JavaScript Interview Guide: 100+ Questions for 2025

October 17, 2025 · 22 min read
Tam Nguyen
Full Stack Developer, Next.js for Production Creator

Landing a frontend developer role in 2025 requires mastering both React and advanced JavaScript concepts. Whether you're an experienced developer with 10+ years or just starting your React journey, this comprehensive guide covers everything you need to ace your next interview.

This guide combines essential React fundamentals, advanced hooks patterns, practical coding challenges, and senior-level JavaScript concepts to give you the complete preparation toolkit.

Part 1: React Fundamentals & Core Concepts​

1. What is React and Its Benefits?​

React is a JavaScript library by Facebook for building user interfaces, especially in single-page apps. It allows reusable components with their own state.

Key Benefits:

  • Component-Based Structure: Build encapsulated components that manage their own state
  • Virtual DOM: Efficient updates with minimal direct DOM manipulation
  • Declarative UI: Describe what the UI should look like, React handles updates
  • Strong Community: Extensive ecosystem and third-party libraries
  • Performance: Minimizes direct DOM manipulations, which are expensive
  • Cross-browser Compatibility: React abstracts browser quirks
function Counter() {
  const [count, setCount] = React.useState(0);

  return <button onClick={() => setCount(count + 1)}>Clicked {count} times</button>;
}

2. Understanding React's Virtual DOM​

The Virtual DOM (VDOM) is a lightweight, in-memory representation of the real DOM. When a React component's state or props change, React first updates the VDOM instead of the actual DOM.

How It Works:

  1. React creates a VDOM tree representation
  2. When state/props change, a new VDOM tree is created
  3. React performs a "diffing" algorithm to find minimal changes
  4. Only the necessary changes are applied to the real DOM

Benefits:

  • Minimizes expensive DOM operations
  • Batch updates for efficiency
  • Predictable rendering behavior
  • Enables React's declarative programming model

3. React's Reconciliation Algorithm​

React's reconciliation algorithm identifies changes in the VDOM tree and updates only the affected parts of the real DOM.

Process:

  1. Diffing: Compares previous and current VDOM tree
  2. Key Comparison: Uses key props to identify stable elements across renders
  3. Batch Updates: Minimizes updates by batching multiple state changes into a single DOM operation

4. Fiber Architecture​

The Fiber architecture is a re-implementation of React's reconciliation algorithm designed to improve rendering. It breaks rendering into units of work that can be paused and resumed.

Benefits:

  • Non-blocking rendering: Doesn't block the main thread
  • Improved responsiveness: Better for animations and transitions
  • Prioritization: High-priority tasks (user input) get processed first
  • Time slicing: Break work into chunks for smoother updates

5. Difference Between React Node, Element, and Component​

React Node: Any renderable unit in React (element, string, number, or null)

React Element: An immutable object describing what to render, created with JSX or React.createElement

const element = <h1>Hello, world!</h1>;
// Equivalent to:
const element = React.createElement('h1', null, 'Hello, world!');

React Component: A function or class that returns React Elements, allowing for reusable UI pieces

function Welcome(props) {
  return <h1>Hello, {props.name}</h1>;
}

6. What is JSX?​

JSX (JavaScript XML) is a syntax extension for JavaScript that lets you write HTML-like code within JavaScript. It simplifies creating React components.

const element = <div>Hello, world!</div>;

JSX is transformed into JavaScript function calls by Babel:

const element = React.createElement('div', null, 'Hello, world!');

7. State vs Props in React​

Props (Properties):

  • Immutable and passed from parent to child component
  • Allow components to be dynamic by providing external values
  • Read-only from the child's perspective
// Parent component passes props
const Parent = () => {
  return <Child name="John" />;
};

// Child component receives props
const Child = ({ name }) => {
  return <h1>Hello, {name}</h1>;
};

State:

  • Mutable and managed within the component itself
  • Can change over time, usually in response to user actions or network responses
  • Private to the component
function Counter() {
  const [count, setCount] = useState(0);
  return <div>{count}</div>;
}

8. The Purpose of the key Prop​

The key prop uniquely identifies elements in a list, helping React optimize rendering by efficiently updating and reordering items.

{
  items.map((item) => <ListItem key={item.id} value={item.value} />);
}

Why Keys Matter:

  • Without unique keys, React may unnecessarily re-render elements
  • Leads to performance issues and bugs
  • Helps React identify which items have changed, been added, or removed

Consequences of Using Array Indices:

  • When the order of items changes, React may fail to correctly identify which items have changed
  • Can lead to unnecessary re-renders or incorrect updates
  • Better to use unique identifiers for keys

9. Controlled vs Uncontrolled Components​

Controlled Components: React manages the form element's value via state. Changes are handled through event handlers.

function ControlledInput() {
  const [value, setValue] = useState('');
  return <input type="text" value={value} onChange={(e) => setValue(e.target.value)} />;
}

Uncontrolled Components: The DOM handles the state, and React uses refs to access the current value.

function UncontrolledInput() {
  const inputRef = useRef();
  return <input type="text" ref={inputRef} />;
}

When to Use:

  • Controlled: When you need form validation, conditional rendering, or complex state management
  • Uncontrolled: For simple forms or when integrating with non-React code

10. React Fragments​

React Fragments allow grouping child elements without adding extra DOM nodes.

function List() {
  return (
    <>
      <li>Item 1</li>
      <li>Item 2</li>
    </>
  );
}

When to Use:

  • Avoiding unnecessary <div> elements that can cause layout or CSS issues
  • Returning multiple elements from a component's render method
  • Improving semantic HTML structure

Part 2: React Hooks - Essential & Advanced​

11. What are React Hooks?​

React hooks are functions that allow developers to use state and other React features in functional components. Prior to hooks, these features were only available in class components.

Benefits of Hooks:

  • Use state and lifecycle features in functional components
  • Eliminate the need for classes
  • Simplify code by reducing reliance on lifecycle methods
  • Improve code readability and reusability
  • Make it easier to reuse stateful logic across components

12. Rules of React Hooks​

Hooks must follow two critical rules:

  1. Only call hooks at the top level: Never inside loops, conditions, or nested functions
  2. Only call hooks from React functions: From React function components or custom hooks
// ❌ Wrong
function Component({ condition }) {
  if (condition) {
    const [state, setState] = useState(); // Don't do this!
  }
}

// ✅ Correct
function Component({ condition }) {
  const [state, setState] = useState();
  if (condition) {
    // Use state here
  }
}

13. useState - Managing Component State​

The useState hook allows adding state to functional components. It returns an array with two elements: the current state value and a function to update it.

const [count, setCount] = useState(0);

Functional Updates: When the new state depends on the previous state, pass a function:

setCount((prevCount) => prevCount + 1);

Why Use Functional Updates:

  • Ensures updates are based on the most current state
  • Essential when the new state depends on the previous state
  • Avoids issues related to asynchronous state updates

14. useEffect - Handling Side Effects​

The useEffect hook handles side effects like data fetching, DOM updates, or subscriptions in functional components.

useEffect(() => {
  console.log('Effect ran');

  return () => console.log('Cleanup logic'); // Cleanup runs on unmount or dependency change
}, [dependency]);

Dependency Array Patterns:

PatternBehavior
No dependenciesRuns after every render
Empty array []Runs only once after initial render
[a, b]Runs when a or b changes

Data Fetching Example:

useEffect(() => {
  const fetchData = async () => {
    try {
      const response = await fetch('https://api.example.com/data');
      const data = await response.json();
      setData(data);
    } catch (error) {
      console.error('Error fetching data:', error);
    }
  };
  fetchData();
}, []);

Cleanup Function: Return a function from useEffect to handle cleanup:

useEffect(() => {
  const subscription = subscribeToData();

  return () => {
    subscription.unsubscribe(); // Cleanup
  };
}, []);

15. useEffect vs useLayoutEffect​

useEffect:

  • Runs asynchronously after the DOM has painted
  • Ideal for data fetching, subscriptions, or non-visual side effects
  • Doesn't block the browser from painting

useLayoutEffect:

  • Runs synchronously after DOM mutations but before browser paints
  • Useful for measuring DOM elements or synchronizing UI with DOM
  • Can block visual updates if heavy computation is performed
function Example() {
  const ref = useRef();

  useEffect(() => {
    console.log('useEffect: Runs after DOM paint');
  });

  useLayoutEffect(() => {
    console.log('useLayoutEffect: Runs before DOM paint');
    console.log('Element width:', ref.current.offsetWidth);
  });

  return <div ref={ref}>Hello</div>;
}

16. useRef - Persisting Values & DOM Access​

The useRef hook creates a mutable object that persists through renders without causing re-renders.

Use Cases:

  1. Accessing DOM elements directly
  2. Storing mutable values without triggering re-renders
  3. Maintaining references to values across renders
function TextInputWithFocusButton() {
  const inputEl = useRef(null);

  useEffect(() => {
    inputEl.current.focus();
  }, []);

  return <input ref={inputEl} type="text" />;
}

Form Validation with useRef:

const inputRef = useRef();

function handleSubmit() {
  const value = inputRef.current.value;
  if (value.trim() === '') {
    console.log('Input is required!');
  } else {
    console.log('Input value:', value);
  }
}

return <input ref={inputRef} />;

17. useContext - Sharing State Across Components​

The useContext hook allows accessing the value of a context in a functional component, eliminating prop drilling.

const ThemeContext = React.createContext();

const App = () => {
  const [theme, setTheme] = useState('light');

  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <SomeComponent />
    </ThemeContext.Provider>
  );
};

function SomeComponent() {
  const { theme, setTheme } = useContext(ThemeContext);
  return <div>Current theme: {theme}</div>;
}

Benefits:

  • Simplifies state sharing across components
  • Eliminates prop drilling through multiple layers
  • Makes code more maintainable

Limitations:

  • Inefficient for frequent updates (re-renders all consumers)
  • Not suitable for large-scale state management (consider Redux/Zustand)
  • Can make code harder to understand if overused

18. useMemo - Memoizing Expensive Calculations​

The useMemo hook memoizes costly calculations, recomputing them only when dependencies change.

const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);

When to Use:

  • Computationally intensive functions that don't need to run on every render
  • Preventing expensive recalculations
  • Optimizing performance in large applications

Example:

function ExpensiveComponent({ items }) {
  const sortedItems = useMemo(() => {
    console.log('Sorting items...');
    return items.sort((a, b) => a.value - b.value);
  }, [items]);

  return (
    <div>
      {sortedItems.map((item) => (
        <div key={item.id}>{item.value}</div>
      ))}
    </div>
  );
}

19. useCallback - Memoizing Functions​

The useCallback hook memoizes functions to prevent their recreation on every render.

const memoizedCallback = useCallback(() => {
  doSomething(a, b);
}, [a, b]);

Difference from useMemo:

  • useMemo caches the result of a computation
  • useCallback caches the function itself

When to Use:

  • Passing callbacks to optimized child components
  • Preventing child components from re-rendering
  • Ensuring function reference equality
function Parent() {
  const [count, setCount] = useState(0);

  // Without useCallback, this function is recreated on every render
  const handleClick = useCallback(() => {
    console.log('Button clicked');
  }, []);

  return <Child onClick={handleClick} />;
}

const Child = React.memo(({ onClick }) => {
  console.log('Child rendered');
  return <button onClick={onClick}>Click me</button>;
});

20. useReducer - Complex State Management​

The useReducer hook manages complex state logic in functional components, serving as an alternative to useState.

const [state, dispatch] = useReducer(reducer, initialState);

When to Use:

  • State has multiple sub-values
  • Next state depends on the previous one
  • Complex state transitions
  • State logic is getting complicated

Example:

const initialState = { count: 0, step: 1 };

function reducer(state, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + state.step };
    case 'DECREMENT':
      return { ...state, count: state.count - state.step };
    case 'SET_STEP':
      return { ...state, step: action.payload };
    default:
      return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, initialState);

  return (
    <div>
      <p>Count: {state.count}</p>
      <button onClick={() => dispatch({ type: 'INCREMENT' })}>+</button>
      <button onClick={() => dispatch({ type: 'DECREMENT' })}>-</button>
    </div>
  );
}

21. useId - Generating Unique IDs​

The useId hook generates unique IDs for elements within a component, crucial for accessibility.

function MyComponent() {
  const id = useId();

  return (
    <div>
      <label htmlFor={id}>Name:</label>
      <input id={id} type="text" />
    </div>
  );
}

Benefits:

  • Guarantees unique IDs across the application
  • Safe for server-side rendering
  • Prevents ID collisions in component reuse

22. Custom Hooks - Reusing Stateful Logic​

Custom hooks are JavaScript functions that allow you to reuse stateful logic across multiple components.

function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);
  const increment = () => setCount((prev) => prev + 1);
  const decrement = () => setCount((prev) => prev - 1);
  const reset = () => setCount(initialValue);

  return { count, increment, decrement, reset };
}

// Usage
function CounterComponent() {
  const { count, increment, decrement, reset } = useCounter(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={increment}>+</button>
      <button onClick={decrement}>-</button>
      <button onClick={reset}>Reset</button>
    </div>
  );
}

useFetch Custom Hook:

const useFetch = (url) => {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const fetchData = async () => {
      try {
        const response = await fetch(url);
        const result = await response.json();
        setData(result);
      } catch (err) {
        setError(err);
      } finally {
        setLoading(false);
      }
    };

    fetchData();
  }, [url]);

  return { data, loading, error };
};

Part 3: React Performance Optimization​

23. Preventing Unnecessary Re-renders​

React.memo: Memoizes a component, preventing re-renders when props haven't changed.

const MyComponent = React.memo(({ name }) => {
  return <h1>{name}</h1>;
});

React.PureComponent: Class component that performs shallow comparison of props and state.

class MyComponent extends React.PureComponent {
  render() {
    return <div>{this.props.data}</div>;
  }
}

shouldComponentUpdate: Lifecycle method that determines if a component should re-render.

shouldComponentUpdate(nextProps, nextState) {
  return nextProps.id !== this.props.id;
}

Key Prop in Lists: Using proper keys helps React efficiently update only necessary DOM elements.

24. Code Splitting and Lazy Loading​

Code splitting enhances performance by dividing code into smaller chunks loaded on demand.

const LazyComponent = React.lazy(() => import('./LazyComponent'));

function App() {
  return (
    <React.Suspense fallback={<div>Loading...</div>}>
      <LazyComponent />
    </React.Suspense>
  );
}

Benefits:

  • Reduces initial load time
  • Loads components only when needed
  • Improves overall application performance
  • Better user experience for large applications

25. Performance Bottlenecks in Large-Scale React Applications​

Common Issues:

  1. Excessive Re-renders: Components re-rendering unnecessarily
  2. Large Component Trees: Deep nesting causing performance issues
  3. Unoptimized Lists: Not using proper keys or virtualization
  4. Heavy Computations: Expensive calculations on every render

Solutions:

// ✅ Code Splitting
const HeavyComponent = React.lazy(() => import('./HeavyComponent'));

// ✅ Memoization
const computedValue = useMemo(() => expensiveComputation(a, b), [a, b]);

// ✅ Debouncing/Throttling
const debouncedSearch = useMemo(() => debounce((value) => search(value), 300), []);

// ✅ Pagination and Infinite Scroll
function DataList({ items }) {
  const [page, setPage] = useState(1);
  const displayedItems = items.slice(0, page * 20);

  return (
    <>
      {displayedItems.map((item) => (
        <Item key={item.id} {...item} />
      ))}
      <button onClick={() => setPage((p) => p + 1)}>Load More</button>
    </>
  );
}

26. React Suspense​

React Suspense allows handling asynchronous operations more elegantly within components, providing fallback content while waiting for resources.

const LazyComponent = React.lazy(() => import('./LazyComponent'));

function MyComponent() {
  return (
    <React.Suspense fallback={<div>Loading...</div>}>
      <LazyComponent />
    </React.Suspense>
  );
}

Use Cases:

  • Code splitting with React.lazy
  • Data fetching (with libraries like React Query)
  • Resource loading
  • Improving user experience during async operations

27. Concurrent Mode​

Concurrent Mode allows React to work on multiple tasks simultaneously without blocking the main UI thread.

Features:

  • Time Slicing: Break up large updates into smaller chunks
  • Suspense for Data Fetching: Better async handling
  • Priority System: High-priority updates (user input) processed first
  • Improved Responsiveness: Smoother rendering for complex applications

Part 4: React Patterns & Best Practices​

28. Higher-Order Components (HOCs)​

HOCs are functions that take a component and return a new one with added props or behavior.

const withExtraProps = (WrappedComponent) => {
  return (props) => <WrappedComponent {...props} extraProp="value" />;
};

const EnhancedComponent = withExtraProps(MyComponent);

Use Cases:

  • Code reuse and logic sharing
  • Props manipulation
  • State abstraction
  • Render hijacking

29. Render Props Pattern​

Render props allow code sharing between components through a prop that is a function.

class DataFetcher extends React.Component {
  state = { data: null };

  componentDidMount() {
    fetch(this.props.url)
      .then((response) => response.json())
      .then((data) => this.setState({ data }));
  }

  render() {
    return this.props.render(this.state.data);
  }
}

// Usage
<DataFetcher url="/api/data" render={(data) => <div>{data ? data.name : 'Loading...'}</div>} />;

30. Composition Pattern​

The composition pattern involves building components by combining smaller, reusable ones instead of using inheritance.

function WelcomeDialog() {
  return (
    <Dialog>
      <h1>Welcome</h1>
      <p>Thank you for visiting our spacecraft!</p>
    </Dialog>
  );
}

function Dialog(props) {
  return <div className="dialog">{props.children}</div>;
}

Benefits:

  • Encourages reusability
  • More flexible than inheritance
  • Easier to understand and maintain
  • React's recommended approach

31. Presentational vs Container Components​

Presentational Components:

  • Focus on how things look
  • Receive data and callbacks via props
  • Rarely have their own state
  • Written as functional components
function UserProfile({ user, onEdit }) {
  return (
    <div>
      <h1>{user.name}</h1>
      <button onClick={onEdit}>Edit</button>
    </div>
  );
}

Container Components:

  • Focus on how things work
  • Manage state and data fetching
  • Pass data and behavior to presentational components
  • Often use hooks or connect to state management
function UserProfileContainer({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    fetchUser(userId).then(setUser);
  }, [userId]);

  const handleEdit = () => {
    // Edit logic
  };

  return user ? <UserProfile user={user} onEdit={handleEdit} /> : <Loading />;
}

32. React Anti-Patterns to Avoid​

Common Anti-Patterns:

  1. Directly mutating state instead of using setState
  2. Using componentWillMount for data fetching
  3. Overusing componentWillReceiveProps
  4. Not using keys in lists
  5. Excessive inline functions in render
  6. Deeply nested state
  7. Using index as key in dynamic lists
  8. Mixing controlled and uncontrolled components
// ❌ Wrong: Mutating state directly
this.state.items.push(newItem);

// ✅ Correct: Using setState
this.setState((prevState) => ({
  items: [...prevState.items, newItem],
}));

Part 5: React Router & Navigation​

33. Dynamic Routing with React Router​

React Router maps URL paths to components, enabling navigation in single-page apps.

export default function App() {

Nested routes allow creating hierarchies of components.

function App() {

HashRouter:

  • No server-side configuration needed
  • Suitable for static hosting

Part 7: Error Handling & Debugging​

41. Error Boundaries​

Error boundaries catch JavaScript errors in their child components and display fallback UI.

class ErrorBoundary extends React.Component {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  componentDidCatch(error, info) {
    console.log(error, info);
  }

  render() {
    if (this.state.hasError) {
      return <h1>Something went wrong!</h1>;
    }
    return this.props.children;
  }
}

// Usage
<ErrorBoundary>
  <MyComponent />
</ErrorBoundary>;

const fetchData = async () => {

    const result = await data.json();
    setData(result);

    setError(error.message);
  }
};

Part 8: Advanced JavaScript for React Developers​

45. Microtask Queue​

The microtask queue is where tasks like promise callbacks (then and catch), async functions, and APIs like MutationObserver are queued for execution.

console.log('Start');

setTimeout(() => console.log('Timeout'), 0);

Promise.resolve().then(() => console.log('Promise'));

console.log('End');

// Output:
// Start
// End
// Promise
// Timeout

Key Points:

  • Microtasks have higher priority than macrotasks
  • Processed immediately after current execution context
  • FIFO (First In, First Out) order

46. Closures - Power and Pitfalls​

Potential Pitfalls:

  • Memory Leaks: Closures keep outer function scopes alive
  • Variable Sharing: Unexpected sharing between closures
  • Performance Issues: Increased memory usage
  • Debugging Complexity: Complex scope chains
function createCounter() {
  let count = 0; // This stays in memory

  return {
    increment: () => ++count,
    getCount: () => count,
  };
}

const counter = createCounter();
console.log(counter.increment()); // 1
console.log(counter.getCount()); // 1

47. Event Loop Deep Dive​

Components:

  1. Call Stack: Tracks function calls (LIFO)
  2. Web APIs: Handle async tasks (setTimeout, fetch, etc.)
  3. Task Queue (Macrotask Queue): Stores callbacks from async tasks
  4. Microtasks Queue: Higher priority (Promises, async/await)

Execution Order:

  1. Execute synchronous code
  2. Process all microtasks
  3. Execute one macrotask
  4. Process all microtasks again
  5. Repeat
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => console.log('3'));

console.log('4');

// Output: 1, 4, 3, 2

49. Generators and Iterators​

Iterators define a sequence and potentially return a value.

const iterator = {
  current: 0,
  last: 5,
  next() {
    if (this.current <= this.last) {
      return { value: this.current++, done: false };
    } else {
      return { value: undefined, done: true };
    }
  },
};

let result = iterator.next();
while (!result.done) {
  console.log(result.value);
  result = iterator.next();
}

Generators use function* syntax and yield keyword.

function* numberGenerator() {
  let num = 0;
  while (num <= 5) {
    yield num++;
  }
}

const gen = numberGenerator();
console.log(gen.next()); // { value: 0, done: false }
console.log(gen.next()); // { value: 1, done: false }

50. Memoization in JavaScript​

Memoization caches the results of expensive function calls.

function memoize(fn) {
  const cache = {};
  return function (...args) {
    const key = JSON.stringify(args);
    return cache[key] || (cache[key] = fn.apply(this, args));
  };
}

function fibonacci(n) {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}

const memoizedFibonacci = memoize(fibonacci);
console.log(memoizedFibonacci(40)); // Much faster!

58. Todo List with Local Storage​

function TodoList() {
  const [todos, setTodos] = useState(() => {
    const saved = localStorage.getItem('todos');
    return saved ? JSON.parse(saved) : [];
  });
  const [input, setInput] = useState('');

  useEffect(() => {
    localStorage.setItem('todos', JSON.stringify(todos));
  }, [todos]);

  const addTodo = () => {
    if (input.trim()) {
      setTodos([...todos, { id: Date.now(), text: input, completed: false }]);
      setInput('');
    }
  };

  const toggleTodo = (id) => {
    setTodos(todos.map((todo) => (todo.id === id ? { ...todo, completed: !todo.completed } : todo)));
  };

  const deleteTodo = (id) => {
    setTodos(todos.filter((todo) => todo.id !== id));
  };

  return (
    <div>
      <input value={input} onChange={(e) => setInput(e.target.value)} />
      <button onClick={addTodo}>Add</button>
      <ul>
        {todos.map((todo) => (
          <li key={todo.id}>
            <input type="checkbox" checked={todo.completed} onChange={() => toggleTodo(todo.id)} />
            <span style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>{todo.text}</span>
            <button onClick={() => deleteTodo(todo.id)}>Delete</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

59. Infinite Scroll​

function InfiniteScroll() {
  const [items, setItems] = useState([]);
  const [page, setPage] = useState(1);
  const [loading, setLoading] = useState(false);
  const observerRef = useRef();

  useEffect(() => {
    const fetchData = async () => {
      setLoading(true);
      const response = await fetch(`/api/items?page=${page}`);
      const data = await response.json();
      setItems((prev) => [...prev, ...data]);
      setLoading(false);
    };
    fetchData();
  }, [page]);

  useEffect(() => {
    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting && !loading) {
          setPage((prev) => prev + 1);
        }
      },
      { threshold: 1.0 },
    );

    if (observerRef.current) {
      observer.observe(observerRef.current);
    }

    return () => observer.disconnect();
  }, [loading]);

  return (
    <div>
      {items.map((item) => (
        <div key={item.id}>{item.name}</div>
      ))}
      <div ref={observerRef}>{loading && 'Loading...'}</div>
    </div>
  );
}

60. Debounced Search Input​

function SearchInput() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);

  useEffect(() => {
    const handler = setTimeout(() => {
      if (query.trim()) {
        fetch(`/api/search?q=${query}`)
          .then((res) => res.json())
          .then(setResults);
      }
    }, 300);

    return () => clearTimeout(handler);
  }, [query]);

  return (
    <div>
      <input type="text" value={query} onChange={(e) => setQuery(e.target.value)} placeholder="Search..." />
      <ul>
        {results.map((result) => (
          <li key={result.id}>{result.name}</li>
        ))}
      </ul>
    </div>
  );
}
