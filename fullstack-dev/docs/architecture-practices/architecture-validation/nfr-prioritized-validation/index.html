Validating Prioritized Non-functional Requirements

This playbook ensures that the top-priority non-functional requirements (NFRs) agreed with business stakeholders are mapped with the official template and continuously validated across Next.js frontends, NestJS backends, and GCP-hosted infrastructure using GitHub Actions automation.

1. Objective & Scope​

  • Confirm every critical NFR (performance, security, scalability, availability, compliance) is documented in the shared NFR template.
  • Guarantee validation evidence exists before each release and is traceable to automated checks.
  • Align product, engineering, and platform teams around measurable targets within a two-sprint horizon.

2. Mapping Workflow​

  1. Prioritize NFRs with product/business (MoSCoW or RICE scoring).
  2. Map each selected NFR into the template stored at docs/non-functional-requirements/nfr-template.md.
  3. Assign owners (architect, QA lead, SRE) and validation cadence.
  4. Baseline metrics (load targets, SLA/SLO, OWASP Top 10 coverage, recovery RTO/RPO, etc.).
  5. Check in the template updates via pull request so the history is auditable.

Template Snippet​

## NFR-{ID}: {Name}

- **Business Value:** …
- **Category:** Performance | Security | Scalability | Availability | Compliance
- **Target Metric:** e.g., "p95 < 400 ms", "Zero critical CVEs"
- **Validation Method:** Automated load test, ZAP scan, chaos drill…
- **Owner:** {Role / Name}
- **Evidence Link:** Dashboard, report, or run log
- **Status:** Draft | In Validation | Passed | Blocked

4. NestJS Validation Matrix Service​

// src/nfr/nfr-validation.service.ts
import { Injectable } from '@nestjs/common';
import { HttpService } from '@nestjs/axios';

export interface NfrRecord {
  id: string;
  category: 'performance' | 'security' | 'scalability' | 'availability' | 'compliance';
  target: string;
  validator: string;
  evidenceUrl: string;
  status: 'passed' | 'failing' | 'awaiting-validation';
  lastValidatedAt: Date | null;
}

@Injectable()
export class NfrValidationService {
  // Inject an HttpService client to hit GitHub raw file or an internal API
  constructor(private readonly http: HttpService) {}

  async fetchPrioritizedNfrs(): Promise<NfrRecord[]> {
    const response = await this.http.axiosRef.get(
      'https://raw.githubusercontent.com/org/repo/main/docs/non-functional-requirements/nfr-template.json',
    );
    return response.data.filter((nfr: NfrRecord) => nfr.status !== 'draft');
  }

  async computeValidationScore(): Promise<{ total: number; valid: number; failing: number }> {
    const nfrs = await this.fetchPrioritizedNfrs();
    const valid = nfrs.filter((nfr) => nfr.status === 'passed').length;
    return { total: nfrs.length, valid, failing: nfrs.length - valid };
  }
}

5. Next.js Dashboard Widget​

// app/admin/nfr-validation/page.tsx
'use client';
import useSWR from 'swr';

const fetcher = (url: string) => fetch(url).then((res) => res.json());

export default function NfrValidationDashboard() {
  const { data, error, isLoading } = useSWR('/api/nfr/status', fetcher, { refreshInterval: 60000 });

  if (isLoading) return <p className="p-6">Loading prioritized NFR status…</p>;
  if (error) return <p className="p-6 text-red-500">Failed to load NFR status.</p>;

  return (
    <div className="p-6 space-y-4">
      <header>
        <h1 className="text-2xl font-semibold">Prioritized NFR Validation</h1>
        <p className="text-gray-600">Real-time check on mapped NFR evidence.</p>
      </header>
      <div className="grid gap-4 md:grid-cols-2 lg:grid-cols-3">
        {data.map((nfr: any) => (
          <article key={nfr.id} className="rounded border bg-white p-4 shadow">
            <h2 className="text-lg font-medium">
              {nfr.id} · {nfr.category}
            </h2>
            <p className="text-sm text-gray-600">Target: {nfr.target}</p>
            <p className="text-sm">Validator: {nfr.validator}</p>
            <a className="text-sm text-blue-600 underline" href={nfr.evidenceUrl} target="_blank" rel="noreferrer">
              Evidence
            </a>
            <p
              className={`mt-2 inline-flex items-center rounded px-2 py-1 text-xs font-semibold ${
                nfr.status === 'passed' ? 'bg-green-100 text-green-700' : 'bg-yellow-100 text-yellow-700'
              }`}
            >
              {nfr.status.toUpperCase()}
            </p>
          </article>
        ))}
      </div>
    </div>
  );
}

6. GitHub Actions Enforcement​

# .github/workflows/nfr-validation-check.yml
name: Validate Prioritized NFRs

on:
  pull_request:
    paths:
      - 'docs/non-functional-requirements/**'
      - 'tests/nfr/**'

jobs:
  validate-nfrs:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Ensure prioritized NFRs mapped
        run: |
          node scripts/validate-nfr-template.js

      - name: Execute automated evidence checks
        run: |
          pnpm install
          pnpm run test:nfr

      - name: Publish evidence summary
        uses: actions/upload-artifact@v4
        with:
          name: nfr-evidence
          path: reports/nfr-summary.json

7. GCP Monitoring & Alerting​

  • Cloud Monitoring Dashboards track p95 latency, error rates, and uptime mapped to each NFR ID.
  • Cloud Logging Metrics aggregate security scan events, vulnerability findings, and audit trails.
  • Cloud Scheduler + Cloud Functions trigger weekly audits that update evidence links in Firestore, which the NestJS service consumes.

8. Governance Checklist​

  • Prioritized NFRs documented in template with targets and owners.
  • Automated validation tasks scheduled (CI pipelines + GCP jobs).
  • Evidence accessible (dashboards, PDF reports, test logs).
  • Release go/no-go includes NFR validation score.
  • Retrospective review when validation fails to capture learnings.

By enforcing templated documentation, automated validation, and cloud-native observability, teams maintain continuous assurance that business-critical NFRs remain satisfied throughout the delivery lifecycle.
