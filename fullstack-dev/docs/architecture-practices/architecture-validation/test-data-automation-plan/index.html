Automated Test Data Loading Plan

This guide defines how automated test data is prepared and loaded to reproduce critical business flows in Next.js/NestJS applications deployed on GCP, with validation wired into GitHub Actions.

1. Purpose​

  • Guarantee every automated test run starts with reliable, business-aligned datasets.
  • Document ownership, storage, refresh cadence, and masking rules for reusable fixtures.
  • Provide repeatable infrastructure scripts so developers and CI pipelines can hydrate environments on demand.

2. Test Data Categories​

CategoryDescriptionSourceRefresh Cadence
Core AccountsDefault buyers, admins, service accountsSeed scriptsNightly
Catalog SamplesRepresentative product sets with pricing rulesCSV in GCS bucketWeekly
Transactional DataOrders, payments, refunds for regression flowsSanitized prod snapshotBi-weekly
Edge CasesBoundary values, fraud scenarios, feature flagsJSON fixtures in repoOn change

3. NestJS Data Loader Module​

// src/testing/test-data.module.ts
import { Module } from '@nestjs/common';
import { TestDataService } from './test-data.service';
import { PrismaModule } from '../prisma/prisma.module';

@Module({
  imports: [PrismaModule],
  providers: [TestDataService],
  exports: [TestDataService],
})
export class TestDataModule {}

// src/testing/test-data.service.ts
import { Injectable, Logger } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';
import * as csvParser from 'csv-parse/sync';
import { Storage } from '@google-cloud/storage';

@Injectable()
export class TestDataService {
  private readonly storage = new Storage();
  private readonly logger = new Logger(TestDataService.name);

  constructor(private readonly prisma: PrismaService) {}

  async seedCoreAccounts() {
    await this.prisma.user.deleteMany({ where: { email: { contains: '+fixture@' } } });
    await this.prisma.user.createMany({
      data: [
        { email: 'buyer+fixture@example.com', role: 'buyer', password: 'hashed' },
        { email: 'admin+fixture@example.com', role: 'admin', password: 'hashed' },
      ],
    });
  }

  async loadCatalogFromGcs(bucket: string, objectPath: string) {
    const [file] = await this.storage.bucket(bucket).file(objectPath).download();
    const records = csvParser.parse(file.toString(), { columns: true });
    await this.prisma.product.createMany({ data: records });
  }

  async prepareTransactionalData(fixtures: any[]) {
    await this.prisma.order.createMany({ data: fixtures });
  }
}

4. Next.js Test Harness​

// app/test-data/checklist/page.tsx
'use client';
import useSWR from 'swr';

const fetcher = (url: string) => fetch(url).then((res) => res.json());

export default function TestDataChecklist() {
  const { data, isLoading, error } = useSWR('/api/test-data/status', fetcher, { refreshInterval: 30000 });

  if (isLoading) return <p className="p-6">Checking data fixtures…</p>;
  if (error) return <p className="p-6 text-red-500">Unable to fetch test data status.</p>;

  return (
    <section className="space-y-4 p-6">
      <header>
        <h1 className="text-2xl font-semibold">Automated Test Data Status</h1>
        <p className="text-gray-600">Business-critical fixtures validated before test execution.</p>
      </header>
      <ul className="space-y-2">
        {data.map((item: any) => (
          <li key={item.id} className="flex items-center justify-between rounded border bg-white p-3 shadow">
            <span>
              <strong>{item.name}</strong> · {item.category}
            </span>
            <span
              className={`rounded px-2 py-1 text-xs font-semibold ${
                item.status === 'ready' ? 'bg-green-100 text-green-700' : 'bg-yellow-100 text-yellow-700'
              }`}
            >
              {item.status.toUpperCase()}
            </span>
          </li>
        ))}
      </ul>
    </section>
  );
}

6. GCP Data Management​

  • Cloud Storage stores CSV/JSON fixtures; versioning enabled for traceability.
  • Cloud SQL (PostgreSQL) hosts sanitized datasets; point-in-time recovery for rollback tests.
  • Cloud Scheduler triggers weekly refresh pipelines (Cloud Run job invoking NestJS seed service).
  • Secret Manager secures API keys and service credentials used during seeding.

8. Data Masking & Sanitization​

// src/testing/data-sanitizer.service.ts
import { Injectable } from '@nestjs/common';
import * as crypto from 'crypto';

@Injectable()
export class DataSanitizerService {
  maskEmail(email: string): string {
    const [local, domain] = email.split('@');
    const masked = local.slice(0, 2) + '***' + local.slice(-1);
    return `${masked}@${domain}`;
  }

  maskCreditCard(cardNumber: string): string {
    return cardNumber.slice(0, 4) + ' **** **** ' + cardNumber.slice(-4);
  }

  hashPII(value: string): string {
    return crypto.createHash('sha256').update(value).digest('hex').slice(0, 16);
  }

  async sanitizeProductionSnapshot(data: any[]): Promise<any[]> {
    return data.map((record) => ({
      ...record,
      email: this.maskEmail(record.email),
      phone: this.hashPII(record.phone),
      creditCard: record.creditCard ? this.maskCreditCard(record.creditCard) : null,
      ssn: null, // Remove completely
      // Preserve structure but protect PII
    }));
  }
}

10. Advanced Loading Strategies​

Parallel Data Loading​

// scripts/seed-test-data.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from '../src/app.module';
import { TestDataService } from '../src/testing/test-data.service';

async function bootstrap() {
  const app = await NestFactory.createApplicationContext(AppModule);
  const testDataService = app.get(TestDataService);

  console.log('🌱 Starting test data seeding...');

  // Parallel loading for independent datasets
  await Promise.all([
    testDataService.seedCoreAccounts(),
    testDataService.loadCatalogFromGcs('test-fixtures', 'catalog/products.csv'),
    testDataService.loadReferenceData(),
  ]);

  // Sequential loading for dependent datasets
  await testDataService.prepareTransactionalData();
  await testDataService.setupFeatureFlags();

  console.log('✅ Test data seeding completed');
  await app.close();
}

bootstrap();

Incremental Data Updates​

// src/testing/test-data.service.ts (additional methods)
export class TestDataService {
  // ... existing methods ...

  async updateIncrementalData(lastUpdateTime: Date) {
    const newProducts = await this.fetchNewProductsSince(lastUpdateTime);
    if (newProducts.length > 0) {
      await this.prisma.product.createMany({ data: newProducts });
      this.logger.log(`Added ${newProducts.length} new products`);
    }
  }

  async loadDataSnapshot(snapshotId: string) {
    const snapshot = await this.storage.bucket('test-snapshots').file(`${snapshotId}.json`).download();

    const data = JSON.parse(snapshot[0].toString());
    await this.restoreFromSnapshot(data);
  }

  private async restoreFromSnapshot(data: any) {
    await this.prisma.$transaction(async (tx) => {
      await tx.user.deleteMany({});
      await tx.product.deleteMany({});
      await tx.order.deleteMany({});

      await tx.user.createMany({ data: data.users });
      await tx.product.createMany({ data: data.products });
      await tx.order.createMany({ data: data.orders });
    });
  }
}

11. GitHub Actions: Complete Pipeline​

# .github/workflows/test-data-lifecycle.yml
name: Test Data Lifecycle Management

on:
  schedule:
    - cron: '0 2 * * *' # Daily at 2 AM UTC
  workflow_dispatch:
    inputs:
      environment:
        description: 'Target environment'
        required: true
        default: 'staging'
        type: choice
        options:
          - dev
          - staging
          - qa
      data_type:
        description: 'Data type to load'
        required: true
        default: 'full'
        type: choice
        options:
          - core
          - catalog
          - transactional
          - full

jobs:
  validate-data-plan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Validate data plan document
        run: |
          if [ ! -f "docs/test-data-plan.md" ]; then
            echo "❌ Test data plan document missing"
            exit 1
          fi
          echo "✅ Test data plan validated"

  prepare-environment:
    needs: validate-data-plan
    runs-on: ubuntu-latest
    outputs:
      db_instance: ${{ steps.setup.outputs.db_instance }}
      gcs_bucket: ${{ steps.setup.outputs.gcs_bucket }}

    steps:
      - uses: actions/checkout@v4

      - uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Setup GCP resources
        id: setup
        run: |
          ENV="${{ github.event.inputs.environment || 'staging' }}"
          echo "db_instance=test-db-${ENV}" >> $GITHUB_OUTPUT
          echo "gcs_bucket=test-data-${ENV}" >> $GITHUB_OUTPUT

  load-test-data:
    needs: prepare-environment
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install

      - uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Download sanitized production snapshot
        if: ${{ github.event.inputs.data_type == 'transactional' || github.event.inputs.data_type == 'full' }}
        run: |
          gsutil cp gs://${{ needs.prepare-environment.outputs.gcs_bucket }}/snapshots/latest.json ./data/snapshot.json

      - name: Run data seeding
        env:
          DATABASE_URL: ${{ secrets.TEST_DATABASE_URL }}
          GCS_BUCKET: ${{ needs.prepare-environment.outputs.gcs_bucket }}
          DATA_TYPE: ${{ github.event.inputs.data_type }}
        run: |
          pnpm ts-node scripts/seed-test-data.ts --type ${DATA_TYPE}

      - name: Verify data integrity
        run: |
          pnpm ts-node scripts/verify-test-data.ts

      - name: Generate data report
        run: |
          pnpm ts-node scripts/generate-data-report.ts > reports/data-load-summary.json

      - name: Upload data report
        uses: actions/upload-artifact@v4
        with:
          name: test-data-report-${{ github.run_id }}
          path: reports/data-load-summary.json

  notify-completion:
    needs: load-test-data
    runs-on: ubuntu-latest
    if: always()

    steps:
      - name: Send Slack notification
        uses: slackapi/slack-github-action@v1
        with:
          webhook-url: ${{ secrets.SLACK_WEBHOOK_URL }}
          payload: |
            {
              "text": "Test Data Loading ${{ job.status }}",
              "blocks": [
                {
                  "type": "section",

12. Data Verification Scripts​

// scripts/verify-test-data.ts
import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

interface VerificationResult {
  check: string;
  status: 'pass' | 'fail';
  details: string;
}

async function verifyTestData(): Promise<void> {
  const results: VerificationResult[] = [];

  // Check 1: Core accounts exist
  const userCount = await prisma.user.count({ where: { email: { contains: '+fixture@' } } });
  results.push({
    check: 'Core accounts',
    status: userCount >= 2 ? 'pass' : 'fail',
    details: `Found ${userCount} test accounts (expected: >= 2)`,
  });

  // Check 2: Catalog data loaded
  const productCount = await prisma.product.count();
  results.push({
    check: 'Catalog data',
    status: productCount >= 10 ? 'pass' : 'fail',
    details: `Found ${productCount} products (expected: >= 10)`,
  });

  // Check 3: Transactional data
  const orderCount = await prisma.order.count({ where: { status: 'completed' } });
  results.push({
    check: 'Transactional data',
    status: orderCount >= 5 ? 'pass' : 'fail',
    details: `Found ${orderCount} completed orders (expected: >= 5)`,
  });

  // Check 4: Data relationships
  const ordersWithUsers = await prisma.order.count({ where: { user: { isNot: null } } });
  results.push({
    check: 'Data relationships',
    status: ordersWithUsers === orderCount ? 'pass' : 'fail',
    details: `All orders linked to users: ${ordersWithUsers === orderCount}`,
  });

  // Print results
  console.log('\n📊 Test Data Verification Results:\n');
  results.forEach((result) => {
    const icon = result.status === 'pass' ? '✅' : '❌';
    console.log(`${icon} ${result.check}: ${result.details}`);
  });

  const failedChecks = results.filter((r) => r.status === 'fail').length;
  if (failedChecks > 0) {
    console.error(`\n❌ ${failedChecks} verification check(s) failed`);
    process.exit(1);
  }

  console.log('\n✅ All verification checks passed');
  await prisma.$disconnect();
}

verifyTestData();

13. Operational Checklist​

Planning Phase​

  • Data templates reviewed with product/business for completeness.
  • Business flows mapped to required test data categories.
  • Data ownership assigned (who maintains each fixture set).
  • PII stripped or masked before committing fixtures.
  • Data refresh cadence defined and documented.

Implementation Phase​

  • Seed scripts idempotent and safe for concurrent runs.
  • Data loading scripts support both full and incremental modes.
  • Verification scripts validate data integrity post-load.
  • GCS buckets configured with proper IAM permissions.
  • Cloud SQL instances configured for test environments.

Automation Phase​

  • GitHub workflow executed in pre-prod nightly to detect schema drift.
  • Workflow supports manual triggers with environment selection.
  • Monitoring dashboards track seed job success/failure.
  • Slack notifications configured for load failures.
  • Data reports archived for audit trail.

Maintenance Phase​

  • Monthly review of test data coverage vs. production patterns.
  • Quarterly sanitization of production snapshots.
  • Document updates when business flows change.
  • Performance optimization of data loading scripts.

A disciplined test data strategy ensures automated suites exercise real-world scenarios, satisfying business expectations without compromising data governance. By implementing proper planning, sanitization, automation, and verification, teams maintain high-quality test data that accurately reflects production behavior.
