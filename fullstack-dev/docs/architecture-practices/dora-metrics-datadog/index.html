DORA Metrics Implementation with Github Action

What are DORA Metrics?​

DORA metrics are four key indicators used to measure DevOps performance:

  • Deployment Frequency: How often code is deployed to production.
  • Lead Time for Changes: The time it takes for a code change to reach production.
  • Change Failure Rate: The percentage of deployments that cause a failure in production.
  • Mean Time to Recovery (MTTR): How quickly teams recover from a failure in production.

These metrics help organizations assess and improve their software delivery and operational performance.

Overview​

DORA metrics (Deployment Frequency, Lead Time for Changes, Change Failure Rate, Mean Time to Recovery) help measure DevOps performance. Datadog provides native support for DORA metrics and integrates with CI/CD, source control, and incident management tools.

Steps to Implement DORA Metrics with Datadog​

1. Integrate Source Control & CI/CD​

To integrate your source control and CI/CD pipeline for DORA metrics collection:

a. Connect GitHub to Datadog​

  • Go to Datadog Integrations and search for "GitHub".
  • Follow the instructions to connect your repository. This enables Datadog to ingest commit, PR, and deployment data.
  • Reference: Datadog GitHub Integration

b. Enable CI Visibility for GitHub Actions​

  • In Datadog, enable CI Visibility for your organization.
  • In your GitHub Actions workflow, add the Datadog CI Visibility Action: 
    - name: Datadog CI Visibility
      uses: DataDog/ci-visibility-github-actions@v1
      with:
        api-key: ${{ secrets.DATADOG_API_KEY }}
        datadog-site: datadoghq.com
  • This will send pipeline, job, and test data to Datadog for analysis.
  • Reference: Datadog CI Visibility

c. Track Deployment Events​

  • In your deployment workflow, send deployment events to Datadog: 
    - name: Notify Datadog of Deployment
      uses: DataDog/datadog-actions@v1
      with:
        api-key: ${{ secrets.DATADOG_API_KEY }}
        datadog-site: datadoghq.com
        event-title: 'Deployment to production'
        event-text: 'Deployed commit ${{ github.sha }}'
        tags: 'env:production,service:api-gateway'
  • This enables Datadog to correlate deployments with incidents and performance data for DORA metrics.

2. Configure Deployment Tracking​

  • Use Datadog's Deployment Tracking to send deployment events from GitHub Actions or ArgoCD.
  • Example GitHub Actions step: 
    - name: Notify Datadog of Deployment
      uses: DataDog/datadog-actions@v1
      with:
        api-key: ${{ secrets.DATADOG_API_KEY }}
        datadog-site: datadoghq.com
        event-title: 'Deployment to production'
        event-text: 'Deployed commit ${{ github.sha }}'
        tags: 'env:production,service:api-gateway'

3. Monitor Incidents & Failures​

  • Integrate incident management (PagerDuty, Opsgenie, or Datadog monitors) to track change failure rate and MTTR.
  • Use Datadog monitors to alert on failed deployments or service outages.

4. Visualize DORA Metrics​

  • Use the DORA Metrics dashboard in Datadog to view and analyze metrics.
  • Customize dashboards to filter by service, environment, or deployment type.

Example: GitHub Actions + Datadog Integration​

Add the following to your CI/CD pipeline to send deployment events:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      # ... your build & deploy steps ...
      - name: Notify Datadog of Deployment
        uses: DataDog/datadog-actions@v1
        with:
          api-key: ${{ secrets.DATADOG_API_KEY }}
          datadog-site: datadoghq.com
          event-title: 'Deployment to production'
          event-text: 'Deployed commit ${{ github.sha }}'
          tags: 'env:production,service:api-gateway'

How to Calculate DORA Metrics with GitHub Actions, BigQuery, and Looker​

You can automate DORA metric collection and visualization using GitHub Actions for data collection, BigQuery for storage and analysis, and Looker for dashboards.

Step 1: Collect DORA Data in GitHub Actions​

Add steps to your workflow to log deployment events and failures. Example:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      # ... your build & deploy steps ...
      - name: Log deployment event
        run: |
          echo '{"timestamp": "$(date -u +%Y-%m-%dT%H:%M:%SZ)", "commit": "${GITHUB_SHA}", "status": "success", "workflow": "deploy"}' >> dora_metrics.json
      - name: Upload metrics to artifact
        uses: actions/upload-artifact@v3
        with:
          name: dora_metrics
          path: dora_metrics.json

For failures, add a similar step in the error handling section.

Step 2: Export Data to BigQuery​

Use a scheduled workflow or post-deployment job to upload the metrics file to Google Cloud Storage. Example:

jobs:
  export_metrics:
    runs-on: ubuntu-latest
    steps:
      - name: Download metrics artifact
        uses: actions/download-artifact@v3
        with:
          name: dora_metrics
      - name: Upload to Google Cloud Storage
        uses: google-github-actions/upload-cloud-storage@v1
        with:
          path: dora_metrics.json
          destination: gs://your-bucket/dora_metrics/

You can later import or query this data from BigQuery, or connect Looker directly to BigQuery after loading the data from Cloud Storage.

(Optional) Load Data from Google Cloud Storage to BigQuery​

After uploading your metrics file to Google Cloud Storage, you can load it into BigQuery using the bq CLI or a scheduled job:

jobs:
  load_to_bigquery:
    runs-on: ubuntu-latest
    steps:
      - name: Load metrics from GCS to BigQuery
        run: |
          bq load --source_format=NEWLINE_DELIMITED_JSON your_dataset.dora_metrics gs://your-bucket/dora_metrics/dora_metrics.json

This step makes your metrics available for SQL analysis and Looker dashboards.​

Step 3: Model DORA Metrics in BigQuery​

Write SQL queries to calculate each metric:

  • Deployment Frequency

    SELECT COUNT(*) AS deployments, DATE(timestamp) AS day
    FROM `your_dataset.dora_metrics`
    WHERE status = 'success'
    GROUP BY day
    ORDER BY day DESC

  • Lead Time for Changes

    SELECT AVG(TIMESTAMP_DIFF(deploy_time, commit_time, HOUR)) AS avg_lead_time
    FROM (
      SELECT
        commit_time,
        MIN(deploy_time) AS deploy_time
      FROM `your_dataset.dora_metrics`
      GROUP BY commit_time
    )

  • Change Failure Rate

    SELECT
      COUNTIF(status = 'failure') / COUNT(*) AS failure_rate
    FROM `your_dataset.dora_metrics`

  • MTTR

    SELECT AVG(TIMESTAMP_DIFF(recovery_time, failure_time, MINUTE)) AS avg_mttr
    FROM `your_dataset.incidents`

Step 4: Visualize in Looker​

  • Connect Looker to your BigQuery dataset.
  • Create Looks and dashboards using the above queries.
  • Use filters and charts to visualize trends over time.

Notes:

  • Enrich your metrics file with commit timestamps, deployment timestamps, and incident data as needed.
  • Automate the workflow to run after every deployment or on a schedule.
  • Ensure your GitHub Actions runner has access to Google Cloud credentials.
