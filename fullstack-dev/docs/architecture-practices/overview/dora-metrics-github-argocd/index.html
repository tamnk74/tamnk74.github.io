DORA Metrics Implementation for Microservices with GitHub Actions and ArgoCD

What are DORA Metrics?​

DORA (DevOps Research and Assessment) metrics are four key indicators used to measure DevOps performance:

  • Deployment Frequency: How often code is deployed to production.
  • Lead Time for Changes: The time it takes for a code change (from commit) to reach production.
  • Change Failure Rate: The percentage of deployments that cause a failure in production.
  • Mean Time to Recovery (MTTR): How quickly teams recover from a failure in production.

These metrics help organizations assess and improve their software delivery and operational performance. For microservices architectures, tracking these metrics per service provides valuable insights into team performance and system reliability.

Architecture Overview​

This guide covers DORA metrics collection for a microservices system using:

  • GitHub Actions: CI pipeline for building, testing, and creating deployment artifacts
  • ArgoCD: GitOps CD tool for deploying to Kubernetes
  • BigQuery: Data collection and analysis platform
  • Kubernetes/GKE: Container orchestration platform

Data Flow​

GitHub (Code) → GitHub Actions (Build/Test) → Container Registry
                                                       ↓
                                            ArgoCD (Deploy) → Kubernetes
                                                       ↓
                                            BigQuery (Metrics) → Looker/Data Studio

Implementation Overview​

This guide provides a custom solution for building DORA metrics collection using GitHub Actions, BigQuery, and visualization tools.

Step 1: Define BigQuery Schema​

Create a BigQuery dataset and table for DORA metrics:

-- Create dataset
CREATE SCHEMA IF NOT EXISTS `your_project.dora_metrics`
OPTIONS (
  location = 'US'
);

-- Create deployments table
CREATE TABLE IF NOT EXISTS `your_project.dora_metrics.deployments` (
  deployment_id STRING NOT NULL,
  service_name STRING NOT NULL,
  environment STRING NOT NULL,
  commit_sha STRING NOT NULL,
  commit_timestamp TIMESTAMP NOT NULL,
  commit_author STRING,
  pr_number INT64,
  build_started_at TIMESTAMP NOT NULL,
  build_completed_at TIMESTAMP NOT NULL,
  deployment_started_at TIMESTAMP NOT NULL,
  deployment_completed_at TIMESTAMP,
  deployment_status STRING NOT NULL,  -- success, failed, rolled_back
  deployment_tool STRING NOT NULL,    -- argocd, kubectl, helm
  lead_time_minutes INT64,
  deployed_by STRING,
  rollback_of STRING,  -- deployment_id if this is a rollback
  tags ARRAY<STRING>,
  metadata JSON
) PARTITION BY DATE(deployment_completed_at);

-- Create incidents table
CREATE TABLE IF NOT EXISTS `your_project.dora_metrics.incidents` (
  incident_id STRING NOT NULL,
  service_name STRING NOT NULL,
  environment STRING NOT NULL,
  severity STRING NOT NULL,
  incident_started_at TIMESTAMP NOT NULL,
  incident_detected_at TIMESTAMP NOT NULL,
  incident_resolved_at TIMESTAMP,
  caused_by_deployment_id STRING,
  resolution_type STRING,  -- fixed, rolled_back, mitigated
  mttr_minutes INT64,
  tags ARRAY<STRING>,
  metadata JSON
) PARTITION BY DATE(incident_started_at);

-- Create a view for DORA metrics calculation
CREATE OR REPLACE VIEW `your_project.dora_metrics.dora_summary` AS
WITH deployment_stats AS (
  SELECT
    service_name,
    environment,
    DATE(deployment_completed_at) as deploy_date,
    COUNT(*) as deployment_count,
    COUNTIF(deployment_status = 'failed') as failed_deployments,
    AVG(lead_time_minutes) as avg_lead_time_minutes
  FROM `your_project.dora_metrics.deployments`
  WHERE deployment_status IN ('success', 'failed')
    AND deployment_completed_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
  GROUP BY service_name, environment, deploy_date
),
incident_stats AS (
  SELECT
    service_name,
    environment,
    DATE(incident_started_at) as incident_date,
    COUNT(*) as incident_count,
    AVG(mttr_minutes) as avg_mttr_minutes
  FROM `your_project.dora_metrics.incidents`
  WHERE incident_resolved_at IS NOT NULL
    AND incident_started_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
  GROUP BY service_name, environment, incident_date
)
SELECT
  COALESCE(d.service_name, i.service_name) as service_name,
  COALESCE(d.environment, i.environment) as environment,
  COALESCE(d.deploy_date, i.incident_date) as date,
  COALESCE(d.deployment_count, 0) as deployments_per_day,
  COALESCE(d.avg_lead_time_minutes, 0) as avg_lead_time_minutes,
  SAFE_DIVIDE(COALESCE(d.failed_deployments, 0), COALESCE(d.deployment_count, 1)) * 100 as change_failure_rate,
  COALESCE(i.avg_mttr_minutes, 0) as avg_mttr_minutes
FROM deployment_stats d
FULL OUTER JOIN incident_stats i
  ON d.service_name = i.service_name
  AND d.environment = i.environment
  AND d.deploy_date = i.incident_date
ORDER BY date DESC, service_name;

Step 2: Enhanced GitHub Actions Workflow​

Create a comprehensive workflow that collects all necessary metrics:

name: Build, Deploy, and Track Metrics

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  SERVICE_NAME: user-service
  GCP_PROJECT: your-gcp-project
  BQ_DATASET: dora_metrics
  ENVIRONMENT: production

jobs:
  build-and-track:
    runs-on: ubuntu-latest

    outputs:
      deployment-id: ${{ steps.generate-id.outputs.deployment-id }}
      commit-time: ${{ steps.git-info.outputs.commit-time }}

    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0

      # Generate unique deployment ID
      - name: Generate deployment ID
        id: generate-id
        run: |
          DEPLOYMENT_ID="${{ env.SERVICE_NAME }}-$(date +%Y%m%d-%H%M%S)-${{ github.sha }}"
          echo "deployment-id=$DEPLOYMENT_ID" >> $GITHUB_OUTPUT
          echo "DEPLOYMENT_ID=$DEPLOYMENT_ID" >> $GITHUB_ENV

      # Extract Git information
      - name: Extract Git metadata
        id: git-info
        run: |
          COMMIT_TIME=$(git log -1 --format=%cI)
          COMMIT_AUTHOR=$(git log -1 --format=%an)
          PR_NUMBER=${{ github.event.pull_request.number }}

          echo "commit-time=$COMMIT_TIME" >> $GITHUB_OUTPUT
          echo "commit-author=$COMMIT_AUTHOR" >> $GITHUB_OUTPUT
          echo "pr-number=$PR_NUMBER" >> $GITHUB_OUTPUT
          echo "BUILD_START=$(date -u +%Y-%m-%dT%H:%M:%SZ)" >> $GITHUB_ENV

      - name: Set up Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test -- --ci --coverage

      - name: Build Docker image
        run: |
          docker build -t gcr.io/${{ env.GCP_PROJECT }}/${{ env.SERVICE_NAME }}:${{ github.sha }} .
          docker tag gcr.io/${{ env.GCP_PROJECT }}/${{ env.SERVICE_NAME }}:${{ github.sha }} \
                     gcr.io/${{ env.GCP_PROJECT }}/${{ env.SERVICE_NAME }}:latest

      # Authenticate to Google Cloud
      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v1
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Configure Docker for GCR
        run: gcloud auth configure-docker gcr.io

      - name: Push to Container Registry
        run: |
          docker push gcr.io/${{ env.GCP_PROJECT }}/${{ env.SERVICE_NAME }}:${{ github.sha }}
          docker push gcr.io/${{ env.GCP_PROJECT }}/${{ env.SERVICE_NAME }}:latest
          echo "BUILD_END=$(date -u +%Y-%m-%dT%H:%M:%SZ)" >> $GITHUB_ENV

      # Update ArgoCD manifest
      - name: Update ArgoCD manifest
        id: update-manifest
        run: |
          git clone https://x-access-token:${{ secrets.GH_TOKEN }}@github.com/${{ github.repository_owner }}/k8s-manifests.git
          cd k8s-manifests

          # Update image tag in kustomization
          sed -i "s|image: gcr.io/${{ env.GCP_PROJECT }}/${{ env.SERVICE_NAME }}:.*|image: gcr.io/${{ env.GCP_PROJECT }}/${{ env.SERVICE_NAME }}:${{ github.sha }}|" \
            overlays/${{ env.ENVIRONMENT }}/${{ env.SERVICE_NAME }}/kustomization.yaml

          git config user.name "GitHub Actions"
          git config user.email "actions@github.com"
          git add .
          git commit -m "Deploy ${{ env.SERVICE_NAME }}:${{ github.sha }} [deployment-id: ${{ env.DEPLOYMENT_ID }}]"
          git push

          echo "DEPLOYMENT_START=$(date -u +%Y-%m-%dT%H:%M:%SZ)" >> $GITHUB_ENV

      # Send build metrics to BigQuery
      - name: Record build metrics
        run: |
          cat << EOF > /tmp/deployment_metric.json
          {
            "deployment_id": "${{ env.DEPLOYMENT_ID }}",
            "service_name": "${{ env.SERVICE_NAME }}",
            "environment": "${{ env.ENVIRONMENT }}",
            "commit_sha": "${{ github.sha }}",
            "commit_timestamp": "${{ steps.git-info.outputs.commit-time }}",
            "commit_author": "${{ steps.git-info.outputs.commit-author }}",
            "pr_number": ${{ steps.git-info.outputs.pr-number || 'null' }},
            "build_started_at": "${{ env.BUILD_START }}",
            "build_completed_at": "${{ env.BUILD_END }}",
            "deployment_started_at": "${{ env.DEPLOYMENT_START }}",
            "deployment_status": "in_progress",
            "deployment_tool": "argocd",
            "deployed_by": "${{ github.actor }}",
            "tags": ["github-actions", "automated"],
            "metadata": {
              "workflow_run_id": "${{ github.run_id }}",
              "repository": "${{ github.repository }}",
              "branch": "${{ github.ref_name }}"
            }
          }
          EOF

          bq insert --project_id=${{ env.GCP_PROJECT }} \
            ${{ env.BQ_DATASET }}.deployments \
            /tmp/deployment_metric.json

  # Wait for ArgoCD to complete deployment
  wait-for-deployment:
    needs: build-and-track
    runs-on: ubuntu-latest
    steps:
      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v1
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Get GKE credentials
        run: |
          gcloud container clusters get-credentials ${{ secrets.GKE_CLUSTER }} \
            --region ${{ secrets.GKE_REGION }} \
            --project ${{ env.GCP_PROJECT }}

      - name: Install ArgoCD CLI
        run: |
          curl -sSL -o /usr/local/bin/argocd https://github.com/argoproj/argo-cd/releases/latest/download/argocd-linux-amd64
          chmod +x /usr/local/bin/argocd

      - name: Wait for ArgoCD sync
        id: argocd-wait
        run: |
          DEPLOYMENT_START=$(date +%s)

          # Login to ArgoCD
          argocd login ${{ secrets.ARGOCD_SERVER }} \
            --username admin \
            --password ${{ secrets.ARGOCD_PASSWORD }} \
            --grpc-web

          # Wait for sync to complete (timeout 10 minutes)
          TIMEOUT=600
          ELAPSED=0

          while [ $ELAPSED -lt $TIMEOUT ]; do
            SYNC_STATUS=$(argocd app get ${{ env.SERVICE_NAME }} -o json | jq -r '.status.sync.status')
            HEALTH_STATUS=$(argocd app get ${{ env.SERVICE_NAME }} -o json | jq -r '.status.health.status')
            
            echo "Sync: $SYNC_STATUS, Health: $HEALTH_STATUS"
            
            if [ "$SYNC_STATUS" == "Synced" ] && [ "$HEALTH_STATUS" == "Healthy" ]; then
              echo "DEPLOYMENT_STATUS=success" >> $GITHUB_ENV
              echo "DEPLOYMENT_END=$(date -u +%Y-%m-%dT%H:%M:%SZ)" >> $GITHUB_ENV
              DEPLOYMENT_END=$(date +%s)
              LEAD_TIME=$(( ($DEPLOYMENT_END - $(date -d "${{ needs.build-and-track.outputs.commit-time }}" +%s)) / 60 ))
              echo "LEAD_TIME=$LEAD_TIME" >> $GITHUB_ENV
              echo "✅ Deployment successful"
              exit 0
            elif [ "$HEALTH_STATUS" == "Degraded" ] || [ "$SYNC_STATUS" == "Unknown" ]; then
              echo "DEPLOYMENT_STATUS=failed" >> $GITHUB_ENV
              echo "DEPLOYMENT_END=$(date -u +%Y-%m-%dT%H:%M:%SZ)" >> $GITHUB_ENV
              echo "❌ Deployment failed"
              exit 1
            fi
            
            sleep 10
            ELAPSED=$((ELAPSED + 10))
          done

          echo "DEPLOYMENT_STATUS=timeout" >> $GITHUB_ENV
          echo "⏱️  Deployment timeout"
          exit 1

      # Update deployment status in BigQuery
      - name: Update deployment status
        if: always()
        run: |
          bq query --project_id=${{ env.GCP_PROJECT }} --use_legacy_sql=false "
            UPDATE \`${{ env.GCP_PROJECT }}.${{ env.BQ_DATASET }}.deployments\`
            SET 
              deployment_completed_at = TIMESTAMP('${{ env.DEPLOYMENT_END }}'),
              deployment_status = '${{ env.DEPLOYMENT_STATUS }}',
              lead_time_minutes = ${{ env.LEAD_TIME || 'NULL' }}
            WHERE deployment_id = '${{ needs.build-and-track.outputs.deployment-id }}'
          "

      # Send notification
      - name: Notify team
        if: failure()
        run: |
          # Send Slack notification, PagerDuty alert, etc.
          echo "Deployment failed for ${{ env.SERVICE_NAME }}"

Step 3: ArgoCD Monitoring Script​

Create a Kubernetes CronJob to monitor ArgoCD applications and track deployment status:

apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-metrics-collector
  namespace: argocd
data:
  collect_metrics.sh: |
    #!/bin/bash
    set -e

    # Configuration
    ARGOCD_SERVER="argocd-server.argocd.svc.cluster.local"
    BQ_PROJECT="${GCP_PROJECT}"
    BQ_DATASET="dora_metrics"

    # Login to ArgoCD
    argocd login $ARGOCD_SERVER --auth-token $ARGOCD_TOKEN --grpc-web

    # Get all applications
    APPS=$(argocd app list -o json)

    # Process each application
    echo "$APPS" | jq -c '.[]' | while read app; do
      NAME=$(echo $app | jq -r '.metadata.name')
      SYNC_STATUS=$(echo $app | jq -r '.status.sync.status')
      HEALTH=$(echo $app | jq -r '.status.health.status')
      REVISION=$(echo $app | jq -r '.status.sync.revision')
      SYNCED_AT=$(echo $app | jq -r '.status.operationState.finishedAt // empty')
      
      if [ -n "$SYNCED_AT" ]; then
        # Check if this deployment is already recorded
        EXISTING=$(bq query --project_id=$BQ_PROJECT --format=csv --use_legacy_sql=false "
          SELECT COUNT(*) as count
          FROM \`$BQ_PROJECT.$BQ_DATASET.deployments\`
          WHERE service_name = '$NAME'
            AND commit_sha = '$REVISION'
            AND deployment_completed_at = TIMESTAMP('$SYNCED_AT')
        " | tail -n 1)
        
        if [ "$EXISTING" == "0" ]; then
          # This is a new deployment, record it
          STATUS="success"
          if [ "$HEALTH" != "Healthy" ]; then
            STATUS="failed"
          fi
          
          # Insert deployment record
          cat << EOF | bq insert --project_id=$BQ_PROJECT $BQ_DATASET.deployments
          {
            "deployment_id": "$NAME-$REVISION-$(date +%s)",
            "service_name": "$NAME",
            "environment": "production",
            "commit_sha": "$REVISION",
            "commit_timestamp": "$SYNCED_AT",
            "build_started_at": "$SYNCED_AT",
            "build_completed_at": "$SYNCED_AT",
            "deployment_started_at": "$SYNCED_AT",

Step 4: Incident Tracking​

Implement automated incident tracking by monitoring your services:

# Kubernetes monitoring script for incidents
apiVersion: v1
kind: ConfigMap
metadata:
  name: incident-tracker
  namespace: monitoring
data:
  track_incidents.py: |
    #!/usr/bin/env python3
    import os
    import json
    from datetime import datetime
    from kubernetes import client, config
    from google.cloud import bigquery

    # Initialize Kubernetes client
    config.load_incluster_config()
    v1 = client.CoreV1Api()
    apps_v1 = client.AppsV1Api()

    # Initialize BigQuery client
    bq_client = bigquery.Client()
    project_id = os.environ['GCP_PROJECT']
    dataset_id = 'dora_metrics'
    table_id = 'incidents'

    def check_pod_health(namespace='production'):
        """Check for unhealthy pods"""
        pods = v1.list_namespaced_pod(namespace)
        incidents = []
        
        for pod in pods.items:
            # Check if pod is in a failed or pending state
            if pod.status.phase in ['Failed', 'Unknown']:
                service_name = pod.metadata.labels.get('app', 'unknown')
                incident_id = f"{service_name}-{pod.metadata.name}-{int(datetime.now().timestamp())}"
                
                incident = {
                    'incident_id': incident_id,
                    'service_name': service_name,
                    'environment': namespace,
                    'severity': 'high',
                    'incident_started_at': pod.status.start_time.isoformat() if pod.status.start_time else datetime.now().isoformat(),
                    'incident_detected_at': datetime.now().isoformat(),
                    'tags': ['kubernetes', 'pod-failure'],
                    'metadata': json.dumps({
                        'pod_name': pod.metadata.name,
                        'pod_status': pod.status.phase,
                        'container_statuses': [
                            {
                                'name': cs.name,
                                'ready': cs.ready,
                                'restart_count': cs.restart_count
                            } for cs in (pod.status.container_statuses or [])
                        ]
                    })
                }
                incidents.append(incident)
        
        return incidents

    def check_deployment_health(namespace='production'):
        """Check for deployments with insufficient replicas"""
        deployments = apps_v1.list_namespaced_deployment(namespace)
        incidents = []
        
        for deployment in deployments.items:
            desired = deployment.spec.replicas
            available = deployment.status.available_replicas or 0
            
            if available < desired:
                service_name = deployment.metadata.name
                incident_id = f"{service_name}-replica-deficit-{int(datetime.now().timestamp())}"
                
                incident = {
                    'incident_id': incident_id,
                    'service_name': service_name,
                    'environment': namespace,
                    'severity': 'medium',
                    'incident_started_at': datetime.now().isoformat(),
                    'incident_detected_at': datetime.now().isoformat(),
                    'tags': ['kubernetes', 'replica-deficit'],
                    'metadata': json.dumps({
                        'desired_replicas': desired,
                        'available_replicas': available,
                        'ready_replicas': deployment.status.ready_replicas or 0
                    })
                }
                incidents.append(incident)
        
        return incidents

    def insert_incidents(incidents):
        """Insert incidents into BigQuery"""
        if not incidents:
            return
        
        table_ref = f"{project_id}.{dataset_id}.{table_id}"
        errors = bq_client.insert_rows_json(table_ref, incidents)
        
        if errors:
            print(f"Errors inserting incidents: {errors}")
        else:
            print(f"Inserted {len(incidents)} incidents")

    def main():
        all_incidents = []
        
        # Check pod health
        pod_incidents = check_pod_health()
        all_incidents.extend(pod_incidents)
        
        # Check deployment health
        deployment_incidents = check_deployment_health()
        all_incidents.extend(deployment_incidents)
        
        # Insert into BigQuery
        insert_incidents(all_incidents)
        
        print(f"Total incidents detected: {len(all_incidents)}")

    if __name__ == '__main__':
        main()
---

Step 5: Create DORA Metrics Queries​

Query your DORA metrics from BigQuery:

-- 1. Deployment Frequency (per day, per service, last 30 days)
SELECT
  service_name,
  environment,
  DATE(deployment_completed_at) as deployment_date,
  COUNT(*) as deployments_count,
  -- Elite: Multiple deploys per day, High: Once per day to once per week
  CASE
    WHEN COUNT(*) >= 7 THEN 'Elite'
    WHEN COUNT(*) >= 1 THEN 'High'
    WHEN COUNT(*) >= 0.14 THEN 'Medium'  -- Once per week
    ELSE 'Low'
  END as performance_tier
FROM `your_project.dora_metrics.deployments`
WHERE deployment_completed_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
  AND deployment_status = 'success'
GROUP BY service_name, environment, deployment_date
ORDER BY deployment_date DESC, deployments_count DESC;

-- 2. Lead Time for Changes (minutes from commit to production)
SELECT
  service_name,
  environment,
  AVG(lead_time_minutes) as avg_lead_time_minutes,
  PERCENTILE_CONT(lead_time_minutes, 0.5) OVER() as median_lead_time,
  PERCENTILE_CONT(lead_time_minutes, 0.95) OVER() as p95_lead_time,
  -- Elite: Less than 1 hour, High: 1 day to 1 week
  CASE
    WHEN AVG(lead_time_minutes) < 60 THEN 'Elite'
    WHEN AVG(lead_time_minutes) < 1440 THEN 'High'  -- 1 day
    WHEN AVG(lead_time_minutes) < 10080 THEN 'Medium'  -- 1 week
    ELSE 'Low'
  END as performance_tier
FROM `your_project.dora_metrics.deployments`
WHERE deployment_completed_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
  AND deployment_status = 'success'
  AND lead_time_minutes IS NOT NULL
GROUP BY service_name, environment
ORDER BY avg_lead_time_minutes ASC;

-- 3. Change Failure Rate (percentage of failed deployments)
SELECT
  service_name,
  environment,
  COUNT(*) as total_deployments,
  COUNTIF(deployment_status = 'failed') as failed_deployments,
  SAFE_DIVIDE(COUNTIF(deployment_status = 'failed'), COUNT(*)) * 100 as failure_rate_percent,
  -- Elite: 0-15%, High: 16-30%
  CASE
    WHEN SAFE_DIVIDE(COUNTIF(deployment_status = 'failed'), COUNT(*)) <= 0.15 THEN 'Elite'
    WHEN SAFE_DIVIDE(COUNTIF(deployment_status = 'failed'), COUNT(*)) <= 0.30 THEN 'High'
    WHEN SAFE_DIVIDE(COUNTIF(deployment_status = 'failed'), COUNT(*)) <= 0.45 THEN 'Medium'
    ELSE 'Low'
  END as performance_tier
FROM `your_project.dora_metrics.deployments`
WHERE deployment_completed_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
GROUP BY service_name, environment
ORDER BY failure_rate_percent DESC;

-- 4. Mean Time to Recovery (MTTR in minutes)
SELECT
  service_name,
  environment,
  COUNT(*) as total_incidents,
  AVG(mttr_minutes) as avg_mttr_minutes,
  PERCENTILE_CONT(mttr_minutes, 0.5) OVER() as median_mttr,
  PERCENTILE_CONT(mttr_minutes, 0.95) OVER() as p95_mttr,
  -- Elite: Less than 1 hour, High: Less than 1 day
  CASE
    WHEN AVG(mttr_minutes) < 60 THEN 'Elite'
    WHEN AVG(mttr_minutes) < 1440 THEN 'High'  -- 1 day
    WHEN AVG(mttr_minutes) < 10080 THEN 'Medium'  -- 1 week
    ELSE 'Low'
  END as performance_tier
FROM `your_project.dora_metrics.incidents`
WHERE incident_started_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
  AND incident_resolved_at IS NOT NULL
  AND mttr_minutes IS NOT NULL
GROUP BY service_name, environment
ORDER BY avg_mttr_minutes ASC;

-- 5. Combined DORA Metrics Dashboard Query
SELECT
  service_name,
  environment,
  -- Deployment Frequency
  ROUND(AVG(deployments_per_week), 2) as avg_deployments_per_week,
  -- Lead Time
  ROUND(AVG(avg_lead_time_hours), 2) as avg_lead_time_hours,
  -- Change Failure Rate
  ROUND(AVG(change_failure_rate * 100), 2) as change_failure_rate_percent,
  -- MTTR
  ROUND(AVG(mttr_hours), 2) as mttr_hours,
  -- Overall Performance Tier
  CASE
    WHEN AVG(deployments_per_week) >= 7
      AND AVG(avg_lead_time_hours) < 1
      AND AVG(change_failure_rate) <= 0.15
      AND AVG(mttr_hours) < 1 THEN 'Elite'
    WHEN AVG(deployments_per_week) >= 1
      AND AVG(avg_lead_time_hours) < 24
      AND AVG(change_failure_rate) <= 0.30
      AND AVG(mttr_hours) < 24 THEN 'High'
    WHEN AVG(deployments_per_week) >= 0.14
      AND AVG(avg_lead_time_hours) < 168
      AND AVG(change_failure_rate) <= 0.45
      AND AVG(mttr_hours) < 168 THEN 'Medium'
    ELSE 'Low'
  END as overall_tier
FROM (
  SELECT
    d.service_name,
    d.environment,
    DATE_TRUNC(DATE(d.deployment_completed_at), WEEK) as week,
    COUNT(*) as deployments_per_week,
    AVG(d.lead_time_minutes) / 60 as avg_lead_time_hours,
    SAFE_DIVIDE(
      COUNTIF(d.deployment_status = 'failed'),
      COUNT(*)
    ) as change_failure_rate,
    COALESCE(AVG(i.mttr_minutes) / 60, 0) as mttr_hours
  FROM `your_project.dora_metrics.deployments` d
  LEFT JOIN `your_project.dora_metrics.incidents` i
    ON d.service_name = i.service_name
    AND d.environment = i.environment
    AND DATE(d.deployment_completed_at) = DATE(i.incident_started_at)
  WHERE d.deployment_completed_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 90 DAY)
  GROUP BY d.service_name, d.environment, week
)
GROUP BY service_name, environment
ORDER BY overall_tier, service_name;

-- 6. Trend Analysis (week over week improvement)
WITH weekly_metrics AS (
  SELECT
    service_name,
    environment,
    DATE_TRUNC(DATE(deployment_completed_at), WEEK) as week,
    COUNT(*) as deployment_count,
    AVG(lead_time_minutes) as avg_lead_time,
    SAFE_DIVIDE(COUNTIF(deployment_status = 'failed'), COUNT(*)) as failure_rate
  FROM `your_project.dora_metrics.deployments`
  WHERE deployment_completed_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 12 WEEK)
  GROUP BY service_name, environment, week
)
SELECT
  service_name,
  environment,
  week,
  deployment_count,
  avg_lead_time,
  failure_rate,
  deployment_count - LAG(deployment_count) OVER (
    PARTITION BY service_name, environment ORDER BY week
  ) as deployment_delta,
  avg_lead_time - LAG(avg_lead_time) OVER (
    PARTITION BY service_name, environment ORDER BY week
  ) as lead_time_delta,
  failure_rate - LAG(failure_rate) OVER (
    PARTITION BY service_name, environment ORDER BY week
  ) as failure_rate_delta
FROM weekly_metrics
ORDER BY week DESC, service_name;

Best Practices for Microservices DORA Metrics​

1. Service-Level Granularity​

Track metrics per microservice to identify bottlenecks:

  • Tag all events with service name
  • Create separate dashboards per team/service
  • Set service-specific targets

2. Environment Segmentation​

Separate metrics by environment:

  • Production vs staging vs development
  • Different thresholds per environment
  • Track promotion velocity

3. Automated Alerting​

Set up alerts for metric degradation:

# Example alerting rule
- alert: High Change Failure Rate
  expr: (failed_deployments / total_deployments) > 0.30
  for: 1h
  annotations:
    summary: 'Change failure rate above 30% for {{ $labels.service_name }}'

4. Continuous Improvement​

  • Review metrics weekly in team meetings
  • Set quarterly improvement goals
  • Celebrate achievements
  • Post-mortem failed deployments

5. Context and Metadata​

Enrich your metrics with:

  • Team ownership
  • Service dependencies
  • Feature flags enabled
  • Deployment strategies (blue/green, canary)

Summary​

This guide provides a comprehensive approach for implementing DORA metrics in a microservices architecture using BigQuery and custom tooling.

Key Takeaways​

  • Automate everything: Use GitHub Actions and ArgoCD webhooks to automatically collect metrics
  • Track at service level: Monitor each microservice independently for granular insights
  • Set realistic goals: Start with baseline measurements, then set improvement targets
  • Review regularly: Make DORA metrics part of your team's regular retrospectives
  • Link deployments to incidents: Correlate deployment events with failures for accurate CFR and MTTR
