DevOps Metrics Measurement Guide

Overview​

Once a project reaches a certain maturity level in DevOps, it's essential for the team to start measuring data to apply continuous improvement on the DevOps lifecycle. This aligns with Lean's Kaizen mindset - the practice of continuous improvement through small, incremental changes.

This guide provides a comprehensive approach to implementing DevOps metrics measurement for Next.js frontend applications and NestJS microservices deployed on Google Cloud Platform (GCP) using GitHub Actions for CI/CD.

Why Measure DevOps Metrics?​

BenefitDescription
VisibilityGain insight into your delivery pipeline's health and efficiency
Continuous ImprovementIdentify bottlenecks and areas for optimization
Data-Driven DecisionsMake informed decisions based on actual performance data
Team AlignmentCreate shared understanding of delivery performance
AccountabilityTrack progress toward DevOps maturity goals

Key DevOps Metrics (DORA Metrics)​

The DevOps Research and Assessment (DORA) team has identified four key metrics that indicate software delivery performance:

1. Lead Time for Changes​

Definition: The length of time between when a code change is committed to the trunk branch and when it is in a deployable state.

Performance Levels:

LevelLead Time
EliteLess than 1 hour
High1 day to 1 week
Medium1 week to 1 month
LowMore than 1 month

2. Deployment Frequency​

Definition: How often new code is deployed into production. Many practitioners distinguish between:

  • Delivery: Code changes released into a pre-production staging environment
  • Deployment: Code changes released into production

Performance Levels:

LevelFrequency
EliteMultiple times per day
HighOnce per day to once per week
MediumOnce per week to once per month
LowLess than once per month

3. Mean Time to Recovery (MTTR)​

Definition: How quickly a team can recover from a failure in production.

Performance Levels:

LevelMTTR
EliteLess than 1 hour
HighLess than 1 day
MediumLess than 1 week
LowMore than 1 week

4. Change Failure Rate​

Definition: The percentage of deployments that cause a failure in production requiring a hotfix, rollback, or patch.

Performance Levels:

LevelFailure Rate
Elite0-15%
High16-30%
Medium31-45%
Low46-60%

Step-by-Step Implementation​

Step 1: Set Up BigQuery Dataset for Metrics Storage​

First, create a BigQuery dataset and tables to store your DevOps metrics.

Create Dataset via gcloud CLI​

# Set your project ID
export PROJECT_ID="your-gcp-project-id"

# Create the dataset
gcloud bigquery datasets create devops_metrics \
  --project=$PROJECT_ID \
  --location=US \
  --description="DevOps metrics for DORA measurements"

Create Tables Schema​

-- deployment_events table
CREATE TABLE `${PROJECT_ID}.devops_metrics.deployment_events` (
  event_id STRING NOT NULL,
  timestamp TIMESTAMP NOT NULL,
  service_name STRING NOT NULL,
  environment STRING NOT NULL,
  commit_sha STRING NOT NULL,
  commit_timestamp TIMESTAMP,
  branch STRING,
  status STRING NOT NULL,
  deployer STRING,
  workflow_run_id STRING,
  duration_seconds INT64,
  is_rollback BOOLEAN DEFAULT FALSE,
  metadata JSON
)
PARTITION BY DATE(timestamp)
CLUSTER BY service_name, environment;

-- commit_events table
CREATE TABLE `${PROJECT_ID}.devops_metrics.commit_events` (
  commit_sha STRING NOT NULL,
  timestamp TIMESTAMP NOT NULL,
  author STRING NOT NULL,
  service_name STRING NOT NULL,
  branch STRING NOT NULL,
  message STRING,
  files_changed INT64,
  lines_added INT64,
  lines_removed INT64,
  is_merge BOOLEAN DEFAULT FALSE,
  pull_request_number INT64,
  metadata JSON
)
PARTITION BY DATE(timestamp)
CLUSTER BY service_name, branch;

-- incident_events table
CREATE TABLE `${PROJECT_ID}.devops_metrics.incident_events` (
  incident_id STRING NOT NULL,
  service_name STRING NOT NULL,
  environment STRING NOT NULL,
  started_at TIMESTAMP NOT NULL,
  detected_at TIMESTAMP,
  resolved_at TIMESTAMP,
  severity STRING,
  cause_deployment_id STRING,
  root_cause STRING,
  resolution_type STRING,
  metadata JSON
)
PARTITION BY DATE(started_at)
CLUSTER BY service_name, severity;

-- build_events table
CREATE TABLE `${PROJECT_ID}.devops_metrics.build_events` (
  build_id STRING NOT NULL,
  timestamp TIMESTAMP NOT NULL,
  service_name STRING NOT NULL,
  commit_sha STRING NOT NULL,
  branch STRING,
  status STRING NOT NULL,
  duration_seconds INT64,
  workflow_name STRING,
  job_name STRING,
  runner_type STRING,
  metadata JSON
)
PARTITION BY DATE(timestamp)
CLUSTER BY service_name, status;

Step 2: Create GitHub Actions Workflow for Metrics Collection​

Create a reusable workflow that collects and sends metrics to BigQuery.

.github/workflows/metrics-collector.yml​

name: DevOps Metrics Collector

on:
  workflow_call:
    inputs:
      service_name:
        required: true
        type: string
      environment:
        required: true
        type: string
      event_type:
        required: true
        type: string
        description: 'deployment, build, or commit'
      status:
        required: true
        type: string
      duration_seconds:
        required: false
        type: number
        default: 0
    secrets:
      GCP_SA_KEY:
        required: true
      GCP_PROJECT_ID:
        required: true

jobs:
  collect-metrics:
    runs-on: ubuntu-latest
    steps:
      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Set up Cloud SDK
        uses: google-github-actions/setup-gcloud@v2

      - name: Collect and Send Deployment Metrics
        if: inputs.event_type == 'deployment'
        run: |
          # Get commit timestamp
          COMMIT_TIMESTAMP=$(git log -1 --format=%cI ${{ github.sha }} 2>/dev/null || echo "")

          # Create JSON payload
          cat > /tmp/deployment_event.json << EOF
          {
            "event_id": "${{ github.run_id }}-${{ github.run_attempt }}",
            "timestamp": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
            "service_name": "${{ inputs.service_name }}",
            "environment": "${{ inputs.environment }}",
            "commit_sha": "${{ github.sha }}",
            "commit_timestamp": "${COMMIT_TIMESTAMP}",
            "branch": "${{ github.ref_name }}",
            "status": "${{ inputs.status }}",
            "deployer": "${{ github.actor }}",
            "workflow_run_id": "${{ github.run_id }}",
            "duration_seconds": ${{ inputs.duration_seconds }},
            "is_rollback": false,
            "metadata": {
              "repository": "${{ github.repository }}",
              "workflow": "${{ github.workflow }}",
              "trigger": "${{ github.event_name }}"
            }
          }
          EOF

          # Insert into BigQuery
          bq insert \
            --project_id=${{ secrets.GCP_PROJECT_ID }} \
            devops_metrics.deployment_events \
            /tmp/deployment_event.json

      - name: Collect and Send Build Metrics
        if: inputs.event_type == 'build'
        run: |
          cat > /tmp/build_event.json << EOF
          {
            "build_id": "${{ github.run_id }}-${{ github.run_attempt }}",
            "timestamp": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
            "service_name": "${{ inputs.service_name }}",
            "commit_sha": "${{ github.sha }}",
            "branch": "${{ github.ref_name }}",
            "status": "${{ inputs.status }}",
            "duration_seconds": ${{ inputs.duration_seconds }},
            "workflow_name": "${{ github.workflow }}",
            "job_name": "${{ github.job }}",
            "runner_type": "${{ runner.os }}",
            "metadata": {
              "repository": "${{ github.repository }}",
              "actor": "${{ github.actor }}"
            }
          }
          EOF

          bq insert \
            --project_id=${{ secrets.GCP_PROJECT_ID }} \
            devops_metrics.build_events \
            /tmp/build_event.json

Step 3: Integrate Metrics Collection into CI/CD Workflows​

NestJS Backend Service Workflow​

.github/workflows/nestjs-deploy.yml

name: NestJS Backend Deploy

on:
  push:
    branches: [main, develop]
    paths:
      - 'apps/api/**'
      - '.github/workflows/nestjs-deploy.yml'

env:
  SERVICE_NAME: api-gateway
  GCP_REGION: us-central1
  GKE_CLUSTER: production-cluster

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      build_duration: ${{ steps.build_time.outputs.duration }}
    steps:
      - uses: actions/checkout@v4

      - name: Start Build Timer
        id: build_start
        run: echo "start=$(date +%s)" >> $GITHUB_OUTPUT

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run Tests
        run: pnpm test:cov

      - name: Build Application
        run: pnpm build

      - name: Build Docker Image
        run: |
          docker build -t gcr.io/${{ secrets.GCP_PROJECT_ID }}/${{ env.SERVICE_NAME }}:${{ github.sha }} .

      - name: Calculate Build Duration
        id: build_time
        run: |
          END=$(date +%s)
          DURATION=$((END - ${{ steps.build_start.outputs.start }}))
          echo "duration=$DURATION" >> $GITHUB_OUTPUT

  # Collect build metrics
  collect-build-metrics:
    needs: build
    uses: ./.github/workflows/metrics-collector.yml
    with:
      service_name: api-gateway
      environment: build
      event_type: build
      status: ${{ needs.build.result }}
      duration_seconds: ${{ needs.build.outputs.build_duration }}
    secrets:
      GCP_SA_KEY: ${{ secrets.GCP_SA_KEY }}
      GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}

  deploy-staging:
    needs: build
    runs-on: ubuntu-latest
    environment: staging
    outputs:
      deploy_duration: ${{ steps.deploy_time.outputs.duration }}
    steps:
      - name: Start Deploy Timer
        id: deploy_start
        run: echo "start=$(date +%s)" >> $GITHUB_OUTPUT

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Configure kubectl
        uses: google-github-actions/get-gke-credentials@v2
        with:
          cluster_name: ${{ env.GKE_CLUSTER }}
          location: ${{ env.GCP_REGION }}

      - name: Deploy to GKE
        run: |
          kubectl set image deployment/${{ env.SERVICE_NAME }} \
            ${{ env.SERVICE_NAME }}=gcr.io/${{ secrets.GCP_PROJECT_ID }}/${{ env.SERVICE_NAME }}:${{ github.sha }} \
            -n staging
          kubectl rollout status deployment/${{ env.SERVICE_NAME }} -n staging

      - name: Calculate Deploy Duration
        id: deploy_time
        run: |
          END=$(date +%s)
          DURATION=$((END - ${{ steps.deploy_start.outputs.start }}))
          echo "duration=$DURATION" >> $GITHUB_OUTPUT

  # Collect staging deployment metrics
  collect-staging-metrics:
    needs: deploy-staging
    uses: ./.github/workflows/metrics-collector.yml
    with:
      service_name: api-gateway
      environment: staging
      event_type: deployment
      status: ${{ needs.deploy-staging.result }}
      duration_seconds: ${{ needs.deploy-staging.outputs.deploy_duration }}
    secrets:
      GCP_SA_KEY: ${{ secrets.GCP_SA_KEY }}
      GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}

  deploy-production:
    needs: [build, deploy-staging]
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production
    outputs:
      deploy_duration: ${{ steps.deploy_time.outputs.duration }}
    steps:
      - name: Start Deploy Timer
        id: deploy_start
        run: echo "start=$(date +%s)" >> $GITHUB_OUTPUT

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Configure kubectl
        uses: google-github-actions/get-gke-credentials@v2
        with:
          cluster_name: ${{ env.GKE_CLUSTER }}
          location: ${{ env.GCP_REGION }}

      - name: Deploy to GKE Production
        run: |
          kubectl set image deployment/${{ env.SERVICE_NAME }} \
            ${{ env.SERVICE_NAME }}=gcr.io/${{ secrets.GCP_PROJECT_ID }}/${{ env.SERVICE_NAME }}:${{ github.sha }} \
            -n production
          kubectl rollout status deployment/${{ env.SERVICE_NAME }} -n production

      - name: Calculate Deploy Duration
        id: deploy_time
        run: |
          END=$(date +%s)
          DURATION=$((END - ${{ steps.deploy_start.outputs.start }}))
          echo "duration=$DURATION" >> $GITHUB_OUTPUT

  # Collect production deployment metrics
  collect-production-metrics:
    needs: deploy-production
    uses: ./.github/workflows/metrics-collector.yml
    with:
      service_name: api-gateway
      environment: production
      event_type: deployment
      status: ${{ needs.deploy-production.result }}
      duration_seconds: ${{ needs.deploy-production.outputs.deploy_duration }}
    secrets:
      GCP_SA_KEY: ${{ secrets.GCP_SA_KEY }}
      GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}

          bq query --use_legacy_sql=false \
            "UPDATE devops_metrics.incident_events 
             SET resolved_at = CURRENT_TIMESTAMP(),
                 resolution_type = 'manual'
             WHERE incident_id = '${{ inputs.incident_id }}'"

Step 5: BigQuery SQL Queries for DORA Metrics​

Create SQL queries to calculate each DORA metric.

Lead Time for Changes Query​

-- Calculate Lead Time for Changes (in hours)
WITH deployment_with_commit AS (
  SELECT
    d.event_id,
    d.service_name,
    d.environment,
    d.timestamp AS deploy_timestamp,
    d.commit_timestamp,
    d.status
  FROM `${PROJECT_ID}.devops_metrics.deployment_events` d
  WHERE d.environment = 'production'
    AND d.status = 'success'
    AND d.commit_timestamp IS NOT NULL
)
SELECT
  service_name,
  DATE(deploy_timestamp) AS deployment_date,
  AVG(TIMESTAMP_DIFF(deploy_timestamp, commit_timestamp, HOUR)) AS avg_lead_time_hours,
  MIN(TIMESTAMP_DIFF(deploy_timestamp, commit_timestamp, HOUR)) AS min_lead_time_hours,
  MAX(TIMESTAMP_DIFF(deploy_timestamp, commit_timestamp, HOUR)) AS max_lead_time_hours,
  PERCENTILE_CONT(TIMESTAMP_DIFF(deploy_timestamp, commit_timestamp, HOUR), 0.5)
    OVER (PARTITION BY service_name) AS median_lead_time_hours,
  COUNT(*) AS deployment_count
FROM deployment_with_commit
WHERE deploy_timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
GROUP BY service_name, DATE(deploy_timestamp)
ORDER BY deployment_date DESC;

-- Calculate Deployment Frequency
SELECT
  service_name,
  DATE_TRUNC(timestamp, WEEK) AS week_start,
  COUNT(*) AS total_deployments,
  COUNTIF(status = 'success') AS successful_deployments,
  COUNTIF(status = 'failure') AS failed_deployments,
  ROUND(COUNTIF(status = 'success') / COUNT(*) * 100, 2) AS success_rate_percent
FROM `${PROJECT_ID}.devops_metrics.deployment_events`
WHERE environment = 'production'
  AND timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 90 DAY)
GROUP BY service_name, week_start
ORDER BY week_start DESC, service_name;

-- Daily Deployment Frequency
SELECT
  service_name,
  DATE(timestamp) AS deployment_date,
  COUNT(*) AS deployments_per_day,
  CASE
    WHEN COUNT(*) >= 3 THEN 'Elite'
    WHEN COUNT(*) >= 1 THEN 'High'
    ELSE 'Medium'
  END AS performance_level
FROM `${PROJECT_ID}.devops_metrics.deployment_events`
WHERE environment = 'production'
  AND status = 'success'
  AND timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
GROUP BY service_name, DATE(timestamp)
ORDER BY deployment_date DESC;

Mean Time to Recovery (MTTR) Query​

-- Calculate Mean Time to Recovery
WITH incident_recovery AS (
  SELECT
    incident_id,
    service_name,
    environment,
    severity,
    started_at,
    resolved_at,
    TIMESTAMP_DIFF(resolved_at, started_at, MINUTE) AS recovery_time_minutes
  FROM `${PROJECT_ID}.devops_metrics.incident_events`
  WHERE resolved_at IS NOT NULL
    AND environment = 'production'
)
SELECT
  service_name,
  severity,
  COUNT(*) AS incident_count,
  AVG(recovery_time_minutes) AS avg_mttr_minutes,
  MIN(recovery_time_minutes) AS min_mttr_minutes,
  MAX(recovery_time_minutes) AS max_mttr_minutes,
  PERCENTILE_CONT(recovery_time_minutes, 0.5) OVER (PARTITION BY service_name) AS median_mttr_minutes,
  CASE
    WHEN AVG(recovery_time_minutes) < 60 THEN 'Elite'
    WHEN AVG(recovery_time_minutes) < 1440 THEN 'High'
    WHEN AVG(recovery_time_minutes) < 10080 THEN 'Medium'
    ELSE 'Low'
  END AS performance_level
FROM incident_recovery
WHERE started_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 90 DAY)
GROUP BY service_name, severity
ORDER BY service_name, severity;

Change Failure Rate Query​

-- Calculate Change Failure Rate
WITH deployment_outcomes AS (
  SELECT
    d.service_name,
    DATE_TRUNC(d.timestamp, WEEK) AS week_start,
    d.event_id AS deployment_id,
    d.status,
    CASE
      WHEN i.cause_deployment_id IS NOT NULL THEN TRUE
      WHEN d.status = 'failure' THEN TRUE
      ELSE FALSE
    END AS caused_failure
  FROM `${PROJECT_ID}.devops_metrics.deployment_events` d
  LEFT JOIN `${PROJECT_ID}.devops_metrics.incident_events` i
    ON d.event_id = i.cause_deployment_id
  WHERE d.environment = 'production'
)
SELECT
  service_name,
  week_start,
  COUNT(*) AS total_deployments,
  COUNTIF(caused_failure) AS failed_deployments,
  ROUND(COUNTIF(caused_failure) / COUNT(*) * 100, 2) AS change_failure_rate_percent,
  CASE
    WHEN COUNTIF(caused_failure) / COUNT(*) <= 0.15 THEN 'Elite'
    WHEN COUNTIF(caused_failure) / COUNT(*) <= 0.30 THEN 'High'
    WHEN COUNTIF(caused_failure) / COUNT(*) <= 0.45 THEN 'Medium'
    ELSE 'Low'
  END AS performance_level
FROM deployment_outcomes
WHERE week_start >= DATE_SUB(CURRENT_DATE(), INTERVAL 90 DAY)
GROUP BY service_name, week_start
ORDER BY week_start DESC, service_name;

import { Injectable, Logger } from '@nestjs/common';
import { BigQuery } from '@google-cloud/bigquery';
import { ConfigService } from '@nestjs/config';

export interface DeploymentEvent {
  eventId: string;
  serviceName: string;
  environment: string;
  commitSha: string;
  commitTimestamp?: Date;
  status: 'success' | 'failure' | 'in_progress';
  durationSeconds?: number;
  isRollback?: boolean;
  metadata?: Record<string, unknown>;
}

export interface DoraMetrics {
  leadTimeHours: number;
  deploymentFrequency: number;
  mttrMinutes: number;
  changeFailureRate: number;
}

@Injectable()
export class MetricsService {
  private readonly logger = new Logger(MetricsService.name);
  private readonly bigquery: BigQuery;
  private readonly projectId: string;
  private readonly datasetId = 'devops_metrics';

  constructor(private configService: ConfigService) {
    this.projectId = this.configService.get<string>('GCP_PROJECT_ID');
    this.bigquery = new BigQuery({ projectId: this.projectId });
  }

  async recordDeployment(event: DeploymentEvent): Promise<void> {
    const table = this.bigquery.dataset(this.datasetId).table('deployment_events');

    const row = {
      event_id: event.eventId,
      timestamp: new Date().toISOString(),
      service_name: event.serviceName,
      environment: event.environment,
      commit_sha: event.commitSha,
      commit_timestamp: event.commitTimestamp?.toISOString(),
      status: event.status,
      duration_seconds: event.durationSeconds,
      is_rollback: event.isRollback ?? false,
      metadata: JSON.stringify(event.metadata ?? {}),
    };

    try {
      await table.insert([row]);
      this.logger.log(`Recorded deployment event: ${event.eventId}`);
    } catch (error) {
      this.logger.error(`Failed to record deployment: ${error.message}`);
      throw error;
    }
  }

  async getDoraMetrics(serviceName: string, daysBack: number = 30): Promise<DoraMetrics> {
    const [leadTime] = await this.bigquery.query({
      query: `
        SELECT AVG(TIMESTAMP_DIFF(timestamp, commit_timestamp, HOUR)) as avg_lead_time
        FROM \`${this.projectId}.${this.datasetId}.deployment_events\`
        WHERE service_name = @serviceName
          AND environment = 'production'
          AND status = 'success'
          AND timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL @daysBack DAY)
      `,
      params: { serviceName, daysBack },
    });

    const [frequency] = await this.bigquery.query({
      query: `
        SELECT COUNT(*) / @daysBack as daily_frequency
        FROM \`${this.projectId}.${this.datasetId}.deployment_events\`
        WHERE service_name = @serviceName
          AND environment = 'production'
          AND status = 'success'
          AND timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL @daysBack DAY)
      `,
      params: { serviceName, daysBack },
    });

    const [mttr] = await this.bigquery.query({
      query: `
        SELECT AVG(TIMESTAMP_DIFF(resolved_at, started_at, MINUTE)) as avg_mttr
        FROM \`${this.projectId}.${this.datasetId}.incident_events\`
        WHERE service_name = @serviceName
          AND environment = 'production'
          AND resolved_at IS NOT NULL
          AND started_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL @daysBack DAY)
      `,
      params: { serviceName, daysBack },
    });

    const [failureRate] = await this.bigquery.query({
      query: `
        WITH deployments AS (
          SELECT event_id, status
          FROM \`${this.projectId}.${this.datasetId}.deployment_events\`
          WHERE service_name = @serviceName
            AND environment = 'production'
            AND timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL @daysBack DAY)
        ),
        failures AS (
          SELECT COUNT(DISTINCT cause_deployment_id) as failure_count
          FROM \`${this.projectId}.${this.datasetId}.incident_events\`
          WHERE service_name = @serviceName
            AND cause_deployment_id IS NOT NULL
            AND started_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL @daysBack DAY)
        )
        SELECT 
          COALESCE(f.failure_count / NULLIF(COUNT(*), 0) * 100, 0) as failure_rate
        FROM deployments d
        CROSS JOIN failures f
        GROUP BY f.failure_count
      `,
      params: { serviceName, daysBack },
    });

    return {
      leadTimeHours: leadTime[0]?.avg_lead_time ?? 0,
      deploymentFrequency: frequency[0]?.daily_frequency ?? 0,
      mttrMinutes: mttr[0]?.avg_mttr ?? 0,
      changeFailureRate: failureRate[0]?.failure_rate ?? 0,
    };
  }

  async getDeploymentTrend(
    serviceName: string,
    daysBack: number = 90,
  ): Promise<Array<{ date: string; count: number; successRate: number }>> {
    const [rows] = await this.bigquery.query({
      query: `
        SELECT 
          DATE(timestamp) as deployment_date,
          COUNT(*) as total_count,
          COUNTIF(status = 'success') / COUNT(*) * 100 as success_rate
        FROM \`${this.projectId}.${this.datasetId}.deployment_events\`
        WHERE service_name = @serviceName
          AND environment = 'production'
          AND timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL @daysBack DAY)
        GROUP BY DATE(timestamp)
        ORDER BY deployment_date
      `,
      params: { serviceName, daysBack },
    });

    return rows.map((row: any) => ({
      date: row.deployment_date.value,
      count: row.total_count,
      successRate: row.success_rate,
    }));
  }
}

Best Practices and Recommendations​

1. Data Collection Best Practices​

PracticeDescription
Automate EverythingNever rely on manual data entry for metrics
Consistent TimestampsAlways use UTC timestamps for consistency
Include ContextAdd metadata like repository, branch, and actor
Handle FailuresImplement retry logic for metrics collection

2. Measurement Guidelines​

  • Lead Time: Measure from the first commit in a PR to production deployment
  • Deployment Frequency: Count only successful production deployments
  • MTTR: Start from incident detection, not incident occurrence
  • Change Failure Rate: Include rollbacks and hotfixes

3. Dashboard and Alerting​

  • Set up real-time dashboards for immediate visibility
  • Configure alerts for metrics falling below thresholds
  • Review metrics in weekly team retrospectives
  • Track trends over time, not just point-in-time values

4. Continuous Improvement Process​

  2. Analyze: Review trends in weekly/monthly meetings

  4. Repeat: Continuously iterate on the process
