Database Schema Version Control & Conflict Detection

This guide establishes database schema versioning practices for NestJS applications on GCP, ensuring database schemas are tracked as code, versioned alongside application code, and conflicts are detected during code merges.

1. Overview​

Database schema as code treats database definitions as first-class citizens in version control, enabling the same development practices (branching, merging, code review, CI/CD) used for application code. This approach prevents manual schema drift, enables conflict detection, and maintains database-application compatibility.

2. Schema as Code Principles​

2.1 Core Principles​

PrincipleDescriptionBenefit
Single Source of TruthSchema defined in version-controlled filesEliminates drift between environments
Declarative SchemaDefine desired state, not migration stepsEasier to understand and review
Code Review for SchemaSchema changes go through PR processCatches issues before production
Automated ValidationCI/CD validates schema consistencyPrevents invalid schema states
Conflict DetectionGit detects schema merge conflictsPrevents incompatible schema changes
Environment ParitySame schema source for all environmentsConsistent behavior across stages

    conflict_detection: Line-based

  yaml:
    extension: .yml
    type: YAML configuration
    readability: Excellent
    tooling: Liquibase, Flyway
    git_friendly: Yes
    conflict_detection: Line-based

2.3 Recommended Repo Layout (Tracked Artifacts)​

To satisfy “database objects follow the same policies as code” and enable merge-time conflict detection, keep both:

  • Source-of-truth schema definition (Prisma DSL / TypeORM entities / Liquibase YAML)
  • Generated schema export snapshot(s) (SQL/YAML) committed to the repo

Recommended layout:

prisma/
  schema.prisma                 # declarative schema (reviewed like code)
  migrations/                   # ordered migrations (reviewed like code)

db/
  schema.snapshot.sql           # exported schema snapshot (committed)
  schema.snapshot.yml           # optional; if you use Liquibase-style exports
  schema.manifest.json          # optional; hash + compatibility metadata

.github/workflows/
  schema-validation.yml         # CI gates: drift, snapshot, conflicts

Why commit db/schema.snapshot.sql?

  • Produces a stable, reviewable diff in PRs (especially for “add column / add index” changes).
  • Lets Git surface line-based merge conflicts when two branches change the same DB object.
  • Enables a CI rule: “if schema changed, snapshot must be updated”, preventing silent drift.

2.4 Exporting the Schema Snapshot (SQL/YAML)​

There are two safe approaches:

  1. Export from a clean DB after applying migrations (most accurate)
  • CI spins up a temporary Postgres service, applies migrations, then exports --schema-only.
  1. Export from declarative schema definition (fast, tool-dependent)
  • Prisma: generate SQL via prisma migrate diff --from-empty ... --script.
  • Liquibase: generate changelog / snapshot from DB or reference.

Example (CI-friendly) snapshot generation for Postgres:

# 1) Apply all migrations to a clean DB
npx prisma migrate deploy

# 2) Export canonical schema snapshot
pg_dump --schema-only --no-owner --no-privileges \
  -h localhost -U test -d test_db \
  > db/schema.snapshot.sql

# 3) Ensure stable formatting (optional but recommended)
# e.g., run a SQL formatter here if your repo standardizes it

2.5 GitHub Actions Gate: “Snapshot Must Match”​

Add a job that fails the PR if schema/migrations change but the committed snapshot wasn’t updated.

# Add to .github/workflows/schema-validation.yml
jobs:
  schema-snapshot-up-to-date:
    name: Schema Snapshot Up-to-date
    runs-on: ubuntu-latest
    if: github.event_name == 'pull_request'

    services:
      postgres:
        image: postgres:15
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: test_db
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
        ports:
          - 5432:5432

    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - run: pnpm install

      - name: Apply migrations
        env:
          DATABASE_URL: postgresql://test:test@localhost:5432/test_db
        run: npx prisma migrate deploy

      - name: Export schema snapshot
        env:
          PGPASSWORD: test
        run: |
          mkdir -p db
          pg_dump --schema-only --no-owner --no-privileges \
            -h localhost -U test -d test_db \
            > db/schema.snapshot.sql

      - name: Fail if snapshot not committed
        run: |
          if ! git diff --exit-code -- db/schema.snapshot.sql; then
            echo "❌ db/schema.snapshot.sql is out of date. Regenerate and commit it."
            echo "Tip: run the same export locally after applying migrations."
            exit 1
          fi

This is the key “merge conflict / conflict detection” mechanism: it forces every DB change to produce a deterministic, reviewable diff that Git can merge (or flag as conflicting) using the same policies as code.

3.2 Schema Metadata Tracking​

// src/database/schema-metadata.service.ts
import { Injectable, Logger } from '@nestjs/common';
import { PrismaClient } from '@prisma/client';
import { execSync } from 'child_process';
import * as fs from 'fs';
import * as path from 'path';
import * as crypto from 'crypto';

export interface SchemaMetadata {
  schemaVersion: string;
  schemaHash: string;
  lastModified: Date;
  lastModifiedBy: string;
  compatibleAppVersion: string;
  databaseVersion: string;
  conflicts: SchemaConflict[];
}

export interface SchemaConflict {
  type: 'table' | 'column' | 'index' | 'constraint';
  object: string;
  description: string;
  severity: 'error' | 'warning';
}

@Injectable()
export class SchemaMetadataService {
  private readonly logger = new Logger(SchemaMetadataService.name);
  private prisma = new PrismaClient();

  async getSchemaMetadata(): Promise<SchemaMetadata> {
    const schemaPath = path.join(process.cwd(), 'prisma', 'schema.prisma');
    const schemaContent = fs.readFileSync(schemaPath, 'utf8');
    const schemaHash = this.calculateHash(schemaContent);

    // Get Git information
    const lastCommit = execSync('git log -1 --format="%H|%an|%ad" -- prisma/schema.prisma', {
      encoding: 'utf-8',
    }).trim();

    const [commitHash, author, date] = lastCommit.split('|');

    // Get database version
    const dbVersion = await this.getDatabaseVersion();

    // Check for conflicts
    const conflicts = await this.detectSchemaConflicts();

    return {
      schemaVersion: commitHash.substring(0, 8),
      schemaHash,
      lastModified: new Date(date),
      lastModifiedBy: author,
      compatibleAppVersion: this.extractAppVersion(schemaContent),
      databaseVersion: dbVersion,
      conflicts,
    };
  }

  async validateSchemaSync(): Promise<boolean> {
    try {
      // Compare schema file with database state
      const result = execSync('npx prisma migrate status', {
        encoding: 'utf-8',
      });

      return !result.includes('following migrations have not yet been applied');
    } catch (error) {
      this.logger.error('Schema validation failed:', error.message);
      return false;
    }
  }

  async detectSchemaConflicts(): Promise<SchemaConflict[]> {
    const conflicts: SchemaConflict[] = [];

    try {
      // Get current branch
      const currentBranch = execSync('git branch --show-current', {
        encoding: 'utf-8',
      }).trim();

      // Check for unmerged changes
      const unmergedFiles = execSync('git diff --name-only --diff-filter=U', {
        encoding: 'utf-8',
      }).trim();

      if (unmergedFiles.includes('prisma/schema.prisma')) {
        conflicts.push({
          type: 'table',
          object: 'schema.prisma',
          description: 'Schema file has merge conflicts',
          severity: 'error',
        });
      }

      // Check for pending migrations
      const status = execSync('npx prisma migrate status', {
        encoding: 'utf-8',
      });

      if (status.includes('drift detected')) {
        conflicts.push({
          type: 'table',
          object: 'database',
          description: 'Database schema drift detected',
          severity: 'warning',
        });
      }
    } catch (error) {
      // Ignore git command errors in non-git environments
    }

    return conflicts;
  }

  async exportSchemaToSQL(): Promise<string> {
    const outputPath = path.join(process.cwd(), 'exports', 'schema-export.sql');

    // Create exports directory if it doesn't exist
    fs.mkdirSync(path.dirname(outputPath), { recursive: true });

    // Export current database schema
    execSync(
      `npx prisma db pull && npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script > ${outputPath}`,
      {
        encoding: 'utf-8',
      },
    );

    return outputPath;
  }

  async compareSchemaVersions(baseRef: string, compareRef: string): Promise<string> {
    try {
      // Get schema at base ref
      const baseSchemа = execSync(`git show ${baseRef}:prisma/schema.prisma`, {
        encoding: 'utf-8',
      });

      // Get schema at compare ref
      const compareSchema = execSync(`git show ${compareRef}:prisma/schema.prisma`, {
        encoding: 'utf-8',
      });

      // Generate diff
      const diffPath = path.join(process.cwd(), 'exports', 'schema-diff.txt');
      fs.writeFileSync(diffPath, `=== Schema Comparison ===\nBase: ${baseRef}\nCompare: ${compareRef}\n\n`);

      const diff = execSync(`git diff ${baseRef} ${compareRef} -- prisma/schema.prisma`, {
        encoding: 'utf-8',
      });

      fs.appendFileSync(diffPath, diff);
      return diffPath;
    } catch (error) {
      this.logger.error('Failed to compare schema versions:', error.message);
      throw error;
    }
  }

  private calculateHash(content: string): string {
    return crypto.createHash('sha256').update(content).digest('hex').substring(0, 16);
  }

  private extractAppVersion(schemaContent: string): string {
    const match = schemaContent.match(/Compatible with app version: >= ([\d.]+)/);
    return match ? match[1] : 'unknown';
  }

  private async getDatabaseVersion(): Promise<string> {
    try {
      const result = await this.prisma.$queryRaw<Array<{ version: string }>>`
        SELECT version() as version
      `;
      return result[0]?.version || 'unknown';
    } catch (error) {
      return 'unknown';
    }
  }
}

// src/database/schema-metadata.controller.ts
import { Controller, Get, Query, UseGuards } from '@nestjs/common';
import { ApiTags, ApiOperation, ApiResponse } from '@nestjs/swagger';
import { SchemaMetadataService } from './schema-metadata.service';

@ApiTags('Schema Management')
@Controller('api/schema')
export class SchemaMetadataController {
  constructor(private readonly schemaService: SchemaMetadataService) {}

  @Get('metadata')
  @ApiOperation({ summary: 'Get current schema metadata' })
  async getMetadata() {
    return this.schemaService.getSchemaMetadata();
  }

  @Get('validate')
  @ApiOperation({ summary: 'Validate schema synchronization' })
  async validateSync() {
    const isValid = await this.schemaService.validateSchemaSync();
    return { isValid, message: isValid ? 'Schema is in sync' : 'Schema drift detected' };
  }

  @Get('conflicts')
  @ApiOperation({ summary: 'Detect schema conflicts' })
  async detectConflicts() {
    const conflicts = await this.schemaService.detectSchemaConflicts();
    return { conflicts, hasConflicts: conflicts.length > 0 };
  }

  @Get('export')
  @ApiOperation({ summary: 'Export current schema to SQL' })
  async exportSchema() {
    const filePath = await this.schemaService.exportSchemaToSQL();
    return { filePath, message: 'Schema exported successfully' };
  }

  @Get('compare')
  @ApiOperation({ summary: 'Compare schema between two Git refs' })
  async compareVersions(@Query('base') baseRef: string = 'main', @Query('compare') compareRef: string = 'HEAD') {
    const diffPath = await this.schemaService.compareSchemaVersions(baseRef, compareRef);
    return { diffPath };
  }
}

4.2 Schema Export Service​

// src/database/typeorm-schema-export.service.ts
import { Injectable, Logger } from '@nestjs/common';
import { DataSource } from 'typeorm';
import * as fs from 'fs';
import * as path from 'path';

@Injectable()
export class TypeOrmSchemaExportService {
  private readonly logger = new Logger(TypeOrmSchemaExportService.name);

  constructor(private dataSource: DataSource) {}

  async exportSchemaToSQL(): Promise<string> {
    const entities = this.dataSource.entityMetadatas;
    const outputPath = path.join(process.cwd(), 'exports', 'typeorm-schema.sql');

    fs.mkdirSync(path.dirname(outputPath), { recursive: true });

    let sql = '-- TypeORM Schema Export\n';
    sql += `-- Generated: ${new Date().toISOString()}\n`;
    sql += `-- Total Tables: ${entities.length}\n\n`;

    // Generate CREATE TABLE statements
    for (const entity of entities) {
      sql += this.generateCreateTableSQL(entity);
      sql += '\n\n';
    }

    fs.writeFileSync(outputPath, sql);
    this.logger.log(`Schema exported to: ${outputPath}`);

    return outputPath;
  }

  async exportSchemaToYAML(): Promise<string> {
    const entities = this.dataSource.entityMetadatas;
    const outputPath = path.join(process.cwd(), 'exports', 'typeorm-schema.yml');

    const schema = {
      version: '2.5.0',
      generatedAt: new Date().toISOString(),
      database: this.dataSource.options.type,
      tables: entities.map((entity) => ({
        name: entity.tableName,
        columns: entity.columns.map((col) => ({
          name: col.propertyName,
          type: col.type,
          nullable: col.isNullable,
          unique: col.isUnique,
          primary: col.isPrimary,
          default: col.default,
        })),
        indexes: entity.indices.map((idx) => ({
          name: idx.name,
          columns: idx.columns.map((col) => col.propertyName),
          unique: idx.isUnique,
        })),
        relations: entity.relations.map((rel) => ({
          name: rel.propertyName,
          type: rel.relationType,
          target: rel.inverseEntityMetadata.tableName,
        })),
      })),
    };

    fs.writeFileSync(outputPath, JSON.stringify(schema, null, 2));
    this.logger.log(`Schema exported to: ${outputPath}`);

    return outputPath;
  }

  private generateCreateTableSQL(entity: any): string {
    let sql = `CREATE TABLE ${entity.tableName} (\n`;

    // Add columns
    const columns = entity.columns.map((col) => {
      let colDef = `  ${col.databaseName} ${this.mapTypeToSQL(col.type)}`;
      if (col.isPrimary) colDef += ' PRIMARY KEY';
      if (!col.isNullable) colDef += ' NOT NULL';
      if (col.isUnique) colDef += ' UNIQUE';
      if (col.default !== undefined) colDef += ` DEFAULT ${col.default}`;
      return colDef;
    });

    sql += columns.join(',\n');
    sql += '\n);';

    // Add indexes
    entity.indices.forEach((idx) => {
      if (!idx.isPrimary) {
        const indexName = idx.name || `idx_${entity.tableName}_${idx.columns.map((c) => c.databaseName).join('_')}`;
        sql += `\nCREATE INDEX ${indexName} ON ${entity.tableName} (${idx.columns
          .map((c) => c.databaseName)
          .join(', ')});`;
      }
    });

    return sql;
  }

  private mapTypeToSQL(type: any): string {
    const typeMap: Record<string, string> = {
      varchar: 'VARCHAR',
      text: 'TEXT',
      int: 'INTEGER',
      decimal: 'DECIMAL',
      boolean: 'BOOLEAN',
      timestamp: 'TIMESTAMP',
      enum: 'VARCHAR',
    };

    return typeMap[type] || 'TEXT';
  }
}

// scripts/lint-schema.js
const fs = require('fs');
const path = require('path');

const schemaPath = path.join(__dirname, '../prisma/schema.prisma');
const schema = fs.readFileSync(schemaPath, 'utf8');

console.log('🔍 Linting Prisma schema...\n');

let hasErrors = false;
let hasWarnings = false;

// Check 1: Schema has version comment
if (!schema.includes('Compatible with app version')) {
  console.error('❌ Error: Schema missing version compatibility comment');
  hasErrors = true;
} else {
  console.log('✅ Version compatibility documented');
}

// Check 2: All tables have indexes
const models = schema.match(/model \w+ {[\s\S]*?}/g) || [];
models.forEach((model) => {
  const modelName = model.match(/model (\w+)/)[1];

  if (!model.includes('@@index')) {
    console.warn(`⚠️  Warning: Model ${modelName} has no indexes`);
    hasWarnings = true;
  }

  if (!model.includes('@@map')) {
    console.warn(`⚠️  Warning: Model ${modelName} missing @@ map to table name`);
    hasWarnings = true;
  }
});

// Check 3: All timestamp fields use snake_case
const timestampFields = ['createdAt', 'updatedAt'];
timestampFields.forEach((field) => {
  const regex = new RegExp(`${field}\\s+DateTime.*(?!@map)`, 'g');
  if (regex.test(schema)) {
    console.warn(`⚠️  Warning: ${field} field should use @map for snake_case column name`);
    hasWarnings = true;
  }
});

// Check 4: Foreign keys follow naming convention
const foreignKeys = schema.match(/\w+Id\s+Int/g) || [];
foreignKeys.forEach((fk) => {
  const fieldName = fk.match(/(\w+)Id/)[1];
  const mapPattern = new RegExp(`${fieldName}Id.*@map\\("${fieldName}_id"\\)`);

  if (!mapPattern.test(schema)) {
    console.warn(`⚠️  Warning: Foreign key ${fieldName}Id should map to ${fieldName}_id`);
    hasWarnings = true;
  }
});

// Check 5: No raw SQL in schema
if (schema.includes('@@native') || schema.includes('sql`')) {
  console.warn('⚠️  Warning: Schema contains native SQL - may not be portable');
  hasWarnings = true;
}

// Check 6: All enums are properly defined
const enumUsages = schema.match(/\w+\s+\w+\s+@default\(\w+\)/g) || [];
const definedEnums = schema.match(/enum \w+ {/g) || [];

console.log(`\n📊 Schema Statistics:`);
console.log(`- Models: ${models.length}`);
console.log(`- Enums: ${definedEnums.length}`);
console.log(`- Foreign Keys: ${foreignKeys.length}`);

if (hasErrors) {
  console.error('\n❌ Schema linting failed with errors');
  process.exit(1);
}

if (hasWarnings) {
  console.warn('\n⚠️  Schema linting completed with warnings');
  process.exit(0);
}

console.log('\n✅ Schema linting passed');

6.3 Conflict Detection Service​

// src/database/schema-conflict-detector.service.ts
import { Injectable, Logger } from '@nestjs/common';
import { execSync } from 'child_process';
import * as fs from 'fs';

export interface ConflictReport {
  hasConflicts: boolean;
  conflicts: SchemaConflict[];
  recommendations: string[];
}

export interface SchemaConflict {
  location: string;
  type: 'model' | 'field' | 'relation' | 'enum';
  description: string;
  currentVersion: string;
  incomingVersion: string;
  resolution?: string;
}

@Injectable()
export class SchemaConflictDetectorService {
  private readonly logger = new Logger(SchemaConflictDetectorService.name);

  detectConflicts(): ConflictReport {
    const conflicts: SchemaConflict[] = [];
    const recommendations: string[] = [];

    try {
      // Check for Git merge conflicts
      const status = execSync('git status --porcelain', { encoding: 'utf-8' });

      if (status.includes('UU prisma/schema.prisma')) {
        this.logger.warn('Merge conflict detected in schema file');

        const schemaContent = fs.readFileSync('prisma/schema.prisma', 'utf8');
        const conflictSections = this.parseConflictMarkers(schemaContent);

        conflictSections.forEach((section) => {
          conflicts.push({
            location: section.location,
            type: section.type,
            description: 'Conflicting schema definitions',
            currentVersion: section.current,
            incomingVersion: section.incoming,
            resolution: this.suggestResolution(section),
          });
        });
      }

      // Check for schema drift
      const driftCheck = execSync('npx prisma migrate status', {
        encoding: 'utf-8',
      });

      if (driftCheck.includes('drift')) {
        conflicts.push({
          location: 'database',
          type: 'model',
          description: 'Database schema has drifted from Prisma schema',
          currentVersion: 'database state',
          incomingVersion: 'schema file',
          resolution: 'Run: npx prisma migrate dev to sync',
        });
      }

      // Generate recommendations
      if (conflicts.length > 0) {
        recommendations.push('Review each conflict carefully before resolving');
        recommendations.push('Test schema changes on a separate branch');
        recommendations.push('Coordinate with team members who made conflicting changes');
        recommendations.push('Run full test suite after resolving conflicts');
      }
    } catch (error) {
      this.logger.error('Error detecting conflicts:', error.message);
    }

    return {
      hasConflicts: conflicts.length > 0,
      conflicts,
      recommendations,
    };
  }

  private parseConflictMarkers(content: string): any[] {
    const sections = [];
    const conflictRegex = /<<<<<<< HEAD([\s\S]*?)=======([\s\S]*?)>>>>>>>/g;

    let match;
    while ((match = conflictRegex.exec(content)) !== null) {
      sections.push({
        location: this.identifyLocation(match[1]),
        type: this.identifyType(match[1]),
        current: match[1].trim(),
        incoming: match[2].trim(),
      });
    }

    return sections;
  }

  private identifyLocation(content: string): string {
    const modelMatch = content.match(/model\s+(\w+)/);
    if (modelMatch) return `Model: ${modelMatch[1]}`;

    const enumMatch = content.match(/enum\s+(\w+)/);
    if (enumMatch) return `Enum: ${enumMatch[1]}`;

    return 'Unknown location';
  }

  private identifyType(content: string): 'model' | 'field' | 'relation' | 'enum' {
    if (content.includes('model ')) return 'model';
    if (content.includes('enum ')) return 'enum';
    if (content.includes('@relation')) return 'relation';
    return 'field';
  }

  private suggestResolution(section: any): string {
    // Provide intelligent resolution suggestions
    if (section.type === 'model') {
      return 'Consider merging both changes or renaming to avoid conflict';
    }
    if (section.type === 'field') {
      return 'Keep both fields if they serve different purposes, or merge into one';
    }
    return 'Manual review required';
  }
}

// src/database/schema-backup.service.ts
import { Injectable, Logger } from '@nestjs/common';
import { Storage } from '@google-cloud/storage';
import * as fs from 'fs';
import * as path from 'path';

@Injectable()
export class SchemaBackupService {
  private readonly logger = new Logger(SchemaBackupService.name);
  private storage = new Storage();
  private bucketName = process.env.GCS_SCHEMA_BUCKET || 'ecom-schema-versions';

  async backupSchema(version: string): Promise<string> {
    const schemaPath = path.join(process.cwd(), 'prisma', 'schema.prisma');
    const schemaContent = fs.readFileSync(schemaPath, 'utf8');

    const timestamp = new Date().toISOString().replace(/[:.]/g, '-');
    const fileName = `schema-${version}-${timestamp}.prisma`;

    const bucket = this.storage.bucket(this.bucketName);
    const file = bucket.file(`schemas/${fileName}`);

    await file.save(schemaContent, {
      metadata: {
        contentType: 'text/plain',
        metadata: {
          version,
          timestamp: new Date().toISOString(),
          appVersion: process.env.APP_VERSION || 'unknown',
        },
      },
    });

    this.logger.log(`Schema backed up to GCS: ${fileName}`);
    return `gs://${this.bucketName}/schemas/${fileName}`;
  }

  async listSchemaVersions(): Promise<Array<{ name: string; created: Date; version: string }>> {
    const bucket = this.storage.bucket(this.bucketName);
    const [files] = await bucket.getFiles({ prefix: 'schemas/' });

    return files.map((file) => ({
      name: file.name,
      created: new Date(file.metadata.timeCreated),
      version: file.metadata.metadata?.version || 'unknown',
    }));
  }

  async restoreSchema(fileName: string): Promise<void> {
    const bucket = this.storage.bucket(this.bucketName);
    const file = bucket.file(`schemas/${fileName}`);

    const [content] = await file.download();
    const schemaPath = path.join(process.cwd(), 'prisma', 'schema.prisma');

    // Backup current schema before restore
    await this.backupSchema('pre-restore');

    fs.writeFileSync(schemaPath, content);
    this.logger.log(`Schema restored from: ${fileName}`);
  }

  async compareSchemaVersions(version1: string, version2: string): Promise<string> {
    const bucket = this.storage.bucket(this.bucketName);

    const [content1] = await bucket.file(`schemas/${version1}`).download();
    const [content2] = await bucket.file(`schemas/${version2}`).download();

    // Generate diff
    const diff = this.generateDiff(content1.toString(), content2.toString());
    return diff;
  }

  private generateDiff(schema1: string, schema2: string): string {
    // Simple line-by-line diff
    const lines1 = schema1.split('\n');
    const lines2 = schema2.split('\n');

    let diff = '';
    const maxLines = Math.max(lines1.length, lines2.length);

    for (let i = 0; i < maxLines; i++) {
      if (lines1[i] !== lines2[i]) {
        diff += `Line ${i + 1}:\n`;
        diff += `- ${lines1[i] || '(removed)'}\n`;
        diff += `+ ${lines2[i] || '(added)'}\n\n`;
      }
    }

    return diff;
  }
}

8. Best Practices​

8.1 Schema Change Workflow​

# Database Schema Change Workflow

## 1. Planning Phase

- [ ] Document reason for schema change
- [ ] Identify affected tables and relationships
- [ ] Assess impact on application code
- [ ] Plan migration strategy (if needed)
- [ ] Consider backward compatibility

## 2. Development Phase

- [ ] Create feature branch: `git checkout -b feature/add-user-preferences`
- [ ] Modify schema file (prisma/schema.prisma or entities)
- [ ] Add version comment to schema
- [ ] Generate migration: `npx prisma migrate dev --name add_user_preferences`
- [ ] Update application code to use new schema
- [ ] Write tests for schema changes

## 3. Review Phase

- [ ] Commit schema changes with descriptive message
- [ ] Push branch and create pull request
- [ ] CI runs schema validation
- [ ] Review schema diff in PR
- [ ] Team reviews changes
- [ ] Address feedback

## 4. Merge & Deploy

- [ ] Merge to main branch after approval
- [ ] CI automatically backs up current schema
- [ ] CI runs migrations in staging
- [ ] Verify staging deployment
- [ ] Deploy to production with migration
- [ ] Monitor for issues

## 5. Post-Deployment

- [ ] Verify schema applied correctly
- [ ] Check application functionality
- [ ] Monitor performance metrics
- [ ] Document any issues
- [ ] Update team on changes

8.2 Schema Conflict Resolution Guide​

/**
 * Common Schema Conflict Scenarios and Resolutions
 */

// Scenario 1: Two developers add different columns to same table
// Resolution: Accept both changes, merge columns

// Before (base):
model User {
  id    Int    @id
  email String
}

// Developer A adds:
model User {
  id    Int    @id
  email String
  name  String // Added by Dev A
}

// Developer B adds:
model User {
  id    Int    @id
  email String
  role  String // Added by Dev B
}

// Resolution (merge both):
model User {
  id    Int    @id
  email String
  name  String // From Dev A
  role  String // From Dev B
}

// ============================================

// Scenario 2: Same column added with different types
// Resolution: Discuss with team, choose one type

// Developer A adds:
model Product {
  price Decimal @db.Decimal(10, 2)
}

// Developer B adds:
model Product {
  price Int // Different type!
}

// Resolution: Use team standard (typically Decimal for currency)
model Product {
  price Decimal @db.Decimal(10, 2)
}

// ============================================

// Scenario 3: Conflicting enum values
// Resolution: Merge all unique enum values

// Developer A adds:
enum OrderStatus {
  PENDING
  SHIPPED
  DELIVERED // Added by Dev A
}

// Developer B adds:
enum OrderStatus {
  PENDING
  SHIPPED
  CANCELLED // Added by Dev B
}

// Resolution (merge both):
enum OrderStatus {
  PENDING
  SHIPPED
  DELIVERED // From Dev A
  CANCELLED // From Dev B
}

By implementing database schema version control with conflict detection, teams ensure database changes are tracked, reviewed, and merged safely, maintaining consistency between database schema and application code across all environments.
