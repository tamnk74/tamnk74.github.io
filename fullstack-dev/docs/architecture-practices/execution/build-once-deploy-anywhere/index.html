Build Once, Deploy Anywhere Strategy

Overview​

One of the fundamental principles of Continuous Delivery is Build Binaries Only Once. The same package that was tested in Dev and Stage environments should be promoted to production without rebuilding. Subsequent deployments, testing, and releases should never attempt to build the binary artifacts again.

This principle ensures that:

  • The exact same artifact is tested and deployed across all environments
  • Build inconsistencies are eliminated
  • Deployment speed is maximized
  • Configuration drift is prevented
  • Confidence in deployments is increased

This guide demonstrates how to implement "Build Once, Deploy Anywhere" for Next.js frontend applications and NestJS microservices on Google Cloud Platform (GCP) using GitHub Actions.

Why Build Once, Deploy Anywhere?​

The Problem with Rebuilding​

IssueDescriptionImpact
Inconsistent ArtifactsDifferent builds can produce different outputsWhat works in staging may fail in production
Dependency DriftPackage versions may change between buildsUnpredictable behavior across environments
Time WasteBuilding the same code multiple timesSlower deployment pipeline
Testing InvalidationTesting one artifact, deploying anotherQuality assurance is meaningless
Debugging DifficultyHard to reproduce issuesLonger incident resolution time

The Solution: Immutable Artifacts​

Implementation Architecture​

Artifact Flow​

Key Components​

  1. Artifact Registry: Google Container Registry (GCR) or Artifact Registry
  2. CI/CD Platform: GitHub Actions
  3. Container Orchestration: Google Kubernetes Engine (GKE) or Cloud Run
  4. Configuration Management: ConfigMaps, Secrets, Environment Variables
  5. Image Tagging Strategy: Git SHA + semantic versioning

Step-by-Step Implementation​

Step 1: Docker Image Strategy​

Immutable Docker Images​

The key is to build Docker images that contain only the application code and dependencies, not environment-specific configuration.

NestJS Microservice Multi-Stage Dockerfile​
# Dockerfile for NestJS Backend
# Build once, configure at runtime

# ============================================
# Stage 1: Dependencies
# ============================================
FROM node:20-alpine AS deps
WORKDIR /app

# Copy package files
COPY package.json pnpm-lock.yaml ./

# Install dependencies
RUN corepack enable pnpm && \
    pnpm install --frozen-lockfile --prod

# ============================================
# Stage 2: Build
# ============================================
FROM node:20-alpine AS builder
WORKDIR /app

# Copy package files
COPY package.json pnpm-lock.yaml ./

# Install all dependencies (including dev)
RUN corepack enable pnpm && \
    pnpm install --frozen-lockfile

# Copy source code
COPY . .

# Build application
RUN pnpm build

# ============================================
# Stage 3: Production Runtime
# ============================================
FROM node:20-alpine AS runner
WORKDIR /app

# Create non-root user
RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 nestjs

# Copy only necessary files
COPY --from=builder --chown=nestjs:nodejs /app/dist ./dist
COPY --from=deps --chown=nestjs:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=nestjs:nodejs /app/package.json ./

# Set NODE_ENV (can be overridden at runtime)
ENV NODE_ENV=production
ENV PORT=3000

# Expose port
EXPOSE 3000

# Switch to non-root user
USER nestjs

# Health check
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s --retries=3 \
    CMD node -e "require('http').get('http://localhost:3000/health', (r) => { process.exit(r.statusCode === 200 ? 0 : 1); })"

# Start application
CMD ["node", "dist/main.js"]
Next.js Frontend Multi-Stage Dockerfile​
# Dockerfile for Next.js Frontend
# Build once, configure at runtime

# ============================================
# Stage 1: Dependencies
# ============================================
FROM node:20-alpine AS deps
WORKDIR /app

# Copy package files
COPY package.json pnpm-lock.yaml ./

# Install dependencies
RUN corepack enable pnpm && \
    pnpm install --frozen-lockfile

# ============================================
# Stage 2: Build
# ============================================
FROM node:20-alpine AS builder
WORKDIR /app

# Copy dependencies from deps stage
COPY --from=deps /app/node_modules ./node_modules

# Copy source code
COPY . .

# Build Next.js application
# Note: Environment variables are NOT embedded at build time
# They will be injected at runtime
RUN corepack enable pnpm && \
    pnpm build

# ============================================
# Stage 3: Production Runtime
# ============================================
FROM node:20-alpine AS runner
WORKDIR /app

# Create non-root user
RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 nextjs

# Copy only necessary files
COPY --from=builder --chown=nextjs:nodejs /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

# Set environment
ENV NODE_ENV=production
ENV PORT=3000

# Expose port
EXPOSE 3000

# Switch to non-root user
USER nextjs

# Health check
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s --retries=3 \
    CMD node -e "require('http').get('http://localhost:3000/api/health', (r) => { process.exit(r.statusCode === 200 ? 0 : 1); })"

# Start application
CMD ["node", "server.js"]

Key Points:

  • No environment-specific configuration baked in
  • Configuration injected at runtime via environment variables
  • Same image works across all environments

Step 2: Image Tagging Strategy​

Use a combination of Git SHA and semantic versioning for immutable, traceable artifacts.

# Image tagging strategy
# Format: gcr.io/${PROJECT_ID}/${SERVICE_NAME}:${TAG}

# Examples:
# gcr.io/my-project/api-gateway:abc123def456  # Git SHA (primary)
# gcr.io/my-project/api-gateway:v1.2.3       # Semantic version (alias)
# gcr.io/my-project/api-gateway:latest       # Latest (for dev only)

Step 3: GitHub Actions Workflow - Build Stage​

Create a centralized build workflow that produces artifacts once.

.github/workflows/build-and-push.yml​

name: Build and Push Docker Images

on:
  push:
    branches:
      - main
      - develop
    paths:
      - 'apps/**'
      - 'libs/**'
      - 'package.json'
      - 'pnpm-lock.yaml'
  pull_request:
    branches:
      - main
      - develop

env:
  GCP_REGION: us-central1
  GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}
  REGISTRY: gcr.io

jobs:
  # ========================================
  # Detect Changed Services
  # ========================================
  detect-changes:
    runs-on: ubuntu-latest
    outputs:
      api-gateway: ${{ steps.filter.outputs.api-gateway }}
      user-service: ${{ steps.filter.outputs.user-service }}
      web-frontend: ${{ steps.filter.outputs.web-frontend }}
    steps:
      - uses: actions/checkout@v4

      - uses: dorny/paths-filter@v3
        id: filter
        with:
          filters: |
            api-gateway:
              - 'apps/api-gateway/**'
              - 'libs/**'
            user-service:
              - 'apps/user-service/**'
              - 'libs/**'
            web-frontend:
              - 'apps/web/**'
              - 'libs/**'

  # ========================================
  # Build NestJS API Gateway
  # ========================================
  build-api-gateway:
    needs: detect-changes
    if: needs.detect-changes.outputs.api-gateway == 'true'
    runs-on: ubuntu-latest
    outputs:
      image-digest: ${{ steps.build.outputs.digest }}
      image-tag: ${{ steps.meta.outputs.tags }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # Full history for proper git SHA

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Set up Cloud SDK
        uses: google-github-actions/setup-gcloud@v2

      - name: Configure Docker for GCR
        run: gcloud auth configure-docker

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.GCP_PROJECT_ID }}/api-gateway
          tags: |
            type=sha,prefix=,suffix=,format=long
            type=ref,event=branch
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}

      - name: Build and push Docker image
        id: build
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./apps/api-gateway/Dockerfile
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          build-args: |
            GIT_SHA=${{ github.sha }}
            BUILD_DATE=${{ github.event.head_commit.timestamp }}
            VERSION=${{ github.ref_name }}

      - name: Generate SBOM
        uses: anchore/sbom-action@v0
        with:
          image: ${{ env.REGISTRY }}/${{ env.GCP_PROJECT_ID }}/api-gateway@${{ steps.build.outputs.digest }}
          format: cyclonedx-json
          output-file: sbom-api-gateway.json

      - name: Scan for vulnerabilities
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ env.REGISTRY }}/${{ env.GCP_PROJECT_ID }}/api-gateway@${{ steps.build.outputs.digest }}
          format: sarif
          output: trivy-results.sarif

      - name: Upload scan results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy-results.sarif

      - name: Output image info
        run: |
          echo "Image built and pushed successfully!"
          echo "Image: ${{ steps.meta.outputs.tags }}"
          echo "Digest: ${{ steps.build.outputs.digest }}"
          echo "Git SHA: ${{ github.sha }}"

  # ========================================
  # Build Next.js Web Frontend
  # ========================================
  build-web-frontend:
    needs: detect-changes
    if: needs.detect-changes.outputs.web-frontend == 'true'
    runs-on: ubuntu-latest
    outputs:
      image-digest: ${{ steps.build.outputs.digest }}
      image-tag: ${{ steps.meta.outputs.tags }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Set up Cloud SDK
        uses: google-github-actions/setup-gcloud@v2

      - name: Configure Docker for GCR
        run: gcloud auth configure-docker

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.GCP_PROJECT_ID }}/web-frontend
          tags: |
            type=sha,prefix=,suffix=,format=long
            type=ref,event=branch
            type=semver,pattern={{version}}

      - name: Build and push Docker image
        id: build
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./apps/web/Dockerfile
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          build-args: |
            GIT_SHA=${{ github.sha }}
            BUILD_DATE=${{ github.event.head_commit.timestamp }}

      - name: Scan for vulnerabilities
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ env.REGISTRY }}/${{ env.GCP_PROJECT_ID }}/web-frontend@${{ steps.build.outputs.digest }}
          format: sarif
          output: trivy-results.sarif

      - name: Upload scan results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy-results.sarif

Step 4: Deployment Workflows - Using the Same Artifact​

Create separate deployment workflows that reference the same built artifact.

.github/workflows/deploy-dev.yml​

name: Deploy to Development

on:
  workflow_run:
    workflows: ['Build and Push Docker Images']
    types:
      - completed
    branches:
      - develop

env:
  GCP_REGION: us-central1
  GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}
  GKE_CLUSTER: dev-cluster
  NAMESPACE: default

jobs:
  deploy-to-dev:
    runs-on: ubuntu-latest
    if: ${{ github.event.workflow_run.conclusion == 'success' }}
    environment:
      name: development
      url: https://dev.example.com
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Get GKE credentials
        uses: google-github-actions/get-gke-credentials@v2
        with:
          cluster_name: ${{ env.GKE_CLUSTER }}
          location: ${{ env.GCP_REGION }}

      - name: Deploy API Gateway
        run: |
          # Use the exact image built in the previous workflow
          IMAGE_TAG=${{ github.sha }}

          kubectl set image deployment/api-gateway \
            api-gateway=gcr.io/${{ env.GCP_PROJECT_ID }}/api-gateway:${IMAGE_TAG} \
            -n ${{ env.NAMESPACE }}

          kubectl rollout status deployment/api-gateway -n ${{ env.NAMESPACE }} --timeout=5m

      - name: Deploy Web Frontend
        run: |
          IMAGE_TAG=${{ github.sha }}

          kubectl set image deployment/web-frontend \
            web-frontend=gcr.io/${{ env.GCP_PROJECT_ID }}/web-frontend:${IMAGE_TAG} \
            -n ${{ env.NAMESPACE }}

          kubectl rollout status deployment/web-frontend -n ${{ env.NAMESPACE }} --timeout=5m

      - name: Run Integration Tests
        run: |
          # Run integration tests against dev environment
          kubectl run integration-tests \
            --image=gcr.io/${{ env.GCP_PROJECT_ID }}/integration-tests:latest \
            --restart=Never \
            --env="API_URL=https://dev-api.example.com" \
            -n ${{ env.NAMESPACE }}

          kubectl wait --for=condition=completed pod/integration-tests -n ${{ env.NAMESPACE }} --timeout=10m

.github/workflows/deploy-staging.yml​

name: Deploy to Staging

on:
  workflow_dispatch:
    inputs:
      git_sha:
        description: 'Git SHA to deploy (defaults to latest from main)'
        required: false
        type: string

env:
  GCP_REGION: us-central1
  GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}
  GKE_CLUSTER: staging-cluster
  NAMESPACE: default

jobs:
  deploy-to-staging:
    runs-on: ubuntu-latest
    environment:
      name: staging
      url: https://staging.example.com
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Determine deployment SHA
        id: deployment-sha
        run: |
          if [ -n "${{ inputs.git_sha }}" ]; then
            echo "sha=${{ inputs.git_sha }}" >> $GITHUB_OUTPUT
          else
            echo "sha=${{ github.sha }}" >> $GITHUB_OUTPUT
          fi

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Get GKE credentials
        uses: google-github-actions/get-gke-credentials@v2
        with:
          cluster_name: ${{ env.GKE_CLUSTER }}
          location: ${{ env.GCP_REGION }}

      - name: Verify images exist
        run: |
          IMAGE_TAG=${{ steps.deployment-sha.outputs.sha }}

          # Check if images exist in registry
          gcloud container images describe \
            gcr.io/${{ env.GCP_PROJECT_ID }}/api-gateway:${IMAGE_TAG}

          gcloud container images describe \
            gcr.io/${{ env.GCP_PROJECT_ID }}/web-frontend:${IMAGE_TAG}

      - name: Deploy to Staging
        run: |
          IMAGE_TAG=${{ steps.deployment-sha.outputs.sha }}

          # Deploy API Gateway
          kubectl set image deployment/api-gateway \
            api-gateway=gcr.io/${{ env.GCP_PROJECT_ID }}/api-gateway:${IMAGE_TAG} \
            -n ${{ env.NAMESPACE }}

          # Deploy Web Frontend
          kubectl set image deployment/web-frontend \
            web-frontend=gcr.io/${{ env.GCP_PROJECT_ID }}/web-frontend:${IMAGE_TAG} \
            -n ${{ env.NAMESPACE }}

          # Wait for rollout
          kubectl rollout status deployment/api-gateway -n ${{ env.NAMESPACE }} --timeout=5m
          kubectl rollout status deployment/web-frontend -n ${{ env.NAMESPACE }} --timeout=5m

      - name: Run E2E Tests
        run: |
          # Run comprehensive E2E tests
          kubectl run e2e-tests \
            --image=gcr.io/${{ env.GCP_PROJECT_ID }}/e2e-tests:latest \
            --restart=Never \
            --env="BASE_URL=https://staging.example.com" \
            -n ${{ env.NAMESPACE }}

          kubectl wait --for=condition=completed pod/e2e-tests -n ${{ env.NAMESPACE }} --timeout=20m

      - name: Run Performance Tests
        run: |
          # Run performance tests
          kubectl run performance-tests \
            --image=gcr.io/${{ env.GCP_PROJECT_ID }}/performance-tests:latest \
            --restart=Never \
            --env="TARGET_URL=https://staging.example.com" \
            -n ${{ env.NAMESPACE }}

          kubectl wait --for=condition=completed pod/performance-tests -n ${{ env.NAMESPACE }} --timeout=15m

.github/workflows/deploy-production.yml​

name: Deploy to Production

on:
  workflow_dispatch:
    inputs:
      git_sha:
        description: 'Git SHA to deploy (must be tested in staging)'
        required: true
        type: string
      deployment_strategy:
        description: 'Deployment strategy'
        required: true
        type: choice
        options:
          - blue-green
          - rolling
          - canary
        default: rolling

env:
  GCP_REGION: us-central1
  GCP_PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}
  GKE_CLUSTER: production-cluster
  NAMESPACE: production

jobs:
  validate-deployment:
    runs-on: ubuntu-latest
    outputs:
      validated: ${{ steps.validate.outputs.validated }}
    steps:
      - name: Validate Git SHA
        id: validate
        run: |
          # Verify the image exists and has been scanned
          gcloud auth activate-service-account --key-file=<(echo '${{ secrets.GCP_SA_KEY }}')

          IMAGE_TAG=${{ inputs.git_sha }}

          # Check if image exists
          if gcloud container images describe gcr.io/${{ env.GCP_PROJECT_ID }}/api-gateway:${IMAGE_TAG}; then
            echo "validated=true" >> $GITHUB_OUTPUT
          else
            echo "validated=false" >> $GITHUB_OUTPUT
            echo "ERROR: Image not found in registry"
            exit 1
          fi

      - name: Check staging deployment history
        run: |
          # Verify this SHA was deployed to staging first
          echo "Checking deployment history for ${{ inputs.git_sha }}"
          # Add logic to verify staging deployment

  deploy-to-production:
    needs: validate-deployment
    if: needs.validate-deployment.outputs.validated == 'true'
    runs-on: ubuntu-latest
    environment:
      name: production
      url: https://example.com
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
        with:
          ref: ${{ inputs.git_sha }}

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Get GKE credentials
        uses: google-github-actions/get-gke-credentials@v2
        with:
          cluster_name: ${{ env.GKE_CLUSTER }}
          location: ${{ env.GCP_REGION }}

      - name: Create deployment backup
        run: |
          # Backup current deployment state
          kubectl get deployments -n ${{ env.NAMESPACE }} -o yaml > backup-deployments.yaml

          # Upload to GCS
          gsutil cp backup-deployments.yaml \
            gs://${{ env.GCP_PROJECT_ID }}-backups/deployments/$(date +%Y%m%d-%H%M%S)-backup.yaml

      - name: Deploy with Rolling Strategy
        if: inputs.deployment_strategy == 'rolling'
        run: |
          IMAGE_TAG=${{ inputs.git_sha }}

          # Set new image
          kubectl set image deployment/api-gateway \
            api-gateway=gcr.io/${{ env.GCP_PROJECT_ID }}/api-gateway:${IMAGE_TAG} \
            -n ${{ env.NAMESPACE }}

          kubectl set image deployment/web-frontend \
            web-frontend=gcr.io/${{ env.GCP_PROJECT_ID }}/web-frontend:${IMAGE_TAG} \
            -n ${{ env.NAMESPACE }}

          # Monitor rollout
          kubectl rollout status deployment/api-gateway -n ${{ env.NAMESPACE }} --timeout=10m
          kubectl rollout status deployment/web-frontend -n ${{ env.NAMESPACE }} --timeout=10m

      - name: Deploy with Blue-Green Strategy
        if: inputs.deployment_strategy == 'blue-green'
        run: |
          IMAGE_TAG=${{ inputs.git_sha }}

          # Create green deployment
          kubectl apply -f k8s/blue-green/green-deployment.yaml

          # Wait for green to be ready
          kubectl wait --for=condition=available deployment/api-gateway-green \
            -n ${{ env.NAMESPACE }} --timeout=10m

          # Switch traffic
          kubectl patch service api-gateway -n ${{ env.NAMESPACE }} \
            -p '{"spec":{"selector":{"version":"green"}}}'

          # Monitor for 5 minutes
          sleep 300

          # Delete blue deployment if successful
          kubectl delete deployment api-gateway-blue -n ${{ env.NAMESPACE }}

      - name: Smoke Tests
        run: |
          # Run smoke tests to verify deployment
          curl -f https://example.com/health || exit 1
          curl -f https://example.com/api/health || exit 1

      - name: Notify deployment success
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {
              "text": "✅ Production Deployment Successful",
              "blocks": [
                {
                  "type": "header",
                  "text": {
                    "type": "plain_text",
                    "text": "🚀 Production Deployment Successful"
                  }
                },
                {
                  "type": "section",
                  "fields": [
                    {"type": "mrkdwn", "text": "*Git SHA:*\n${{ inputs.git_sha }}"},
                    {"type": "mrkdwn", "text": "*Strategy:*\n${{ inputs.deployment_strategy }}"},
                    {"type": "mrkdwn", "text": "*Deployed by:*\n${{ github.actor }}"},
                    {"type": "mrkdwn", "text": "*Time:*\n$(date -u)"}
                  ]
                }
              ]
            }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

      - name: Rollback on failure
        if: failure()
        run: |
          echo "Deployment failed, initiating rollback..."
          kubectl rollout undo deployment/api-gateway -n ${{ env.NAMESPACE }}
          kubectl rollout undo deployment/web-frontend -n ${{ env.NAMESPACE }}

Step 6: Artifact Verification and Promotion​

Create a promotion script to verify and promote artifacts between environments.

scripts/promote-artifact.sh​

#!/bin/bash

# Promote artifact from one environment to another
# Usage: ./promote-artifact.sh <service> <git-sha> <from-env> <to-env>

set -euo pipefail

SERVICE_NAME=$1
GIT_SHA=$2
FROM_ENV=$3
TO_ENV=$4

PROJECT_ID="${GCP_PROJECT_ID}"
REGISTRY="gcr.io"

echo "🚀 Promoting artifact: ${SERVICE_NAME}:${GIT_SHA}"
echo "📦 From: ${FROM_ENV}"
echo "📦 To: ${TO_ENV}"

# Verify image exists
echo "✓ Verifying image exists..."
if ! gcloud container images describe "${REGISTRY}/${PROJECT_ID}/${SERVICE_NAME}:${GIT_SHA}" > /dev/null 2>&1; then
    echo "❌ Error: Image ${SERVICE_NAME}:${GIT_SHA} not found in registry"
    exit 1
fi

# Check vulnerability scan results
echo "✓ Checking vulnerability scan results..."
VULN_COUNT=$(gcloud container images describe "${REGISTRY}/${PROJECT_ID}/${SERVICE_NAME}:${GIT_SHA}" \
    --format='value(image_summary.vulnerability_summary.counts)' || echo "0")

if [ "$VULN_COUNT" != "0" ]; then
    echo "⚠️  Warning: Image has vulnerabilities. Count: ${VULN_COUNT}"
    read -p "Continue with promotion? (y/N) " -n 1 -r
    echo
    if [[ ! $REPLY =~ ^[Yy]$ ]]; then
        exit 1
    fi
fi

# Add promotion tag
echo "✓ Adding promotion tag..."
gcloud container images add-tag \
    "${REGISTRY}/${PROJECT_ID}/${SERVICE_NAME}:${GIT_SHA}" \
    "${REGISTRY}/${PROJECT_ID}/${SERVICE_NAME}:${TO_ENV}-latest" \
    --quiet

# Record promotion in metadata
echo "✓ Recording promotion metadata..."
gcloud container images add-tag \
    "${REGISTRY}/${PROJECT_ID}/${SERVICE_NAME}:${GIT_SHA}" \
    "${REGISTRY}/${PROJECT_ID}/${SERVICE_NAME}:promoted-${TO_ENV}-$(date +%Y%m%d-%H%M%S)" \
    --quiet

echo "✅ Promotion complete!"
echo "Image: ${REGISTRY}/${PROJECT_ID}/${SERVICE_NAME}:${GIT_SHA}"
echo "Environment: ${TO_ENV}"

Step 7: Image Immutability Validation​

Add a script to verify that the same image is being used across environments.

scripts/verify-deployment.sh​

#!/bin/bash

# Verify that the same Docker image is deployed across environments
# Usage: ./verify-deployment.sh <service-name>

set -euo pipefail

SERVICE_NAME=$1
PROJECT_ID="${GCP_PROJECT_ID}"

echo "🔍 Verifying deployment consistency for: ${SERVICE_NAME}"
echo "============================================"

# Get image from dev
DEV_IMAGE=$(kubectl get deployment "${SERVICE_NAME}" -n default \
    -o jsonpath='{.spec.template.spec.containers[0].image}')
DEV_DIGEST=$(echo "${DEV_IMAGE}" | cut -d'@' -f2 || echo "")

# Get image from staging
STAGING_IMAGE=$(kubectl get deployment "${SERVICE_NAME}" -n staging \
    -o jsonpath='{.spec.template.spec.containers[0].image}')
STAGING_DIGEST=$(echo "${STAGING_IMAGE}" | cut -d'@' -f2 || echo "")

# Get image from production
PROD_IMAGE=$(kubectl get deployment "${SERVICE_NAME}" -n production \
    -o jsonpath='{.spec.template.spec.containers[0].image}')
PROD_DIGEST=$(echo "${PROD_IMAGE}" | cut -d'@' -f2 || echo "")

echo "Dev:        ${DEV_IMAGE}"
echo "Staging:    ${STAGING_IMAGE}"
echo "Production: ${PROD_IMAGE}"
echo ""

# Verify digest-based deployment
if [ -z "${DEV_DIGEST}" ] || [ -z "${STAGING_DIGEST}" ] || [ -z "${PROD_DIGEST}" ]; then
    echo "⚠️  WARNING: Not all environments are using digest-based references!"
    echo "Recommendation: Use image digests for immutable deployments"
else
    echo "✓ All environments using digest-based references"
fi

# Check if using same Git SHA
DEV_SHA=$(echo "${DEV_IMAGE}" | grep -oP '(?<=:)[a-f0-9]{40}' || echo "unknown")
STAGING_SHA=$(echo "${STAGING_IMAGE}" | grep -oP '(?<=:)[a-f0-9]{40}' || echo "unknown")
PROD_SHA=$(echo "${PROD_IMAGE}" | grep -oP '(?<=:)[a-f0-9]{40}' || echo "unknown")

echo ""
echo "Git SHAs:"
echo "Dev:        ${DEV_SHA}"
echo "Staging:    ${STAGING_SHA}"
echo "Production: ${PROD_SHA}"
echo ""

if [ "${STAGING_SHA}" == "${PROD_SHA}" ]; then
    echo "✅ Production and Staging are using the same artifact"
else
    echo "⚠️  Production and Staging are using different artifacts"
fi

Best Practices​

1. Image Tagging Best Practices​

PracticeDescriptionExample
Use Git SHAPrimary identifier for traceabilityabc123def456
Semantic VersioningFor release versionsv1.2.3
Avoid :latestNever use in productionUse explicit tags
Use DigestsFor immutable references@sha256:abc...
Environment TagsOptional for trackingprod-latest

2. Configuration Management​

  • Never hardcode environment-specific values in Docker images
  • Use environment variables for runtime configuration
  • Store secrets in Google Secret Manager or Kubernetes Secrets
  • Use ConfigMaps for non-sensitive configuration
  • Implement feature flags for environment-specific behavior

3. Deployment Verification​

# Always verify before promoting
1. Image exists in registry
2. Security scan passed
3. Tests passed in previous environment
4. No critical vulnerabilities
5. Configuration is correct for target environment

4. Rollback Strategy​

Always maintain the ability to rollback quickly:

# Quick rollback command
kubectl rollout undo deployment/<service-name> -n <namespace>

# Or rollback to specific revision
kubectl rollout undo deployment/<service-name> --to-revision=<number> -n <namespace>

Exceptions: When to Rebuild​

Mobile Applications​

Mobile apps (iOS/Android) often require different builds:

  • App signing differs per environment
  • Embedded API endpoints may differ
  • Store-specific configurations

Single Page Applications (SPAs)​

Some SPAs may require rebuild if:

  • Using environment variables at build time (Next.js NEXT_PUBLIC_*)
  • Generating static sites
  • Embedding configuration in bundles

Solution for Next.js: Use runtime configuration:

// next.config.js
module.exports = {
  output: 'standalone', // Enable for runtime config
  publicRuntimeConfig: {
    // Will be available on both server and client
    apiUrl: process.env.API_URL,
  },
  serverRuntimeConfig: {
    // Will only be available on the server side
    secret: process.env.SECRET_KEY,
  },
};

Verification Checklist​

Before promoting to production:

  • Same image digest deployed to staging
  • All tests passed in staging
  • Security scan completed without critical issues
  • Configuration verified for production
  • Rollback plan documented
  • Monitoring alerts configured
