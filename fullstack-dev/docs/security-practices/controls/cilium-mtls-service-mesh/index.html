Cilium mTLS & Service-to-Service Authorization

Zero-trust service mesh on GKE using Cilium: mutual TLS for every east-west connection, and explicit CiliumNetworkPolicy ensuring no service can reach the payment service without a declared allow rule.

Problem Statement​

In a microservices platform with 12+ services running in the same GKE cluster, any compromised pod can attempt lateral movement to high-value targets like the Payment Service. Traditional Kubernetes NetworkPolicy operates at IP/port — it has no concept of which service is making the request.

The threat model this guide addresses:

ThreatWithout This GuideWith Cilium mTLS
Compromised pod calls payment APIAllowed if same namespaceBlocked — identity not in allow list
Man-in-the-middle between servicesPlaintext gRPC / HTTPAll east-west traffic encrypted (WireGuard / TLS)
Misconfigured service talks to DB directlyIP allow rule missedDefault-deny + explicit port/identity allow
L7 path squatting (call /internal from browser)Requires app-level auth onlyCilium rejects at kernel level before app code runs

Architecture​

Cilium identity is derived from the pod's Kubernetes Service Account labels — not IP addresses, which are ephemeral and spoofable.

Cilium Installation (GKE)​

# Install Cilium with WireGuard node-to-node encryption + Hubble observability
helm repo add cilium https://helm.cilium.io/
helm install cilium cilium/cilium \
  --version 1.15.0 \
  --namespace kube-system \
  --set encryption.enabled=true \
  --set encryption.type=wireguard \
  --set hubble.enabled=true \
  --set hubble.relay.enabled=true \
  --set hubble.ui.enabled=true \
  --set kubeProxyReplacement=true \
  --set k8sServiceHost=<CLUSTER_ENDPOINT> \
  --set k8sServicePort=443

Terraform: GKE cluster with Cilium CNI​

# terraform/modules/gke/cluster.tf
resource "google_container_cluster" "primary" {

  project  = var.project_id

  # Remove default node pool — managed separately

  initial_node_count       = 1

  networking_mode = "VPC_NATIVE"

  subnetwork      = google_compute_subnetwork.gke.id

  datapath_provider = "ADVANCED_DATAPATH"   # enables eBPF / Cilium

  network_policy {
    enabled = false   # standard NetworkPolicy controller disabled; Cilium enforces instead
  }

  ip_allocation_policy {
    cluster_secondary_range_name  = "pods"
    services_secondary_range_name = "services"
  }

  workload_identity_config {
    workload_pool = "${var.project_id}.svc.id.goog"
  }
}

Default-Deny Baseline​

Apply a cluster-wide default-deny policy before adding allow rules. This ensures any new service is blocked until a policy explicitly permits its traffic.

# k8s/cilium/cluster-default-deny.yaml
apiVersion: cilium.io/v2
kind: CiliumClusterwideNetworkPolicy
metadata:
  name: default-deny-all
spec:
  description: "Deny all ingress and egress by default; explicit allow rules required"
  endpointSelector: {}   # matches every pod in the cluster
  ingress:
    - fromEntities:
        - kube-apiserver   # always allow health probes from API server
  egress:
    - toEntities:
        - kube-dns         # allow DNS resolution cluster-wide
        - kube-apiserver   # allow pods to call K8s API (e.g. ESO, ArgoCD)

Payment Service: Explicit Allow Policies​

The payment service namespace (payment) has the strictest policies: only Traefik, Order Service, and Cart Service may call it — at specific HTTP paths.

Ingress: allow only declared callers (L3/L4)​

# k8s/payment/cilium-network-policy-ingress.yaml
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: payment-ingress-allow
  namespace: payment
spec:
  description: "Only traefik, order-service, and cart-service may reach payment-service"
  endpointSelector:
    matchLabels:
      app: payment-service

  ingress:
    # Traefik ingress controller (lives in production namespace)
    - fromEndpoints:
        - matchLabels:
            app: traefik
            io.kubernetes.pod.namespace: production
      toPorts:
        - ports:
            - port: "3003"
              protocol: TCP

    # Order Service
    - fromEndpoints:
        - matchLabels:
            app: order-service
            io.kubernetes.pod.namespace: production
      toPorts:
        - ports:
            - port: "3003"
              protocol: TCP

    # Cart Service (initiates checkout)
    - fromEndpoints:
        - matchLabels:
            app: cart-service
            io.kubernetes.pod.namespace: production
      toPorts:
        - ports:
            - port: "3003"
              protocol: TCP

Ingress: L7 path restriction (Cilium HTTP policy)​

# k8s/payment/cilium-network-policy-l7.yaml
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: payment-l7-policy
  namespace: payment
spec:
  description: "Restrict payment-service to declared HTTP paths only"
  endpointSelector:
    matchLabels:
      app: payment-service

  ingress:
    - fromEndpoints:
        - matchLabels:
            app: order-service
            io.kubernetes.pod.namespace: production
      toPorts:
        - ports:
            - port: "3003"
              protocol: TCP
          rules:
            http:
              - method: "POST"
                path: "/payments/charge"
              - method: "POST"
                path: "/payments/refund"
              # All other paths denied at the eBPF layer

    - fromEndpoints:
        - matchLabels:
            app: cart-service
            io.kubernetes.pod.namespace: production
      toPorts:
        - ports:
            - port: "3003"
              protocol: TCP
          rules:
            http:
              - method: "POST"
                path: "/payments/intents"
              - method: "GET"
                path: "/payments/status"

Egress: payment service outbound allow​

# k8s/payment/cilium-network-policy-egress.yaml
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: payment-egress-allow
  namespace: payment
spec:
  endpointSelector:
    matchLabels:
      app: payment-service

  egress:
    # Cloud SQL via private IP (PostgreSQL)
    - toCIDR:
        - "10.4.0.0/16"     # internal subnet range for Cloud SQL
      toPorts:
        - ports:
            - port: "5432"
              protocol: TCP

    # Stripe API (external)
    - toFQDNs:
        - matchName: "api.stripe.com"
      toPorts:
        - ports:
            - port: "443"
              protocol: TCP

    # Kafka brokers (publish payment events)
    - fromEndpoints:
        - matchLabels:
            app: kafka
            io.kubernetes.pod.namespace: kafka
      toPorts:
        - ports:
            - port: "9092"
              protocol: TCP

mTLS: Transparent Encryption​

Cilium uses WireGuard (node-to-node) or IPsec to encrypt all traffic between nodes. This provides encryption-in-transit for all east-west traffic without requiring application-level TLS configuration.

Verify encryption is active​

# Confirm WireGuard is enabled on all nodes
cilium status | grep Encryption
# Expected: Encryption: Wireguard [NodeEncryption: Disabled, cilium_wg0 (Pubkey: ...]

# Check encryption between two pods
cilium monitor --type drop --related-to <pod-id>

Per-namespace mTLS policy (SPIFFE-based identity)​

For services requiring cryptographic proof of caller identity at the application layer (e.g. gRPC with cert validation), enable Cilium's SPIFFE/SVID integration:

# k8s/cilium/mtls-payment-namespace.yaml
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: payment-mtls-require
  namespace: payment
spec:
  endpointSelector:
    matchLabels:
      app: payment-service
  ingress:
    - fromEndpoints:
        - matchLabels:
            app: order-service
      authentication:
        mode: "required"   # requires successful mTLS handshake; drops if peer has no valid SVID

Service Account Binding (Identity Anchor)​

Cilium derives endpoint identity from pod labels, including io.kubernetes.pod.namespace and app. Ensure each service uses a dedicated Kubernetes Service Account — this prevents identity spoofing if label selectors are accidentally broadened.

# k8s/production/order-service/serviceaccount.yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: order-service
  namespace: production
  annotations:
    iam.gke.io/gcp-service-account: "order-service@my-gcp-project.iam.gserviceaccount.com"
---
# k8s/payment/payment-service/serviceaccount.yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: payment-service
  namespace: payment
  annotations:
    iam.gke.io/gcp-service-account: "payment-service@my-gcp-project.iam.gserviceaccount.com"

Deployment: bind ServiceAccount​

# k8s/production/order-service/deployment.yaml (relevant section)
spec:
  template:
    spec:
      serviceAccountName: order-service   # anchors Cilium identity
      automountServiceAccountToken: false  # no K8s API token unless needed

Hubble: Observability & Policy Verification​

Hubble gives real-time visibility into which flows are allowed vs. dropped, and which policies are matching.

Watch payment service traffic live​

# Install Hubble CLI
cilium hubble port-forward &

# Watch all flows to payment service
hubble observe --namespace payment --follow

# Watch dropped flows only (policy violations)
hubble observe --namespace payment --verdict DROPPED --follow

# Export to JSON for SIEM ingestion
hubble observe --namespace payment --verdict DROPPED -o json | \
  gcloud logging write cilium-policy-drops - --payload-type=json

Hubble metrics (Prometheus)​

# helm values — expose Hubble flow metrics to Prometheus
hubble:
  metrics:
    enabled:
      - dns
      - drop              # policy drop rate per source/destination
      - tcp
      - flow
      - port-distribution
      - httpV2:labelsContext=source_namespace,source_workload,destination_namespace,destination_workload

Alert on policy drops:

# alerting/cilium-policy-drop-alert.yaml (Prometheus AlertManager)
groups:
  - name: cilium-security
    rules:
      - alert: PaymentServiceUnauthorizedAccess
        expr: |
          sum(rate(hubble_drop_total{destination_namespace="payment",reason="POLICY_DENIED"}[5m])) > 0
        for: 1m
        labels:
          severity: critical
          team: security
        annotations:
          summary: "Unauthorized access attempt to payment service"
          description: "{{ $value }} drops/s to payment namespace. Possible lateral movement attempt."

NestJS: Caller Identity Validation (Defence-in-Depth)​

Even with Cilium enforcing network identity, add application-level validation as a second layer. Cilium injects a request header (X-Forwarded-Client-Cert) you can verify in the service:

// src/payment/guards/service-identity.guard.ts
import { CanActivate, ExecutionContext, Injectable, ForbiddenException } from '@nestjs/common';

const ALLOWED_SERVICE_PRINCIPALS = new Set([
  'spiffe://cluster.local/ns/production/sa/order-service',
  'spiffe://cluster.local/ns/production/sa/cart-service',
  'spiffe://cluster.local/ns/ingress/sa/traefik',
]);

@Injectable()
export class ServiceIdentityGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();

    // Cilium/Envoy injects SPIFFE URI of the calling service
    const clientCert = request.headers['x-forwarded-client-cert'] as string;
    if (!clientCert) {
      throw new ForbiddenException('Missing service identity header');
    }

    // Extract URI field: By=...,URI=spiffe://cluster.local/ns/.../sa/...
    const uriMatch = clientCert.match(/URI=([^,;]+)/);
    const callerIdentity = uriMatch?.[1];

    if (!callerIdentity || !ALLOWED_SERVICE_PRINCIPALS.has(callerIdentity)) {
      throw new ForbiddenException(`Service identity not allowed: ${callerIdentity}`);
    }

    return true;
  }
}
// src/payment/payment.controller.ts
import { ServiceIdentityGuard } from './guards/service-identity.guard';

@Controller('payments')
@UseGuards(ServiceIdentityGuard)   // applied to all payment routes
export class PaymentController {
  @Post('charge')
  async charge(@Body() dto: ChargeDto) { /* ... */ }

  @Post('refund')
  async refund(@Body() dto: RefundDto) { /* ... */ }
}

CI/CD: Policy Validation​

Prevent policies from being merged that would open access to the payment service:

# .github/workflows/policy-check.yml
name: Cilium Policy Check
on: [pull_request]

jobs:
  policy-lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install cilium CLI
        run: |
          curl -L --remote-name-all https://github.com/cilium/cilium-cli/releases/latest/download/cilium-linux-amd64.tar.gz
          tar xzvf cilium-linux-amd64.tar.gz -C /usr/local/bin

      - name: Validate CiliumNetworkPolicy YAML
        run: |
          find k8s/ -name 'cilium-*.yaml' -exec \
            kubectl --dry-run=client apply -f {} \;

      - name: OPA: reject policies allowing wildcard access to payment
        run: |
          conftest test k8s/payment/ --policy policies/cilium-payment-no-wildcard.rego

OPA: reject wildcard ingress to payment​

# policies/cilium-payment-no-wildcard.rego
package cilium.payment

deny[msg] {
  input.metadata.namespace == "payment"
  input.kind == "CiliumNetworkPolicy"
  rule := input.spec.ingress[_]
  rule.fromEndpoints[_] == {}   # empty selector = matches all pods
  msg := "CiliumNetworkPolicy in 'payment' namespace must not use empty fromEndpoints (wildcard)"
}

Failure Modes​

FailureDetectionMitigation
Cilium agent crashes on a nodePod CrashLoopBackOff; Datadog alert on cilium_agent_up == 0Node-level DaemonSet auto-restarts; fallback to iptables mode briefly; Hubble drops alert triggers paging
Policy misconfiguration blocks legitimate caller403 / connection refused in Order Service; Hubble DROPPED flowRoll back CiliumNetworkPolicy via GitOps (kubectl apply of previous version); Hubble pinpoints the blocked flow identity
WireGuard key rotation failureEncrypted flows drop; encrypted traffic metric drops to zeroCilium auto-rotates WireGuard keys; if persistent, drain and recycle affected node
New service added without policyAll traffic blocked by default-denyExpected behaviour — developer adds explicit allow CiliumNetworkPolicy in the same PR as the new service
L7 parser overhead under flash salep99 latency increase of ~1–2 ms per hopDisable L7 rules under sustained load; L3/L4 rules have no measurable overhead

Non-Functional Requirements​

NFRTarget
Policy enforcement latency<1 ms per hop (eBPF bypass — no iptables chain traversal)
Encryption overhead<2% CPU per node (WireGuard AES-NI hardware offload)
Policy propagation<5 s from kubectl apply to enforcement on all nodes
AvailabilityDaemonSet; node drain required for update; zero downtime rolling update
Observability100% flow visibility via Hubble (sampled at 10% in prod; 100% for payment namespace)
AuditPolicy drop events exported to Cloud Logging + BigQuery
