A10:2025 - Mishandling of Exceptional Conditions - Real Scenarios

Overview​

Mishandling of Exceptional Conditions is a NEW category in OWASP Top 10 2025. This category contains 24 CWEs focusing on improper error handling, logical errors, failing open, and other related scenarios stemming from abnormal conditions that systems may encounter.

Key Concept: Systems should "fail securely" - defaulting to a secure state (deny access) when errors occur, rather than "failing open" which grants access or exposes information.

Key Concepts​

  • Failing Open vs Failing Closed: Defaulting to insecure vs secure state on errors
  • Information Disclosure: Error messages exposing sensitive details
  • Unhandled Exceptions: Crashes and service disruptions
  • Race Conditions: Timing-based security vulnerabilities
  • Null/Undefined Handling: Improper handling leading to bypasses
  • Logic Errors: Flawed conditional logic in security checks

Vulnerable Scenario 1: Failing Open (Access Control)​

Vulnerable Code (NestJS)​

// auth.guard.ts - VULNERABLE
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';

@Injectable()
export class AdminGuard implements CanActivate {
  constructor(private aclService: AclService) {}

  // ❌ VULNERABLE: Fails open on error
  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();
    const user = request.user;

    try {
      // Check if user has admin role
      const hasAdminRole = await this.aclService.checkAdminRole(user.id);
      return hasAdminRole;
    } catch (error) {
      // ❌ CRITICAL: Returns true on error!
      // If ACL service is down or throws error, grants access
      console.error('Error checking admin role:', error);
      return true; // ❌ Fails open - DANGEROUS!
    }
  }
}
// payment.service.ts - VULNERABLE
@Injectable()
export class PaymentService {
  // ❌ VULNERABLE: Fails open on verification error
  async processPayment(orderId: string, amount: number): Promise<boolean> {
    try {
      // Check if payment amount matches order
      const order = await this.ordersService.findOne(orderId);

      if (order.total !== amount) {
        return false;
      }

      // Process payment
      const result = await this.paymentGateway.charge(amount);
      return result.success;
    } catch (error) {
      // ❌ Returns true on ANY error (including verification errors)!
      console.error('Payment processing error:', error);
      return true; // ❌ Fails open - payment "succeeds" on error!
    }
  }
}

Attack Example​

# Attack 1: Crash the ACL service to gain admin access
# Attacker sends malformed requests to overload ACL service
for i in {1..10000}; do
  curl -X POST https://api.example.com/admin/users &
done

# ❌ ACL service crashes or becomes unresponsive
# ❌ All subsequent requests get admin access (fail open)!

# Attack 2: Trigger payment exception
curl -X POST https://api.example.com/payments \
  -d '{
    "orderId": "null",
    "amount": -1
  }'

# ❌ Causes exception in payment verification
# ❌ Returns true, payment "succeeds" without actually charging!

Secure Solution​

// auth.guard.ts - SECURE
import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';
import { Logger } from '@nestjs/common';

@Injectable()
export class AdminGuard implements CanActivate {
  private readonly logger = new Logger(AdminGuard.name);

  constructor(private aclService: AclService) {}

  // ✅ SECURE: Fails closed on error
  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();
    const user = request.user;

    if (!user) {
      // ✅ Explicit deny
      throw new UnauthorizedException('User not authenticated');
    }

    try {
      // Check if user has admin role
      const hasAdminRole = await this.aclService.checkAdminRole(user.id);

      if (!hasAdminRole) {
        this.logger.warn(`Access denied for user ${user.id} - not admin`);
      }

      return hasAdminRole;
    } catch (error) {
      // ✅ SECURE: Fails closed - deny access on error
      this.logger.error(`ACL check failed for user ${user.id}:`, error);

      // ✅ Alert security team about ACL service issues
      await this.alertService.sendSecurityAlert({
        type: 'ACL_SERVICE_ERROR',
        userId: user.id,
        error: error.message,
      });

      // ✅ Deny access - fail securely
      throw new UnauthorizedException('Unable to verify permissions');
    }
  }
}
// payment.service.ts - SECURE
@Injectable()
export class PaymentService {
  private readonly logger = new Logger(PaymentService.name);

  // ✅ SECURE: Fails closed with explicit error handling
  async processPayment(orderId: string, amount: number): Promise<PaymentResult> {
    // ✅ Input validation first
    if (!orderId || amount <= 0) {
      throw new BadRequestException('Invalid payment parameters');
    }

    try {
      // ✅ Verify order exists and amount matches
      const order = await this.ordersService.findOne(orderId);

      if (!order) {
        throw new NotFoundException('Order not found');
      }

      if (order.total !== amount) {
        this.logger.warn(`Payment amount mismatch for order ${orderId}`);
        throw new BadRequestException('Payment amount does not match order');
      }

      // ✅ Process payment with explicit error handling
      const result = await this.paymentGateway.charge(amount);

      return {
        success: result.success,
        transactionId: result.transactionId,
      };
    } catch (error) {
      // ✅ Log error securely (no sensitive data)
      this.logger.error(`Payment failed for order ${orderId}:`, {
        error: error.message,
        code: error.code,
      });

      // ✅ Return failure - fail securely
      return {
        success: false,
        error: 'Payment processing failed',
      };
    }
  }
}

Vulnerable Scenario 2: Information Disclosure in Error Messages​

Vulnerable Code (NestJS)​

// users.controller.ts - VULNERABLE
@Controller('users')
export class UsersController {
  constructor(private usersService: UsersService) {}

  // ❌ VULNERABLE: Exposes internal error details
  @Get(':id')
  async getUser(@Param('id') id: string) {
    try {
      const user = await this.usersService.findOne(id);
      return user;
    } catch (error) {
      // ❌ Exposes full error details including stack trace
      return {
        error: error.message,
        stack: error.stack,
        query: error.query, // ❌ May expose SQL queries!
      };
    }
  }

  // ❌ VULNERABLE: Different errors reveal system state
  @Post('login')
  async login(@Body() dto: LoginDto) {
    try {
      const user = await this.usersService.findByEmail(dto.email);

      if (!user) {
        // ❌ Reveals that email doesn't exist (user enumeration)
        throw new UnauthorizedException('Email not found');
      }

      const valid = await bcrypt.compare(dto.password, user.password);

      if (!valid) {
        // ❌ Reveals that email exists but password is wrong
        throw new UnauthorizedException('Invalid password');
      }

      return { token: this.generateToken(user) };
    } catch (error) {
      // ❌ Propagates detailed database errors
      if (error.code === 'ECONNREFUSED') {
        throw new Error('Database connection failed on port 5432');
      }
      throw error;
    }
  }
}

Attack Example​

# Attack 1: User enumeration through error messages
curl -X POST https://api.example.com/users/login \
  -d '{"email":"admin@example.com","password":"wrong"}'

# ❌ Response: "Invalid password"
# Attacker learns: email exists!

curl -X POST https://api.example.com/users/login \
  -d '{"email":"notfound@example.com","password":"wrong"}'

# ❌ Response: "Email not found"
# Attacker learns: email doesn't exist

# Attack 2: Information gathering from stack traces
curl https://api.example.com/users/'; DROP TABLE users; --'

# ❌ Response includes:
{
  "error": "Syntax error in SQL query",
  "stack": "Error: Syntax error\n    at Database.query (/app/node_modules/pg/lib/client.js:123)\n...",
  "query": "SELECT * FROM users WHERE id = ''; DROP TABLE users; --'"
}

# ❌ Attacker learns:
# - Using PostgreSQL
# - SQL query structure
# - File paths and directory structure
# - Node.js and package versions

Secure Solution​

// users.controller.ts - SECURE
import { Controller, Get, Post, Body, Param, HttpException, HttpStatus } from '@nestjs/common';
import { Logger } from '@nestjs/common';

@Controller('users')
export class UsersController {
  private readonly logger = new Logger(UsersController.name);

  constructor(private usersService: UsersService) {}

  // ✅ SECURE: Generic error messages for users
  @Get(':id')
  async getUser(@Param('id') id: string) {
    try {
      const user = await this.usersService.findOne(id);

      if (!user) {
        // ✅ Generic message
        throw new HttpException('User not found', HttpStatus.NOT_FOUND);
      }

      return user;
    } catch (error) {
      // ✅ Log detailed error securely (server-side only)
      this.logger.error(`Error fetching user ${id}:`, {
        error: error.message,
        stack: error.stack,
        userId: id,
      });

      // ✅ Return generic message to client
      if (error instanceof HttpException) {
        throw error;
      }

      throw new HttpException('An error occurred while fetching user', HttpStatus.INTERNAL_SERVER_ERROR);
    }
  }

  // ✅ SECURE: Consistent error messages prevent user enumeration
  @Post('login')
  async login(@Body() dto: LoginDto) {
    try {
      // ✅ Rate limiting should be applied (not shown here)

      const user = await this.usersService.findByEmail(dto.email);

      // ✅ Always check password even if user not found (timing attack prevention)
      const validPassword = user
        ? await bcrypt.compare(dto.password, user.password)
        : await bcrypt.compare(dto.password, '$2b$10$fake.hash.to.prevent.timing');

      if (!user || !validPassword) {
        // ✅ Generic message - same for both cases
        this.logger.warn(`Failed login attempt for ${dto.email}`);
        throw new UnauthorizedException('Invalid email or password');
      }

      // ✅ Log successful login
      this.logger.log(`Successful login for user ${user.id}`);

      return { token: this.generateToken(user) };
    } catch (error) {
      // ✅ Log detailed error server-side
      this.logger.error('Login error:', {
        email: dto.email,
        error: error.message,
      });

      // ✅ Generic message to client
      if (error instanceof UnauthorizedException) {
        throw error;
      }

      throw new UnauthorizedException('Login failed');
    }
  }
}

Global Exception Filter:

// http-exception.filter.ts - SECURE
import { ExceptionFilter, Catch, ArgumentsHost, HttpException, HttpStatus, Logger } from '@nestjs/common';

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name);

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse();
    const request = ctx.getRequest();

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let message = 'Internal server error';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      message = exception.message;
    }

    // ✅ Log full error details server-side
    this.logger.error('Exception occurred:', {
      url: request.url,
      method: request.method,
      status,
      error: exception instanceof Error ? exception.message : 'Unknown error',
      stack: exception instanceof Error ? exception.stack : undefined,
      user: request.user?.id,
    });

    // ✅ Send only safe information to client
    response.status(status).json({
      statusCode: status,
      timestamp: new Date().toISOString(),
      path: request.url,
      // ✅ Generic message only (no stack traces, internals, etc.)
      message:
        process.env.NODE_ENV === 'production' ? message : exception instanceof Error ? exception.message : message,
    });
  }
}

Vulnerable Scenario 3: Race Conditions​

Vulnerable Code (NestJS)​

// wallet.service.ts - VULNERABLE
@Injectable()
export class WalletService {
  constructor(
    @InjectRepository(Wallet)
    private walletRepo: Repository<Wallet>,
  ) {}

  // ❌ VULNERABLE: Race condition in balance check
  async withdraw(userId: string, amount: number): Promise<boolean> {
    // ❌ Step 1: Read balance
    const wallet = await this.walletRepo.findOne({ where: { userId } });

    // ❌ Step 2: Check balance (but another request might be processing!)
    if (wallet.balance < amount) {
      throw new BadRequestException('Insufficient funds');
    }

    // ❌ RACE CONDITION: Another withdraw could happen here!
    // ❌ Both requests see sufficient balance and both succeed!

    // ❌ Step 3: Deduct amount
    wallet.balance -= amount;
    await this.walletRepo.save(wallet);

    return true;
  }
}

Attack Example​

# User has $100 in wallet
# Attacker sends two simultaneous $100 withdrawal requests

# Request 1:
curl -X POST https://api.example.com/wallet/withdraw \
  -d '{"amount": 100}' &

# Request 2 (simultaneously):
curl -X POST https://api.example.com/wallet/withdraw \
  -d '{"amount": 100}' &

# ❌ Timeline:
# T1: Request 1 reads balance: $100 ✓
# T2: Request 2 reads balance: $100 ✓  (race condition!)
# T3: Request 1 checks: 100 >= 100 ✓
# T4: Request 2 checks: 100 >= 100 ✓  (still sees $100!)
# T5: Request 1 deducts: balance = $0
# T6: Request 2 deducts: balance = -$100 ❌
# Result: User withdrew $200 with only $100 in account!

Secure Solution​

// wallet.service.ts - SECURE
@Injectable()
export class WalletService {
  constructor(
    @InjectRepository(Wallet)
    private walletRepo: Repository<Wallet>,
    private dataSource: DataSource,
  ) {}

  // ✅ SECURE: Uses database transaction with locking
  async withdraw(userId: string, amount: number): Promise<boolean> {
    return await this.dataSource.transaction(async (entityManager) => {
      // ✅ Use pessimistic locking (FOR UPDATE)
      const wallet = await entityManager
        .createQueryBuilder(Wallet, 'wallet')
        .where('wallet.userId = :userId', { userId })
        .setLock('pessimistic_write') // ✅ Locks the row!
        .getOne();

      if (!wallet) {
        throw new NotFoundException('Wallet not found');
      }

      // ✅ Check balance while holding lock
      if (wallet.balance < amount) {
        throw new BadRequestException('Insufficient funds');
      }

      // ✅ Deduct amount atomically
      wallet.balance -= amount;
      await entityManager.save(wallet);

      return true;
    });
  }

  // ✅ Alternative: Using optimistic locking with version column
  async withdrawOptimistic(userId: string, amount: number): Promise<boolean> {
    const maxRetries = 3;
    let retries = 0;

    while (retries < maxRetries) {
      try {
        const wallet = await this.walletRepo.findOne({ where: { userId } });

        if (!wallet) {
          throw new NotFoundException('Wallet not found');
        }

        if (wallet.balance < amount) {
          throw new BadRequestException('Insufficient funds');
        }

        wallet.balance -= amount;

        // ✅ TypeORM will check version hasn't changed
        // If version changed, throws OptimisticLockVersionMismatchError
        await this.walletRepo.save(wallet);

        return true;
      } catch (error) {
        if (error.name === 'OptimisticLockVersionMismatchError') {
          // ✅ Retry on version conflict
          retries++;
          if (retries >= maxRetries) {
            throw new ConflictException('Transaction conflict - please retry');
          }
          // Wait briefly before retry
          await new Promise((resolve) => setTimeout(resolve, 100 * retries));
        } else {
          throw error;
        }
      }
    }
  }
}

Entity with Version Column:

// wallet.entity.ts
import { Entity, Column, PrimaryGeneratedColumn, VersionColumn } from 'typeorm';

@Entity()
export class Wallet {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column()
  userId: string;

  @Column('decimal', { precision: 10, scale: 2 })
  balance: number;

  // ✅ Version column for optimistic locking
  @VersionColumn()
  version: number;
}

Prevention Checklist​

  • Fail securely: Default to deny on errors (fail closed, not open)
  • Generic error messages: Never expose internals to users
  • Log detailed errors: Capture full details server-side for debugging
  • Handle all exceptions: Use try-catch and global exception filters
  • TypeScript strict mode: Enable strict null checks
  • Validate inputs: Check for null/undefined before processing
  • Use transactions: Prevent race conditions with database locks
  • Rate limiting: Prevent timing attacks and enumeration
  • Consistent timing: Same response time regardless of error path
  • Circuit breakers: Handle external service failures gracefully
  • Graceful degradation: System remains secure when components fail
  • Security monitoring: Alert on repeated error patterns

Testing Methods​

// error-handling.spec.ts
describe('Error Handling Security', () => {
  it('should fail closed on ACL service error', async () => {
    // Mock ACL service to throw error
    jest.spyOn(aclService, 'checkAdminRole').mockRejectedValue(new Error('Service down'));

    // Should deny access
    await expect(guard.canActivate(context)).rejects.toThrow(UnauthorizedException);
  });

  it('should not expose stack traces in production', async () => {
    process.env.NODE_ENV = 'production';

    const response = await request(app.getHttpServer()).get('/users/invalid-id').expect(500);

    // Should not contain stack trace
    expect(response.body.stack).toBeUndefined();
    expect(response.body.error).toBeUndefined();
    expect(response.body.message).toBe('Internal server error');
  });

  it('should prevent user enumeration via error messages', async () => {
    // Login with non-existent user
    const response1 = await request(app.getHttpServer())
      .post('/auth/login')
      .send({ email: 'notfound@example.com', password: 'wrong' });

    // Login with existing user but wrong password
    const response2 = await request(app.getHttpServer())
      .post('/auth/login')
      .send({ email: 'existing@example.com', password: 'wrong' });

    // Messages should be identical
    expect(response1.body.message).toBe(response2.body.message);
  });

  it('should handle race conditions in withdrawals', async () => {
    const userId = 'test-user';
    const initialBalance = 100;

    // Create wallet
    await walletService.create(userId, initialBalance);

    // Attempt two simultaneous withdrawals
    const results = await Promise.allSettled([
      walletService.withdraw(userId, 100),
      walletService.withdraw(userId, 100),
    ]);

    // One should succeed, one should fail
    const succeeded = results.filter((r) => r.status === 'fulfilled').length;
    const failed = results.filter((r) => r.status === 'rejected').length;

    expect(succeeded).toBe(1);
    expect(failed).toBe(1);

    // Final balance should be 0 (not negative!)
    const wallet = await walletService.findOne(userId);
    expect(wallet.balance).toBe(0);
  });
});

Real-World Impact Examples​

  1. Yahoo (2016): Error handling exposed whether email existed during password reset, enabling user enumeration
  2. Uber (2014): Race condition in promo code system allowed unlimited free rides
  3. Coinbase (2021): Race condition allowed users to withdraw more than their balance
  4. Various Cloud Providers: SSRF vulnerabilities often stem from poor error handling in URL validators
  5. GitHub (2016): Race condition in OAuth implementation allowed account takeover

Configuration for Secure Error Handling​

// main.ts - Application bootstrap
import { NestFactory } from '@nestjs/core';
import { Logger, ValidationPipe } from '@nestjs/common';
import { AllExceptionsFilter } from './filters/all-exceptions.filter';

async function bootstrap() {
  const app = await NestFactory.create(AppModule, {
    logger: ['error', 'warn', 'log'], // ✅ Don't log debug in production
  });

  // ✅ Global exception filter
  app.useGlobalFilters(new AllExceptionsFilter());

  // ✅ Global validation with transform
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
      // ✅ Handle validation errors consistently
      exceptionFactory: (errors) => {
        return new BadRequestException('Validation failed');
      },
    }),
  );

  await app.listen(3000);
}
bootstrap();
