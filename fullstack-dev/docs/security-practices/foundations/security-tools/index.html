Trivy​

Trivy is a comprehensive and versatile security scanner developed by Aqua Security. It's designed to find security issues in multiple targets with a single tool.

What It Scans​

Targets:

  • Container Images
  • Filesystems
  • Git Repositories (remote)
  • Virtual Machine Images
  • Kubernetes clusters

What It Finds:

  • OS packages and software dependencies (SBOM)
  • Known vulnerabilities (CVEs)
  • IaC misconfigurations
  • Sensitive information and secrets
  • Software licenses

Key Features​

  • Multi-Target Scanning
  • Output Formats
  • Advanced Features
# Scan a container image
trivy image python:3.4-alpine

# Scan a container image from tar archive
trivy image --input ruby-3.1.tar

# Scan local filesystem
trivy fs .

# Scan Kubernetes cluster
trivy k8s --report summary cluster

# Scan IaC files
trivy config .
  • Table (default) - Human-readable console output
  • JSON - Machine-readable structured data
  • SARIF - Static Analysis Results Interchange Format
  • Template - Custom Go templates
  • SBOM - CycloneDX and SPDX formats
  • GitHub - GitHub dependency snapshot
# Output to JSON
trivy image -f json -o results.json alpine:latest

# Generate SARIF for GitHub Code Scanning
trivy image --format sarif -o report.sarif golang:1.12-alpine

# Generate SBOM
trivy image --format cyclonedx --output sbom.json alpine:3.15

Dependency Graph: Shows the origin of vulnerable dependencies for better understanding of security issues.

Archive Scanning: Scan nested archives (zip, tar, etc.) with --max-archive-depth flag.

Secret Detection: Find hardcoded credentials, API keys, and tokens in images and filesystems.

License Scanning: Identify software licenses to ensure compliance.

# Enable dependency tree
trivy image --dependency-tree alpine:3.15

# Scan with license detection
trivy image --scanners license --severity UNKNOWN,HIGH,CRITICAL alpine:3.15

# Ignore unfixed vulnerabilities
trivy image --ignore-unfixed alpine:3.15

Installation​

  • Homebrew
  • Docker
  • Binary Download
  • Debian/Ubuntu
brew install trivy
docker pull aquasec/trivy:latest

# Scan using Docker
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  aquasec/trivy image nginx:latest

Download from GitHub Releases

# Install script
curl -sfL https://raw.githubusercontent.com/aquasecurity/trivy/main/contrib/install.sh | sh -s -- -b /usr/local/bin
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | sudo apt-key add -
echo "deb https://aquasecurity.github.io/trivy-repo/deb $(lsb_release -sc) main" | sudo tee -a /etc/apt/sources.list.d/trivy.list
sudo apt-get update
sudo apt-get install trivy

Common Use Cases​

CI/CD Integration

Integrate Trivy into your CI/CD pipeline to scan images before deployment:

# GitHub Actions
- name: Run Trivy vulnerability scanner
  uses: aquasecurity/trivy-action@master
  with:
    image-ref: 'myimage:tag'
    format: 'sarif'
    output: 'trivy-results.sarif'
Kubernetes Security

Deploy Trivy Operator to continuously scan your Kubernetes workloads:

helm repo add aquasecurity https://aquasecurity.github.io/helm-charts/
helm install trivy-operator aquasecurity/trivy-operator -n trivy-system --create-namespace

Web-Check​

Web-Check is an all-in-one OSINT tool for quickly checking a website's data and security posture. It provides comprehensive information about domains, SSL certificates, DNS records, and much more.

What It Analyzes​

30+ Supported Checks:

  • SSL/TLS Certificates
  • DNS Records (A, MX, TXT, etc.)
  • Security Headers
  • Server Location & Hosting
  • Open Ports
  • Technology Stack
  • Domain Registration (WHOIS)
  • Archive History (Wayback Machine)
  • Sitemap & Robots.txt
  • Carbon Footprint
  • Performance Metrics (Lighthouse)

Key Features​

  • Security Analysis
  • Infrastructure
  • OSINT & Analysis

SSL/TLS Analysis:

  • Certificate details and validity
  • Issuing authority information
  • Cipher suites and protocols
  • Certificate chain verification

Security Headers:

  • Content Security Policy (CSP)
  • X-Content-Type-Options
  • X-Frame-Options
  • Strict-Transport-Security (HSTS)

Firewall Detection: Identifies Web Application Firewalls (WAF) protecting the site.

DNS Information:

  • Complete DNS record enumeration
  • DNSSEC validation
  • DNS server identification
  • Associated hostnames

Server Details:

  • Geographic location
  • Hosting provider
  • Server software and version
  • Traceroute information

Open Ports: Scans for publicly accessible services and potential vulnerabilities.

Domain Intelligence:

  • WHOIS registration data
  • Historical ownership
  • Domain age
  • Registrar information

Technology Detection:

  • Content Management Systems
  • JavaScript frameworks
  • Analytics platforms
  • CDN providers

Archive History: View historical snapshots via Wayback Machine integration.

Installation & Deployment​

  • Hosted Version
  • Docker
  • Deploy to Vercel
  • From Source

Use the free hosted version at web-check.xyz

# Quick start with Docker
docker run -p 3000:3000 lissy93/web-check

# Access at http://localhost:3000

One-click deployment to your own Vercel instance.

git clone https://github.com/Lissy93/web-check.git
cd web-check
yarn install
yarn build
yarn serve

Use Cases​

Security Auditing

Use Web-Check to perform initial reconnaissance before security assessments:

  • Identify exposed services and open ports
  • Analyze security header configurations
  • Check SSL/TLS implementation
  • Review DNS configuration
Competitive Analysis

Understand competitor technology stacks and infrastructure:

  • Identify hosting providers and CDNs
  • Discover technologies and frameworks
  • Analyze performance metrics
  • Review SEO implementation

Gitleaks​

Gitleaks is a fast, lightweight secrets scanner for git repositories, files, and directories. It helps prevent credential leaks by detecting over 140 different types of secrets.

What It Detects​

140+ Secret Types:

  • API Keys (AWS, Azure, GCP, etc.)
  • Database Credentials
  • Authentication Tokens
  • Private Keys (SSH, SSL/TLS)
  • OAuth Tokens
  • Webhook URLs
  • Service Account Credentials

Key Features​

  • Scanning Modes
  • Configuration
  • CI/CD Integration

Git Repository Scanning:

# Scan entire git history
gitleaks detect --source=/path/to/repo --verbose

# Scan specific commits
gitleaks detect --log-opts="--all commitA..commitB"

# Scan for verified secrets only
gitleaks detect --source=. --results=verified

File & Directory Scanning:

# Scan current directory
gitleaks detect --no-git

# Scan specific files
gitleaks detect --no-git --source=config.json

Pre-Commit Hook:

# Scan staged changes before commit
gitleaks protect --staged

# Install pre-commit hook
gitleaks protect --staged --source=. --verbose

Create a .gitleaks.toml configuration file:

title = "Custom Gitleaks Config"

[[rules]]
id = "custom-api-key"
description = "Custom API Key Pattern"
regex = '''api[_-]?key[_-]?=[\s]*['\"]?[a-zA-Z0-9]{32,45}['\"]?'''
keywords = ["api", "key"]

[[rules.allowlist]]
description = "Ignore test files"
paths = [
  '''.*_test\.go''',
  '''tests/.*'''
]

Key Configuration Options:

  • Custom regex patterns
  • Allowlist/ignore rules
  • Entropy thresholds
  • Path exclusions

GitHub Actions:

name: gitleaks
on: [pull_request, push]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0
      - uses: gitleaks/gitleaks-action@v2
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

GitLab CI:

gitleaks:
  stage: test
  image: zricethezav/gitleaks
  script:
    - gitleaks detect --source . --verbose

Installation​

  • Homebrew
  • Docker
  • Binary
brew install gitleaks
docker pull zricethezav/gitleaks:latest

# Scan current directory
docker run -v ${pwd}:/path zricethezav/gitleaks:latest detect --source="/path" --verbose

Download from GitHub Releases

# Install via script
curl -sSfL https://raw.githubusercontent.com/gitleaks/gitleaks/master/scripts/install.sh | sh -s -- -b /usr/local/bin

Advanced Usage​

Baseline Scanning

Create a baseline to ignore existing secrets:

# Create baseline
gitleaks detect --baseline-path=baseline.json --report-path=baseline.json

# Scan for new secrets only
gitleaks detect --baseline-path=baseline.json --report-path=new-findings.json
.gitleaksignore

Ignore specific findings using fingerprints:

# .gitleaksignore
# Ignore specific secret by fingerprint
cd5226711335c68be1e720b318b7bc3135a30eb2:cmd/generate/config/rules/sidekiq.go:sidekiq-secret:23

Infisical​

Infisical is the open-source secret management platform that developers use to centralize application configuration, secrets, and internal PKI. It helps teams prevent secret leaks and manage secrets across their entire infrastructure.

Core Features​

Secret Management:

  • Centralized secret storage with versioning
  • Environment-based organization (dev, staging, prod)
  • Secret references and templating
  • Point-in-time recovery
  • Secret rotation and dynamic secrets

Access Control:

  • Role-based access control (RBAC)
  • Temporary access grants
  • Access requests and approval workflows
  • Attribute-based access control (ABAC)
  • User groups and permissions

Infrastructure Integration:

  • Native Kubernetes operator
  • Secret syncing to 30+ platforms
  • SDK support (Node, Python, Java, Go, .NET, Ruby)
  • CLI for local development and CI/CD

Key Capabilities​

  • Secret Management
  • Secret Delivery
  • Security Features

Dashboard: Manage secrets across projects and environments through a user-friendly interface.

Secret Versioning: Track every change to secrets with full audit history and rollback capability.

Dynamic Secrets: Generate short-lived credentials on-demand for databases and cloud services:

  • PostgreSQL
  • MySQL
  • AWS IAM
  • GCP Service Accounts
# CLI: Fetch secrets
infisical secrets

# Inject secrets into application
infisical run -- npm start

Kubernetes Operator:

apiVersion: secrets.infisical.com/v1alpha1
kind: InfisicalSecret
metadata:
  name: app-secrets
spec:
  hostAPI: https://app.infisical.com/api
  authentication:
    universalAuth:
      secretsScope:
        projectSlug: my-project
        envSlug: prod

Secret Syncs: Automatically sync secrets to external platforms:

  • GitHub Actions
  • Vercel
  • AWS Secrets Manager
  • Azure Key Vault
  • HashiCorp Vault
  • And 25+ more

SDKs:

// Node.js SDK
const { InfisicalClient } = require('@infisical/sdk');

const client = new InfisicalClient({
  siteUrl: 'https://app.infisical.com',
});

await client.auth().universalAuth.login({
  clientId: 'CLIENT_ID',
  clientSecret: 'CLIENT_SECRET',
});

const secrets = await client.secrets().listSecrets({
  projectId: 'PROJECT_ID',
  environment: 'dev',
});

Secret Scanning: Detect exposed secrets in:

  • Git repositories (GitHub, GitLab, Bitbucket)
  • Local development environments
  • CI/CD pipelines
# Scan local files
infisical scan

# Scan Git history
infisical scan git-changes

PKI Management:

  • Issue X.509 certificates
  • Manage certificate authorities
  • EST protocol support
  • Automated certificate renewal

SSH Certificate Authority:

  • Issue ephemeral SSH credentials
  • Policy-driven access control
  • Certificate-based authentication

TruffleHog​

TruffleHog is the most powerful secrets discovery, classification, validation, and analysis tool. It supports scanning Git repositories, filesystems, S3 buckets, Docker images, and more with over 700 verified credential detectors.

What Makes TruffleHog Unique​

Discovery 🔍

  • Scan Git, filesystems, cloud storage, container images
  • Support for GitHub, GitLab, Docker, S3, GCS
  • Historical commit analysis
  • Binary and document scanning

Classification 📁

  • 700+ secret type detectors
  • Maps secrets to specific identities
  • Distinguishes between different credential types

Validation ✅

  • Active verification against APIs
  • Confirms if credentials are live
  • Reduces false positives significantly

Analysis 🔬

  • Permission enumeration
  • Resource access mapping
  • Credential impact assessment

Key Features​

  • Scanning Capabilities
  • Credential Verification
  • CI/CD Integration
  • Advanced Features

Git Repository Scanning:

# Scan a GitHub organization
trufflehog github --org=trufflesecurity --results=verified

# Scan entire git history
trufflehog git https://github.com/user/repo --results=verified,unknown

# Scan since specific commit
trufflehog git file://. --since-commit main --branch feature-1 --fail

Filesystem Scanning:

# Scan directories
trufflehog filesystem /path/to/scan --results=verified

# Scan specific files
trufflehog filesystem file1.txt file2.txt --json

Docker Image Scanning:

# Scan from remote registry
trufflehog docker --image trufflesecurity/secrets --results=verified

# Scan from local daemon
trufflehog docker --image docker://image:tag

# Scan from tarball
trufflehog docker --image file://path_to_image.tar

Cloud Storage:

# Scan S3 bucket
trufflehog s3 --bucket=my-bucket --results=verified,unknown

# Scan GCS bucket
trufflehog gcs --project-id=PROJECT_ID --results=verified

700+ Verified Detectors:

  • AWS Keys
  • GitHub Tokens
  • Stripe API Keys
  • Slack Tokens
  • Database Credentials
  • And 695+ more...

Private Key Verification: TruffleHog can verify private keys against:

  • Millions of GitHub users
  • Billions of TLS certificates
  • SSH hosts
# Scan and verify secrets
trufflehog git https://github.com/user/repo --results=verified

Custom Detectors: Create custom regex-based detectors for proprietary secrets:

# custom-detector.yaml
detectors:
  - name: MyCustomToken
    keywords:
      - 'myapp'
    regex:
      token: 'myapp_[a-zA-Z0-9]{32}'
    verify:
      - endpoint: https://api.myapp.com/verify
        headers:
          - 'Authorization: Bearer {token}'

GitHub Object Discovery:

# Find deleted commits and hidden objects
trufflehog github-experimental --repo https://github.com/user/repo --object-discovery

Best Practices​

Preventing Credential Leaks

Pre-commit Protection:

# Install pre-commit hook
trufflehog git file://. --since-commit HEAD --results=verified,unknown --fail

# Configure in .git/hooks/pre-commit
#!/bin/bash
trufflehog git file://. --since-commit HEAD --results=verified,unknown --fail
if [ $? -ne 0 ]; then
    echo "⚠️  TruffleHog detected secrets. Commit blocked."
    exit 1
fi
CI/CD Scanning

Always scan:

  • Pull requests before merge
  • New commits to main branch
  • Container images before deployment
  • Infrastructure as Code templates
False Positive Management

Use inline comments to suppress false positives:

# trufflehog:ignore - This is a test key
api_key = "not-a-real-key-just-example"

Tool Comparison​

When to Use Each Tool​

Use CaseRecommended ToolWhy
Container vulnerability scanningTrivyComprehensive CVE database, SBOM generation
Website security auditWeb-CheckAll-in-one OSINT and security analysis
Git history secret scanningGitleaks or TruffleHogBoth excellent; Gitleaks lighter, TruffleHog more detectors
Secret management platformInfisicalComplete lifecycle management, integrations
Pre-commit secret preventionGitleaksFast, focused on git workflows
Active secret verificationTruffleHog700+ verified detectors, analysis features
IaC security scanningTrivyNative support for Terraform, K8s, Docker
Secret rotation automationInfisicalBuilt-in dynamic secrets, rotation policies

Integration Strategy​

Development Phase:

  1. Gitleaks pre-commit hooks prevent secrets from entering git
  2. Infisical CLI for local secret management
  3. Web-Check for external dependency analysis

CI/CD Pipeline:

  1. TruffleHog scans code and git history
  2. Trivy scans container images and IaC
  3. Infisical injects secrets at runtime

Production:

  1. Infisical manages all application secrets
  2. Trivy continuous container scanning
  3. Web-Check periodic security audits
