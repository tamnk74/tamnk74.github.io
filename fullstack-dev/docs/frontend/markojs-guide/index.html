MarkoJS Guide

Overview​

MarkoJS is a powerful, high-performance user interface library developed by eBay. It is designed to be HTML-first, meaning it extends HTML with dynamic tags and logic rather than abstracting it away into JavaScript-heavy virtual DOMs.

Marko's core philosophy centers on performance, specifically Streaming Server-Side Rendering (SSR) and Partial Hydration. Unlike frameworks that send a large JavaScript bundle to hydrate the entire page, Marko automatically sends only the code needed for interactive components, leaving static content as pure HTML. This results in incredibly fast Time to Interactive (TTI) and First Contentful Paint (FCP).

Key Features​

  • HTML-First Syntax: If you know HTML, CSS, and JS, you mostly know Marko.
  • Streaming SSR: Streams content to the browser immediately, reducing load times.
  • Partial Hydration: Only interactive components ship JavaScript to the browser.
  • Isomorphic: Runs seamlessly on both Node.js (server) and the browser.
  • Compiler-Optimized: Analyzing templates at compile time to produce highly optimized code.

Top 10 Common Use Cases and Architectures​

Due to its unique performance characteristics, Marko is particularly well-suited for specific architectural patterns:

  1. High-Traffic E-commerce Platforms:

    • Why: E-commerce requires instant loading for conversion rates. Marko's streaming and partial hydration ensure product pages load fast, even on slow devices.
    • Example: eBay.com.

  2. Server-Driven UI (SDUI):

    • Why: Since Marko templates logic can sit on the server, you can control the UI structure remotely without redeploying client bundles.

  3. Multi-Page Applications (MPAs) with "Islands":

    • Why: Marko treats pages as entries and only hydrates the "islands" of interactivity (like a "Buy" button or a carousel) within a static page.

  4. Micro-Frontends:

    • Why: Marko's lightweight runtime and isolated component structure make it an excellent choice for composing pages from fragments owned by different teams.

  5. SEO-Critical Content Sites:

    • Why: Search engines love fast, server-rendered HTML. Marko delivers fully formed HTML before JavaScript even executes.

  6. Progressive Web Apps (PWA):

    • Why: Fast initial loads combined with service workers allow for app-like experiences that are performant even offline.

  7. Dynamic Email Templates:

    • Why: Marko's text-mode compiler allows it to generate HTML strings for emails, leveraging component reuse for complex email layouts.

  8. Internal Dashboards & Admin Panels:

    • Why: The concise syntax allows for rapid development of complex forms and data tables without the boilerplate of larger frameworks.

  9. Legacy Migration from HTML/JQuery:

    • Why: Because Marko syntax is a superset of HTML, teams can migrate legacy HTML files to Marko just by changing the extension and gradually adding interactivity.

  10. Low-Bandwidth Environments:

    • Why: By shipping minimal JS, Marko apps perform significantly better in developing markets or areas with poor cellular data.

How to Install and Use​

Quick Start (Marko Run)​

The easiest way to start a new project is using Marko Run, the official application framework powered by Vite.

npm init marko

Follow the CLI prompts to set up your project.

Manual Integration (Node.js/Express + Vite)​

If you are adding Marko to an existing Node.js architecture:

  1. Install Dependencies:

    npm install marko
    npm install -D vite @marko/vite

  2. Configure Vite (vite.config.js):

    import { defineConfig } from "vite";
    import marko from "@marko/vite";

    export default defineConfig({
      plugins: [marko()]
    });

  3. Create a Page Component (src/pages/index.marko):

    class {
        onCreate() {
            this.state = { count: 0 };
        }
        increment() {
            this.state.count++;
        }
    }

    style {
        .count { color: blue; font-weight: bold; }
    }

    <div>
        <h1>Welcome to Marko!</h1>
        <p class="count">Count: ${this.state.count}</p>
        <button on-click("increment")>Click me</button>
    </div>

  4. Server Integration (Express Example): Using @marko/express enables res.marko to stream templates directly.

    import markoMiddleware from "@marko/express";
    import template from "./src/pages/index.marko";

    app.use(markoMiddleware());

    app.get("/", (req, res) => {
        // Streams the response automatically
        res.marko(template, { name: "World" });
    });

Best Practices​

1. Project Structure​

Organize components to leverage Marko's auto-discovery tags.

src/
  components/
    app-header/
      index.marko
      style.css
    app-footer.marko
  routes/
    +page.marko
  • Auto-discovery: Components inside a components/ directory are automatically available in parent templates without import.

2. Component Design​

  • Split Logic and View: For complex components, keep logic in component.js and the view in index.marko within the same folder.
  • Styles: Use the style block within the .marko file for collocated, scoped CSS.

3. Performance​

  • Keyed Loops: Always use a key attribute when looping to help the diff algorithm. 
    <for|item| of=items by="id">
        <li key=item.id>${item.name}</li>
    </for>
  • Async Fragments: Use the <await> tag to handle asynchronous data without blocking the HTML stream. 
    <await(userPromise) client-reorder=true>
        <@then|user|>
            <user-profile user=user/>
        </@then>
        <@placeholder>
            <loading-spinner/>
        </@placeholder>
    </await>

4. State Management​

  • Use this.state for local component state.
  • For global state, consider simple stores or leverage Marko's context API. Avoid bringing in heavy Redux/MobX libraries unless absolutely necessary, as they can negate the "lightweight" benefit.

5. Syntax Preferences​

Marko supports both a Concise (indentation-based) and HTML syntax.

  • HTML Style: Better for teams familiar with standard HTML.
  • Concise Style: Better for rapid prototyping and reduced visual clutter.
  • Recommendation: Stick to one style per project to avoid confusion.
