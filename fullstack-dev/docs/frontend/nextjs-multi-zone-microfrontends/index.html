Next.js Multi-Zone Microfrontends (App Router)

Production guide for decomposing a large e-commerce frontend into independently deployable Next.js apps — fully compatible with RSC, Streaming, Server Actions, and Turbopack.

Problem​

Module Federation + App Router is fundamentally incompatible.

React Server Components serialize as a binary stream, not as a JavaScript module. Webpack Module Federation federates JS bundles at runtime. You cannot federate a Server Component across app boundaries — only client-side bundles can be federated.

Attempting to use Module Federation with App Router breaks:

  • RSC streaming
  • Server Actions
  • Suspense boundaries
  • Turbopack dev mode

Solution: Next.js Multi-Zone — the first-party, officially supported approach.

Forces​

ConcernMulti-ZoneModule Federation
RSC / Server Components✅ Full support❌ Client bundles only
Streaming / Suspense✅ Per-app, independent❌ Breaks RSC streams
Server Actions✅❌
Independent team deployments✅✅
Turbopack dev server✅⚠️ Conflicts
Cross-zone <Link> navigation⚠️ Use <a> for cross-zone✅ Client-side nav
Shared componentsTurborepo npm packageRuntime federation
Single domain to browser✅ Via rewrites✅ Via remoteEntry

Solution: Multi-Zone Architecture​

Each domain team owns a fully independent Next.js app (a "zone"). The Shell proxies routes to the correct zone via rewrites. The browser sees a single origin — no CORS, no token sharing issues.

Project Structure (Turborepo Monorepo)​

ecom-frontend/
├── apps/

│   ├── catalog-mfe/         # Products, PDP, categories
│   ├── cart-mfe/            # Cart widget, cart page

├── packages/

Step 1: Shell App (Routing Hub)​

The Shell owns the public domain and proxies all other routes to zone apps. It also handles the shared layout and auth middleware.

// apps/shell/next.config.ts
import type { NextConfig } from 'next';

const ZONE_URLS = {
  catalog:  process.env.CATALOG_URL  ?? 'http://localhost:3001',
  cart:     process.env.CART_URL     ?? 'http://localhost:3002',
  checkout: process.env.CHECKOUT_URL ?? 'http://localhost:3003',
  account:  process.env.ACCOUNT_URL  ?? 'http://localhost:3004',
  search:   process.env.SEARCH_URL   ?? 'http://localhost:3005',
};

const config: NextConfig = {
  async rewrites() {
    return [
      // Route segments owned by each zone
      {
        source: '/products/:path*',
        destination: `${ZONE_URLS.catalog}/products/:path*`,
      },
      {
        source: '/cart/:path*',
        destination: `${ZONE_URLS.cart}/cart/:path*`,
      },
      {
        source: '/checkout/:path*',
        destination: `${ZONE_URLS.checkout}/checkout/:path*`,
      },
      {
        source: '/account/:path*',
        destination: `${ZONE_URLS.account}/account/:path*`,
      },
      {
        source: '/search/:path*',
        destination: `${ZONE_URLS.search}/search/:path*`,
      },
      // Static assets — each zone must have a unique assetPrefix
      {
        source: '/_next/static/catalog/:path*',
        destination: `${ZONE_URLS.catalog}/_next/static/catalog/:path*`,
      },
      {
        source: '/_next/static/cart/:path*',
        destination: `${ZONE_URLS.cart}/_next/static/cart/:path*`,
      },
      {
        source: '/_next/static/checkout/:path*',
        destination: `${ZONE_URLS.checkout}/_next/static/checkout/:path*`,
      },
    ];
  },
};

export default config;

Shell Middleware (Auth + Token Forwarding)​

// apps/shell/middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';
import { verifyToken } from '@/lib/auth';

export async function middleware(request: NextRequest) {
  const response = NextResponse.next();

  // Protect authenticated routes
  const protectedPaths = ['/account', '/checkout', '/orders'];
  const isProtected = protectedPaths.some(p => request.nextUrl.pathname.startsWith(p));

  if (isProtected) {
    const token = request.cookies.get('auth-token')?.value;
    if (!token) {
      return NextResponse.redirect(new URL('/login', request.url));
    }

    const payload = await verifyToken(token);
    if (!payload) {
      return NextResponse.redirect(new URL('/login', request.url));
    }

    // Forward user context to downstream zones
    response.headers.set('x-user-id', payload.sub);
    response.headers.set('x-user-role', payload.role);
  }

  return response;
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};

Step 2: Zone App Configuration​

Each zone app must set a unique assetPrefix to prevent static asset collisions between zones.

  • Catalog MFE
  • Cart MFE
  • Checkout MFE
// apps/catalog-mfe/next.config.ts
import type { NextConfig } from 'next';

const isProd = process.env.NODE_ENV === 'production';

const config: NextConfig = {
  // Unique asset prefix — avoids _next/static chunk collisions
  assetPrefix: isProd ? 'https://catalog.ecom.io' : 'http://localhost:3001',

  // Tell Next.js this app is a zone — no standalone domain needed
  // Do NOT set basePath here; Shell rewrites handle routing

  experimental: {
    // Enable PPR (Partial Pre-rendering) for product pages
    ppr: true,
  },
};

export default config;
// apps/cart-mfe/next.config.ts
import type { NextConfig } from 'next';

const isProd = process.env.NODE_ENV === 'production';

const config: NextConfig = {
  assetPrefix: isProd ? 'https://cart.ecom.io' : 'http://localhost:3002',
};

export default config;
// apps/checkout-mfe/next.config.ts
import type { NextConfig } from 'next';

const isProd = process.env.NODE_ENV === 'production';

const config: NextConfig = {
  assetPrefix: isProd ? 'https://checkout.ecom.io' : 'http://localhost:3003',

Step 3: Zone Pages (Full RSC + Streaming)​

Zones are plain Next.js App Router apps. RSC, streaming, and Server Actions work without restrictions.

Product Detail Page (Catalog MFE)​

// apps/catalog-mfe/app/products/[id]/page.tsx
import { Suspense } from 'react';
import { notFound } from 'next/navigation';
import { ProductDetail } from '@ecom/ui/ProductDetail';
import { ProductRecommendations } from './ProductRecommendations';
import { ProductReviewsSkeleton } from './skeletons';

// Next.js 15: params is always async
type Props = { params: Promise<{ id: string }> };

export async function generateMetadata({ params }: Props) {
  const { id } = await params;
  const product = await fetchProduct(id);
  if (!product) return {};
  return {
    title: `${product.name} — EcomStore`,
    description: product.description,
    openGraph: { images: [product.imageUrl] },
  };
}

export default async function ProductPage({ params }: Props) {
  const { id } = await params;
  const product = await fetchProduct(id);   // Direct internal API call — no client hop

  if (!product) notFound();

  return (
    <>
      {/* Immediate render — no Suspense needed */}
      <ProductDetail product={product} />

      {/* Streamed independently — slow recommendation engine doesn't block page */}
      <Suspense fallback={<ProductReviewsSkeleton />}>
        <ProductRecommendations productId={id} />
      </Suspense>
    </>
  );
}

async function fetchProduct(id: string) {
  const res = await fetch(
    `${process.env.PRODUCT_SERVICE_URL}/products/${id}`,
    {
      next: { tags: [`product-${id}`] },   // Tag-based revalidation
    }
  );
  if (!res.ok) return null;
  return res.json();
}

Cart Server Action (Cart MFE)​

// apps/cart-mfe/app/actions.ts
'use server';

import { revalidateTag } from 'next/cache';
import { cookies } from 'next/headers';

export async function addToCart(productId: string, qty: number) {
  const cookieStore = await cookies();
  const userId = cookieStore.get('user-id')?.value;
  if (!userId) throw new Error('Unauthenticated');

  const res = await fetch(`${process.env.CART_SERVICE_URL}/carts/${userId}/items`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ productId, qty }),
  });

  if (!res.ok) throw new Error('Failed to add to cart');

  revalidateTag(`cart-${userId}`);   // Invalidate cart cache across all RSC renders
}

export async function removeFromCart(itemId: string) {
  const cookieStore = await cookies();
  const userId = cookieStore.get('user-id')?.value;

  await fetch(`${process.env.CART_SERVICE_URL}/carts/${userId}/items/${itemId}`, {
    method: 'DELETE',
  });

  revalidateTag(`cart-${userId}`);
}

Step 4: Cross-Zone Navigation​

The browser sees one domain. Use <a> (hard navigation) for cross-zone links, <Link> within the same zone.

// apps/catalog-mfe/components/AddToCartButton.tsx
'use client';

import { addToCart } from '@/app/actions';   // Server Action — same zone ✅
import { useTransition } from 'react';

export function AddToCartButton({ productId }: { productId: string }) {
  const [pending, startTransition] = useTransition();

  function handleAddToCart() {
    startTransition(async () => {
      await addToCart(productId, 1);
      // Cross-zone navigation to cart — must use window.location or <a>
      window.location.href = '/cart';
    });
  }

  return (
    <button onClick={handleAddToCart} disabled={pending}>
      {pending ? 'Adding...' : 'Add to Cart'}
    </button>
  );
}
// Cross-zone link — use <a>, not <Link>
// <Link> only handles client-side navigation within the SAME zone
export function ViewCartLink() {
  return <a href="/cart">View Cart</a>;   // Hard nav → Shell routes to Cart MFE ✅
}

// Within same zone — use <Link> for RSC client navigation
import Link from 'next/link';
export function RelatedProduct({ id }: { id: string }) {
  return <Link href={`/products/${id}`}>View Product</Link>;   // Same zone ✅
}

Step 5: Shared Component Library​

Shared components live in packages/ui. They can be Server Components or Client Components.

// packages/ui/src/ProductCard/index.tsx   — Server Component
// No 'use client' directive → remains RSC-safe, importable in any zone's RSC tree

import type { Product } from '@ecom/types';
import { formatPrice } from '@ecom/utils';

export function ProductCard({ product }: { product: Product }) {
  return (
    <article>
      <img src={product.imageUrl} alt={product.name} width={300} height={300} />
      <h3>{product.name}</h3>
      <p>{formatPrice(product.price, product.currency)}</p>
    </article>
  );
}
// packages/ui/src/Button/index.tsx   — Client Component
'use client';

export function Button({
  children,
  onClick,
  variant = 'primary',
  disabled,
}: ButtonProps) {
  return (
    <button
      className={`btn btn-${variant}`}
      onClick={onClick}
      disabled={disabled}
    >
      {children}
    </button>
  );
}
Non-serializable props

Props crossing Server → Client boundaries must be JSON-serializable. Never pass Date objects, class instances, functions (except Server Actions), Map, or Set across the boundary.

Step 6: Cross-Zone State Patterns​

Zones are isolated processes — they cannot share in-memory state. Use these patterns instead:

NeedPattern
AuthenticationHTTP-only cookie on shared domain — read in each zone's middleware.ts
Cart item count in Shell headerShell fetches /api/cart/count route handler (lightweight)
Real-time cart updatesRedis Pub/Sub → SSE endpoint in Cart MFE → Shell EventSource
Design tokens / theme@ecom/ui package (build-time sharing)
Feature flagsGCP Cloud Firestore edge config — read in each zone's layout.tsx
User preferencesCookie or localStorage with shared schema via @ecom/types

Cart Count in Shell (SSE Pattern)​

// apps/shell/app/components/CartCountWidget.tsx
'use client';

import { useEffect, useState } from 'react';

export function CartCountWidget({ userId }: { userId: string }) {
  const [count, setCount] = useState(0);

  useEffect(() => {
    // Subscribe to cart updates via SSE from Cart MFE
    const es = new EventSource(`/cart/api/count/stream?userId=${userId}`);
    es.onmessage = (e) => setCount(Number(e.data));
    return () => es.close();
  }, [userId]);

  return <span className="cart-badge">{count}</span>;
}

Error Boundaries per Zone​

Each zone must define its own error.tsx — errors don't propagate across zone boundaries:

// apps/catalog-mfe/app/products/error.tsx
'use client';

import { useEffect } from 'react';

export default function ProductError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    // Report to observability platform
    console.error('[catalog-mfe] product error:', error);
  }, [error]);

  return (
    <div role="alert">
      <h2>Something went wrong loading this product.</h2>
      <button onClick={reset}>Try again</button>
    </div>
  );
}

When to Add Module Federation (Optional Layer)​

Module Federation is still useful for Client Components only when you need runtime sharing without npm publish:

Use Module Federation only if:
  • The component is a self-contained interactive widget (e.g., rich text editor, video player)
  • It changes frequently and the npm publish/install cycle is too slow
  • It has no Next.js routing (page.tsx, layout.tsx, Server Actions)
Never federate:
  • Server Components
  • Server Actions
  • Route segments (page.tsx, layout.tsx)
  • Components that use cookies(), headers(), or other server-only APIs

NFRTargetHow Achieved
Latency (p99)< 100 ms TTFB, < 200 ms LCPRSC streaming, CDN edge caching, PPR

Trade-offs​

Multi-Zone advantages:

  • Full RSC, Streaming, Server Actions — no constraints
  • Teams deploy independently with zero coordination
  • Browser sees one domain — auth cookies, CORS solved by default
  • Scales per zone independently on Kubernetes

Multi-Zone limitations:

  • Cross-zone navigation requires hard reload (<a> not <Link>)
  • No shared client-side state (React context doesn't cross zones)
  • Shell is a SPOF for routing — must be highly available (HPA min 3)
  • assetPrefix must be configured correctly per zone or chunks collide
