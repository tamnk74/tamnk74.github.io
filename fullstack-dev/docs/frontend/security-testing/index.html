Frontend Security Testing Guide

A comprehensive guide to identifying and preventing security vulnerabilities in frontend applications through automated testing and best practices.

Why Frontend Security Testing Matters​

Frontend security is critical because:

  • 🔐 User Data Protection: Prevent data breaches and theft
  • 🛡️ XSS Prevention: Stop malicious script injection
  • 🔒 Authentication Security: Protect user sessions and credentials
  • 📊 Compliance: Meet GDPR, PCI-DSS, HIPAA requirements
  • 💰 Financial Impact: Data breaches cost an average of $4.45M
  • 🎯 Reputation: Security incidents damage brand trust

Security Testing Tools​

1. OWASP ZAP (Zed Attack Proxy)​

Automated security scanner for web applications.

Installation​

# macOS
brew install --cask owasp-zap

# Or download from https://www.zaproxy.org/download/

Command Line Usage​

# Quick scan
zap-cli quick-scan --self-contained http://localhost:3000

# Full scan
zap-cli quick-scan --spider -r http://localhost:3000

# Scan with authentication
zap-cli quick-scan --auth-mode form \
  --auth-url http://localhost:3000/login \
  --auth-username test@example.com \
  --auth-password password123 \
  http://localhost:3000

# Generate report
zap-cli report -o zap-report.html -f html

docker run -v $(pwd):/zap/wrk/:rw \

Automated ZAP Testing​

scripts/zap-scan.js:

import { spawn } from 'child_process';
import fs from 'fs';

async function runZapScan(targetUrl) {
  return new Promise((resolve, reject) => {
    const zap = spawn('docker', [
      'run',
      '-v',
      `${process.cwd()}:/zap/wrk/:rw`,
      '-t',
      'owasp/zap2docker-stable',
      'zap-baseline.py',
      '-t',
      targetUrl,
      '-J',
      'zap-report.json',
      '-r',
      'zap-report.html',
    ]);

    let output = '';

    zap.stdout.on('data', (data) => {
      output += data.toString();
      console.log(data.toString());
    });

    zap.stderr.on('data', (data) => {
      console.error(data.toString());
    });

    zap.on('close', (code) => {
      if (code === 0 || code === 2) {
        // ZAP returns 2 if warnings found
        const report = JSON.parse(fs.readFileSync('zap-report.json', 'utf8'));
        const summary = analyzeZapReport(report);
        resolve(summary);
      } else {
        reject(new Error(`ZAP scan failed with code ${code}`));
      }
    });
  });
}

function analyzeZapReport(report) {
  const alerts = report.site[0].alerts;
  const summary = {
    high: 0,
    medium: 0,
    low: 0,
    informational: 0,
    total: alerts.length,
    issues: [],
  };

  alerts.forEach((alert) => {
    const risk = alert.riskdesc.split(' ')[0].toLowerCase();
    summary[risk]++;

    if (risk === 'high' || risk === 'medium') {
      summary.issues.push({
        name: alert.name,
        risk: alert.riskdesc,
        description: alert.desc,
        solution: alert.solution,
        references: alert.reference,
        instances: alert.instances.length,
      });
    }
  });

  return summary;
}

// Run scan
const targetUrl = process.argv[2] || 'http://localhost:3000';
console.log(`Running ZAP scan on ${targetUrl}...`);

const summary = await runZapScan(targetUrl);
console.log('\n=== Scan Summary ===');
console.log(`High: ${summary.high}`);
console.log(`Medium: ${summary.medium}`);
console.log(`Low: ${summary.low}`);
console.log(`Total: ${summary.total}`);

if (summary.high > 0) {
  console.error('\n❌ High-risk vulnerabilities found!');
  process.exit(1);
} else {
  console.log('\n✅ No high-risk vulnerabilities found');
}

When to Use Header Authentication vs Context Files:

ScenarioRecommended Method
JWT/Bearer tokensHeader authentication (ZAP_AUTH_HEADER_*)
API keysHeader authentication (ZAP_AUTH_HEADER_*)
OAuth tokensHeader authentication (ZAP_AUTH_HEADER_*)
Form-based loginContext file (-n context.xml)
Session cookiesContext file (-n context.xml)
Complex multi-step authContext file (-n context.xml)
Multiple headersScan hooks or context file
Multiple Authentication Headers

No, you cannot add multiple ZAP_AUTH_HEADER environment variables. ZAP's environment variable approach only supports a single authentication header at a time.

Workarounds for Multiple Headers:

  1. Using Scan Hooks (Recommended for multiple headers):
# zap/custom_hooks.py
def zap_started(zap, target):
    """
    This function is called after ZAP has started but before the scan begins.
    Use it to configure multiple headers.
    """
    # Add multiple headers to every request
    zap.replacer.add_rule(
        description='Add X-API-Key Header',
        enabled=True,
        matchtype='REQ_HEADER',
        matchregex=False,
        matchstring='X-API-Key',
        replacement='your-api-key-here',
        initiators=''
    )

    zap.replacer.add_rule(
        description='Add Authorization Header',
        enabled=True,
        matchtype='REQ_HEADER',
        matchregex=False,
        matchstring='Authorization',
        replacement='Bearer your-token-here',
        initiators=''
    )

    zap.replacer.add_rule(
        description='Add X-Custom-Header',
        enabled=True,
        matchtype='REQ_HEADER',
        matchregex=False,
        matchstring='X-Custom-Header',
        replacement='custom-value',
        initiators=''
    )

// zap/proxy-script.js - ModifyRequest script type
function proxyRequest(msg) {
  // Add multiple headers to all requests

Understanding the Rules File:

The rules_file_name parameter in the GitHub Action specifies a configuration file that controls how ZAP handles different vulnerability findings. Each line follows this format:

<rule-id>  <action>  (Rule Name)

Available Actions:

ActionDescriptionExit Code Impact
FAILFails the build if foundCauses workflow to fail
WARNShows warning but continuesExit code 2 (warning)
IGNORESuppresses the alertNo impact
INFOShows as informationalNo impact
OUTOFSCOPEExcludes URLs matching patternNo impact

Rule ID Examples:

# Security Headers - Critical for production
10020   FAIL    (X-Frame-Options Header Not Set)
10021   FAIL    (X-Content-Type-Options Header Missing)
10016   FAIL    (Web Browser XSS Protection Not Enabled)

# Cookie Security - Important but might need time to fix
10010   WARN    (Cookie No HttpOnly Flag)
10011   WARN    (Cookie Without Secure Flag)
10054   WARN    (Cookie without SameSite Attribute)

# Development Environment - Safe to ignore
2       IGNORE  (Private IP Disclosure)
10109   IGNORE  (Modern Web Application)

# Exclude specific URLs (wildcard * applies to all rules)
*       OUTOFSCOPE  .*\.(js|css|png|jpg)$
*       OUTOFSCOPE  .*/node_modules/.*
10027   OUTOFSCOPE  .*/vendor/.*  # Ignore comments in vendor code

Automated Audit Script​

scripts/security-audit.js:

import { execSync } from 'child_process';
import fs from 'fs';

function runSecurityAudit() {
  try {
    const auditOutput = execSync('npm audit --json', {
      encoding: 'utf8',
    });

    const audit = JSON.parse(auditOutput);

    const summary = {
      vulnerabilities: audit.metadata.vulnerabilities,
      dependencies: audit.metadata.dependencies,
      timestamp: new Date().toISOString(),
    };

    console.log('=== Security Audit Summary ===');
    console.log(`Critical: ${summary.vulnerabilities.critical || 0}`);
    console.log(`High: ${summary.vulnerabilities.high || 0}`);
    console.log(`Moderate: ${summary.vulnerabilities.moderate || 0}`);
    console.log(`Low: ${summary.vulnerabilities.low || 0}`);
    console.log(`Total: ${summary.vulnerabilities.total || 0}`);

    // Save detailed report
    fs.writeFileSync('security-audit.json', JSON.stringify(audit, null, 2));

    // Fail if critical or high vulnerabilities found
    if (summary.vulnerabilities.critical > 0 || summary.vulnerabilities.high > 0) {
      console.error('\n❌ Critical or high vulnerabilities found!');
      process.exit(1);
    }

    console.log('\n✅ No critical or high vulnerabilities found');
    return summary;
  } catch (error) {
    if (error.stdout) {
      const audit = JSON.parse(error.stdout);
      console.error('Vulnerabilities found:', audit.metadata.vulnerabilities);
      process.exit(1);
    }
    throw error;
  }
}

runSecurityAudit();

Automated XSS Scanning​

scripts/xss-scanner.js:

import puppeteer from 'puppeteer';

const xssPayloads = [
  '<script>window.__XSS_TEST__=1</script>',
  '<img src=x onerror="window.__XSS_TEST__=1">',
  '<svg/onload="window.__XSS_TEST__=1">',
];

async function testXSSVulnerability(url, inputSelector) {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();

  const vulnerabilities = [];

  try {
    await page.goto(url);

    for (const payload of xssPayloads) {
      await page.evaluate(() => {
        delete window.__XSS_TEST__;
      });

      await page.type(inputSelector, payload);
      await page.keyboard.press('Enter');
      await page.waitForTimeout(500);

      const isVulnerable = await page.evaluate(() => {
        return window.__XSS_TEST__ === 1;
      });

      if (isVulnerable) {
        vulnerabilities.push({
          url,
          selector: inputSelector,
          payload,
          type: 'XSS',
        });
      }

      await page.reload();
    }
  } catch (error) {
    console.error('Error testing XSS:', error);
  } finally {
    await browser.close();
  }

  return vulnerabilities;
}

// Test multiple inputs
const tests = [
  { url: 'http://localhost:3000', selector: '[data-testid="search-input"]' },
  { url: 'http://localhost:3000/products/1', selector: '[data-testid="comment-input"]' },
];

const allVulnerabilities = [];

for (const test of tests) {
  const vulnerabilities = await testXSSVulnerability(test.url, test.selector);
  allVulnerabilities.push(...vulnerabilities);
}

  console.error('❌ XSS vulnerabilities found:');

CSRF (Cross-Site Request Forgery) Testing​

CSRF Token Implementation​

middleware/csrf.ts:

import { NextRequest, NextResponse } from 'next/server';
import { cookies } from 'next/headers';
import crypto from 'crypto';

export function generateCSRFToken(): string {
  return crypto.randomBytes(32).toString('hex');
}

export function verifyCSRFToken(request: NextRequest): boolean {
  const token = request.headers.get('x-csrf-token');
  const cookieToken = cookies().get('csrf-token')?.value;

  return token !== null && token === cookieToken;
}

export function csrfMiddleware(request: NextRequest) {
  // Skip CSRF check for safe methods
  if (['GET', 'HEAD', 'OPTIONS'].includes(request.method)) {
    return NextResponse.next();
  }

  if (!verifyCSRFToken(request)) {
    return NextResponse.json({ error: 'Invalid CSRF token' }, { status: 403 });
  }

  return NextResponse.next();
}

Testing for Exposed Secrets​

test/security/secrets.test.ts:

import { test, expect } from '@playwright/test';
import fs from 'fs';
import path from 'path';

const sensitivePatterns = [
  /(?:api[_-]?key|apikey|access[_-]?token|auth[_-]?token).*?['"][a-zA-Z0-9_-]{20,}['"]/gi,
  /(?:password|passwd|pwd).*?['"][^'"]{8,}['"]/gi,
  /(?:secret|private[_-]?key).*?['"][^'"]{20,}['"]/gi,
  /sk_live_[a-zA-Z0-9]{24,}/g, // Stripe
  /AKIA[0-9A-Z]{16}/g, // AWS
  /AIza[0-9A-Za-z_-]{35}/g, // Google API
  /[0-9a-f]{32}/g, // MD5 hashes
];

function scanFileForSecrets(filePath: string): Array<{ line: number; match: string }> {
  const content = fs.readFileSync(filePath, 'utf8');
  const lines = content.split('\n');
  const findings: Array<{ line: number; match: string }> = [];

  lines.forEach((line, index) => {
    sensitivePatterns.forEach((pattern) => {
      const matches = line.match(pattern);
      if (matches) {
        findings.push({
          line: index + 1,
          match: matches[0],
        });
      }
    });
  });

  return findings;
}

function scanDirectory(dir: string, findings: Map<string, any[]> = new Map()) {
  const files = fs.readdirSync(dir);

  files.forEach((file) => {
    const filePath = path.join(dir, file);
    const stat = fs.statSync(filePath);

    if (stat.isDirectory()) {
      if (!['node_modules', '.next', 'dist', '.git'].includes(file)) {
        scanDirectory(filePath, findings);
      }
    } else if (['.ts', '.tsx', '.js', '.jsx', '.env'].some((ext) => file.endsWith(ext))) {
      const secrets = scanFileForSecrets(filePath);
      if (secrets.length > 0) {
        findings.set(filePath, secrets);
      }
    }
  });

  return findings;
}

    // Navigate to protected page - should trigger token refresh
    await page.goto('http://localhost:3000/profile');

    // Wait for token refresh to complete
    await page.waitForTimeout(1000);

    // Verify new access token was set
    const cookies = await context.cookies();
    const accessToken = cookies.find((c) => c.name === 'access_token');
    expect(accessToken).toBeDefined();
    expect(accessToken?.value).toBeTruthy();
  });
});

Best Practices for Cookie-Based Authentication Testing​

  1. Use storageState for E2E tests - Fastest approach, reuses authentication
  2. Set realistic cookie attributes - Match production security settings
  3. Test token expiration - Verify refresh flow works correctly
  4. Test different user roles - Use fixtures for different permission levels
  5. Clear cookies between tests - Use context.clearCookies() when needed
  6. Validate cookie security - Check HttpOnly, Secure, SameSite attributes
  7. Test cookie deletion on logout - Ensure sessions are properly invalidated

import { test, expect } from '@playwright/test';

test.describe('Authentication & Authorization Tests', () => {
  test('should not access protected routes without authentication', async ({ page }) => {
    const protectedRoutes = ['/profile', '/orders', '/settings', '/admin'];

    for (const route of protectedRoutes) {
      await page.goto(`http://localhost:3000${route}`);

      // Should redirect to login or show 401/403
      expect(page.url()).toMatch(/\/(login|unauthorized|403)/);
    }
  });

  test('should enforce role-based access control', async ({ page, context }) => {
    // Login as regular user
    await page.goto('http://localhost:3000/login');
    await page.fill('[name="email"]', 'user@example.com');
    await page.fill('[name="password"]', 'password123');
    await page.click('[data-testid="login-button"]');

    await page.waitForURL('**/');

    // Try to access admin route
    await page.goto('http://localhost:3000/admin');

    // Should be redirected or show 403
    const status = await page.evaluate(() => {
      return document.querySelector('[data-testid="error-code"]')?.textContent;
    });

    expect(['401', '403']).toContain(status);
  });

  test('should enforce strong password requirements', async ({ page }) => {
    await page.goto('http://localhost:3000/register');

    const weakPasswords = ['123456', 'password', 'abc123', '12345678', 'qwerty'];

    for (const password of weakPasswords) {
      await page.fill('[name="password"]', password);
      await page.click('[data-testid="register-button"]');

      const errorMessage = await page.textContent('[data-testid="password-error"]');
      expect(errorMessage).toBeTruthy();
      expect(errorMessage).toMatch(/weak|invalid|requirements/i);
    }
  });

  test('should implement account lockout after failed attempts', async ({ page }) => {
    await page.goto('http://localhost:3000/login');

    const attempts = 5;
    for (let i = 0; i < attempts; i++) {
      await page.fill('[name="email"]', 'test@example.com');
      await page.fill('[name="password"]', 'wrongpassword');
      await page.click('[data-testid="login-button"]');
      await page.waitForTimeout(500);
    }

    // Next attempt should show lockout message
    await page.fill('[name="email"]', 'test@example.com');
    await page.fill('[name="password"]', 'wrongpassword');
    await page.click('[data-testid="login-button"]');

    const errorMessage = await page.textContent('[data-testid="error-message"]');
    expect(errorMessage).toMatch(/locked|too many attempts/i);
  });

  test('should invalidate session on logout', async ({ page, context }) => {
    // Login
    await page.goto('http://localhost:3000/login');
    await page.fill('[name="email"]', 'test@example.com');
    await page.fill('[name="password"]', 'password123');
    await page.click('[data-testid="login-button"]');

    await page.waitForURL('**/');

    // Get session token
    const cookies = await context.cookies();
    const sessionCookie = cookies.find((c) => c.name === 'session');
    expect(sessionCookie).toBeTruthy();

    // Logout
    await page.click('[data-testid="logout-button"]');
    await page.waitForURL('**/login');

    // Try to access protected route with old session
    await page.goto('http://localhost:3000/profile');
    expect(page.url()).toMatch(/login/);
  });
});

Security Testing Checklist​

Pre-Deployment Checklist​

  • Dependencies

    • No critical/high vulnerabilities in npm audit
    • All dependencies up to date
    • No known vulnerable packages

  • XSS Protection

    • All user inputs sanitized
    • Content Security Policy configured
    • No dangerouslySetInnerHTML without sanitization
    • URL parameters validated and escaped

  • CSRF Protection

    • CSRF tokens on all state-changing requests
    • SameSite cookie attribute set
    • Origin/Referer header validation

  • Authentication

    • Strong password requirements enforced
    • Account lockout after failed attempts
    • Secure password reset flow
    • Session timeout configured
    • Logout invalidates session

  • Authorization

    • Role-based access control enforced
    • API endpoints protected
    • Client-side checks + server-side validation

  • Data Protection

    • Sensitive data not in localStorage
    • No secrets in source code
    • HTTPS enforced
    • Secure cookies (HttpOnly, Secure, SameSite)

  • Security Headers

    • Content-Security-Policy
    • X-Frame-Options
    • X-Content-Type-Options
    • Strict-Transport-Security
    • Referrer-Policy

  • Third-Party Code

    • CDN resources use SRI
    • Third-party scripts reviewed
    • Minimal third-party dependencies

Best Practices​

1. Defense in Depth​

  • Multiple layers of security
  • Don't rely on client-side validation alone
  • Implement server-side validation

2. Least Privilege​

  • Grant minimum necessary permissions
  • Implement proper RBAC
  • Regular access reviews

3. Security by Default​

  • Secure defaults in configuration
  • Opt-in for risky features
  • Fail securely

4. Regular Updates​

  • Keep dependencies updated
  • Monitor security advisories
  • Automated dependency updates

5. Input Validation​

  • Validate all user inputs
  • Sanitize before output
  • Use allowlists over denylists

6. Secure Communication​

  • HTTPS everywhere
  • Secure WebSocket connections
  • Validate SSL certificates

7. Error Handling​

  • Don't expose sensitive info in errors
  • Log security events
  • Graceful error handling

8. Security Testing​

  • Automated security scans in CI/CD
  • Regular penetration testing
  • Bug bounty program

Conclusion​

Frontend security testing is essential for protecting users and data. By implementing:

✅ Automated vulnerability scanning ✅ XSS and CSRF protection testing ✅ Security header validation ✅ Authentication and authorization tests ✅ Dependency scanning ✅ CI/CD security integration ✅ Regular security audits

You can significantly reduce security risks in your frontend applications.
