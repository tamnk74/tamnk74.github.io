SolidJS Guide

Overview​

SolidJS is a modern, high-performance JavaScript library for building user interfaces. It is known for its fine-grained reactivity and absence of a Virtual DOM (VDOM). Unlike frameworks that diff a VDOM to determine updates, SolidJS compiles its templates to real DOM nodes and updates them directly and surgically when state changes.

Key features include:

  • Fine-Grained Reactivity: Updates are tracked at the individual value level, not the component level.
  • No Virtual DOM: Eliminates the overhead of VDOM diffing, resulting in consistently high performance.
  • Small Bundle Size: Extremely lightweight runtime.
  • JSX Support: Uses JSX for templating, making it familiar to React developers.

Pros and Cons Compared to Other Frameworks​

Pros​

  • Superior Performance: Consistently tops benchmarks due to the absence of a Virtual DOM and direct DOM updates.
  • True Reactivity: Updates are fine-grained. Only the specific text node or attribute that changed is updated, not the entire component tree.
  • Small Footprint: Significantly smaller bundle sizes compared to React or Angular.
  • Familiar Syntax: Uses JSX, making it very approachable for developers coming from React.
  • No Dependency Array Fatigue: Effects automatically track dependencies, removing the need to manually manage dependency arrays like in React's useEffect.

Cons​

  • Smaller Ecosystem: While growing, the selection of third-party libraries (UI kits, specific integrations) is smaller than React's or Vue's.
  • "Unlearning" React Habits: Despite looking like React, the mental model is different. Components execute only once (setup phase), which can confuse developers used to components re-rendering.
  • Destructuring Props Pitfall: You cannot destructure props without losing reactivity (unless using splitProps or mergeProps), which is a common "gotcha" for new users.
  • Maturity: While stable, it has fewer years of production hardening in massive enterprise environments compared to the "Big 3" (React, Angular, Vue).

Top 10 Common Use Cases and Architectures​

SolidJS is versatile and can be used in various scenarios where performance and reactivity are paramount.

Common Use Cases​

  1. High-Performance Web Applications: Dashboards and tools handling large datasets with real-time updates.
  2. Highly Interactive Single-Page Applications (SPAs): Applications with complex user interactions and frequent state changes.
  3. Real-time Applications: Chat apps, stock tickers, or collaborative tools using WebSockets.
  4. Lightweight Widgets and Web Components: Embeddable widgets where bundle size matters.
  5. Data Visualization: Rendering complex charts and graphs that need to update smoothly.
  6. Embedded Systems and IoT Interfaces: UIs for devices with limited processing power.
  7. Performance Migration: Rewriting legacy or slow parts of existing applications.
  8. Developer Tools: Building responsive IDEs or devtools extensions.
  9. Gaming Interfaces: HUDs and menus for web-based games.
  10. Low-Bandwidth Environments: Applications prioritizing minimal initial load and bundle size.

Architectural Patterns​

  1. Component-Based Architecture: Building UIs from reusable, modular components.
  2. Signals for State: Using createSignal for local, atomic state management.
  3. Stores for Complex State: Using createStore for nested reactivity and global state (often replacing Redux/MobX).
  4. Unidirectional Data Flow: Data flows down via props; events bubble up.
  5. Context API: Injecting dependencies and sharing state across component trees to avoid prop drilling.
  6. Renderless Components: Encapsulating logic in components that don't render UI (Headless UI patterns).
  7. Compound Components: Components designed to work together, sharing state via Context.
  8. Lifecycle Management: Using onMount and onCleanup for side effects and resource disposal.
  9. Memoization: Using createMemo to cache expensive computations.
  10. Streaming SSR: Leveraging Solid's streaming capabilities for fast server-side rendering.

Installation and Usage​

Installation​

The recommended way to start a SolidJS project is using Vite templates.

For JavaScript:

npx degit solidjs/templates/js my-solid-project
cd my-solid-project
npm install
npm run dev

For TypeScript:

npx degit solidjs/templates/ts my-solid-project
cd my-solid-project
npm install
npm run dev

Basic Usage Example​

A simple counter component demonstrating signals and effects:

import { createSignal, createEffect } from "solid-js";
import { render } from "solid-js/web";

function Counter() {
  const [count, setCount] = createSignal(0);

  // Effect runs whenever 'count' changes
  createEffect(() => {
    console.log("The count is now", count());
  });

  return (
    <button onClick={() => setCount(count() + 1)}>
      Clicks: {count()}
    </button>
  );
}

render(() => <Counter />, document.getElementById("app"));

Integration with Other Components​

SolidJS integrates well with the broader ecosystem.

  • Routing: Use @solidjs/router for declarative routing. 
    npm install @solidjs/router
  • Global State: While createStore covers most needs, libraries like solid-pebble or adapters for Redux/MobX exist.
  • UI Libraries:
    • Hope UI: Accessible and themable components.
    • SUID: Material-UI port for Solid.
    • Solid Bootstrap: Bootstrap components.
    • Kobalte: Low-level accessible UI primitives.
  • Third-Party JS Libraries: Direct DOM access via ref allows easy integration with libraries like D3.js, Chart.js, or Leaflet.

Best Practices​

To get the most out of SolidJS, follow these guidelines:

  1. Access Props Directly: Do not destructure props in the component function arguments. Destructuring removes reactivity.
    • Bad: function MyComponent({ name }) { ... }
    • Good: function MyComponent(props) { ... props.name ... }
  2. Call Signals in JSX: When passing a signal to a prop, call it as a function so the child receives the value (unless you want to pass the reactive signal itself).
    • Example: <Child value={count()} />
  3. Derive Data with Memos: Use createMemo(() => ...) for expensive calculations based on other signals. This prevents re-calculation unless dependencies change.
  4. Avoid Unnecessary Effects: Don't use createEffect to sync state manually. Use derived signals (memos) instead.
  5. Understand Reactive Scopes: Reactive code runs only inside tracking scopes (like JSX expressions, Effects, or Memos). Code in the component body runs only once during initialization.
  6. Keyed Loops: Use the <For> component for looping over arrays instead of array.map(). <For> is optimized for minimizing DOM operations when the array changes.
    • Example: <For each={items()}>{(item) => <div>{item.name}</div>}</For>
