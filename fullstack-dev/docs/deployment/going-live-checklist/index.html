Going Live Checklist

A comprehensive checklist to ensure your project is production-ready before going live. This guide covers all critical areas from browser testing to server configuration.

Source

This checklist is based on best practices from Spatie's Going Live Checklist, used for production deployments at Spatie.be.

Overview​

Use this checklist systematically before any production deployment to catch common issues and ensure a smooth launch. Work through each section methodically, checking off items as you verify them.

1. Browser Testing​

Desktop Testing​

Test on the latest versions of major browsers:

  • Chrome - Test all critical user flows
  • Firefox - Verify layout and functionality
  • Safari - Check webkit-specific rendering
  • Edge - Ensure compatibility with Chromium-based Edge

Mobile Testing​

Test on the latest versions of mobile browsers:

  • Mobile Safari (iOS) - Test on iPhone/iPad
  • Chrome/Android - Test on Android devices
  • Responsive design - Verify breakpoints work correctly
  • Touch interactions - Test tap targets and gestures
Browser Testing Tools

Use BrowserStack or similar services for comprehensive cross-browser testing across multiple devices and OS versions.

2. Frontend Checklist​

Assets​

  • Security & Protocol
  • Web Fonts
  • CSS
  • HTTPS Migration - Search all sources for http:// and replace with https://
  • Mixed Content - Ensure no HTTP resources loaded on HTTPS pages
  • SSL Certificate - Verify certificate is valid and properly configured
  • Font Services - Configure live domain in services like:
    • Typekit/Adobe Fonts
    • Fonts.com
    • Google Fonts (if API key required)
  • Font Loading - Verify fonts load correctly
  • FOUT/FOIT - Implement font-display strategy
  • Linting - Run CSS/SCSS linter and fix all errors
  • Autoprefixer - Verify browserslist is properly configured
  • PurgeCSS - If using PurgeCSS, verify layout is preserved
  • Critical CSS - Consider implementing critical CSS for above-the-fold content
  • Minification - Ensure CSS is minified in production

Scripts​

  • Dependency Lock - Ensure yarn.lock or package-lock.json is present and committed
  • JavaScript Linting - Check and fix all JS lint errors
  • Console Cleanup - Remove all console.log, console.warn, and debug statements
  • Babel Configuration - Verify babel-preset-env is properly configured for target browsers
  • Error Handling - Check browser console for runtime errors
  • Minification - Ensure JavaScript is minified and optimized for production
Debug Code

Always remove or disable debug code, console logging, and development-only features before going live. These can expose sensitive information and degrade performance.

Page Weight & Performance​

  • Performance Analysis
  • Caching Strategy
  • Compression
  • Total Page Weight - Evaluate total weight of at least the homepage
    • Target: < 2MB for initial page load
    • Use Chrome DevTools Network tab to measure
  • Heavy Assets - Identify large assets using Network/Timeline tab
  • Image Optimization - Ensure images are properly compressed and sized
  • Lazy Loading - Implement lazy loading for below-the-fold images
  • Browser Caching - Verify cache headers are set correctly
  • Asset Caching - Ensure static assets have long cache times
  • Cache Busting - Implement cache busting for CSS/JS (versioning or hashing)
  • CDN Configuration - If using CDN, verify it's properly configured
  • Gzip/Brotli - Enable text compression on server
  • Image Formats - Use modern formats (WebP, AVIF) with fallbacks
  • Minification - Verify all assets are minified

Audits​

Run comprehensive audits using Chrome DevTools Lighthouse:

# Using Chrome DevTools (Incognito Mode)
# 1. Open DevTools (F12)
# 2. Navigate to Lighthouse tab
# 3. Configure audit settings
# 4. Run audit
  • Mobile Audit - Run with throttling enabled (Slow 4G, 4x CPU slowdown)
    • Target: Performance score > 90
    • Fix issues flagged in report
  • Desktop Audit - Run desktop audit
    • Target: Performance score > 95
  • PWA Audit - If applicable, verify PWA requirements
  • Best Practices - Address all best practice violations
  • SEO Audit - Fix SEO issues identified
Lighthouse CI

Consider integrating Lighthouse CI into your deployment pipeline to automatically catch performance regressions.

3. Content Verification​

Open your browser console while checking content to catch any runtime errors.

General Content​

  • Text Content - Verify all strings/copy are present and correct
  • Images - Ensure all images are present and loading correctly
  • Translations - Check all translated content (if multi-language)
  • Navigation - Verify menu/submenu has correct active state on every page
  • Links - Test internal and external links
  • N+1 Queries - Check all pages for N+1 database query problems

Error Pages​

Create user-friendly error pages that provide helpful navigation:

  • 404 Page - Not Found page with:
    • Link back to home
    • Search functionality (if available)
    • Navigation tree or sitemap
  • 500 Page - Internal Server Error page
  • 503 Page - Service Unavailable/Maintenance page
<!-- Example 404 Page Elements -->
<div class="error-page">
  <h1>Page Not Found</h1>
  <p>The page you're looking for doesn't exist.</p>
  <a href="/" class="btn-home">Go to Homepage</a>
  <form action="/search" class="search-form">
    <input type="search" placeholder="Search..." />
  </form>
</div>

Meta Tags & Social Sharing​

  • SEO Meta Tags
  • Social Sharing
  • Favicons & Icons
  • Page Titles - Verify unique, descriptive titles for each page (50-60 characters)
  • Meta Descriptions - Check descriptions are compelling (150-160 characters)
  • Canonical URLs - Ensure canonical tags are set correctly
  • Robots Meta - Verify robots directives are appropriate
  • Open Graph Tags - Test Facebook/LinkedIn sharing 
    <meta property="og:title" content="Page Title" />
    <meta property="og:description" content="Page Description" />
    <meta property="og:image" content="https://example.com/image.jpg" />
    <meta property="og:url" content="https://example.com/page" />
  • Twitter Cards - Verify Twitter card meta tags 
    <meta name="twitter:card" content="summary_large_image" />
    <meta name="twitter:title" content="Page Title" />
    <meta name="twitter:image" content="https://example.com/image.jpg" />
  • Share Testing - Use Facebook Debugger and Twitter Card Validator
  • Favicon - Verify favicon.ico loads correctly
  • Apple Touch Icons - Test icons appear on iOS devices
  • Safari Pinned Tab - Pin tab in Safari to verify SVG pinned icon
  • Manifest Icons - Check PWA manifest icons (if applicable)
Multi-Language Sites

For multi-language websites, repeat the content verification section for each language to ensure consistency across all locales.

Interactive Components​

  • Google Maps
  • Forms
  • Media
  • Newsletter
  • API Key - Verify API key is configured for production domain
  • Billing - Ensure billing is set up to avoid service interruption
  • Info Windows - Test clicking on markers and info window content
  • Zoom Limits - Prevent zoom out beyond 1x world
  • Custom Styling - Verify map styling matches design
  • Performance - Check map loads efficiently
  • Validation - Test with incorrect and correct values
  • Error Messages - Verify helpful error messages display
  • Success States - Check success messages and redirects
  • Required Fields - Ensure required validation works
  • CSRF Protection - Verify CSRF tokens are implemented
  • Rate Limiting - Test form submission rate limits
  • Accessibility - Ensure forms are keyboard accessible with proper labels
  • Video Players - Test video playback with sound on/off
  • Audio Controls - Verify audio controls work correctly
  • Autoplay - Respect user preferences for autoplay
  • Captions/Subtitles - Check accessibility features
  • Mobile Playback - Test on mobile devices
  • Subscribe Flow - Test with incorrect email format
  • Valid Email - Test with correct email address
  • Double Opt-in - If implemented, verify confirmation email
  • Already Subscribed - Submit same email twice to verify duplicate handling
  • Unsubscribe - Test unsubscribe flow
  • Email Layout - Preview and test email templates
    • Check on multiple email clients (Gmail, Outlook, Apple Mail)
    • Verify responsive design
    • Test all links work

Structured Data​

  • Schema Markup - Implement appropriate schema.org markup:
    • Articles/Blog posts
    • Products
    • Events
    • Organizations
    • Breadcrumbs
  • Rich Snippets Testing - Validate using Google's Rich Results Test
  • JSON-LD - Prefer JSON-LD format for structured data
<!-- Example Article Schema -->
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Article",
    "headline": "Article Title",
    "image": "https://example.com/image.jpg",
    "datePublished": "2025-01-01",
    "author": {
      "@type": "Person",
      "name": "Author Name"
    }
  }
</script>

4. Backend Checklist​

Admin Panel​

  • Access - Verify admin panel is accessible at correct URL
  • Main Menu - Remove unused modules from navigation
  • Analytics Dashboard - Configure analytics/metrics dashboard
  • User Management - Create test admin account and verify login
  • Password Reset - Test password reset flow for existing users
  • Permissions - Verify role-based access control works correctly

Content Management​

  • Create/Edit - Test saving articles, news, pages, etc.
  • Media Uploads - Verify file upload functionality
  • WYSIWYG Editor - Test rich text editor features
  • Publishing Flow - Test draft, publish, schedule workflows
  • Versioning - If implemented, test content versioning

Email Configuration​

  • Recipients - Verify all email recipients are correct (no dev/test emails)
  • From Address - Check "From" addresses are correct
  • SMTP Settings - Verify SMTP/email service is properly configured
  • Email Templates - Review all transactional email templates
  • Test Emails - Send test emails for all automated notifications

Database​

  • Development URLs - Scan database for URLs pointing to development domain 
    -- Example MySQL query to find development URLs
    SELECT * FROM posts WHERE content LIKE '%dev.example.com%';
    SELECT * FROM settings WHERE value LIKE '%localhost%';
  • Placeholder Content - Remove test/dummy data
  • Indexes - Verify database indexes are optimized
  • Migrations - Ensure all migrations have run successfully

Branding​

  • Client Logo - Verify client's logo appears in header/admin panel
  • Favicon - Check favicon in admin area
  • Email Branding - Ensure email templates use correct branding

5. Server, DNS & Services​

SSL & HTTPS​

  • SSL Certificate
  • HTTPS Redirects
  • Install Certificate - Set up Let's Encrypt or commercial SSL certificate
  • Certificate Health - Check SSL configuration at SSL Labs
    • Target: A+ rating
    • Fix any vulnerabilities or warnings
  • Certificate Expiry - Set up renewal reminders/automation
  • Intermediate Certificates - Ensure certificate chain is complete
  • HTTP → HTTPS - Verify all HTTP traffic redirects to HTTPS
  • HSTS Header - Implement HTTP Strict Transport Security 
    # Nginx example
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
  • Mixed Content - Scan for and fix mixed content issues using Mixed Content Scanner

Domain & DNS​

  • WWW Redirect - Test www.example.com redirects to example.com (or vice versa)
  • Check Hostfile - Clear local hostfile entries to ensure viewing live site
  • DNS Propagation - Verify DNS propagation at WhatsMyDNS
  • Remove Dev DNS - Delete development DNS records
  • TTL Values - Consider lowering TTL before launch, increase after

Redirects & Status Codes​

  • Old → New URLs - Implement 301 redirects from old to new pages if redesigning 
    # Nginx redirect examples
    rewrite ^/old-page$ /new-page permanent;
    rewrite ^/blog/(.*)$ /articles/$1 permanent;
  • HTTP Status Check - Verify all status codes using HTTP Status Check
  • 404 Handling - Ensure 404s return proper status code (not 200)

Robots & Indexing​

  • Robots.txt - Verify robots.txt is configured correctly 
    User-agent: *
    Allow: /
    Sitemap: https://example.com/sitemap.xml
  • X-Robots-Tag - Ensure production isn't blocking robots 
    # Check for blocking header
    curl -I https://example.com | grep 'x-robots-tag'
    # Should NOT return: x-robots-tag: none
  • Allow Indexing - Verify ALLOW_ROBOTS=true in .env
  • Meta Robots - Check individual pages for proper robots meta tags

Analytics & Tracking​

  • Google Tag Manager - Verify GTM container is installed and firing
  • Google Analytics - Ensure GA4 property is tracking correctly
  • Tag Assistant - Use Google Tag Assistant to verify implementation
  • Event Tracking - Test custom events are firing
  • Privacy Compliance - Ensure cookie consent is implemented (GDPR, CCPA)
  • Exclude Internal Traffic - Filter out internal IPs from analytics

6. Google Search Console​

Setup & Configuration​

  • Add Property - Submit all variations:
    • https://example.com
    • https://www.example.com
    • http://example.com (if redirecting)
    • http://www.example.com (if redirecting)
  • Preferred Domain - Set https://example.com (non-www HTTPS) as preferred
  • Sitemap Submission - Submit XML sitemap 
    # Typical sitemap URL
    https://example.com/sitemap.xml
  • Verify Ownership - Complete verification process

Kickstart Indexing​

  • Fetch as Google - Use URL Inspection tool
  • Request Indexing - Submit important pages for immediate indexing
  • Monitor Coverage - Check Index Coverage report for errors
Search Console Setup

Set up Search Console well before launch. It can take several days for Google to start collecting data, and you'll want historical data to compare post-launch performance.

7. Server & Infrastructure​

Backups​

  • Automated Backups
  • Application Backups
  • Cloud Provider Backups - Enable on hosting platform:
    • DigitalOcean: Enable automated backups
    • AWS: Configure EBS snapshots or AWS Backup
    • Google Cloud: Set up persistent disk snapshots
  • Database Backups - Verify automated database backups
  • Backup Testing - Test restore process from backup
  • Retention Policy - Configure appropriate retention (e.g., 30 days)
  • Artisan Backup - If using Laravel, verify backup:run command works 
    php artisan backup:run
  • Backup Storage - Ensure backups stored off-server (S3, etc.)
  • Backup Monitoring - Set up alerts for failed backups
  • Schedule - Verify backup schedule is configured

Task Scheduling​

  • Cron/Scheduler - Verify scheduled tasks are running
    • Laravel Forge: Check scheduler is configured
    • Add to crontab if not using Forge
    * * * * * cd /path-to-project && php artisan schedule:run >> /dev/null 2>&1
  • Queue Workers - Ensure queue workers are running
  • Horizon - If using Laravel Horizon, configure in Supervisor:
    • Command: php artisan horizon
    • Path: /home/forge/example.com/current
    • Auto-restart: Yes

Monitoring​

  • Uptime Monitoring - Configure monitoring service:
    • Oh Dear!
    • Pingdom
    • UptimeRobot
  • Server Monitoring - Monitor server resources:
    • CPU usage
    • Memory usage
    • Disk space
    • Network traffic
  • Application Monitoring - Set up APM (Application Performance Monitoring):
    • New Relic
    • Datadog
    • Sentry for error tracking
  • Log Monitoring - Configure log aggregation and alerting

Security​

  • Firewall - Verify firewall rules are configured
  • SSH Access - Disable password authentication, use SSH keys only
  • Server Updates - Ensure server is up to date
  • Security Headers - Verify security headers are set: 
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

8. Version Control​

Repository Cleanup​

  • Remove Stale Branches - Delete develop, staging, or other outdated branches
  • Tag Release - Create a release tag for the production version 
    git tag -a v1.0.0 -m "Production release"
    git push origin v1.0.0
  • Branch Protection - Enable branch protection on main/production branch
  • Update README - Ensure README has production-relevant information

Documentation​

  • Deployment Docs - Document deployment process
  • Environment Variables - Document all required env variables
  • Runbook - Create operations runbook for common tasks
  • Emergency Contacts - Document who to contact for issues

9. Post-Launch​

Immediate Actions (First 24 Hours)​

  • Monitor Error Logs - Watch for unexpected errors
  • Check Analytics - Verify tracking is working
  • Test Critical Flows - Verify key user journeys work
  • Monitor Performance - Watch response times and server load
  • Check Email - Ensure transactional emails are being sent

First Week​

  • Review Analytics - Check traffic patterns and user behavior
  • Search Console - Monitor for crawl errors
  • User Feedback - Collect and address user issues
  • Performance Review - Analyze Core Web Vitals
  • Security Scan - Run security audit

Ongoing Maintenance​

  • Regular Backups - Verify backups continue running
  • Dependency Updates - Plan for security updates
  • Content Updates - Establish content update schedule
  • Performance Monitoring - Track performance metrics over time

Quick Reference Checklist​

Use this condensed version for rapid verification:

Pre-Launch Essentials​

✅ Browser testing completed
✅ Performance audits passed
✅ SSL certificate installed
✅ DNS configured and propagated
✅ Backups enabled and tested
✅ Monitoring configured
✅ Analytics tracking verified
✅ Error pages created
✅ All content verified
✅ Security headers set

Launch Day​

✅ Switch DNS to production
✅ Clear CDN cache
✅ Submit sitemap to Search Console
✅ Monitor error logs
✅ Test critical user flows
✅ Announce launch
