Applying Traefik as an Ingress Controller for E-commerce Microservices

Overview​

Traefik is a modern, cloud-native edge router and reverse proxy that is well-suited for dynamic microservices environments. In this e-commerce platform, Traefik can be used as the primary ingress controller to manage external traffic, provide SSL termination, load balancing, and advanced routing for both frontend and backend services running on Kubernetes (GKE).

Why Traefik?​

  • Dynamic Service Discovery: Automatically detects new services and routes traffic without manual configuration.
  • Kubernetes Native: Integrates seamlessly with Kubernetes Ingress resources and CRDs.
  • SSL/TLS Automation: Supports Let's Encrypt for automatic certificate management.
  • Observability: Built-in dashboard, metrics, and tracing support.
  • Advanced Routing: Path, host, header, and method-based routing.
  • Security: Middleware for rate limiting, authentication, and IP whitelisting.

Architecture Integration​

[Internet]
    |
[Cloud Armor (WAF)]
    |
[Global Load Balancer]
    |
[Traefik Ingress Controller]
    |         |         |
[Next.js] [API Gateway] [Microservices]
  • Traefik sits behind the global load balancer and Cloud Armor, acting as the entry point for all HTTP(S) traffic into the GKE cluster.
  • It routes requests to frontend (Next.js), API Gateway, and individual microservices based on Ingress rules.

Key Features Used​

  • Ingress Routing: Define Kubernetes Ingress or Traefik IngressRoute CRDs for each service.
  • Automatic HTTPS: Enable Let's Encrypt for all domains/subdomains.
  • Load Balancing: Distributes traffic across service pods.
  • Middleware: Use for rate limiting, authentication, CORS, and more.
  • Observability: Enable Traefik dashboard and Prometheus metrics.

Example: Deploying Traefik on GKE​

  1. Install Traefik via Helm
helm repo add traefik https://traefik.github.io/charts
helm repo update
helm install traefik traefik/traefik \
  --namespace traefik --create-namespace \
  --set service.type=LoadBalancer \
  --set ingressClass.enabled=true \
  --set ingressClass.isDefaultClass=true
  1. Configure Ingress for Next.js Frontend
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nextjs-ingress
  namespace: frontend
  annotations:
    kubernetes.io/ingress.class: traefik
spec:
  rules:
    - host: shop.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: nextjs-service
                port:
                  number: 80
  tls:
    - hosts:
        - shop.example.com
      secretName: nextjs-tls
  1. Configure Ingress for API Gateway
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: api-gateway-ingress
  namespace: backend
  annotations:
    kubernetes.io/ingress.class: traefik
spec:
  rules:
    - host: api.shop.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: api-gateway-service
                port:
                  number: 80
  tls:
    - hosts:
        - api.shop.example.com
      secretName: api-gateway-tls
  1. Enable Let's Encrypt (values.yaml)
additionalArguments:
  - '--certificatesresolvers.le.acme.email=admin@example.com'
  - '--certificatesresolvers.le.acme.storage=/data/acme.json'
  - '--certificatesresolvers.le.acme.tlschallenge=true'
  - '--entrypoints.websecure.http.tls.certresolver=le'
  1. Observability
  • Enable Traefik dashboard and metrics for monitoring traffic and health.

Best Practices​

  • Use separate namespaces for Traefik, frontend, and backend.
  • Restrict access to the Traefik dashboard.
  • Use middleware for security (rate limiting, IP whitelisting, authentication).
  • Regularly update Traefik for security patches.
