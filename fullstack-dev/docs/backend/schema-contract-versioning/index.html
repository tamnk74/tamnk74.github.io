Schema and Contract Versioning Guide

Overview​

In microservices architecture, managing API contracts and data schemas is crucial for maintaining backward compatibility and enabling independent service deployment. This guide covers versioning strategies, implementation patterns, and best practices for API contracts, database schemas, and message formats.

Versioning Strategies​

Semantic Versioning​

MAJOR.MINOR.PATCH

MAJOR: Incompatible API changes (breaking changes)
MINOR: Backward-compatible functionality additions
PATCH: Backward-compatible bug fixes

@ApiTags('Users V1')

import { CreateUserDtoV2 } from './dto/create-user.dto';

@ApiTags('Users V2')
@Controller('users')
export class UsersV2Controller {
  constructor(private readonly usersService: UsersService) {}

  @Get()
  @ApiOperation({ summary: 'Get all users - V2 with pagination' })
  async findAll(
    @Query('page') page: number = 1,
    @Query('limit') limit: number = 10,
  ): Promise<PaginatedResponseV2<UserResponseDtoV2>> {
    const result = await this.usersService.findAllPaginated(page, limit);
    return {
      data: result.items.map((user) => this.toV2Response(user)),
      meta: {
        page: result.page,
        limit: result.limit,
        total: result.total,
        totalPages: Math.ceil(result.total / result.limit),
      },
    };
  }

  @Get(':id')
  @ApiOperation({ summary: 'Get user by ID - V2 with extended fields' })
  async findOne(@Param('id') id: string): Promise<UserResponseDtoV2> {
    const user = await this.usersService.findOne(id);
    return this.toV2Response(user);
  }

  @Post()
  @ApiOperation({ summary: 'Create user - V2 with profile' })
  async create(@Body() createUserDto: CreateUserDtoV2): Promise<UserResponseDtoV2> {
    const user = await this.usersService.create(createUserDto);
    return this.toV2Response(user);
  }

  private toV2Response(user: any): UserResponseDtoV2 {
    return {
      id: user.id,
      username: user.username,
      email: user.email,
      profile: {
        firstName: user.firstName,
        lastName: user.lastName,
        avatar: user.avatar,
        bio: user.bio,
      },
      metadata: {
        createdAt: user.createdAt,
        updatedAt: user.updatedAt,
        lastLoginAt: user.lastLoginAt,
      },
    };
  }
}

3. Header-Based Versioning​

// shared/common/src/decorators/api-version.decorator.ts
import { SetMetadata } from '@nestjs/common';

export const API_VERSION_KEY = 'apiVersion';
export const ApiVersion = (version: string) => SetMetadata(API_VERSION_KEY, version);
// shared/common/src/guards/api-version.guard.ts
import { Injectable, CanActivate, ExecutionContext, BadRequestException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { API_VERSION_KEY } from '../decorators/api-version.decorator';

@Injectable()
export class ApiVersionGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredVersion = this.reflector.getAllAndOverride<string>(API_VERSION_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    if (!requiredVersion) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const version = request.headers['accept-version'] || request.headers['api-version'];

    if (!version) {
      throw new BadRequestException('API version is required');
    }

    if (version !== requiredVersion) {
      throw new BadRequestException(`API version ${requiredVersion} is required`);
    }

    return true;
  }
}
// Usage example
@Controller('users')
@UseGuards(ApiVersionGuard)
export class UsersController {

  async findAllV1(): Promise<UserResponseDtoV1[]> {
    // V1 implementation
  }

  @Get()
  @ApiVersion('v2')
  async findAllV2(): Promise<UserResponseDtoV2[]> {
    // V2 implementation
  }
}

4. Content Negotiation Versioning​

// shared/common/src/interceptors/content-negotiation.interceptor.ts
import { Injectable, NestInterceptor, ExecutionContext, CallHandler, NotAcceptableException } from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

@Injectable()
export class ContentNegotiationInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const request = context.switchToHttp().getRequest();
    const accept = request.headers['accept'];

    // Parse accept header for version
    const versionMatch = accept?.match(/version=(\d+)/);
    const version = versionMatch ? parseInt(versionMatch[1]) : 1;

    request.apiVersion = version;

    return next.handle().pipe(
      map((data) => {
        // Transform response based on version
        return this.transformResponse(data, version);
      }),
    );
  }

  private transformResponse(data: any, version: number): any {
    switch (version) {
      case 1:
        return this.toV1Format(data);
      case 2:
        return this.toV2Format(data);
      default:
        throw new NotAcceptableException(`API version ${version} is not supported`);
    }
  }

  private toV1Format(data: any): any {
    // Transform to V1 format
    return data;
  }

  private toV2Format(data: any): any {
    // Transform to V2 format
    return data;
  }
}

3. Backward Compatible Schema Changes​

// migrations/1700200000000-AddUserStatusBackwardCompatible.ts
import { MigrationInterface, QueryRunner, TableColumn } from 'typeorm';

export class AddUserStatusBackwardCompatible1700200000000 implements MigrationInterface {
  public async up(queryRunner: QueryRunner): Promise<void> {
    // Add new column as nullable first
    await queryRunner.addColumn(
      'users',
      new TableColumn({
        name: 'status',
        type: 'varchar',
        length: '20',
        isNullable: true,
        default: null,
      }),
    );

    // Backfill data for existing rows
    await queryRunner.query(`
      UPDATE users 
      SET status = 'active' 
      WHERE status IS NULL
    `);

    // Make column non-nullable after backfill
    await queryRunner.changeColumn(
      'users',
      'status',
      new TableColumn({
        name: 'status',
        type: 'varchar',
        length: '20',
        isNullable: false,
        default: "'active'",
      }),
    );

    // Add index for better query performance
    await queryRunner.query(`
      CREATE INDEX idx_users_status ON users(status)
    `);
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`DROP INDEX idx_users_status`);
    await queryRunner.dropColumn('users', 'status');
  }
}

// shared/events/src/publishers/user-event.publisher.ts
import { Injectable, Logger } from '@nestjs/common';
import { ClientKafka } from '@nestjs/microservices';
import { UserEventsV1 } from '../schemas/user.events.v1';
import { UserEventsV2 } from '../schemas/user.events.v2';

@Injectable()
export class UserEventPublisher {
  private readonly logger = new Logger(UserEventPublisher.name);

  constructor(private readonly kafkaClient: ClientKafka) {}

  async publishUserCreatedV1(event: UserEventsV1.UserCreated): Promise<void> {
    await this.publish('user.events.v1', event);
  }

  async publishUserCreatedV2(event: UserEventsV2.UserCreated): Promise<void> {
    await this.publish('user.events.v2', event);
  }

  private async publish(topic: string, event: any): Promise<void> {
    try {
      await this.kafkaClient.emit(topic, {
        key: event.data.userId,
        value: JSON.stringify(event),
        headers: {
          version: event.version,
          eventType: event.eventType,
          timestamp: event.timestamp,
        },
      });

      this.logger.debug(`Event published to ${topic}:`, event.eventType);
    } catch (error) {
      this.logger.error(`Failed to publish event to ${topic}:`, error);
      throw error;
    }
  }
}

import { UserEventsV1 } from '@ecommerce/events/schemas/user.events.v1';
import { UserEventsV2 } from '@ecommerce/events/schemas/user.events.v2';
import { NotificationService } from '../services/notification.service';

@Controller()
export class UserEventConsumer {
  constructor(private readonly notificationService: NotificationService) {}

  @EventPattern('user.events.v1')
  async handleUserEventsV1(@Payload() message: any, @Ctx() context: KafkaContext): Promise<void> {
    const event = JSON.parse(message.value);
    const version = message.headers?.version || event.version;

    switch (event.eventType) {
      case 'user.created':
        await this.handleUserCreatedV1(event as UserEventsV1.UserCreated);
        break;
      case 'user.updated':
        await this.handleUserUpdatedV1(event as UserEventsV1.UserUpdated);
        break;
    }
  }

  @EventPattern('user.events.v2')
  async handleUserEventsV2(@Payload() message: any, @Ctx() context: KafkaContext): Promise<void> {

      case 'user.created':
        await this.handleUserCreatedV2(event as UserEventsV2.UserCreated);

      case 'user.profile.updated':

Schema Registry Implementation​

1. Confluent Schema Registry Integration​

// shared/schema-registry/src/schema-registry.service.ts
import { Injectable, Logger } from '@nestjs/common';
import { SchemaRegistry, SchemaType } from '@kafkajs/confluent-schema-registry';

@Injectable()
export class SchemaRegistryService {
  private readonly logger = new Logger(SchemaRegistryService.name);
  private registry: SchemaRegistry;

  constructor() {
    this.registry = new SchemaRegistry({
      host: process.env.SCHEMA_REGISTRY_URL || 'http://schema-registry:8081',
    });
  }

  async registerSchema(subject: string, schema: any): Promise<number> {
    try {
      const { id } = await this.registry.register(
        {
          type: SchemaType.AVRO,
          schema: JSON.stringify(schema),
        },
        { subject },
      );

      this.logger.log(`Schema registered for subject ${subject} with ID ${id}`);
      return id;
    } catch (error) {
      this.logger.error(`Failed to register schema for ${subject}:`, error);
      throw error;
    }
  }

  async getSchema(id: number): Promise<any> {
    try {
      return await this.registry.getSchema(id);
    } catch (error) {
      this.logger.error(`Failed to get schema ${id}:`, error);
      throw error;
    }
  }

  async getLatestSchema(subject: string): Promise<any> {
    try {
      return await this.registry.getLatestSchemaId(subject);
    } catch (error) {
      this.logger.error(`Failed to get latest schema for ${subject}:`, error);
      throw error;
    }
  }

  async encode(subject: string, data: any): Promise<Buffer> {
    try {
      return await this.registry.encode(await this.getLatestSchema(subject), data);
    } catch (error) {
      this.logger.error(`Failed to encode data for ${subject}:`, error);
      throw error;
    }
  }

  async decode(buffer: Buffer): Promise<any> {
    try {
      return await this.registry.decode(buffer);
    } catch (error) {
      this.logger.error('Failed to decode buffer:', error);
      throw error;
    }
  }

  async checkCompatibility(subject: string, schema: any): Promise<boolean> {
    try {
      const result = await this.registry.checkCompatibility(subject, {
        type: SchemaType.AVRO,
        schema: JSON.stringify(schema),
      });
      return result.compatible;
    } catch (error) {
      this.logger.error(`Failed to check compatibility for ${subject}:`, error);
      throw error;
    }
  }
}

// Strategy: Run both versions simultaneously during migration
@Controller()
export class UsersController {
  constructor(private readonly usersService: UsersService, private readonly metricsService: MetricsService) {}

  @Post()
  async create(@Body() createUserDto: any, @Req() request: Request): Promise<any> {
    const version = this.getVersionFromRequest(request);

    // Publish metrics to track version usage
    this.metricsService.recordApiVersionUsage('users.create', version);

    if (version === 'v1') {
      return this.createV1(createUserDto);
    } else if (version === 'v2') {
      return this.createV2(createUserDto);
    }

    throw new BadRequestException('Unsupported API version');
  }

  private async createV1(dto: CreateUserDtoV1): Promise<UserResponseDtoV1> {
    const user = await this.usersService.create({
      username: dto.username,
      email: dto.email,
      password: dto.password,
    });

    return {
      id: user.id,
      username: user.username,
      email: user.email,
      createdAt: user.createdAt,
    };
  }

  private async createV2(dto: CreateUserDtoV2): Promise<UserResponseDtoV2> {
    const user = await this.usersService.create({
      username: dto.username,
      email: dto.email,
      password: dto.password,
      firstName: dto.profile?.firstName,
      lastName: dto.profile?.lastName,
      avatar: dto.profile?.avatar,
      bio: dto.profile?.bio,
    });

    return {
      id: user.id,
      username: user.username,
      email: user.email,
      profile: {
        firstName: user.firstName,
        lastName: user.lastName,
        avatar: user.avatar,
        bio: user.bio,
      },
      metadata: {
        createdAt: user.createdAt,
        updatedAt: user.updatedAt,

@Injectable()
export class UsersService {
  async update(id: string, updateDto: UpdateUserDto): Promise<User> {
    const user = await this.usersRepository.findOne({ where: { id } });

    // Write to both old and new columns during transition
    if (updateDto.firstName) {
      user.first_name = updateDto.firstName; // Old column
      user.first_name_new = updateDto.firstName; // New column
    }

    if (updateDto.lastName) {
      user.last_name = updateDto.lastName; // Old column
      user.last_name_new = updateDto.lastName; // New column
    }

    return await this.usersRepository.save(user);
  }
}

3. Deprecation Strategy​

// shared/common/src/decorators/deprecated.decorator.ts
import { SetMetadata } from '@nestjs/common';

export const DEPRECATED_KEY = 'deprecated';

export interface DeprecationInfo {
  version: string;
  deprecatedAt: string;
  sunsetDate?: string;
  replacement?: string;
  message?: string;
}

export const Deprecated = (info: DeprecationInfo) => SetMetadata(DEPRECATED_KEY, info);
// shared/common/src/interceptors/deprecation.interceptor.ts
import { Injectable, NestInterceptor, ExecutionContext, CallHandler, Logger } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Observable } from 'rxjs';
import { tap } from 'rxjs/operators';
import { DEPRECATED_KEY, DeprecationInfo } from '../decorators/deprecated.decorator';

@Injectable()
export class DeprecationInterceptor implements NestInterceptor {
  private readonly logger = new Logger(DeprecationInterceptor.name);

  constructor(private reflector: Reflector) {}

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const deprecationInfo = this.reflector.getAllAndOverride<DeprecationInfo>(DEPRECATED_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    if (deprecationInfo) {
      const response = context.switchToHttp().getResponse();
      const request = context.switchToHttp().getRequest();

      // Add deprecation headers
      response.setHeader('Deprecation', 'true');
      response.setHeader('Sunset', deprecationInfo.sunsetDate || '');

      if (deprecationInfo.replacement) {
        response.setHeader('Link', `<${deprecationInfo.replacement}>; rel="alternate"`);
      }

      // Log deprecation usage
      this.logger.warn(
        `Deprecated API called: ${request.method} ${request.url} - ${deprecationInfo.message || 'No message'}`,
      );

      // Send warning in response body
      return next.handle().pipe(
        tap((data) => {
          if (data && typeof data === 'object') {
            data._deprecation = {
              version: deprecationInfo.version,
              deprecatedAt: deprecationInfo.deprecatedAt,
              sunsetDate: deprecationInfo.sunsetDate,
              replacement: deprecationInfo.replacement,
              message: deprecationInfo.message,
            };
          }
        }),
      );
    }

    return next.handle();
  }
}

  })

Best Practices​

1. Versioning Guidelines​

✅ Do:

  • Use semantic versioning (MAJOR.MINOR.PATCH)
  • Version at the resource level (not globally)
  • Document all breaking changes
  • Provide migration guides
  • Support at least 2 versions simultaneously
  • Give deprecation notices well in advance (6-12 months)
  • Monitor version usage with metrics

❌ Don't:

  • Break backward compatibility without notice
  • Remove old versions without migration path
  • Version every small change
  • Use vague version names
  • Skip version documentation

2. Schema Evolution​

✅ Do:

  • Add new fields as optional/nullable
  • Use default values for new required fields
  • Maintain backward compatibility
  • Test schema migrations thoroughly
  • Use database migration tools
  • Version your schemas
  • Document schema changes

❌ Don't:

  • Remove fields without deprecation period
  • Change field types directly
  • Add required fields without defaults
  • Skip migration rollback scripts
  • Modify data without backups

3. Contract Management​

✅ Do:

  • Use contract testing (Pact, etc.)
  • Define clear API contracts
  • Version message schemas
  • Use schema registries for events
  • Validate contracts in CI/CD
  • Share contracts between services
  • Monitor contract violations

❌ Don't:

  • Change contracts without versioning
  • Skip contract tests
  • Assume consumers are updated
  • Deploy breaking changes without coordination

4. Migration Strategy​

✅ Do:

  • Use expand-contract pattern
  • Run versions in parallel during migration
  • Monitor version usage
  • Communicate changes to stakeholders
  • Provide adequate deprecation notice
  • Test migrations in staging
  • Have rollback plans

❌ Don't:

  • Force immediate migrations
  • Remove old versions prematurely
  • Skip communication
  • Migrate without metrics
  • Ignore edge cases

5. Documentation​

✅ Do:

  • Document all API versions
  • Maintain changelog
  • Provide migration guides
  • Include examples for each version
  • Document deprecation timeline
  • Use OpenAPI/Swagger specs
  • Keep documentation up-to-date

❌ Don't:

  • Assume self-documenting code
  • Skip version documentation
  • Forget to update examples
  • Leave outdated docs

Summary​

Effective schema and contract versioning is essential for:

  • Independent deployments - Services can evolve independently
  • Backward compatibility - Existing clients continue to work
  • Smooth migrations - Gradual transitions without downtime
  • Clear communication - Stakeholders know what to expect
  • Quality assurance - Contract tests prevent breaking changes

Choose versioning strategies based on your needs:

  • URI versioning for clear separation
  • Header versioning for cleaner URLs
  • Content negotiation for fine-grained control
  • Expand-contract pattern for database migrations
  • Parallel running for risk-free transitions

Remember: The cost of versioning is far less than the cost of breaking production!
