BASE Properties in Distributed Systems

Overview​

BASE is an alternative to ACID properties, designed for distributed systems and NoSQL databases where high availability and partition tolerance are prioritized over strong consistency. BASE stands for Basically Available, Soft state, and Eventual consistency.

While ACID guarantees immediate consistency, BASE accepts temporary inconsistencies in exchange for better availability and performance in distributed environments.

BASE vs ACID​

AspectACIDBASE
ConsistencyStrong, immediateEventual, delayed
AvailabilityMay sacrifice for consistencyAlways available
Partition ToleranceLimitedHigh
Data ModelRelationalFlexible (NoSQL)
Use CasesBanking, transactionsSocial media, analytics
Example DBsPostgreSQL, MySQLMongoDB, Cassandra, DynamoDB

CAP Theorem Context​

BASE emerges from the CAP theorem, which states you can only have 2 of 3:

  • Consistency - All nodes see the same data
  • Availability - System always responds
  • Partition tolerance - System works despite network failures

ACID chooses: CP (Consistency + Partition tolerance) BASE chooses: AP (Availability + Partition tolerance)

The Three BASE Properties​

1. Basically Available​

Definition: The system guarantees availability of data even in the face of failures. The system appears to work most of the time, but responses may be stale or incomplete.

Characteristics:​

  • ✅ System always responds to requests
  • ✅ Accepts partial failures
  • ✅ May return stale data
  • ✅ Degrades gracefully

Example: Distributed Product Catalog​

Scenario: E-commerce with product data replicated across 3 regions.

// MongoDB with replica set
import { MongoClient } from 'mongodb';

const client = new MongoClient('mongodb://node1,node2,node3/?replicaSet=rs0');

@Injectable()
export class ProductService {
  private db: Db;

  async getProduct(id: string): Promise<Product> {
    try {
      // Try to read from primary
      const product = await this.db.collection('products')
        .findOne({ _id: id }, { readPreference: 'primary' });
      
      return product;
    } catch (error) {
      // Primary unavailable - read from secondary (may be stale)
      console.warn('Primary unavailable, reading from secondary');
      
      const product = await this.db.collection('products')
        .findOne({ _id: id }, { readPreference: 'secondaryPreferred' });
      
      return product; // Basically available - returns stale data if needed
    }
  }
}

Real-World: Social Media Feed​

// User's feed is always available, even if some nodes are down
@Injectable()
export class FeedService {
  async getUserFeed(userId: string): Promise<Post[]> {
    const regions = ['us-east', 'us-west', 'eu-west'];
    const results: Post[] = [];

    // Try to fetch from all regions
    await Promise.allSettled(
      regions.map(async (region) => {
        try {
          const posts = await this.fetchFromRegion(region, userId);
          results.push(...posts);
        } catch (error) {
          // Region failed - continue with others
          console.warn(`Region ${region} unavailable`);
        }
      })
    );

    // Return whatever we got - basically available
    return results.length > 0 ? results : this.getCachedFeed(userId);
  }
}

2. Soft State​

Definition: The state of the system may change over time, even without new input, due to eventual consistency. Data is not expected to be immediately consistent across all nodes.

Characteristics:​

  • 🔄 State can change without user action
  • 🔄 Temporary inconsistencies allowed
  • 🔄 Background synchronization processes
  • 🔄 No guarantee of instant propagation

Example: Shopping Cart Synchronization​

import { Injectable } from '@nestjs/common';
import { InjectRedis } from '@nestjs/redis';
import Redis from 'ioredis';

@Injectable()
export class CartService {
  constructor(
    @InjectRedis() private redis: Redis,
    private eventBus: EventBus,
  ) {}

  async addToCart(userId: string, productId: string, quantity: number): Promise<void> {
    const cartKey = `cart:${userId}`;
    
    // 1. Update local cache immediately (fast response)
    await this.redis.hset(cartKey, productId, quantity);
    
    // 2. Emit event for async synchronization to other nodes
    this.eventBus.publish('cart.updated', {
      userId,
      productId,
      quantity,
      timestamp: Date.now(),
    });
    
    // 3. Schedule background sync to database (soft state)
    await this.scheduleSync(userId);
  }

  private async scheduleSync(userId: string): Promise<void> {
    // Sync happens asynchronously
    setTimeout(async () => {
      const cart = await this.redis.hgetall(`cart:${userId}`);
      await this.syncToDatabase(userId, cart);
    }, 5000); // 5 second delay - soft state period
  }

  private async syncToDatabase(userId: string, cart: Record<string, string>): Promise<void> {
    // Eventually consistent write to permanent storage
    await this.cartRepository.upsert({
      userId,
      items: cart,
      lastSynced: new Date(),
    });
  }
}

Example: Like Counter​

// Like counts don't need to be immediately consistent
@Injectable()
export class LikeService {
  async likePost(postId: string, userId: string): Promise<void> {
    // 1. Update Redis counter immediately
    await this.redis.incr(`likes:${postId}`);
    
    // 2. Add to likes set
    await this.redis.sadd(`liked:${userId}`, postId);
    
    // 3. Queue database update (soft state - happens later)
    await this.queue.add('sync-likes', {
      postId,
      userId,
      action: 'like',
    }, {
      delay: 10000, // 10 second delay
    });
  }

  async getLikeCount(postId: string): Promise<number> {
    // Might be out of sync with database
    const count = await this.redis.get(`likes:${postId}`);
    return count ? parseInt(count, 10) : 0;
  }
}

3. Eventual Consistency​

Definition: The system will eventually reach a consistent state, given enough time without new updates. All nodes will have the same data eventually, but not immediately.

Characteristics:​

  • ⏱️ Consistency achieved over time
  • ⏱️ No guarantee when consistency will occur
  • ⏱️ Replicas may temporarily disagree
  • ⏱️ Conflict resolution strategies needed

Example: Multi-Region User Profile​

import { DynamoDB } from '@aws-sdk/client-dynamodb';
import { DynamoDBDocument } from '@aws-sdk/lib-dynamodb';

@Injectable()
export class UserProfileService {
  private dynamoDB: DynamoDBDocument;

  async updateProfile(userId: string, updates: Partial<UserProfile>): Promise<void> {
    // Write to primary region
    await this.dynamoDB.update({
      TableName: 'users',
      Key: { userId },
      UpdateExpression: 'SET #name = :name, #email = :email',
      ExpressionAttributeNames: {
        '#name': 'name',
        '#email': 'email',
      },
      ExpressionAttributeValues: {
        ':name': updates.name,
        ':email': updates.email,
      },
    });

    // DynamoDB automatically replicates to other regions
    // But replicas will be eventually consistent (may take seconds)
  }

  async getProfile(userId: string, consistentRead = false): Promise<UserProfile> {
    const result = await this.dynamoDB.get({
      TableName: 'users',
      Key: { userId },
      ConsistentRead: consistentRead, // false = eventually consistent (faster)
    });

    return result.Item as UserProfile;
  }
}

Cassandra Example with Tunable Consistency​

import { Client } from 'cassandra-driver';

@Injectable()
export class AnalyticsService {
  private client: Client;

  async writeEvent(event: AnalyticsEvent): Promise<void> {
    const query = 'INSERT INTO events (id, user_id, event_type, data) VALUES (?, ?, ?, ?)';
    
    // Write with ONE consistency (fast, eventually consistent)
    await this.client.execute(query, 
      [event.id, event.userId, event.type, event.data],
      { consistency: types.consistencies.one } // Eventually consistent
    );
  }

  async getEvents(userId: string, needsConsistency = false): Promise<AnalyticsEvent[]> {
    const query = 'SELECT * FROM events WHERE user_id = ?';
    
    const consistency = needsConsistency 
      ? types.consistencies.quorum  // Strong consistency (slower)
      : types.consistencies.one;     // Eventual consistency (faster)

    const result = await this.client.execute(query, [userId], { consistency });
    return result.rows;
  }
}

Conflict Resolution Strategies​

When multiple nodes update the same data concurrently, conflicts arise. BASE systems need strategies to resolve them.

1. Last Write Wins (LWW)​

interface VersionedData {
  value: string;
  timestamp: number;
  nodeId: string;
}

class LastWriteWinsResolver {
  resolve(local: VersionedData, remote: VersionedData): VersionedData {
    if (remote.timestamp > local.timestamp) {
      return remote; // Remote is newer
    } else if (remote.timestamp === local.timestamp) {
      // Tie-breaker using node ID
      return remote.nodeId > local.nodeId ? remote : local;
    }
    return local; // Local is newer
  }
}

// Example usage
@Injectable()
export class DistributedCacheService {
  async updateValue(key: string, value: string): Promise<void> {
    const timestamp = Date.now();
    const nodeId = process.env.NODE_ID;

    await this.redis.hset(key, {
      value,
      timestamp,
      nodeId,
    });

    // Replicate to other nodes with metadata
    await this.replicateToOtherNodes(key, { value, timestamp, nodeId });
  }

  async reconcile(key: string, incoming: VersionedData): Promise<void> {
    const local = await this.redis.hgetall(key) as VersionedData;
    
    const resolver = new LastWriteWinsResolver();
    const winner = resolver.resolve(local, incoming);

    if (winner !== local) {
      await this.redis.hset(key, winner);
    }
  }
}

2. Vector Clocks​

interface VectorClock {
  [nodeId: string]: number;
}

class VectorClockResolver {
  increment(clock: VectorClock, nodeId: string): VectorClock {
    return {
      ...clock,
      [nodeId]: (clock[nodeId] || 0) + 1,
    };
  }

  compare(clock1: VectorClock, clock2: VectorClock): 'before' | 'after' | 'concurrent' {
    const keys = new Set([...Object.keys(clock1), ...Object.keys(clock2)]);
    
    let clock1Greater = false;
    let clock2Greater = false;

    for (const key of keys) {
      const v1 = clock1[key] || 0;
      const v2 = clock2[key] || 0;

      if (v1 > v2) clock1Greater = true;
      if (v2 > v1) clock2Greater = true;
    }

    if (clock1Greater && !clock2Greater) return 'after';
    if (clock2Greater && !clock1Greater) return 'before';
    return 'concurrent'; // Conflict!
  }

  merge(clock1: VectorClock, clock2: VectorClock): VectorClock {
    const keys = new Set([...Object.keys(clock1), ...Object.keys(clock2)]);
    const merged: VectorClock = {};

    for (const key of keys) {
      merged[key] = Math.max(clock1[key] || 0, clock2[key] || 0);
    }

    return merged;
  }
}

3. Application-Specific Resolution​

// E-commerce: Merge cart items from different sessions
@Injectable()
export class CartMergeService {
  mergeCart items(local: CartItem[], remote: CartItem[]): CartItem[] {
    const merged = new Map<string, CartItem>();

    // Add local items
    local.forEach(item => merged.set(item.productId, item));

    // Merge remote items
    remote.forEach(remoteItem => {
      const localItem = merged.get(remoteItem.productId);
      
      if (!localItem) {
        merged.set(remoteItem.productId, remoteItem);
      } else {
        // Conflict resolution: sum quantities
        merged.set(remoteItem.productId, {
          ...localItem,
          quantity: localItem.quantity + remoteItem.quantity,
        });
      }
    });

    return Array.from(merged.values());
  }
}

Real-World BASE Examples​

1. Social Media Platform​

@Injectable()
export class SocialMediaService {
  // Basically Available: Feed always loads
  async getFeed(userId: string): Promise<Post[]> {
    try {
      return await this.primaryDB.find({ followers: userId }).limit(50);
    } catch (error) {
      // Fallback to cache - may be stale
      return await this.cache.get(`feed:${userId}`) || [];
    }
  }

  // Soft State: Follower count updates asynchronously
  async followUser(followerId: string, followedId: string): Promise<void> {
    // Immediate acknowledgment
    await this.redis.sadd(`following:${followerId}`, followedId);
    
    // Increment counter (soft state)
    await this.redis.incr(`followers:${followedId}`);
    
    // Queue database sync (eventual consistency)
    await this.queue.add('sync-follow', { followerId, followedId });
  }

  // Eventual Consistency: Like counts sync eventually
  async likePost(postId: string, userId: string): Promise<void> {
    // Fast response
    await this.redis.incr(`likes:${postId}`);
    await this.redis.sadd(`liked:${userId}`, postId);
    
    // Sync to database later (0-30 seconds delay)
    this.scheduleSync(postId);
  }
}

2. DNS System​

// DNS is fundamentally a BASE system
class DNSService {
  async updateDNSRecord(domain: string, ip: string, ttl: number): Promise<void> {
    // Update authoritative server
    await this.authoritativeServer.update(domain, ip, ttl);
    
    // Eventually propagates to all DNS servers worldwide
    // Can take minutes to hours (TTL-dependent)
  }

  async resolveomain(domain: string): Promise<string> {
    // May return old IP until propagation completes
    const cached = await this.cache.get(domain);
    if (cached) return cached; // Possibly stale

    const ip = await this.queryAuthoritativeServer(domain);
    await this.cache.set(domain, ip, ttl);
    
    return ip;
  }
}

3. Content Delivery Network (CDN)​

@Injectable()
export class CDNService {
  async updateContent(path: string, content: Buffer): Promise<void> {
    // Update origin server
    await this.originServer.write(path, content);
    
    // Invalidate edge caches (eventually consistent)
    await this.invalidateCache(path);
    
    // Edge servers will fetch new content on next request
    // Old content may be served for minutes
  }

  async getContent(path: string): Promise<Buffer> {
    // Try edge server (fast, may be stale)
    const cached = await this.edgeServer.read(path);
    if (cached) return cached;

    // Fetch from origin (slow, consistent)
    const content = await this.originServer.read(path);
    
    // Cache at edge (soft state)
    await this.edgeServer.write(path, content);
    
    return content;
  }
}

MongoDB Example: Read/Write Concerns​

import { MongoClient, WriteConcern, ReadPreference } from 'mongodb';

@Injectable()
export class MongoDBService {
  private client: MongoClient;

  // BASE: Write to primary, don't wait for replication
  async createPost(post: Post): Promise<void> {
    await this.client.db().collection('posts').insertOne(post, {
      writeConcern: { w: 1 }, // Don't wait for replicas
    });
    // Post written locally, eventually consistent across replicas
  }

  // Read from secondary (eventually consistent)
  async getPosts(userId: string): Promise<Post[]> {
    return await this.client.db().collection('posts')
      .find({ userId })
      .setReadPreference(ReadPreference.SECONDARY_PREFERRED)
      .toArray();
    // May read stale data, but faster and more available
  }

  // Strong consistency when needed
  async getAccountBalance(userId: string): Promise<number> {
    const result = await this.client.db().collection('accounts')
      .findOne({ userId }, {
        readPreference: ReadPreference.PRIMARY,
        readConcern: { level: 'majority' },
      });
    return result.balance;
  }
}

Best Practices​

1. Choose BASE When:​

✅ High availability is critical ✅ Can tolerate temporary inconsistencies ✅ Dealing with large-scale distributed systems ✅ Read-heavy workloads ✅ Partitions across geographic regions

Examples:

  • Social media feeds
  • Product catalogs
  • Analytics dashboards
  • Content delivery
  • Caching systems

2. Avoid BASE When:​

❌ Financial transactions ❌ Inventory management ❌ Booking systems (double-booking risk) ❌ Medical records ❌ Legal documents

Use ACID instead!

3. Hybrid Approach​

@Injectable()
export class HybridDataService {
  async processOrder(order: Order): Promise<void> {
    // ACID: Critical financial data
    await this.postgresDB.transaction(async (trx) => {
      await trx('orders').insert(order);
      await trx('inventory').decrement('stock', order.quantity);
      await trx('payments').insert(order.payment);
    });

    // BASE: Non-critical data (eventual consistency OK)
    await this.mongoDBanalytics').insertOne({
      orderId: order.id,
      timestamp: new Date(),
      items: order.items,
    }, {
      writeConcern: { w: 1 }, // BASE approach
    });

    // Update cache (soft state)
    await this.redis.set(`order:${order.id}`, JSON.stringify(order), 'EX', 3600);
  }
}

4. Design for Eventual Consistency​

// Show pending state in UI
interface Post {
  id: string;
  content: string;
  status: 'pending' | 'published';
  syncStatus: 'syncing' | 'synced';
}

@Injectable()
export class PostService {
  async createPost(content: string, userId: string): Promise<Post> {
    const post: Post = {
      id: uuid(),
      content,
      status: 'pending',
      syncStatus: 'syncing',
    };

    // Immediate local write
    await this.localDB.insert(post);

    // Async replication
    this.replicateToCluster(post).then(() => {
      post.syncStatus = 'synced';
      post.status = 'published';
    });

    return post; // Return immediately with pending status
  }
}

5. Monitor Consistency Lag​

@Injectable()
export class ConsistencyMonitorService {
  async checkReplicationLag(): Promise<number> {
    // MongoDB
    const replicationInfo = await this.admin.replSetGetStatus();
    const lag = replicationInfo.members
      .filter(m => m.stateStr === 'SECONDARY')
      .map(m => Date.now() - m.optimeDate.getTime());

    const maxLag = Math.max(...lag);
    
    if (maxLag > 10000) { // 10 seconds
      this.logger.warn(`High replication lag: ${maxLag}ms`);
    }

    return maxLag;
  }
}

Summary​

BASE Properties:

PropertyMeaningExample
Basically AvailableSystem always respondsCDN returns cached content during origin failure
Soft StateData changes without inputShopping cart syncs in background
Eventual ConsistencyConverges over timeFollower count updates across datacenters

Key Takeaways:

  • 🌐 BASE enables global-scale distributed systems
  • ⚖️ Trades immediate consistency for availability
  • ⏱️ Accept temporary inconsistencies
  • 🛠️ Requires conflict resolution strategies
  • 🎯 Choose based on business requirements
  • 🔄 Hybrid ACID+BASE approach often best

Remember: BASE doesn't mean "broken" - it's a deliberate trade-off for building systems that can serve billions of users across the globe with high availability!
