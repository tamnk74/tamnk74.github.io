Hadoop and Apache Spark Guide

Overview​

Apache Hadoop and Apache Spark are the cornerstones of the modern Big Data ecosystem. While they are often mentioned together, they serve different purposes and have evolved to work complementarily.

Apache Hadoop​

Hadoop is an open-source framework that allows for the distributed processing of large data sets across clusters of computers using simple programming models. It is designed to scale up from single servers to thousands of machines.

  • HDFS (Hadoop Distributed File System): The storage layer. It splits files into blocks and distributes them across nodes, ensuring high availability through replication.
  • YARN (Yet Another Resource Negotiator): The resource management layer. It schedules jobs and manages cluster resources.
  • MapReduce: The original processing engine (disk-based, slower).

Apache Spark​

Spark is a unified analytics engine for large-scale data processing. It was designed to address the limitations of Hadoop MapReduce.

  • In-Memory Processing: Spark processes data in RAM, making it up to 100x faster than MapReduce for certain workloads.
  • Unified Engine: Supports SQL, streaming, machine learning, and graph processing.
  • Interoperability: Spark can run on Hadoop YARN, Kubernetes, or standalone, and can read from HDFS, S3, Cassandra, and more.

Top 10 Common Use Cases and Architectures​

1. ETL (Extract, Transform, Load) at Scale​

  • Use Case: Cleaning, transforming, and moving terabytes of logs or user data from raw storage to a data warehouse.
  • Architecture: Raw Data (S3/HDFS) -> Spark Job (Cleanse/Format) -> Parquet/Delta Lake -> Data Warehouse (BigQuery/Snowflake)

2. Stream Processing (Near Real-Time)​

  • Use Case: Fraud detection in banking transactions or IoT sensor monitoring.
  • Architecture: Kafka (Ingest) -> Spark Structured Streaming -> NoSQL DB (HBase/Cassandra)

3. Machine Learning Pipelines​

  • Use Case: Training recommendation models on user behavior history.
  • Architecture: Feature Engineering (Spark SQL) -> Model Training (Spark MLlib) -> Model Registry (MLflow)

4. Interactive Data Analytics​

  • Use Case: Data scientists running ad-hoc SQL queries on petabytes of data.
  • Architecture: Spark SQL (via Jupyter Notebooks) -> HDFS/S3

5. Log Aggregation and Analysis​

  • Use Case: Analyzing server logs to detect security breaches or system errors.
  • Architecture: Filebeat -> Kafka -> Spark -> Elasticsearch -> Kibana (ELK Stack + Spark)

6. Graph Processing​

  • Use Case: Social network analysis (finding influencers) or fraud rings.
  • Architecture: Spark GraphX applied to relationship data stored in HDFS.

7. Data Warehousing Offloading​

  • Use Case: Moving expensive, heavy transformations out of a traditional warehouse to cheaper commodity hardware.
  • Architecture: Enterprise DW -> Spark (Heavy Lift) -> Enterprise DW (Refined Data)

8. IoT Data Processing​

  • Use Case: Aggregating data from millions of smart meters.
  • Architecture: MQTT -> Kafka -> Spark Streaming (Windowed Aggregation) -> Time Series DB

9. Lambda Architecture​

  • Use Case: Systems requiring both real-time views and comprehensive historical accuracy.
  • Architecture: Data enters and splits into a Speed Layer (Spark Streaming) and a Batch Layer (Hadoop MapReduce or Spark Batch).

10. Data Lakehouse Implementation​

  • Use Case: Combining the best of Data Warehouses and Data Lakes.
  • Architecture: Spark + Delta Lake/Iceberg running on object storage (S3/GCS) to provide ACID transactions on raw data files.

Installation and Integration​

Prerequisites​

  • Java Development Kit (JDK): Version 8 or 11.
  • Python: For PySpark (recommended 3.8+).
  • Scala: If writing native Spark applications (optional for Python users).

Installation (Local/Standalone Mode)​

  1. Download Spark: Visit the Apache Spark Downloads page. Choose "Pre-built for Apache Hadoop".

  2. Extract and Set Environment Variables:

    tar -xvf spark-3.x.x-bin-hadoop3.tgz
    export SPARK_HOME=~/spark-3.x.x-bin-hadoop3
    export PATH=$SPARK_HOME/bin:$PATH

  3. Verify Installation: Run the interactive shell:

    pyspark

Integration with Other Components​

1. Connecting to S3 (AWS)​

Add the Hadoop-AWS dependency jars to your Spark classpath.

conf = SparkConf()
conf.set("spark.hadoop.fs.s3a.access.key", "YOUR_KEY")
conf.set("spark.hadoop.fs.s3a.secret.key", "YOUR_SECRET")
spark = SparkSession.builder.config(conf=conf).getOrCreate()

df = spark.read.parquet("s3a://my-bucket/data/")

2. Connecting to Relational Databases (JDBC)​

Download the JDBC driver (e.g., PostgreSQL jar) and pass it during launch.

pyspark --packages org.postgresql:postgresql:42.2.18
df = spark.read \
    .format("jdbc") \
    .option("url", "jdbc:postgresql://host:port/db") \
    .option("dbtable", "schema.table") \
    .option("user", "user") \
    .option("password", "pass") \
    .load()

3. Connecting to Kafka​

Use the spark-sql-kafka library for structured streaming.

df = spark.readStream \
  .format("kafka") \
  .option("kafka.bootstrap.servers", "host1:port1,host2:port2") \
  .option("subscribe", "topic1") \
  .load()

Best Practices​

Data Optimization​

  1. File Formats: Always prefer columnar formats like Parquet or ORC over CSV or JSON. They allow Spark to skip unnecessary data (predicate pushdown).
  2. Partitioning: Partition data based on query patterns (e.g., year/month/day). Avoid too many small files (small file problem).
  3. Compression: Use Snappy (fast) or Zstd (high compression) to reduce I/O and storage costs.

Performance Tuning​

  1. Serialization: Switch to Kryo serialization instead of Java default for better performance. 
    conf.set("spark.serializer", "org.apache.spark.serializer.KryoSerializer")
  2. Broadcasting: Use broadcast() variables for joining a large table with a small reference table to avoid shuffling data across the network.
  3. Caching: Use .cache() or .persist() only when a dataframe is reused multiple times in the same job. Unpersist when done.

Operational​

  1. Resource Management: Don't allocate all cores to a single executor. A good rule of thumb is 5 cores per executor.
  2. Monitoring: Use the Spark UI (usually localhost:4040) to visualize the DAG (Directed Acyclic Graph) and identify bottlenecks (stages taking too long).

Code Quality​

  1. DataFrame API vs RDD: Stick to the DataFrame/Dataset API. It utilizes the Catalyst Optimizer, which is significantly faster than low-level RDD manipulations.
  2. Testing: Write unit tests for your transformation logic using spark-testing-base or local Spark sessions.
