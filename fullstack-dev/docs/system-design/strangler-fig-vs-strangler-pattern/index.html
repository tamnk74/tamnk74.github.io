Strangler Fig Pattern vs Strangler Pattern

Overview​

When migrating legacy monolithic applications to microservices architecture, two closely related patterns emerge: the Strangler Pattern and the Strangler Fig Pattern. While these terms are often used interchangeably, understanding their nuances can help you choose the right migration strategy for your system.

What is the Strangler Pattern?​

Origin and Concept​

The Strangler Pattern was introduced by Martin Fowler in 2004. It's named after the strangler vines that grow around trees in rainforests, eventually replacing them entirely.

Core Principles​

The Strangler Pattern involves:

  1. Incremental Migration: Gradually replacing functionality rather than doing a complete rewrite
  2. Facade Layer: Creating an abstraction layer that routes requests to either the legacy system or new services
  3. Parallel Running: Both old and new systems coexist during the migration period
  4. Eventual Replacement: The legacy system is eventually fully replaced

Implementation Strategy​

Key Steps:

  1. Identify Migration Boundaries: Select specific features or modules to migrate
  2. Create Facade/Proxy: Implement a routing layer (API Gateway, reverse proxy)
  3. Build New Service: Develop the new microservice for selected functionality
  4. Route Traffic: Configure the facade to route traffic to the new service
  5. Decommission Old Code: Remove the replaced functionality from the legacy system
  6. Repeat: Continue until the entire monolith is replaced

Example Implementation​

// API Gateway routing configuration
const router = express.Router();

// Strangler Pattern routing
router.get('/api/users', (req, res) => {
  // Route to new microservice
  return proxyToNewService('user-service', req, res);
});

router.get('/api/legacy-feature', (req, res) => {
  // Still route to legacy system
  return proxyToLegacySystem(req, res);
});

What is the Strangler Fig Pattern?​

Evolution and Distinction​

The Strangler Fig Pattern is a more specific and modern interpretation of the Strangler Pattern, often associated with cloud-native architectures and popularized by companies like AWS, Microsoft, and cloud architects.

Enhanced Characteristics​

The Strangler Fig Pattern extends the original concept with:

  1. Cloud-Native Focus: Emphasizes cloud services and infrastructure
  2. Event-Driven Architecture: Strong focus on asynchronous communication
  3. Data Migration Strategy: Explicit handling of data synchronization
  4. Anti-Corruption Layer: Protective boundary between old and new systems
  5. Gradual Cutover: More emphasis on feature flags and progressive rollout

Architecture Components​

Implementation Strategy​

Key Components:

  1. API Gateway with Intelligent Routing
  2. Anti-Corruption Layer (ACL)
  3. Data Synchronization Mechanism
  4. Event-Driven Communication
  5. Feature Toggles/Flags
  6. Monitoring and Observability

Example Implementation​

// Strangler Fig Pattern with feature flags
import { FeatureFlag } from './feature-flags';
import { AntiCorruptionLayer } from './acl';

class StranglerFigRouter {
  constructor(private featureFlags: FeatureFlag, private acl: AntiCorruptionLayer) {}

  async handleUserRequest(req: Request, res: Response) {
    const userId = req.params.userId;

    // Check feature flag
    const useNewService = await this.featureFlags.isEnabled('new-user-service', userId);

    if (useNewService) {
      // Route to new microservice
      const userData = await this.newUserService.getUser(userId);
      return res.json(userData);
    } else {
      // Route through ACL to legacy system
      const legacyData = await this.legacySystem.getUser(userId);
      const transformedData = this.acl.transformLegacyUser(legacyData);
      return res.json(transformedData);
    }
  }
}

When to Use Each Pattern​

Use Strangler Pattern When:​

  • ✅ You have a simpler migration path
  • ✅ Your organization is new to microservices
  • ✅ You need a straightforward routing mechanism
  • ✅ Data consistency is not complex
  • ✅ You're not heavily invested in cloud infrastructure
  • ✅ Budget and timeline are constrained

Use Strangler Fig Pattern When:​

  • ✅ Migrating to cloud-native architecture
  • ✅ You need sophisticated rollback capabilities
  • ✅ Data synchronization is critical
  • ✅ You require event-driven communication
  • ✅ You want progressive feature rollout
  • ✅ Your team has microservices expertise
  • ✅ You need fine-grained observability

Implementation Comparison​

Strangler Pattern: Basic Implementation​

// Simple proxy-based strangler
const express = require('express');
const { createProxyMiddleware } = require('http-proxy-middleware');

const app = express();

// Route to new microservice
app.use(
  '/api/v2/orders',
  createProxyMiddleware({
    target: 'http://orders-service:3000',
    changeOrigin: true,
  }),
);

// Route to legacy system
app.use(
  '/api',
  createProxyMiddleware({
    target: 'http://legacy-monolith:8080',
    changeOrigin: true,
  }),
);

app.listen(80);

Strangler Fig Pattern: Advanced Implementation​

// Cloud-native strangler fig with feature flags and ACL
import { APIGateway } from '@aws/api-gateway';
import { FeatureFlags } from '@aws/feature-flags';
import { EventBridge } from '@aws/event-bridge';

class StranglerFigGateway {
  constructor(
    private featureFlags: FeatureFlags,
    private eventBridge: EventBridge,
    private acl: AntiCorruptionLayer,
    private metrics: CloudWatch,
  ) {}

  async routeRequest(request: APIGatewayRequest): Promise<Response> {
    const feature = this.extractFeature(request);
    const userId = request.user.id;

    // Canary deployment: 10% of users
    const useNewService = await this.featureFlags.evaluate({
      flag: `new-${feature}-service`,
      userId,
      rolloutPercentage: 10,
    });

    try {
      let response;

      if (useNewService) {
        // Route to new microservice
        response = await this.callNewService(feature, request);

        // Publish event for downstream services
        await this.eventBridge.publish({
          source: 'new-service',
          detailType: `${feature}.processed`,
          detail: { userId, timestamp: Date.now() },
        });

        this.metrics.recordSuccess('new-service', feature);
      } else {
        // Route through ACL to legacy
        const legacyResponse = await this.callLegacySystem(feature, request);
        response = this.acl.transform(legacyResponse);

        this.metrics.recordSuccess('legacy-system', feature);
      }

      return response;
    } catch (error) {
      // Automatic fallback on error
      this.metrics.recordError(useNewService ? 'new-service' : 'legacy');

      if (useNewService) {
        // Fallback to legacy
        const legacyResponse = await this.callLegacySystem(feature, request);
        return this.acl.transform(legacyResponse);
      }

      throw error;
    }
  }

  private async callNewService(feature: string, request: any) {
    // Call new microservice with retry and circuit breaker
    return await this.serviceClient.call(feature, request, {
      timeout: 5000,
      retries: 3,
      circuitBreaker: true,
    });
  }

  private async callLegacySystem(feature: string, request: any) {
    // Call legacy system
    return await this.legacyClient.call(feature, request);
  }
}

Data Migration Strategies​

Strangler Pattern: Basic Approach​

// Simple data access with migration logic
class UserRepository {
  async getUser(userId) {
    // Try new service first
    try {
      const user = await newUserService.getUser(userId);
      if (user) return user;
    } catch (error) {
      console.warn('New service unavailable, falling back to legacy');
    }

    // Fallback to legacy
    return await legacyDatabase.findUser(userId);
  }
}

Strangler Fig Pattern: Advanced Synchronization​

// Bidirectional data synchronization
class DataSynchronizationService {
  constructor(
    private legacyDB: LegacyDatabase,
    private newDB: NewDatabase,
    private eventBus: EventBus,
    private conflictResolver: ConflictResolver,
  ) {
    this.setupEventHandlers();
  }

  setupEventHandlers() {
    // Listen for changes in new system
    this.eventBus.subscribe('user.updated', async (event) => {
      await this.syncToLegacy(event.data);
    });

    // Listen for changes in legacy system (via CDC)
    this.legacyDB.onChange('users', async (change) => {
      await this.syncToNew(change);
    });
  }

  async syncToLegacy(userData: NewUserData) {
    const legacyFormat = this.acl.transformToLegacy(userData);

    // Check for conflicts
    const existingUser = await this.legacyDB.findUser(userData.id);
    if (this.hasConflict(existingUser, legacyFormat)) {
      const resolved = await this.conflictResolver.resolve(existingUser, legacyFormat);
      await this.legacyDB.updateUser(resolved);
    } else {
      await this.legacyDB.updateUser(legacyFormat);
    }
  }

  async syncToNew(legacyData: LegacyUserData) {
    const newFormat = this.acl.transformToNew(legacyData);
    await this.newDB.upsertUser(newFormat);

    // Publish event
    await this.eventBus.publish('user.synced', {
      userId: legacyData.id,
      source: 'legacy',
    });
  }

  private hasConflict(existing: any, incoming: any): boolean {
    return existing.version > incoming.version;
  }
}

Anti-Corruption Layer (ACL)​

The ACL is a critical component in the Strangler Fig Pattern:

// Anti-Corruption Layer implementation
class UserAntiCorruptionLayer {
  // Transform legacy data to new format
  transformToNew(legacyUser: LegacyUser): NewUser {
    return {
      id: legacyUser.user_id,
      email: legacyUser.email_address,
      profile: {
        firstName: legacyUser.first_name,
        lastName: legacyUser.last_name,
        fullName: `${legacyUser.first_name} ${legacyUser.last_name}`,
      },
      settings: {
        notifications: this.parseNotificationSettings(legacyUser.notification_flags),
        privacy: this.parsePrivacySettings(legacyUser.privacy_level),
      },
      metadata: {
        createdAt: new Date(legacyUser.created_timestamp),
        updatedAt: new Date(legacyUser.modified_timestamp),
        version: legacyUser.record_version,
      },
    };
  }

  // Transform new data to legacy format
  transformToLegacy(newUser: NewUser): LegacyUser {
    return {
      user_id: newUser.id,
      email_address: newUser.email,
      first_name: newUser.profile.firstName,
      last_name: newUser.profile.lastName,
      notification_flags: this.serializeNotificationSettings(newUser.settings.notifications),
      privacy_level: this.serializePrivacySettings(newUser.settings.privacy),
      created_timestamp: newUser.metadata.createdAt.getTime(),
      modified_timestamp: newUser.metadata.updatedAt.getTime(),
      record_version: newUser.metadata.version,
    };
  }

  private parseNotificationSettings(flags: number): NotificationSettings {
    // Convert bit flags to structured settings
    return {
      email: Boolean(flags & 0x01),
      sms: Boolean(flags & 0x02),
      push: Boolean(flags & 0x04),
    };
  }

  private serializeNotificationSettings(settings: NotificationSettings): number {
    let flags = 0;
    if (settings.email) flags |= 0x01;
    if (settings.sms) flags |= 0x02;
    if (settings.push) flags |= 0x04;
    return flags;
  }

  private parsePrivacySettings(level: number): PrivacySettings {
    const levels = ['public', 'friends', 'private'];
    return {
      profile: levels[level] || 'private',
      activity: levels[level] || 'private',
    };
  }

  private serializePrivacySettings(settings: PrivacySettings): number {
    const levels = { public: 0, friends: 1, private: 2 };
    return levels[settings.profile] || 2;
  }
}

Monitoring and Observability​

Strangler Pattern: Basic Monitoring​

// Simple logging and metrics
const monitoringMiddleware = (req, res, next) => {
  const start = Date.now();

  res.on('finish', () => {
    const duration = Date.now() - start;
    const isNewService = req.path.startsWith('/api/v2');

    console.log({
      service: isNewService ? 'new' : 'legacy',
      path: req.path,
      status: res.statusCode,
      duration,
    });
  });

  next();
};

Strangler Fig Pattern: Comprehensive Observability​

// Advanced monitoring with distributed tracing
import { Tracer } from '@opentelemetry/api';
import { CloudWatch } from '@aws-sdk/client-cloudwatch';

class StranglerFigObservability {
  constructor(private tracer: Tracer, private metrics: CloudWatch, private logger: Logger) {}

  async instrumentRequest(request: Request, handler: () => Promise<Response>): Promise<Response> {
    const span = this.tracer.startSpan('strangler-fig-request', {
      attributes: {
        'http.method': request.method,
        'http.path': request.path,
        'user.id': request.user?.id,
      },
    });

    const startTime = Date.now();

    try {
      const response = await handler();

      // Record successful routing
      await this.recordMetric({
        name: 'RequestSuccess',
        value: 1,
        dimensions: [
          { Name: 'Service', Value: response.service },
          { Name: 'Endpoint', Value: request.path },
        ],
      });

      // Record latency
      const duration = Date.now() - startTime;
      await this.recordMetric({
        name: 'RequestDuration',
        value: duration,
        unit: 'Milliseconds',
        dimensions: [{ Name: 'Service', Value: response.service }],
      });

      span.setAttributes({
        'http.status_code': response.statusCode,
        'service.routed_to': response.service,
        'response.from_cache': response.cached || false,
      });

      span.setStatus({ code: 1 }); // OK

      return response;
    } catch (error) {
      // Record error
      await this.recordMetric({
        name: 'RequestError',
        value: 1,
        dimensions: [
          { Name: 'ErrorType', Value: error.name },
          { Name: 'Endpoint', Value: request.path },
        ],
      });

      span.recordException(error);
      span.setStatus({ code: 2, message: error.message }); // ERROR

      this.logger.error('Request failed', {
        error,
        request,
        trace: span.spanContext(),
      });

      throw error;
    } finally {
      span.end();
    }
  }

  private async recordMetric(metric: CloudWatchMetric): Promise<void> {
    await this.metrics.putMetricData({
      Namespace: 'StranglerFig',
      MetricData: [metric],
    });
  }
}

Migration Phases​

Phase 1: Setup and Preparation​

Strangler Pattern:

  • Set up routing layer
  • Identify first feature to migrate
  • Create basic monitoring

Strangler Fig Pattern:

  • Set up API Gateway and feature flags
  • Implement ACL framework
  • Set up event-driven infrastructure
  • Establish comprehensive monitoring
  • Create data synchronization pipeline

Phase 2: First Service Migration​

Strangler Pattern:

// Simple routing for first service
router.use('/api/orders', (req, res, next) => {
  if (req.path === '/new') {
    return proxyToNewService(req, res);
  }
  next();
});

router.use('/api/orders', legacyProxy);

Strangler Fig Pattern:

// Feature-flagged rollout
const orderServiceMigration = {
  flag: 'new-order-service',
  rollout: {
    percentage: 5, // Start with 5%
    userGroups: ['beta-testers'],
    excludedUsers: ['premium-users'], // Be cautious with paying users
  },
  monitoring: {
    errorRateThreshold: 0.01,
    latencyThreshold: 500,
    autoRollback: true,
  },
};

Phase 3: Gradual Expansion​

Strangler Pattern:

  • Migrate additional features one by one
  • Update routing rules
  • Remove old code incrementally

Strangler Fig Pattern:

  • Increase feature flag percentages
  • Add more event-driven interactions
  • Expand data synchronization
  • Monitor A/B testing results
  • Gradually shift traffic

Phase 4: Complete Migration​

Strangler Pattern:

  • Remove routing layer
  • Decommission legacy system
  • Consolidate services

Strangler Fig Pattern:

  • Set feature flags to 100%
  • Decommission data sync
  • Remove ACL
  • Retire legacy system
  • Optimize new architecture

Real-World Examples​

Example 1: E-commerce Platform (Strangler Pattern)​

// Simple strangler for e-commerce
const app = express();

// New product catalog service
app.use('/api/products', async (req, res, next) => {
  try {
    const response = await newProductService.handleRequest(req);
    res.json(response);
  } catch (error) {
    // Fallback to legacy
    next();
  }
});

// Legacy system handles everything else
app.use('/api', legacyProxy);

Example 2: Banking Application (Strangler Fig Pattern)​

// Cloud-native banking migration
class BankingStranglerFig {
  async processTransaction(transaction: Transaction): Promise<Result> {
    const span = this.tracer.startSpan('process-transaction');

    // Check if user is in new system
    const useNewSystem = await this.featureFlags.check({
      flag: 'new-transaction-service',
      userId: transaction.userId,
      context: {
        amount: transaction.amount,
        type: transaction.type,
      },
    });

    if (useNewSystem) {
      try {
        // Process in new event-driven system
        const result = await this.newTransactionService.process(transaction);

        // Publish event
        await this.eventBridge.publish({
          source: 'transaction-service',
          detailType: 'transaction.completed',
          detail: result,
        });

        // Sync to legacy for reporting
        await this.syncToLegacy(result);

        return result;
      } catch (error) {
        // Critical: banking requires automatic fallback
        this.logger.error('New service failed, using legacy', { error });
        return await this.legacyTransactionService.process(transaction);
      }
    } else {
      // Use legacy system
      const result = await this.legacyTransactionService.process(transaction);

      // Sync to new system for future migration
      await this.syncToNew(result);

      return result;
    }
  }
}

Best Practices​

For Both Patterns:​

  1. Start Small: Begin with non-critical features
  2. Monitor Everything: Track errors, latency, and user experience
  3. Plan for Rollback: Always have a way to revert changes
  4. Communicate: Keep stakeholders informed of progress
  5. Test Thoroughly: Both old and new systems must work correctly

Strangler Pattern Specific:​

  1. Keep routing logic simple
  2. Document which features have been migrated
  3. Set clear migration timelines
  4. Minimize the lifetime of the facade layer

Strangler Fig Pattern Specific:​

  1. Invest in feature flag infrastructure
  2. Implement comprehensive observability from day one
  3. Design robust ACL with bidirectional transformation
  4. Use event-driven patterns for loose coupling
  5. Automate rollback based on metrics
  6. Plan data migration strategy carefully
  7. Use canary deployments for gradual rollout

Common Pitfalls​

Strangler Pattern:​

  • ❌ Not planning the routing layer properly
  • ❌ Forgetting to remove deprecated legacy code
  • ❌ Poor error handling during migration
  • ❌ Insufficient testing of both paths

Strangler Fig Pattern:​

  • ❌ Over-engineering the solution
  • ❌ Complex ACL leading to bugs
  • ❌ Data synchronization conflicts
  • ❌ Feature flag sprawl (too many flags)
  • ❌ Inadequate monitoring
  • ❌ Not planning for eventual consistency

Conclusion​

Both the Strangler Pattern and Strangler Fig Pattern provide effective strategies for migrating legacy systems to microservices. The choice between them depends on your specific needs:

Choose Strangler Pattern for:

  • Simpler migrations
  • Smaller teams
  • Limited cloud infrastructure
  • Budget constraints
  • Less complex data requirements

Choose Strangler Fig Pattern for:

  • Cloud-native transformations
  • Large-scale enterprise migrations
  • Complex data synchronization needs
  • Teams with microservices expertise
  • Requirements for sophisticated rollout strategies

Remember: both patterns share the same fundamental principle—gradual, incremental replacement. The Strangler Fig Pattern adds modern cloud-native capabilities, but that complexity isn't always necessary. Choose the approach that matches your organization's capabilities and requirements.
