Uber — Ride-Hailing System Design

A Solution Architect's guide to designing a production-grade ride-hailing platform: real-time geospatial matching, dynamic pricing, trip lifecycle management, and global-scale dispatch at 25 million trips/day.

Problem Statement​

Design a ride-hailing platform that:

  • Matches riders to nearby drivers in <2 s with sub-100 m location precision
  • Handles 25 million trips/day globally across 10,000+ cities
  • Supports real-time location streaming for 5 million concurrent active drivers
  • Computes dynamic surge pricing every 30 s based on supply/demand
  • Achieves 99.99% availability — a 1-minute outage blocks thousands of trips
  • Scales to 10× normal load during peak events (stadiums, concerts, airport rush)

Core Subsystems​

1. Real-Time Location Service​

The most write-heavy component: 5 million drivers send GPS updates every second.

Redis GEO stores driver positions as sorted sets using the geohash score. A single GEORADIUS query returns all available drivers within N km:

// location.service.ts
async getNearbyDrivers(
  lat: number,
  lng: number,
  radiusKm: number,
  vehicleClass: string,
): Promise<NearbyDriver[]> {
  // GEORADIUS drivers {lng} {lat} {radius} km WITHCOORD WITHDIST ASC COUNT 50
  const results = await this.redis.georadius(
    `drivers:available:${vehicleClass}`,
    lng, lat,
    radiusKm, 'km',
    'WITHCOORD', 'WITHDIST', 'ASC', 'COUNT', 50,
  );
  return results.map(([driverId, dist, [dLng, dLat]]) => ({
    driverId: driverId as string,
    distanceKm: parseFloat(dist as string),
    lat: parseFloat(dLat as string),
    lng: parseFloat(dLng as string),
  }));
}

async updateDriverLocation(
  driverId: string,
  lat: number,
  lng: number,
  vehicleClass: string,
): Promise<void> {
  await this.redis.geoadd(`drivers:available:${vehicleClass}`, lng, lat, driverId);
  await this.redis.set(
    `driver:loc:${driverId}`,
    JSON.stringify({ lat, lng, ts: Date.now() }),
    'EX', 30,  // stale if driver hasn't updated in 30 s
  );
}

Scaling: At 5M updates/sec, a single Redis instance is insufficient. Shard by city (one Redis cluster per metro area). City assignment uses a geohash prefix lookup.

2. Matching Engine​

// matching.service.ts
async matchRider(request: RideRequest): Promise<MatchResult> {
  const candidates = await this.location.getNearbyDrivers(
    request.pickupLat, request.pickupLng,
    5,  // 5 km radius
    request.vehicleClass,
  );
  if (candidates.length === 0) {
    return { matched: false, reason: 'NO_DRIVERS_AVAILABLE' };
  }

  // Score: lower ETA = better; adjust for acceptance rate
  const scored = await Promise.all(
    candidates.slice(0, 10).map(async (d) => {
      const eta = await this.eta.compute(d.lat, d.lng, request.pickupLat, request.pickupLng);
      const profile = await this.driver.getProfile(d.driverId);
      return {
        ...d,
        score: eta.minutes * (1 / (profile.acceptanceRate || 0.5)),
      };
    })
  );
  scored.sort((a, b) => a.score - b.score);

  // Dispatch to top candidate with 15 s timeout
  for (const candidate of scored.slice(0, 3)) {
    const accepted = await this.dispatch.offerTrip(candidate.driverId, request, 15_000);
    if (accepted) {
      await this.location.removeFromAvailable(candidate.driverId, request.vehicleClass);
      return { matched: true, driverId: candidate.driverId, eta: candidate.score };
    }
  }
  return { matched: false, reason: 'ALL_DRIVERS_DECLINED' };
}

3. Trip Lifecycle (Finite State Machine)​

// trip.service.ts
async transition(tripId: string, event: TripEvent, actor: Actor): Promise<Trip> {
  const trip = await this.tripRepo.findById(tripId);

  const allowed: Record<TripStatus, TripEvent[]> = {
    REQUESTED:       ['DRIVER_MATCHED', 'RIDER_CANCELLED', 'SYSTEM_CANCELLED'],
    MATCHED:         ['DRIVER_EN_ROUTE', 'DRIVER_CANCELLED'],
    DRIVER_EN_ROUTE: ['DRIVER_ARRIVED', 'DRIVER_CANCELLED'],
    ARRIVED:         ['TRIP_STARTED', 'NO_SHOW_CANCEL'],
    IN_PROGRESS:     ['TRIP_COMPLETED', 'EMERGENCY_CANCEL'],
    COMPLETED:       [],
    CANCELLED:       [],
  };

  if (!allowed[trip.status]?.includes(event)) {
    throw new BadRequestException(
      `Cannot apply ${event} to trip in status ${trip.status}`
    );
  }

  const newStatus = this.nextStatus(event);
  await this.tripRepo.updateStatus(tripId, newStatus);

  // Publish domain event for downstream consumers
  await this.kafka.send('trip-events', {
    type: `trip.${event.toLowerCase()}`,
    tripId,
    riderId:  trip.riderId,
    driverId: trip.driverId,
    status:   newStatus,
    ts:       new Date().toISOString(),
  });

  return { ...trip, status: newStatus };
}

4. Surge Pricing Engine​

Surge is computed every 30 s per geohash cell (precision 6 = ~1.2 km²) based on supply/demand ratio.

// pricing.service.ts
async computeSurge(geohash: string): Promise<number> {
  const [drivers, requests] = await Promise.all([
    this.redis.scard(`available:${geohash}`),       // available drivers in cell
    this.redis.zcount(`requests:${geohash}`, Date.now() - 60_000, '+inf'),  // demand in last 60 s
  ]);

  if (drivers === 0) return 5.0;  // cap at 5×

  const ratio = requests / drivers;

  // Piecewise surge curve
  let multiplier: number;
  if (ratio < 0.5)      multiplier = 1.0;
  else if (ratio < 1.0) multiplier = 1.0 + (ratio - 0.5) * 1.2;
  else if (ratio < 2.0) multiplier = 1.6 + (ratio - 1.0) * 0.8;
  else                  multiplier = Math.min(2.4 + (ratio - 2.0) * 0.3, 5.0);

  // Round to nearest 0.1x and clamp
  multiplier = Math.round(multiplier * 10) / 10;

  await this.redis.setex(`surge:${geohash}`, 60, multiplier.toString());
  return multiplier;
}

async getFareEstimate(
  pickupGeohash: string,
  distanceKm: number,
  durationMin: number,
  vehicleClass: VehicleClass,
): Promise<FareEstimate> {
  const surge = parseFloat(
    (await this.redis.get(`surge:${pickupGeohash}`)) ?? '1.0'
  );

  const rates: Record<VehicleClass, { base: number; perKm: number; perMin: number }> = {
    UberX:     { base: 1.50, perKm: 1.20, perMin: 0.20 },
    UberXL:    { base: 2.50, perKm: 1.80, perMin: 0.30 },
    UberBlack: { base: 8.00, perKm: 3.50, perMin: 0.65 },
  };

  const rate = rates[vehicleClass];
  const baseFare = rate.base + distanceKm * rate.perKm + durationMin * rate.perMin;
  const totalFare = Math.max(baseFare * surge, rate.base * 2);  // minimum fare

  return {
    estimatedFare: Math.round(totalFare * 100) / 100,
    surgeMultiplier: surge,
    currency: 'USD',
    breakdown: {
      baseFare: rate.base,
      distanceCharge: distanceKm * rate.perKm,
      timeCharge: durationMin * rate.perMin,
      surgeCharge: totalFare - baseFare,
    },
  };
}

5. ETA Service​

ETA is computed using a routing engine backed by Google Maps / HERE, with Redis caching for popular origin–destination pairs:

// eta.service.ts
async compute(
  originLat: number, originLng: number,
  destLat: number,   destLng: number,
): Promise<ETAResult> {
  const cacheKey = `eta:${originLat.toFixed(3)},${originLng.toFixed(3)}:${destLat.toFixed(3)},${destLng.toFixed(3)}`;
  const cached = await this.redis.get(cacheKey);
  if (cached) return JSON.parse(cached);

  const result = await this.mapsClient.distanceMatrix({
    origins:      [{ lat: originLat, lng: originLng }],
    destinations: [{ lat: destLat,   lng: destLng   }],
    mode:         'driving',
    departure_time: 'now',
    traffic_model: 'best_guess',
  });

  const element = result.rows[0].elements[0];
  const eta: ETAResult = {
    minutes:    Math.ceil(element.duration_in_traffic.value / 60),
    distanceKm: element.distance.value / 1000,
  };

  // Cache 90 s — traffic changes quickly
  await this.redis.setex(cacheKey, 90, JSON.stringify(eta));
  return eta;
}

Geospatial Strategy: S2 Geometry​

Uber's H3 (Hexagonal Hierarchical Geospatial Index) — or S2 cells — divides the Earth into hierarchical cells for efficient regional queries:

// For city-level sharding and surge zone computation
import { cellToParent, latLngToCell } from 'h3-js';

const RESOLUTION = 9;   // ~0.1 km² per cell — driver proximity
const SURGE_RES  = 7;   // ~5 km² per surge zone

function getDriverCell(lat: number, lng: number): string {
  return latLngToCell(lat, lng, RESOLUTION);
}

function getSurgeCell(lat: number, lng: number): string {
  return latLngToCell(lat, lng, SURGE_RES);
}

// Compact key for Redis sharding — first 4 chars = metro area prefix
function getCityShard(lat: number, lng: number): string {
  return latLngToCell(lat, lng, 4).slice(0, 4);
}

WebSocket Architecture (Live Tracking)​

Riders track their driver's position in real time via WebSocket:

// ws-gateway/location.gateway.ts
import { WebSocketGateway, SubscribeMessage, MessageBody, ConnectedSocket } from '@nestjs/websockets';
import { Socket } from 'socket.io';
import { InjectRedis } from '@liaoliaots/nestjs-redis';
import Redis from 'ioredis';

@WebSocketGateway({ namespace: '/tracking' })
export class LocationGateway {
  private subscriber: Redis;

  constructor(@InjectRedis() private readonly redis: Redis) {
    this.subscriber = redis.duplicate();
  }

  @SubscribeMessage('track_trip')
  async handleTrackTrip(
    @MessageBody() { tripId }: { tripId: string },
    @ConnectedSocket() client: Socket,
  ): Promise<void> {
    // Client subscribes to this trip's location channel
    await this.subscriber.subscribe(`trip:${tripId}:location`);
    this.subscriber.on('message', (channel, message) => {
      if (channel === `trip:${tripId}:location`) {
        client.emit('driver_location', JSON.parse(message));
      }
    });

    client.on('disconnect', async () => {
      await this.subscriber.unsubscribe(`trip:${tripId}:location`);
    });
  }

  @SubscribeMessage('driver_location')
  async handleDriverLocation(
    @MessageBody() update: { tripId: string; lat: number; lng: number },
    @ConnectedSocket() driver: Socket,
  ): Promise<void> {
    const payload = JSON.stringify({ lat: update.lat, lng: update.lng, ts: Date.now() });
    await this.redis.publish(`trip:${update.tripId}:location`, payload);
    await this.redis.geoadd('drivers:active', update.lng, update.lat, driver.id);
  }
}

Scaling WebSocket gateways: gateways are stateful. Use Redis Pub/Sub as the message bus so any gateway node can forward to any subscriber — horizontal scaling with no sticky sessions.

Cluster Topology​

Multi-region by design: riders/drivers are routed to their nearest regional cluster. Trip data is written to the local region's Cassandra cluster and replicated asynchronously to other regions (Cassandra multi-DC replication).

Payments Flow​

Payment Method Vaulting: card details are tokenized by Braintree at registration — never stored by Uber. The paymentMethodToken is stored in PostgreSQL and used on every trip completion.

Security Architecture​

  • JWT per request: short-lived (15 min) JWT issued by Auth service; refreshed silently by mobile SDK
  • Rate limiting: Envoy enforces per-rider (10 req/s) and per-driver (100 req/s) limits
  • Driver GPS spoofing detection: velocity check + cross-reference with cell tower data
  • Payment security: Braintree vault tokenization; PCI-DSS Level 1 compliance
  • Driver document storage: AES-256 encrypted in GCS; access via signed URLs only
