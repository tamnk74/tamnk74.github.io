Google Cloud Professional Cloud Architect - Complete Learning Guide with Examples

Introduction​

This comprehensive guide provides hands-on examples and practical exercises for every topic in the Google Cloud Professional Cloud Architect certification roadmap. Each section includes theory, code examples, and real-world scenarios.

Phase 1: Foundation (2-3 months)​

1.1 Cloud Computing Fundamentals​

Understanding Cloud Service Models​

IaaS (Infrastructure as a Service)

Definition: Virtualized computing resources over the internet
Provider Manages: Hardware, networking, storage
You Manage: OS, middleware, runtime, data, applications

GCP Examples:
  - Compute Engine (Virtual Machines)
  - Persistent Disk
  - Cloud Storage

Example: IaaS Use Case

# Create a VM instance (IaaS)
gcloud compute instances create web-server \
  --zone=us-central1-a \
  --machine-type=e2-medium \
  --image-family=ubuntu-2204-lts \
  --image-project=ubuntu-os-cloud \
  --boot-disk-size=20GB \
  --tags=http-server,https-server

# SSH into the instance
gcloud compute ssh web-server --zone=us-central1-a

# Install and configure your own web server (you manage everything)
sudo apt update
sudo apt install nginx -y
sudo systemctl start nginx
sudo systemctl enable nginx

PaaS (Platform as a Service)

Definition: Platform for developing, running, and managing applications
Provider Manages: Hardware, OS, runtime, middleware
You Manage: Applications and data

GCP Examples:
  - App Engine
  - Cloud Run
  - Cloud Functions

Example: PaaS Use Case

// app.js - Simple Express app for App Engine
const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.send('Hello from App Engine!');
});

const PORT = process.env.PORT || 8080;
app.listen(PORT, () => {
  console.log(`Server listening on port ${PORT}`);
});
# app.yaml - App Engine configuration (PaaS)
runtime: nodejs18
instance_class: F2

automatic_scaling:
  target_cpu_utilization: 0.65
  min_instances: 1
  max_instances: 10

env_variables:
  NODE_ENV: 'production'
# Deploy to App Engine (Google manages infrastructure)
gcloud app deploy

SaaS (Software as a Service)

Definition: Complete applications delivered over the internet
Provider Manages: Everything (hardware, OS, applications)
You Use: The application

GCP Examples:
  - Google Workspace (Gmail, Drive, Docs)
  - BigQuery (data warehouse)
  - Looker (business intelligence)

Example: SaaS Use Case

-- BigQuery: Just write SQL, Google manages everything
-- No servers, no infrastructure to manage

-- Analyze web logs stored in BigQuery
SELECT
  user_id,
  COUNT(*) as page_views,
  AVG(session_duration) as avg_duration
FROM `my-project.analytics.web_logs`
WHERE DATE(timestamp) = CURRENT_DATE()
GROUP BY user_id
ORDER BY page_views DESC
LIMIT 100;

Cloud Deployment Models​

Public Cloud

Characteristics:
  - Services over the public internet
  - Multi-tenant environment
  - Pay-as-you-go pricing
  - Highly scalable

Use Cases:
  - Startups with limited budget
  - Variable workloads
  - Development and testing
  - Web applications

Example: Deploy a public web application on GCP

Private Cloud

Characteristics:
  - Dedicated infrastructure
  - Single-tenant environment
  - Higher control and security
  - On-premises or hosted

Use Cases:
  - Highly regulated industries (healthcare, finance)
  - Sensitive data processing
  - Legacy application compatibility

Example: GCP Bare Metal Solution for SAP HANA

Hybrid Cloud

Characteristics:
  - Combination of public and private cloud
  - Data and applications shared between environments
  - Flexibility and optimization

Use Cases:
  - Gradual cloud migration
  - Data residency requirements
  - Burst capacity scenarios

Example: On-premises database with GCP compute

Example: Hybrid Cloud Architecture

# Set up Cloud VPN to connect on-premises to GCP
# 1. Create VPN Gateway
gcloud compute target-vpn-gateways create on-prem-vpn-gateway \
  --network=my-vpc \
  --region=us-central1

# 2. Reserve static IP for VPN
gcloud compute addresses create vpn-static-ip \
  --region=us-central1

# 3. Create VPN tunnel
gcloud compute vpn-tunnels create tunnel-to-on-prem \
  --peer-address=203.0.113.1 \
  --shared-secret=MY_SECRET_KEY \
  --ike-version=2 \
  --local-traffic-selector=0.0.0.0/0 \
  --remote-traffic-selector=0.0.0.0/0 \
  --target-vpn-gateway=on-prem-vpn-gateway \
  --region=us-central1

# 4. Add route to on-premises network
gcloud compute routes create route-to-on-prem \
  --network=my-vpc \
  --next-hop-vpn-tunnel=tunnel-to-on-prem \
  --next-hop-vpn-tunnel-region=us-central1 \
  --destination-range=10.0.0.0/16

Virtualization and Containerization​

Virtual Machines

Concept: Run multiple OS on a single physical machine
Hypervisor: Software that creates and runs VMs
Benefits: Resource isolation, easier management, cost savings

Example: Create and Configure VM

# Create VM with custom configuration
gcloud compute instances create app-vm \
  --zone=us-central1-a \
  --machine-type=n1-standard-4 \
  --image-family=debian-11 \
  --image-project=debian-cloud \
  --boot-disk-size=50GB \
  --boot-disk-type=pd-ssd \
  --network=default \
  --subnet=default \
  --metadata=startup-script='#!/bin/bash
    apt-get update
    apt-get install -y docker.io
    systemctl start docker
    systemctl enable docker'

# Create a custom image from this VM
gcloud compute images create app-vm-image \
  --source-disk=app-vm \
  --source-disk-zone=us-central1-a \
  --family=app-vm-family

# Create instance template for scaling
gcloud compute instance-templates create app-template \
  --machine-type=n1-standard-2 \
  --image-family=app-vm-family \
  --boot-disk-size=50GB \
  --tags=http-server

Containers

Concept: Package application with dependencies
Container Engine: Docker, containerd
Benefits: Lightweight, portable, fast startup, consistent environment

Example: Containerize Application

# Dockerfile - Multi-stage build for Node.js app
FROM node:18-alpine AS builder

WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies
RUN npm ci --only=production

# Copy application code
COPY . .

# Build application
RUN npm run build

# Production stage
FROM node:18-alpine

WORKDIR /app

# Copy built application and dependencies
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package*.json ./

# Run as non-root user
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001

USER nodejs

EXPOSE 3000

CMD ["node", "dist/main.js"]
# Build and push container to Artifact Registry
# 1. Create repository
gcloud artifacts repositories create my-app-repo \
  --repository-format=docker \
  --location=us-central1 \
  --description="Docker repository for my app"

# 2. Configure Docker authentication
gcloud auth configure-docker us-central1-docker.pkg.dev

# 3. Build image
docker build -t us-central1-docker.pkg.dev/my-project/my-app-repo/my-app:v1.0 .

# 4. Push to registry
docker push us-central1-docker.pkg.dev/my-project/my-app-repo/my-app:v1.0

# 5. Deploy to Cloud Run
gcloud run deploy my-app \
  --image=us-central1-docker.pkg.dev/my-project/my-app-repo/my-app:v1.0 \
  --platform=managed \
  --region=us-central1 \
  --allow-unauthenticated \
  --memory=512Mi \
  --cpu=1 \
  --max-instances=10 \
  --set-env-vars="NODE_ENV=production"

Networking Fundamentals​

TCP/IP Basics

OSI Model Layers:
  Layer 7 - Application: HTTP, HTTPS, FTP, DNS
  Layer 4 - Transport: TCP, UDP
  Layer 3 - Network: IP, ICMP
  Layer 2 - Data Link: Ethernet, MAC addresses
  Layer 1 - Physical: Cables, switches

IP Addressing:
  IPv4: 32-bit (e.g., 192.168.1.1)
  IPv6: 128-bit (e.g., 2001:db8::1)

CIDR Notation: 10.0.0.0/8   → 16,777,216 addresses
  10.0.0.0/16  → 65,536 addresses
  10.0.0.0/24  → 256 addresses
  10.0.0.0/32  → 1 address (single host)

Example: Subnetting Practice

# Scenario: Design network for 3 tiers (web, app, db)
# Requirement: 200 hosts per tier, room for growth

# Network: 10.0.0.0/16 (65,536 addresses)
# Divide into /24 subnets (256 addresses each)

# Web Tier
gcloud compute networks subnets create web-subnet \
  --network=my-vpc \
  --region=us-central1 \
  --range=10.0.1.0/24 \
  --enable-private-ip-google-access

# App Tier
gcloud compute networks subnets create app-subnet \
  --network=my-vpc \
  --region=us-central1 \
  --range=10.0.2.0/24 \
  --enable-private-ip-google-access

# Database Tier
gcloud compute networks subnets create db-subnet \
  --network=my-vpc \
  --region=us-central1 \
  --range=10.0.3.0/24 \
  --enable-private-ip-google-access

# Management Tier (bastion hosts)
gcloud compute networks subnets create mgmt-subnet \
  --network=my-vpc \
  --region=us-central1 \
  --range=10.0.255.0/24

DNS (Domain Name System)

Purpose: Translate domain names to IP addresses
Record Types:
  A: IPv4 address
  AAAA: IPv6 address
  CNAME: Canonical name (alias)
  MX: Mail exchange
  TXT: Text information
  NS: Name server

Example: Cloud DNS Configuration

# Create a managed DNS zone
gcloud dns managed-zones create my-zone \
  --dns-name="example.com." \
  --description="Production DNS zone"

# Add DNS records
# A record for web server
gcloud dns record-sets create www.example.com. \
  --zone=my-zone \
  --type=A \
  --ttl=300 \
  --rrdatas="34.120.45.67"

# CNAME for subdomain
gcloud dns record-sets create blog.example.com. \
  --zone=my-zone \
  --type=CNAME \
  --ttl=300 \
  --rrdatas="www.example.com."

# MX record for email
gcloud dns record-sets create example.com. \
  --zone=my-zone \
  --type=MX \
  --ttl=3600 \
  --rrdatas="10 mail.example.com.","20 mail2.example.com."

# Get name servers to configure at domain registrar
gcloud dns managed-zones describe my-zone

Load Balancing Concepts

Types:
  Layer 4 (Transport): TCP/UDP load balancing
  Layer 7 (Application): HTTP/HTTPS load balancing

Algorithms:
  Round Robin: Distribute requests evenly
  Least Connections: Send to server with fewest active connections
  IP Hash: Same client always goes to same server
  Weighted: Distribute based on server capacity

Example: Global HTTP(S) Load Balancer

# 1. Create instance group in multiple regions
gcloud compute instance-groups managed create web-us-central \
  --base-instance-name=web-us \
  --template=web-template \
  --size=2 \
  --zone=us-central1-a

gcloud compute instance-groups managed create web-europe \
  --base-instance-name=web-eu \
  --template=web-template \
  --size=2 \
  --zone=europe-west1-b

# 2. Configure health checks
gcloud compute health-checks create http http-basic-check \
  --port=80 \
  --request-path=/ \
  --check-interval=10s \
  --timeout=5s \
  --unhealthy-threshold=3 \
  --healthy-threshold=2

# 3. Create backend service
gcloud compute backend-services create web-backend \
  --protocol=HTTP \
  --health-checks=http-basic-check \
  --global \
  --enable-cdn \
  --cache-mode=CACHE_ALL_STATIC

# 4. Add instance groups as backends
gcloud compute backend-services add-backend web-backend \
  --instance-group=web-us-central \
  --instance-group-zone=us-central1-a \
  --balancing-mode=UTILIZATION \
  --max-utilization=0.8 \
  --capacity-scaler=1.0 \
  --global

gcloud compute backend-services add-backend web-backend \
  --instance-group=web-europe \
  --instance-group-zone=europe-west1-b \
  --balancing-mode=UTILIZATION \
  --max-utilization=0.8 \
  --capacity-scaler=1.0 \
  --global

# 5. Create URL map
gcloud compute url-maps create web-map \
  --default-service=web-backend

# 6. Create target HTTP proxy
gcloud compute target-http-proxies create http-lb-proxy \
  --url-map=web-map

# 7. Create forwarding rule
gcloud compute forwarding-rules create http-lb-forwarding-rule \
  --global \
  --target-http-proxy=http-lb-proxy \
  --ports=80

# Get the external IP
gcloud compute forwarding-rules describe http-lb-forwarding-rule --global

1.2 Google Cloud Fundamentals​

GCP Global Infrastructure​

Regions and Zones

Region: Geographic location with multiple data centers
  - Examples: us-central1, europe-west1, asia-southeast1
  - Low latency within region
  - Independent failure domains

Zone: Isolated location within a region
  - Examples: us-central1-a, us-central1-b
  - Single failure domain
  - Separate power, cooling, networking

Multi-Regional: Span multiple regions
  - Examples: US, EU, ASIA
  - Highest availability
  - Geo-redundant storage

Example: Multi-Region Architecture

# Create resources in multiple regions for high availability

Core GCP Services Overview​

Compute Services Comparison

Compute Engine:
  - Virtual machines
  - Full control over OS and configuration
  - Suitable for: Legacy apps, custom requirements
  - Pricing: Per-second billing, sustained use discounts

Cloud Run:
  - Serverless containers
  - Auto-scaling (including to zero)
  - Suitable for: Stateless applications, APIs, microservices
  - Pricing: Pay per request and resources used

App Engine:
  - Platform for web applications
  - Automatic scaling and load balancing
  - Suitable for: Web apps, mobile backends
  - Pricing: Per instance hour

Cloud Functions:
  - Event-driven serverless functions
  - Short-lived executions
  - Suitable for: Event processing, webhooks, ETL
  - Pricing: Per invocation and compute time

GKE (Google Kubernetes Engine):
  - Managed Kubernetes clusters
  - Container orchestration
  - Suitable for: Microservices, complex applications
  - Pricing: Per node (VM) + management fee

GCP Pricing and Billing​

Pricing Models

On-Demand Pricing:
  - Pay for what you use
  - No upfront costs
  - Maximum flexibility
  - Example: Standard Compute Engine instances

Committed Use Discounts:
  - 1 or 3 year commitment
  - Up to 57% discount
  - Applied automatically
  - Example: Committed vCPUs and memory

Sustained Use Discounts:
  - Automatic discounts for running resources
  - Up to 30% discount
  - No upfront commitment
  - Applied to Compute Engine

Preemptible/Spot VMs:
  - Up to 80% discount
  - Can be terminated by Google
  - Max 24 hours runtime
  - Example: Batch processing, CI/CD

Free Tier:
  - Always Free: Limited usage of specific services
  - 90-day $300 credit for new customers
  - Example: f1-micro instance, Cloud Storage, BigQuery

Example: Cost Optimization Strategies

# 1. Use committed use discounts for predictable workloads

1.3 Networking Basics​

VPC (Virtual Private Cloud)​

VPC Network Concepts

VPC Network:
  - Global resource spanning all regions
  - Subnets are regional resources
  - No IP address overlap between subnets

Subnet Modes:
  Auto Mode:
    - Automatically creates subnets in each region
    - Predefined IP ranges (10.128.0.0/9)
    - Easy to start, less control

  Custom Mode:
    - Manual subnet creation
    - Full control over IP ranges
    - Production recommended

Example: Custom VPC with Multiple Subnets

# Create custom VPC
gcloud compute networks create production-vpc \
  --subnet-mode=custom \
  --bgp-routing-mode=regional \
  --mtu=1460

# Create subnets in different regions for high availability

# US Central - Primary
gcloud compute networks subnets create us-central-subnet \
  --network=production-vpc \
  --region=us-central1 \
  --range=10.1.0.0/20 \
  --enable-private-ip-google-access \
  --enable-flow-logs \
  --logging-aggregation-interval=interval-5-sec \
  --logging-flow-sampling=0.5

# Europe West - Secondary
gcloud compute networks subnets create europe-west-subnet \
  --network=production-vpc \
  --region=europe-west1 \
  --range=10.2.0.0/20 \
  --enable-private-ip-google-access \
  --enable-flow-logs

# Asia Southeast - Tertiary
gcloud compute networks subnets create asia-southeast-subnet \

Firewall Rules​

Firewall Rule Components

Direction:
  - Ingress (incoming traffic)
  - Egress (outgoing traffic)

Action:
  - Allow
  - Deny

Priority:
  - 0-65535 (lower number = higher priority)
  - Default: 1000

Target:
  - All instances in network
  - Instances with specific tags
  - Instances with specific service account

Source/Destination:
  - IP ranges (CIDR notation)
  - Tags
  - Service accounts

Example: Comprehensive Firewall Configuration

# 1. Deny all ingress by default (implicit deny exists, but explicit is better)
gcloud compute firewall-rules create deny-all-ingress \
  --network=production-vpc \
  --direction=INGRESS \
  --action=DENY \
  --rules=all \
  --source-ranges=0.0.0.0/0 \
  --priority=65534

# 2. Allow SSH from IAP (Identity-Aware Proxy)
gcloud compute firewall-rules create allow-iap-ssh \
  --network=production-vpc \
  --direction=INGRESS \
  --action=ALLOW \
  --rules=tcp:22 \
  --source-ranges=35.235.240.0/20 \
  --priority=1000 \
  --description="Allow SSH through IAP"

# 3. Allow HTTP/HTTPS from load balancer
gcloud compute firewall-rules create allow-lb-health-check \
  --network=production-vpc \
  --direction=INGRESS \
  --action=ALLOW \
  --rules=tcp:80,tcp:443,tcp:8080 \
  --source-ranges=35.191.0.0/16,130.211.0.0/22 \
  --target-tags=web-server \
  --priority=1000 \
  --description="Allow health checks from load balancer"

# 4. Allow internal communication between tiers
gcloud compute firewall-rules create allow-web-to-app \
  --network=production-vpc \
  --direction=INGRESS \
  --action=ALLOW \
  --rules=tcp:8080 \
  --source-tags=web-tier \
  --target-tags=app-tier \
  --priority=1000

gcloud compute firewall-rules create allow-app-to-db \
  --network=production-vpc \
  --direction=INGRESS \
  --action=ALLOW \
  --rules=tcp:5432,tcp:3306 \
  --source-tags=app-tier \
  --target-tags=db-tier \
  --priority=1000

# 5. Allow health checks within VPC
gcloud compute firewall-rules create allow-internal-health-check \
  --network=production-vpc \
  --direction=INGRESS \
  --action=ALLOW \
  --rules=tcp \
  --source-ranges=10.0.0.0/8 \
  --priority=1000

# 6. Egress rule for external API calls
gcloud compute firewall-rules create allow-api-egress \
  --network=production-vpc \
  --direction=EGRESS \
  --action=ALLOW \
  --rules=tcp:443 \
  --destination-ranges=0.0.0.0/0 \
  --target-tags=api-client \
  --priority=1000

# List all firewall rules
gcloud compute firewall-rules list --filter="network:production-vpc"

Cloud NAT and Cloud VPN​

Cloud NAT (Network Address Translation)

Purpose:
  - Allow private instances to access internet
  - No need for external IPs
  - Managed service, highly available

Use Cases:
  - Software updates for private VMs
  - API calls to external services
  - Outbound internet access without public IP

Example: Cloud NAT Configuration

# 1. Create Cloud Router (required for Cloud NAT)
gcloud compute routers create nat-router \
  --network=production-vpc \
  --region=us-central1

# 2. Configure Cloud NAT
gcloud compute routers nats create nat-config \
  --router=nat-router \
  --region=us-central1 \
  --nat-all-subnet-ip-ranges \
  --auto-allocate-nat-external-ips \
  --enable-logging \
  --log-filter=ERRORS_ONLY

# 3. Test with private instance
gcloud compute instances create private-instance \
  --zone=us-central1-a \
  --machine-type=e2-micro \
  --subnet=us-central-subnet \
  --no-address \
  --metadata=startup-script='#!/bin/bash
    apt-get update
    apt-get install -y nginx
    curl -I https://www.google.com'

# 4. View NAT logs
gcloud logging read "resource.type=nat_gateway" \
  --limit=50 \
  --format=json

Cloud VPN (Virtual Private Network)

Types:
  HA VPN (High Availability):
    - 99.99% SLA
    - Two external IP addresses
    - Recommended for production

  Classic VPN:
    - 99.9% SLA
    - Single external IP
    - Legacy option

Topologies:
  - Site-to-Site: Connect on-premises to GCP
  - Hub-and-Spoke: Multiple branches to central GCP
  - Mesh: Multiple GCP regions interconnected

Example: HA VPN Configuration

# 1. Create HA VPN gateway
gcloud compute vpn-gateways create ha-vpn-gw-1 \
  --network=production-vpc \
  --region=us-central1

# 2. Create Cloud Router for dynamic routing
gcloud compute routers create vpn-router-1 \
  --region=us-central1 \
  --network=production-vpc \
  --asn=65001

# 3. Create external VPN gateway (represents peer)
gcloud compute external-vpn-gateways create on-prem-gw \
  --interfaces=0=203.0.113.1,1=203.0.113.2

# 4. Create VPN tunnels (two for HA)
gcloud compute vpn-tunnels create tunnel-1 \
  --peer-external-gateway=on-prem-gw \
  --peer-external-gateway-interface=0 \
  --region=us-central1 \
  --ike-version=2 \
  --shared-secret=SECRET_1 \
  --router=vpn-router-1 \
  --vpn-gateway=ha-vpn-gw-1 \
  --interface=0

gcloud compute vpn-tunnels create tunnel-2 \
  --peer-external-gateway=on-prem-gw \
  --peer-external-gateway-interface=1 \
  --region=us-central1 \
  --ike-version=2 \
  --shared-secret=SECRET_2 \
  --router=vpn-router-1 \
  --vpn-gateway=ha-vpn-gw-1 \
  --interface=1

# 5. Configure BGP sessions
gcloud compute routers add-interface vpn-router-1 \
  --interface-name=if-tunnel-1 \
  --ip-address=169.254.1.1 \
  --mask-length=30 \
  --vpn-tunnel=tunnel-1 \
  --region=us-central1

gcloud compute routers add-bgp-peer vpn-router-1 \
  --peer-name=bgp-peer-1 \
  --interface=if-tunnel-1 \
  --peer-ip-address=169.254.1.2 \
  --peer-asn=65002 \
  --region=us-central1

# 6. Verify VPN status
gcloud compute vpn-tunnels describe tunnel-1 \
  --region=us-central1 \
  --format="get(status,detailedStatus)"

Load Balancing Types​

GCP Load Balancer Types

Global Load Balancers:
  HTTP(S) Load Balancer:
    - Layer 7 (application layer)
    - Global anycast IP
    - Content-based routing
    - SSL termination
    - Cloud CDN integration
    - Use: Web applications, APIs

  SSL Proxy Load Balancer:
    - Layer 4 for SSL traffic
    - Global load balancing
    - Non-HTTP SSL traffic
    - Use: SSL/TLS workloads

  TCP Proxy Load Balancer:
    - Layer 4 for TCP traffic
    - Global load balancing
    - Use: TCP traffic without SSL

Regional Load Balancers:
  Network Load Balancer:
    - Layer 4 (transport layer)
    - Regional
    - Preserve client IP
    - Use: UDP traffic, non-HTTP TCP

  Internal Load Balancer:
    - Layer 4
    - Private load balancing
    - Within VPC only
    - Use: Internal services, microservices

Example: Complete HTTP(S) Load Balancer with CDN

apt-get install -y nginx curl

cat > /etc/nginx/sites-available/default <<NGINX
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;

        access_log off;

        add_header Content-Type text/plain;
    }

NGINX

mkdir -p /opt/app

const http = require('http');
const os = require('os');

const server = http.createServer((req, res) => {
  if (req.url === '/health') {
    res.writeHead(200, {'Content-Type': 'text/plain'});
    res.end('healthy\n');
  } else {
    res.writeHead(200, {'Content-Type': 'text/html'});
    res.end(\`
      <h1>Hello from \${os.hostname()}</h1>
      <p>Uptime: \${process.uptime()}s</p>
    \`);
  }
});

server.listen(8080);
console.log('Server running on port 8080');
APP

User=www-data
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
SERVICE
