Google Cloud Storage

Google Cloud Storage (GCS) is a unified object storage service for developers and enterprises, combining the performance of a local filesystem with the scalability of cloud storage. It offers industry-leading availability and durability, making it ideal for storing and serving content, backup and archival, and big data analytics.

Overview​

Google Cloud Storage provides a simple, secure, and scalable solution for storing any amount of data. It's designed for 99.999999999% (11 nines) durability and offers multiple storage classes to optimize costs based on access patterns.

Key Features​

  • Unified Object Storage: Store any type of data in any format
  • Global Accessibility: Access data from anywhere with low latency
  • Strong Consistency: Read-after-write consistency for all operations
  • Security: Encryption at rest and in transit by default
  • Integration: Native integration with GCP services and third-party tools
  • Versioning: Keep multiple versions of objects
  • Lifecycle Management: Automatically transition objects between storage classes

Storage Classes​

GCS offers different storage classes optimized for different use cases:

Standard Storage​

Best for: Frequently accessed data (hot data) and data stored for brief periods

Availability: 99.95% (multi-region), 99.9% (region)
Durability: 99.999999999%
Use Cases:
  - Website content
  - Interactive workloads
  - Mobile and gaming applications
  - Analytics and ML training data

Architecture Example: E-commerce Platform​

Key Characteristics:

  • Access Pattern: Multiple times per day
  • Latency: < 10ms for first byte
  • Cost: Higher storage, no retrieval fees
  • Best for: Content serving, active workloads

Nearline Storage​

Best for: Data accessed less than once per month

Availability: 99.9% (multi-region), 99.0% (region)
Minimum Storage Duration: 30 days
Use Cases:
  - Data backup
  - Long-tail multimedia content
  - Data archiving

Architecture Example: Database Backup System​

Key Characteristics:

  • Access Pattern: Once per month or less
  • Retrieval Fee: $0.01/GB
  • Min Duration: 30 days
  • Cost Savings: ~40% vs Standard
  • Best for: Backups, disaster recovery data

Coldline Storage​

Best for: Data accessed less than once per quarter

Availability: 99.9% (multi-region), 99.0% (region)
Minimum Storage Duration: 90 days
Use Cases:
  - Disaster recovery
  - Archived data with rare access
  - Cold data backup

Architecture Example: Disaster Recovery & Compliance Archive​

Key Characteristics:

  • Access Pattern: Once per quarter or less
  • Retrieval Fee: $0.02/GB
  • Min Duration: 90 days
  • Cost Savings: ~60% vs Standard
  • Best for: Disaster recovery, compliance archives

Archive Storage​

Best for: Data accessed less than once per year

Availability: 99.9% (multi-region), 99.0% (region)
Minimum Storage Duration: 365 days
Use Cases:
  - Long-term digital preservation
  - Regulatory archives
  - Historical data

Architecture Example: Long-term Regulatory Compliance System​

Key Characteristics:

  • Access Pattern: Once per year or never
  • Retrieval Fee: $0.05/GB
  • Min Duration: 365 days (1 year)
  • Cost Savings: ~70% vs Standard
  • Retrieval Time: Milliseconds (same as other classes)
  • Best for: Long-term compliance, regulatory archives, digital preservation

Common Use Cases by Industry:

Location Types​

Multi-Region​

Geo-redundant storage across multiple regions for highest availability:

Available Locations:
  - US (United States)
  - EU (European Union)
  - ASIA (Asia)
Benefits:
  - Highest availability (99.95%)
  - Geo-redundancy
  - Optimal for serving global content

Dual-Region​

Replicated across two specific regions:

Examples:
  - NAM4 (us-central1 and us-east1)
  - EUR4 (europe-north1 and europe-west4)
Benefits:
  - Balance of availability and cost
  - Specific geography requirements
  - Lower latency for regional users

Single Region​

Data stored in one specific location:

Examples:
  - us-central1
  - europe-west1
  - asia-east1
Benefits:
  - Lowest latency for regional access
  - Data residency requirements
  - Cost optimization

Getting Started​

Prerequisites​

# Install gcloud CLI
curl https://sdk.cloud.google.com | bash
exec -l $SHELL

# Initialize and authenticate
gcloud init
gcloud auth login

Creating a Bucket​

Using gcloud CLI​

# Create a bucket in a specific region
gcloud storage buckets create gs://my-bucket-name \
  --location=us-central1 \
  --storage-class=STANDARD

# Create a multi-region bucket
gcloud storage buckets create gs://my-global-bucket \
  --location=US \
  --storage-class=STANDARD

# Create with specific settings
gcloud storage buckets create gs://my-secure-bucket \
  --location=europe-west1 \
  --uniform-bucket-level-access \
  --public-access-prevention

Using gsutil (Legacy)​

# Create a bucket
gsutil mb -c STANDARD -l US gs://my-bucket-name/

# Create with uniform access control
gsutil mb -b on gs://my-bucket-name/

Working with Objects​

Uploading Files​

# Upload a single file
gcloud storage cp local-file.txt gs://my-bucket/

# Upload with metadata
gcloud storage cp local-file.txt gs://my-bucket/ \
  --cache-control="public, max-age=3600" \
  --content-type="text/plain"

# Upload directory recursively
gcloud storage cp -r ./local-directory gs://my-bucket/path/

# Upload with parallel composite uploads (faster for large files)
gcloud storage cp large-file.zip gs://my-bucket/ \
  --parallel-composite-upload-threshold=150M

Downloading Files​

# Download a single file
gcloud storage cp gs://my-bucket/file.txt ./local-path/

# Download directory
gcloud storage cp -r gs://my-bucket/directory/ ./local-path/

# Download with parallel downloads
gcloud storage cp gs://my-bucket/large-file.zip ./ \
  --parallel-process-count=8

Listing Objects​

# List all objects in a bucket
gcloud storage ls gs://my-bucket/

# List with details
gcloud storage ls -l gs://my-bucket/

# List recursively
gcloud storage ls -r gs://my-bucket/

# List with filters
gcloud storage ls gs://my-bucket/**.txt

Deleting Objects​

# Delete a single object
gcloud storage rm gs://my-bucket/file.txt

# Delete multiple objects
gcloud storage rm gs://my-bucket/file1.txt gs://my-bucket/file2.txt

# Delete directory recursively
gcloud storage rm -r gs://my-bucket/directory/

# Delete all objects in bucket
gcloud storage rm -r gs://my-bucket/**

Moving and Copying Objects​

gcloud storage cp -r gs://new-ecom-bucket/languages/ gs://ne-private-files/

# Copy between buckets
gcloud storage cp gs://source-bucket/file.txt gs://dest-bucket/

# Copy folder from one bucket to another
gcloud storage cp -r gs://source-bucket/folder/ gs://dest-bucket/folder/

# Copy entire bucket contents to another bucket
gcloud storage cp -r gs://source-bucket/* gs://dest-bucket/

# Move (copy and delete source)
gcloud storage mv gs://source-bucket/file.txt gs://dest-bucket/

# Move folder from one bucket to another
gcloud storage mv -r gs://source-bucket/folder/ gs://dest-bucket/folder/

# Copy with preservation of metadata
gcloud storage cp --preserve-acl gs://source/file.txt gs://dest/

# Copy folder with parallel processing for better performance
gcloud storage cp -r gs://source-bucket/folder/ gs://dest-bucket/folder/ \
  --parallel-process-count=16

Access Control​

IAM (Identity and Access Management)​

# Grant bucket-level access
gcloud storage buckets add-iam-policy-binding gs://my-bucket \
  --member=user:user@example.com \
  --role=roles/storage.objectViewer

# Grant object-level access
gcloud storage objects add-iam-policy-binding gs://my-bucket/file.txt \
  --member=serviceAccount:sa@project.iam.gserviceaccount.com \
  --role=roles/storage.objectViewer

# Common IAM roles
roles/storage.admin              # Full control
roles/storage.objectAdmin        # Full object control
roles/storage.objectCreator      # Create objects only
roles/storage.objectViewer       # Read objects only
roles/storage.legacyBucketReader # List and read bucket
roles/storage.legacyBucketWriter # Create, list, and delete objects

Uniform Bucket-Level Access​

# Enable uniform bucket-level access
gcloud storage buckets update gs://my-bucket \
  --uniform-bucket-level-access

# Disable (revert to fine-grained ACLs)
gcloud storage buckets update gs://my-bucket \
  --no-uniform-bucket-level-access

Public Access Prevention​

# Enforce public access prevention
gcloud storage buckets update gs://my-bucket \
  --public-access-prevention

# Inherited (use organization policy)
gcloud storage buckets update gs://my-bucket \
  --public-access-prevention=inherited

Making Objects Public​

# Make a single object public
gcloud storage objects update gs://my-bucket/file.txt \
  --add-acl-grant=entity=allUsers,role=READER

# Make all objects in bucket public (requires uniform access disabled)
gsutil iam ch allUsers:objectViewer gs://my-bucket

# Serve public website
gcloud storage buckets update gs://my-bucket \
  --web-main-page-suffix=index.html \
  --web-error-page=404.html

Bucket Access Patterns & Use Cases​

Understanding bucket access configurations is crucial for security and compliance. Choose the right access pattern based on your use case.

Public Access Prevention​

Purpose: Prevent data from being publicly accessible via the internet. This blocks all public access to the bucket and its objects, preventing the bucket from being used for web hosting.

Use Cases​

1. Internal Corporate Data Storage

Scenario: Employee Documents, Internal Reports, HR Records
Requirements:
  - No public access allowed
  - Only authenticated company users can access
  - Compliance with data privacy regulations
Configuration:
  - Public Access Prevention: enforced
  - Access Control: Uniform (IAM)
# Create bucket with public access prevention
gcloud storage buckets create gs://company-internal-docs \
  --location=us-central1 \
  --uniform-bucket-level-access \
  --public-access-prevention

# Grant access only to specific users/groups
gcloud storage buckets add-iam-policy-binding gs://company-internal-docs \
  --member=group:employees@company.com \
  --role=roles/storage.objectViewer

2. Customer Private Data (PII/PHI)

Scenario: Healthcare Records, Financial Data, Personal Information
Requirements:
  - HIPAA/GDPR/PCI-DSS compliance
  - Strict access controls
  - Audit logging enabled
  - Encryption at rest and in transit
Configuration:
  - Public Access Prevention: enforced
  - Access Control: Uniform (IAM)
  - Encryption: CMEK (Customer-Managed Keys)
  - VPC Service Controls: enabled
# Create compliant private bucket
gcloud storage buckets create gs://patient-records-hipaa \
  --location=us-central1 \
  --uniform-bucket-level-access \
  --public-access-prevention \
  --default-encryption-key=projects/PROJECT_ID/locations/us-central1/keyRings/healthcare/cryptoKeys/phi-key

# Enable audit logging
gcloud projects get-iam-policy PROJECT_ID > policy.yaml
# Edit policy.yaml to add audit logs for storage.googleapis.com
gcloud projects set-iam-policy PROJECT_ID policy.yaml

# Grant access only to specific service accounts
gcloud storage buckets add-iam-policy-binding gs://patient-records-hipaa \
  --member=serviceAccount:healthcare-app@PROJECT_ID.iam.gserviceaccount.com \
  --role=roles/storage.objectViewer

3. Application Private Assets

Scenario: User Uploads, Private Documents, Backups
Requirements:
  - Users can only access their own files
  - Application serves files via signed URLs
  - No direct public access
Configuration:
  - Public Access Prevention: enforced
  - Access Control: Uniform (IAM)
  - Access Method: Signed URLs with expiration
# Create bucket for private user uploads
gcloud storage buckets create gs://app-user-uploads \
  --location=us-central1 \
  --uniform-bucket-level-access \
  --public-access-prevention

# Grant application service account access
gcloud storage buckets add-iam-policy-binding gs://app-user-uploads \
  --member=serviceAccount:app-backend@PROJECT_ID.iam.gserviceaccount.com \
  --role=roles/storage.objectAdmin

# Application generates signed URLs for user access
# (See Signed URLs section for implementation)

4. Enterprise Backup & Disaster Recovery

Scenario: Database Backups, VM Snapshots, Archive Storage
Requirements:
  - Long-term retention
  - No public access
  - Versioning enabled
  - Immutable storage (retention policy)
Configuration:
  - Public Access Prevention: enforced
  - Access Control: Uniform (IAM)
  - Versioning: enabled
  - Retention Policy: locked
# Create backup bucket with strict controls
gcloud storage buckets create gs://enterprise-backups \
  --location=us-central1 \
  --uniform-bucket-level-access \
  --public-access-prevention \
  --versioning

# Set retention policy (90 days minimum)
gcloud storage buckets update gs://enterprise-backups \
  --retention-period=90d

# Lock retention policy (irreversible)
gcloud storage buckets update gs://enterprise-backups \
  --lock-retention-period

# Grant backup service access
gcloud storage buckets add-iam-policy-binding gs://enterprise-backups \
  --member=serviceAccount:backup-service@PROJECT_ID.iam.gserviceaccount.com \
  --role=roles/storage.objectCreator

Architecture: Private Bucket with Application Access​

Access Control: Uniform vs Fine-Grained​

Uniform Access (Recommended for Most Use Cases)​

What it is: Uses only bucket-level permissions (IAM) for all objects. Once enabled, becomes permanent after 90 days.

Advantages:

  • Simpler permission management
  • Consistent access control across all objects
  • Better security posture
  • Easier to audit
  • Required for public access prevention

Use Cases:

1. Multi-Tenant SaaS Application

Scenario: SaaS platform with customer data isolation
Requirements:
  - Each customer has isolated data
  - Centralized access management
  - Easy permission updates
Implementation:
  - One bucket per customer with uniform access
  - IAM policies for customer isolation
# Create customer bucket with uniform access
gcloud storage buckets create gs://saas-customer-12345 \
  --location=us-central1 \
  --uniform-bucket-level-access \
  --public-access-prevention

# Grant access to customer's service account
gcloud storage buckets add-iam-policy-binding gs://saas-customer-12345 \
  --member=serviceAccount:customer-12345@PROJECT_ID.iam.gserviceaccount.com \
  --role=roles/storage.objectAdmin

# Grant read-only access to support team
gcloud storage buckets add-iam-policy-binding gs://saas-customer-12345 \
  --member=group:support@company.com \
  --role=roles/storage.objectViewer \
  --condition='expression=request.time < timestamp("2026-12-31T23:59:59Z"),title=temporary-support-access'

2. Data Lake with Team-Based Access

Scenario: Analytics data lake with department access
Requirements:
  - Different teams access different datasets
  - Centralized governance
  - Easy permission management
Implementation:
  - Uniform access with IAM conditions
  - Group-based permissions
# Create data lake bucket
gcloud storage buckets create gs://company-data-lake \
  --location=us-central1 \
  --uniform-bucket-level-access

# Marketing team gets access to marketing data
gcloud storage buckets add-iam-policy-binding gs://company-data-lake \
  --member=group:marketing@company.com \
  --role=roles/storage.objectViewer \
  --condition='expression=resource.name.startsWith("projects/_/buckets/company-data-lake/objects/marketing/"),title=marketing-data-access'

# Finance team gets access to finance data
gcloud storage buckets add-iam-policy-binding gs://company-data-lake \
  --member=group:finance@company.com \
  --role=roles/storage.objectViewer \
  --condition='expression=resource.name.startsWith("projects/_/buckets/company-data-lake/objects/finance/"),title=finance-data-access'

# Data engineers get full access
gcloud storage buckets add-iam-policy-binding gs://company-data-lake \
  --member=group:data-engineers@company.com \
  --role=roles/storage.objectAdmin

3. CI/CD Build Artifacts

Scenario: Store build artifacts, test results, deployment packages
Requirements:
  - CI/CD pipeline needs write access
  - Developers need read access
  - Automated cleanup via lifecycle
Implementation:
  - Uniform access for simplicity
  - Service account for automation
# Create CI/CD artifacts bucket
gcloud storage buckets create gs://cicd-artifacts \
  --location=us-central1 \
  --uniform-bucket-level-access

# Grant CI/CD service account write access
gcloud storage buckets add-iam-policy-binding gs://cicd-artifacts \
  --member=serviceAccount:cicd-bot@PROJECT_ID.iam.gserviceaccount.com \
  --role=roles/storage.objectCreator

# Grant developers read access
gcloud storage buckets add-iam-policy-binding gs://cicd-artifacts \
  --member=group:developers@company.com \
  --role=roles/storage.objectViewer

# Cleanup old artifacts with lifecycle policy
cat > lifecycle.json << 'EOF'
{
  "lifecycle": {
    "rule": [
      {
        "action": {"type": "Delete"},
        "condition": {"age": 30}
      }
    ]
  }
}
EOF

gcloud storage buckets update gs://cicd-artifacts --lifecycle-file=lifecycle.json

Fine-Grained Access (ACLs + IAM)​

What it is: Specify access to individual objects using object-level permissions (ACLs) in addition to bucket-level permissions (IAM).

Advantages:

  • Granular control per object
  • Different permissions per file
  • Useful for mixed access patterns

Disadvantages:

  • More complex to manage
  • Harder to audit
  • Cannot use with public access prevention
  • Not recommended for new projects

Use Cases:

1. Legacy CDN Content with Mixed Access

Scenario: Content delivery with some public and some private files
Requirements:
  - Some objects are public (marketing assets)
  - Some objects are private (customer data)
  - Per-object ACLs needed for legacy system
Note: Consider migrating to uniform access with separate buckets
# Create bucket with fine-grained access (legacy)
gcloud storage buckets create gs://legacy-cdn-content \
  --location=us-central1

# Make specific object public
gcloud storage objects update gs://legacy-cdn-content/public/logo.png \
  --add-acl-grant=entity=allUsers,role=READER

# Make another object private with specific user access
gsutil acl ch -u user@example.com:READ gs://legacy-cdn-content/private/document.pdf

2. Collaborative Document Sharing (Legacy Pattern)

Scenario: Individual file sharing with different users
Requirements:
  - Per-file access control
  - Different collaborators per document
Note: Consider using Google Drive API or uniform access with signed URLs
# Grant specific user access to specific file
gsutil acl ch -u alice@example.com:OWNER gs://shared-docs/project-a/report.pdf
gsutil acl ch -u bob@example.com:READER gs://shared-docs/project-a/report.pdf

# Grant group access to specific file
gsutil acl ch -g team@example.com:READER gs://shared-docs/project-b/presentation.pptx

Best Practices​

  1. Always Use Public Access Prevention for Sensitive Data

    # Enforce at organization level
    gcloud resource-manager org-policies set-policy policy.yaml

  2. Prefer Uniform Access Over Fine-Grained

    # Uniform access is simpler and more secure
    --uniform-bucket-level-access

  3. Use Separate Buckets for Different Access Patterns

    # Public content
    gs://company-public-assets (no prevention)

    # Private data
    gs://company-private-data (prevention enforced)

  4. Implement IAM Conditions for Time-Based Access

    --condition='expression=request.time < timestamp("2026-12-31T23:59:59Z"),title=temporary-access'

  5. Enable Audit Logging for Compliance

    gcloud logging read "resource.type=gcs_bucket AND resource.labels.bucket_name=my-bucket"

  6. Use VPC Service Controls for Additional Security

    gcloud access-context-manager perimeters create secure-storage \
      --resources=projects/PROJECT_NUMBER \
      --restricted-services=storage.googleapis.com

Migration: Fine-Grained to Uniform Access​

If you have an existing bucket with fine-grained access and want to migrate:

# 1. Audit current ACLs
gsutil ls -L gs://my-bucket/** > current-acls.txt

# 2. Convert ACLs to equivalent IAM policies
# (Review and create appropriate IAM bindings)

# 3. Enable uniform access (90-day grace period)
gcloud storage buckets update gs://my-bucket \
  --uniform-bucket-level-access

# 4. During 90-day period, test and verify access
# 5. After 90 days, uniform access becomes permanent

Important: Once uniform access is enabled for 90 days, it becomes permanent and cannot be reverted.

Versioning​

Enable Object Versioning​

# Enable versioning
gcloud storage buckets update gs://my-bucket --versioning

# Disable versioning (keeps existing versions)
gcloud storage buckets update gs://my-bucket --no-versioning

# List all versions of an object
gcloud storage ls -a gs://my-bucket/file.txt

# Download a specific version
gcloud storage cp gs://my-bucket/file.txt#1234567890123456 ./

Lifecycle Management​

Creating Lifecycle Rules​

Create a lifecycle configuration file lifecycle.json:

{
  "lifecycle": {
    "rule": [
      {
        "action": {
          "type": "SetStorageClass",
          "storageClass": "NEARLINE"
        },
        "condition": {
          "age": 30,
          "matchesStorageClass": ["STANDARD"]
        }
      },
      {
        "action": {
          "type": "SetStorageClass",
          "storageClass": "COLDLINE"
        },
        "condition": {
          "age": 90,
          "matchesStorageClass": ["NEARLINE"]
        }
      },
      {
        "action": {
          "type": "Delete"
        },
        "condition": {
          "age": 365,
          "matchesStorageClass": ["COLDLINE", "ARCHIVE"]
        }
      },
      {
        "action": {
          "type": "Delete"
        },
        "condition": {
          "numNewerVersions": 3
        }
      }
    ]
  }
}

Apply lifecycle configuration:

# Set lifecycle configuration
gcloud storage buckets update gs://my-bucket \
  --lifecycle-file=lifecycle.json

# View current lifecycle configuration
gcloud storage buckets describe gs://my-bucket --format="json(lifecycle)"

# Remove lifecycle configuration
gcloud storage buckets update gs://my-bucket --clear-lifecycle

Signed URLs​

Generating Signed URLs​

# Generate a signed URL valid for 1 hour (read access)
gcloud storage sign-url gs://my-bucket/file.txt \
  --duration=1h

# Generate with specific service account
gcloud storage sign-url gs://my-bucket/file.txt \
  --private-key-file=key.json \
  --duration=2h

# Generate for upload (PUT method)
gcloud storage sign-url gs://my-bucket/upload.txt \
  --http-verb=PUT \
  --duration=30m \
  --headers="Content-Type=text/plain"

Using Signed URLs with Python​

from google.cloud import storage
from datetime import timedelta

def generate_signed_url(bucket_name, blob_name):
    """Generate a v4 signed URL for downloading a blob."""
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)
    blob = bucket.blob(blob_name)

    url = blob.generate_signed_url(
        version="v4",
        expiration=timedelta(minutes=15),
        method="GET",
    )
    return url

def generate_upload_signed_url(bucket_name, blob_name):
    """Generate a v4 signed URL for uploading a blob."""
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)
    blob = bucket.blob(blob_name)

    url = blob.generate_signed_url(
        version="v4",
        expiration=timedelta(minutes=15),
        method="PUT",
        content_type="application/octet-stream",
    )
    return url

SDK Integration​

Python Client Library​

# Install the library
pip install google-cloud-storage
from google.cloud import storage

# Initialize client
storage_client = storage.Client()

# Upload a file
def upload_blob(bucket_name, source_file_name, destination_blob_name):
    bucket = storage_client.bucket(bucket_name)
    blob = bucket.blob(destination_blob_name)

    blob.upload_from_filename(source_file_name)
    print(f"File {source_file_name} uploaded to {destination_blob_name}.")

# Download a file
def download_blob(bucket_name, source_blob_name, destination_file_name):
    bucket = storage_client.bucket(bucket_name)
    blob = bucket.blob(source_blob_name)

    blob.download_to_filename(destination_file_name)

    server_name files.example.com;

        # Get signed URL from backend

        proxy_set_header Authorization $http_authorization;
        proxy_set_header X-Original-URI $request_uri;

        # Follow redirect to signed URL
        proxy_intercept_errors on;
        error_page 302 = @redirect;
    }

    location @redirect {
        internal;
        # Proxy to GCS with signed URL
        resolver 8.8.8.8;
        proxy_pass $upstream_http_location;
        proxy_cache gcs_cache;
        proxy_cache_valid 200 60m;
        proxy_cache_key "$upstream_http_location";

        proxy_hide_header x-goog-generation;
        proxy_hide_header x-goog-metageneration;
        proxy_hide_header x-goog-stored-content-length;

        # Add custom headers
        add_header X-Cache-Status $upstream_cache_status;

Performance Optimization​

Parallel Uploads and Downloads​

from google.cloud import storage
from google.cloud.storage import transfer_manager
import os

def upload_directory_parallel(bucket_name, source_directory, workers=8):
    """Upload all files in a directory using parallel uploads."""
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)

    # Get all file paths
    file_paths = []
    for root, dirs, files in os.walk(source_directory):
        for filename in files:
            file_path = os.path.join(root, filename)
            relative_path = os.path.relpath(file_path, source_directory)
            file_paths.append((file_path, relative_path))

    # Upload in parallel
    results = transfer_manager.upload_many_from_filenames(
        bucket,
        [fp[0] for fp in file_paths],
        blob_names=[fp[1] for fp in file_paths],
        max_workers=workers
    )

    for path, result in zip(file_paths, results):
        if isinstance(result, Exception):
            print(f"Failed to upload {path[0]}: {result}")
        else:
            print(f"Uploaded {path[0]} to {path[1]}")

def download_directory_parallel(bucket_name, prefix, destination_directory, workers=8):
    """Download all blobs with a prefix using parallel downloads."""
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)

    blobs = list(bucket.list_blobs(prefix=prefix))
    blob_names = [blob.name for blob in blobs]

    # Create destination paths
    dest_paths = []
    for blob_name in blob_names:
        dest_path = os.path.join(destination_directory, blob_name)
        os.makedirs(os.path.dirname(dest_path), exist_ok=True)
        dest_paths.append(dest_path)

    # Download in parallel
    results = transfer_manager.download_many_to_path(
        bucket,
        blob_names,
        destination_directory=destination_directory,
        max_workers=workers
    )

    for blob_name, result in zip(blob_names, results):
        if isinstance(result, Exception):
            print(f"Failed to download {blob_name}: {result}")
        else:
            print(f"Downloaded {blob_name}")

from google.cloud import storage

def upload_large_file_composite(bucket_name, source_file, destination_blob):
    """Upload a large file using composite upload."""
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)
    blob = bucket.blob(destination_blob)

    # Enable composite upload (automatically used for large files)
    blob.chunk_size = 256 * 1024 * 1024  # 256 MB chunks
    blob.upload_from_filename(source_file)

    print(f"Large file {source_file} uploaded.")

    # Use lifecycle policies to automatically transition data
    # Standard → Nearline → Coldline → Archive

  2. Minimize Early Deletion

    # Each storage class has minimum storage duration
    # Standard: None
    # Nearline: 30 days
    # Coldline: 90 days
    # Archive: 365 days

  3. Reduce Retrieval Costs

    # Nearline: $0.01/GB retrieval
    # Coldline: $0.02/GB retrieval
    # Archive: $0.05/GB retrieval

  4. Use Requester Pays

    # Enable requester pays
    gcloud storage buckets update gs://my-bucket --requester-pays

    # Access with requester pays
    gcloud storage cp gs://my-bucket/file.txt ./ \
      --billing-project=requester-project-id

  5. Optimize Network Costs

    # Use same region for compute and storage
    # Use Cloud CDN for static content
    # Enable compression for text files

Object Composition​

from google.cloud import storage

def compose_objects(bucket_name, source_blobs, destination_blob):
    """Compose multiple objects into one."""
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)

    destination = bucket.blob(destination_blob)
    sources = [bucket.blob(name) for name in source_blobs]

    destination.compose(sources)
    print(f"Composed {len(sources)} objects into {destination_blob}")

Batch Operations​

from google.cloud import storage

def batch_delete(bucket_name, blob_names):
    """Delete multiple blobs in a batch."""
    storage_client = storage.Client()
    bucket = storage_client.bucket(bucket_name)

    with storage_client.batch():
        for blob_name in blob_names:
            blob = bucket.blob(blob_name)
            blob.delete()

    print(f"Deleted {len(blob_names)} blobs")

Summary​

Google Cloud Storage provides a robust, scalable, and secure object storage solution suitable for a wide range of use cases from serving website content to long-term data archival. Key takeaways:

  • Choose appropriate storage classes based on access patterns
  • Implement uniform bucket-level access and public access prevention
  • Use lifecycle policies to automatically manage data transitions
  • Enable versioning and retention policies for data protection
  • Leverage CDN and parallel operations for performance
  • Monitor usage and costs regularly
  • Follow security best practices including encryption and VPC Service Controls
