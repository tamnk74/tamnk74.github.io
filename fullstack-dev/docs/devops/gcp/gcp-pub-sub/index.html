Top 10 Pub/Sub Architecture Patterns

Overview​

Google Cloud Pub/Sub is a messaging service that enables asynchronous communication between services. This guide explores the top 10 architecture patterns for implementing Pub/Sub in modern distributed systems, with practical examples and best practices.

1. Fan-Out Pattern​

Description​

A single message is published to a topic and delivered to multiple subscribers independently. Each subscriber processes the message according to its own logic.

Use Cases​

  • Event broadcasting to multiple microservices
  • Real-time notifications to different channels (email, SMS, push)
  • Data replication across multiple systems

Architecture​

Publisher → Topic → Subscription 1 → Service A
                  → Subscription 2 → Service B
                  → Subscription 3 → Service C

Implementation Example​

// Publisher
import { PubSub } from '@google-cloud/pubsub';

const pubsub = new PubSub();
const topicName = 'order-events';

async function publishOrderEvent(order: any) {
  const dataBuffer = Buffer.from(JSON.stringify(order));

  try {
    const messageId = await pubsub.topic(topicName).publish(dataBuffer);
    console.log(`Message ${messageId} published.`);
  } catch (error) {
    console.error('Error publishing message:', error);
  }
}

// Subscriber 1: Email Service
async function subscribeEmailService() {
  const subscription = pubsub.subscription('email-subscription');

  subscription.on('message', async (message) => {
    const order = JSON.parse(message.data.toString());
    await sendOrderConfirmationEmail(order);
    message.ack();
  });
}

// Subscriber 2: Analytics Service
async function subscribeAnalyticsService() {
  const subscription = pubsub.subscription('analytics-subscription');

  subscription.on('message', async (message) => {
    const order = JSON.parse(message.data.toString());
    await trackOrderMetrics(order);
    message.ack();
  });
}

Best Practices​

  • Create separate subscriptions for each consumer
  • Implement idempotency in all subscribers
  • Use message attributes for filtering
  • Monitor subscription backlog

2. Work Queue Pattern​

Description​

Multiple workers compete to process messages from a single subscription. Load is distributed across workers automatically.

Use Cases​

  • Image processing pipelines
  • Batch job processing
  • Task distribution across worker pools

Architecture​

Publisher → Topic → Subscription → Worker 1
                                 → Worker 2
                                 → Worker 3

Implementation Example​

import { PubSub, Message } from '@google-cloud/pubsub';

const pubsub = new PubSub();
const subscriptionName = 'image-processing-subscription';

// Configure subscription for parallel processing
async function createWorkQueueSubscription() {
  const subscription = pubsub.subscription(subscriptionName);

  // Configure flow control
  subscription.setOptions({
    flowControl: {
      maxMessages: 10, // Process 10 messages concurrently
      allowExcessMessages: false,
    },
    ackDeadline: 600, // 10 minutes for processing
  });

  return subscription;
}

// Worker implementation
async function startWorker(workerId: string) {
  const subscription = await createWorkQueueSubscription();

  subscription.on('message', async (message: Message) => {
    console.log(`Worker ${workerId} processing message ${message.id}`);

    try {
      const task = JSON.parse(message.data.toString());
      await processImage(task);
      message.ack();
    } catch (error) {
      console.error(`Worker ${workerId} error:`, error);
      message.nack(); // Requeue for retry
    }
  });
}

// Start multiple workers
async function startWorkerPool(workerCount: number) {
  for (let i = 0; i < workerCount; i++) {
    await startWorker(`worker-${i}`);
  }
}

startWorkerPool(5);

Best Practices​

  • Set appropriate maxMessages for flow control
  • Use longer ackDeadline for long-running tasks
  • Implement graceful shutdown handling
  • Monitor worker health and task duration

3. Dead Letter Queue Pattern​

Description​

Messages that fail processing repeatedly are moved to a separate topic for analysis and manual intervention.

Use Cases​

  • Error handling and debugging
  • Failed transaction recovery
  • Data quality monitoring

Architecture​

Publisher → Topic → Subscription → Processor
                                 ↓ (on failure)
                              Dead Letter Topic → DLQ Subscription

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';

const pubsub = new PubSub();

// Create dead letter topic
async function setupDeadLetterQueue() {
  const dlqTopicName = 'order-processing-dlq';
  const [dlqTopic] = await pubsub.createTopic(dlqTopicName);

  // Create main subscription with DLQ configuration
  const [subscription] = await pubsub.topic('order-processing').createSubscription('order-subscription', {
    deadLetterPolicy: {
      deadLetterTopic: dlqTopic.name,
      maxDeliveryAttempts: 5,
    },
  });

  return { subscription, dlqTopic };
}

// Process messages with retry logic
async function processWithDLQ() {
  const subscription = pubsub.subscription('order-subscription');

  subscription.on('message', async (message) => {
    try {
      const order = JSON.parse(message.data.toString());
      await processOrder(order);
      message.ack();
    } catch (error) {
      console.error('Processing error:', error);
      // Don't ack - message will be redelivered
      // After 5 attempts, it goes to DLQ
      message.nack();
    }
  });
}

// Monitor and handle DLQ messages
async function monitorDLQ() {
  const dlqSubscription = pubsub.subscription('order-processing-dlq-subscription');

  dlqSubscription.on('message', async (message) => {
    console.error('Message in DLQ:', message.data.toString());
    console.error('Attributes:', message.attributes);

    // Log to error tracking system
    await logToDLQMonitoring({
      messageId: message.id,
      data: message.data.toString(),
      deliveryAttempt: message.deliveryAttempt,
    });

    message.ack();
  });
}

Best Practices​

  • Set appropriate maxDeliveryAttempts (3-10)
  • Monitor DLQ metrics and alerts
  • Implement automated DLQ message analysis
  • Create processes for DLQ message recovery

4. Request-Response Pattern​

Description​

Implement synchronous-like request-response communication using Pub/Sub for better decoupling.

Use Cases​

  • Service-to-service communication
  • Async API calls
  • Long-running operations with callbacks

Architecture​

Requester → Request Topic → Worker
               ↑                ↓
               └─── Response Topic ←┘

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';
import { v4 as uuidv4 } from 'uuid';

const pubsub = new PubSub();

// Requester side
class PubSubRequester {
  private responseHandlers: Map<string, Function> = new Map();

  constructor() {
    this.setupResponseListener();
  }

  async request(requestData: any, timeout: number = 30000): Promise<any> {
    const correlationId = uuidv4();
    const replyTo = 'response-topic';

    // Setup response handler
    const responsePromise = new Promise((resolve, reject) => {
      const timeoutId = setTimeout(() => {
        this.responseHandlers.delete(correlationId);
        reject(new Error('Request timeout'));
      }, timeout);

      this.responseHandlers.set(correlationId, (response: any) => {
        clearTimeout(timeoutId);
        resolve(response);
      });
    });

    // Send request
    await pubsub.topic('request-topic').publish(Buffer.from(JSON.stringify(requestData)), {
      correlationId,
      replyTo,
    });

    return responsePromise;
  }

  private setupResponseListener() {
    const subscription = pubsub.subscription('response-subscription');

    subscription.on('message', (message) => {
      const correlationId = message.attributes.correlationId;
      const handler = this.responseHandlers.get(correlationId);

      if (handler) {
        const response = JSON.parse(message.data.toString());
        handler(response);
        this.responseHandlers.delete(correlationId);
      }

      message.ack();
    });
  }
}

// Worker side
async function setupWorker() {
  const subscription = pubsub.subscription('request-subscription');

  subscription.on('message', async (message) => {
    const request = JSON.parse(message.data.toString());
    const correlationId = message.attributes.correlationId;
    const replyTo = message.attributes.replyTo;

    try {
      // Process request
      const result = await processRequest(request);

      // Send response
      await pubsub.topic(replyTo).publish(Buffer.from(JSON.stringify(result)), { correlationId });

      message.ack();
    } catch (error) {
      console.error('Error processing request:', error);
      message.nack();
    }
  });
}

// Usage
const requester = new PubSubRequester();
const response = await requester.request({ operation: 'getUser', userId: 123 });

Best Practices​

  • Use correlation IDs for matching responses
  • Implement timeout handling
  • Clean up orphaned response handlers
  • Consider using Cloud Tasks for simpler request-response

5. Priority Queue Pattern​

Description​

Process messages with different priorities by using multiple topics/subscriptions or message attributes.

Use Cases​

  • Critical vs. non-critical operations
  • Real-time vs. batch processing
  • SLA-based processing

Architecture​

Publisher → High Priority Topic → Fast Processor
         → Medium Priority Topic → Normal Processor
         → Low Priority Topic → Batch Processor

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';

const pubsub = new PubSub();

// Publisher with priority
async function publishWithPriority(message: any, priority: 'high' | 'medium' | 'low') {
  const topicName = `tasks-${priority}-priority`;
  const dataBuffer = Buffer.from(JSON.stringify(message));

  await pubsub.topic(topicName).publish(dataBuffer, {
    priority,
    timestamp: new Date().toISOString(),
  });
}

// Alternative: Single topic with filtering
async function publishWithAttributeFilter(message: any, priority: number) {
  await pubsub.topic('tasks').publish(Buffer.from(JSON.stringify(message)), { priority: priority.toString() });
}

// Create filtered subscription
async function createPrioritySubscription() {
  const [subscription] = await pubsub.topic('tasks').createSubscription('high-priority-tasks', {
    filter: 'attributes.priority = "high"',
  });

  return subscription;
}

// Priority-based processor
class PriorityProcessor {
  async start() {
    // High priority - 10 workers
    this.setupProcessor('tasks-high-priority', 'high-priority-sub', 10, 5);

    // Medium priority - 5 workers
    this.setupProcessor('tasks-medium-priority', 'medium-priority-sub', 5, 30);

    // Low priority - 2 workers
    this.setupProcessor('tasks-low-priority', 'low-priority-sub', 2, 60);
  }

  private setupProcessor(topicName: string, subName: string, maxMessages: number, ackDeadline: number) {
    const subscription = pubsub.subscription(subName);

    subscription.setOptions({
      flowControl: { maxMessages },
      ackDeadline,
    });

    subscription.on('message', async (message) => {
      const task = JSON.parse(message.data.toString());
      await this.processTask(task, message.attributes.priority);
      message.ack();
    });
  }

  private async processTask(task: any, priority: string) {
    console.log(`Processing ${priority} priority task:`, task);
    // Task processing logic
  }
}

Best Practices​

  • Use separate topics for distinct priority levels
  • Configure appropriate flow control per priority
  • Monitor queue depths by priority
  • Implement priority elevation for aging messages

6. Event Sourcing Pattern​

Description​

Store all changes to application state as a sequence of events in Pub/Sub topics.

Use Cases​

  • Audit logging
  • Event replay and debugging
  • CQRS implementations
  • Temporal queries

Architecture​

Command → Event Store (Topic) → Event Subscription → Read Model
                              → Audit Subscription → Audit Log
                              → Snapshot Subscription → Snapshot Store

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';

const pubsub = new PubSub();

// Event types
interface DomainEvent {
  eventId: string;
  eventType: string;
  aggregateId: string;
  aggregateType: string;
  timestamp: string;
  version: number;
  data: any;
}

// Event publisher
class EventStore {
  private topic = pubsub.topic('event-store');

  async appendEvent(event: DomainEvent): Promise<void> {
    const messageId = await this.topic.publish(Buffer.from(JSON.stringify(event)), {
      eventType: event.eventType,
      aggregateId: event.aggregateId,
      aggregateType: event.aggregateType,
      version: event.version.toString(),
    });

    console.log(`Event ${event.eventId} stored with message ID: ${messageId}`);
  }
}

// Example: Order aggregate events
class OrderEventStore extends EventStore {
  async createOrder(orderId: string, orderData: any): Promise<void> {
    await this.appendEvent({
      eventId: generateId(),
      eventType: 'OrderCreated',
      aggregateId: orderId,
      aggregateType: 'Order',
      timestamp: new Date().toISOString(),
      version: 1,
      data: orderData,
    });
  }

  async updateOrderStatus(orderId: string, status: string, version: number): Promise<void> {
    await this.appendEvent({
      eventId: generateId(),
      eventType: 'OrderStatusUpdated',
      aggregateId: orderId,
      aggregateType: 'Order',
      timestamp: new Date().toISOString(),
      version,
      data: { status },
    });
  }
}

// Event projector - builds read models
class OrderProjector {
  private subscription = pubsub.subscription('order-projector');

  async start(): Promise<void> {
    this.subscription.on('message', async (message) => {
      const event: DomainEvent = JSON.parse(message.data.toString());

      try {
        await this.projectEvent(event);
        message.ack();
      } catch (error) {
        console.error('Projection error:', error);
        message.nack();
      }
    });
  }

  private async projectEvent(event: DomainEvent): Promise<void> {
    switch (event.eventType) {
      case 'OrderCreated':
        await this.createOrderReadModel(event);
        break;
      case 'OrderStatusUpdated':
        await this.updateOrderReadModel(event);
        break;
    }
  }

  private async createOrderReadModel(event: DomainEvent): Promise<void> {
    // Update read database
    await db.orders.insert({
      id: event.aggregateId,
      ...event.data,
      version: event.version,
      createdAt: event.timestamp,
    });
  }

  private async updateOrderReadModel(event: DomainEvent): Promise<void> {
    await db.orders.update(
      { id: event.aggregateId },
      {
        status: event.data.status,
        version: event.version,
        updatedAt: event.timestamp,
      },
    );
  }
}

// Event replay for rebuilding read models
class EventReplayer {
  async replayEvents(aggregateId: string): Promise<any[]> {
    const events: any[] = [];
    const subscription = pubsub.subscription('replay-subscription');

    return new Promise((resolve, reject) => {
      subscription.on('message', (message) => {
        if (message.attributes.aggregateId === aggregateId) {
          events.push(JSON.parse(message.data.toString()));
        }
        message.ack();
      });

      setTimeout(() => resolve(events), 5000); // Collect for 5 seconds
    });
  }
}

Best Practices​

  • Use message ordering for aggregate consistency
  • Include version numbers for optimistic locking
  • Implement event snapshots for performance
  • Store events in Cloud Storage for long-term retention

7. Saga Pattern​

Description​

Coordinate distributed transactions across multiple services using event-driven choreography or orchestration.

Use Cases​

  • Multi-service transactions
  • Order processing workflows
  • Payment processing
  • Booking systems

Architecture​

Order Service → Topic → Payment Service → Topic → Inventory Service
      ↑                      ↓                          ↓
      └──── Compensation Topic ←────────────────────────┘

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';

const pubsub = new PubSub();

// Saga orchestrator
class OrderSagaOrchestrator {
  async startOrderSaga(orderData: any): Promise<void> {
    const sagaId = generateId();

    const sagaState = {
      sagaId,
      orderData,
      steps: [
        { name: 'ValidateOrder', status: 'pending' },
        { name: 'ProcessPayment', status: 'pending' },
        { name: 'ReserveInventory', status: 'pending' },
        { name: 'ShipOrder', status: 'pending' },
      ],
    };

    await this.executeSaga(sagaState);
  }

  private async executeSaga(sagaState: any): Promise<void> {
    try {
      // Step 1: Validate Order
      await this.publishCommand('validate-order', {
        sagaId: sagaState.sagaId,
        orderData: sagaState.orderData,
      });

      // Listen for order validated event
      await this.waitForEvent('order-validated', sagaState.sagaId);

      // Step 2: Process Payment
      await this.publishCommand('process-payment', {
        sagaId: sagaState.sagaId,
        amount: sagaState.orderData.total,
      });

      await this.waitForEvent('payment-processed', sagaState.sagaId);

      // Step 3: Reserve Inventory
      await this.publishCommand('reserve-inventory', {
        sagaId: sagaState.sagaId,
        items: sagaState.orderData.items,
      });

      await this.waitForEvent('inventory-reserved', sagaState.sagaId);

      // Step 4: Ship Order
      await this.publishCommand('ship-order', {
        sagaId: sagaState.sagaId,
        orderId: sagaState.orderData.id,
      });
    } catch (error) {
      console.error('Saga failed:', error);
      await this.compensate(sagaState);
    }
  }

  private async compensate(sagaState: any): Promise<void> {
    // Compensating transactions in reverse order
    const completedSteps = sagaState.steps.filter((s: any) => s.status === 'completed').reverse();

    for (const step of completedSteps) {
      await this.publishCommand(`compensate-${step.name}`, {
        sagaId: sagaState.sagaId,
      });
    }
  }

  private async publishCommand(command: string, data: any): Promise<void> {
    await pubsub.topic('saga-commands').publish(Buffer.from(JSON.stringify(data)), { command });
  }

  private async waitForEvent(eventType: string, sagaId: string): Promise<any> {
    return new Promise((resolve, reject) => {
      const subscription = pubsub.subscription('saga-events');
      const timeout = setTimeout(() => reject(new Error('Event timeout')), 30000);

      subscription.on('message', (message) => {
        if (message.attributes.eventType === eventType && message.attributes.sagaId === sagaId) {
          clearTimeout(timeout);
          resolve(JSON.parse(message.data.toString()));
          message.ack();
        }
      });
    });
  }
}

// Payment service (saga participant)
class PaymentService {
  async start(): Promise<void> {
    const subscription = pubsub.subscription('payment-commands');

    subscription.on('message', async (message) => {
      const command = message.attributes.command;
      const data = JSON.parse(message.data.toString());

      try {
        if (command === 'process-payment') {
          await this.processPayment(data);
          await this.publishEvent('payment-processed', data.sagaId);
        } else if (command === 'compensate-ProcessPayment') {
          await this.refundPayment(data);
          await this.publishEvent('payment-refunded', data.sagaId);
        }

        message.ack();
      } catch (error) {
        await this.publishEvent('payment-failed', data.sagaId, error);
        message.ack();
      }
    });
  }

  private async processPayment(data: any): Promise<void> {
    // Payment processing logic
    console.log('Processing payment:', data);
  }

  private async refundPayment(data: any): Promise<void> {
    // Refund logic
    console.log('Refunding payment:', data);
  }

  private async publishEvent(eventType: string, sagaId: string, error?: any): Promise<void> {
    await pubsub.topic('saga-events').publish(Buffer.from(JSON.stringify({ sagaId, error })), { eventType, sagaId });
  }
}

Best Practices​

  • Implement idempotent operations
  • Design compensating transactions for all steps
  • Use saga state persistence
  • Implement timeout handling
  • Monitor saga completion rates

8. Stream Processing Pattern​

Description​

Process continuous streams of data with transformations, aggregations, and windowing.

Use Cases​

  • Real-time analytics
  • Metrics aggregation
  • IoT data processing
  • Click stream analysis

Architecture​

IoT Devices → Pub/Sub → Dataflow → Aggregated Results → Pub/Sub → Dashboard
                                                                  → BigQuery

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';

const pubsub = new PubSub();

// Stream processor with windowing
class StreamProcessor {
  private windowSize = 60000; // 1 minute
  private windows: Map<string, any[]> = new Map();

  async start(): Promise<void> {
    const subscription = pubsub.subscription('sensor-data-stream');

    subscription.on('message', async (message) => {
      const data = JSON.parse(message.data.toString());
      await this.processStreamData(data);
      message.ack();
    });

    // Flush windows periodically
    setInterval(() => this.flushWindows(), this.windowSize);
  }

  private async processStreamData(data: any): Promise<void> {
    const windowKey = this.getWindowKey(data.timestamp);

    if (!this.windows.has(windowKey)) {
      this.windows.set(windowKey, []);
    }

    this.windows.get(windowKey)!.push(data);
  }

  private getWindowKey(timestamp: string): string {
    const time = new Date(timestamp).getTime();
    const windowStart = Math.floor(time / this.windowSize) * this.windowSize;
    return windowStart.toString();
  }

  private async flushWindows(): Promise<void> {
    const now = Date.now();

    for (const [windowKey, data] of this.windows.entries()) {
      const windowTime = parseInt(windowKey);

      // Flush completed windows
      if (now - windowTime >= this.windowSize) {
        await this.aggregateAndPublish(windowKey, data);
        this.windows.delete(windowKey);
      }
    }
  }

  private async aggregateAndPublish(windowKey: string, data: any[]): Promise<void> {
    const aggregated = {
      window: windowKey,
      count: data.length,
      average: data.reduce((sum, d) => sum + d.value, 0) / data.length,
      min: Math.min(...data.map((d) => d.value)),
      max: Math.max(...data.map((d) => d.value)),
    };

    await pubsub.topic('aggregated-metrics').publish(Buffer.from(JSON.stringify(aggregated)));
  }
}

// Stateful stream processor with session windows
class SessionWindowProcessor {
  private sessions: Map<string, any> = new Map();
  private sessionTimeout = 300000; // 5 minutes

  async start(): Promise<void> {
    const subscription = pubsub.subscription('user-activity-stream');

    subscription.on('message', async (message) => {
      const activity = JSON.parse(message.data.toString());
      await this.processActivity(activity);
      message.ack();
    });

    // Check for expired sessions
    setInterval(() => this.expireSessions(), 60000);
  }

  private async processActivity(activity: any): Promise<void> {
    const userId = activity.userId;
    const now = Date.now();

    if (!this.sessions.has(userId)) {
      this.sessions.set(userId, {
        userId,
        activities: [],
        startTime: now,
        lastActivity: now,
      });
    }

    const session = this.sessions.get(userId)!;
    session.activities.push(activity);
    session.lastActivity = now;
  }

  private async expireSessions(): Promise<void> {
    const now = Date.now();

    for (const [userId, session] of this.sessions.entries()) {
      if (now - session.lastActivity >= this.sessionTimeout) {
        await this.finalizeSession(session);
        this.sessions.delete(userId);
      }
    }
  }

  private async finalizeSession(session: any): Promise<void> {
    const sessionSummary = {
      userId: session.userId,
      duration: session.lastActivity - session.startTime,
      activityCount: session.activities.length,
      activities: session.activities,
    };

    await pubsub.topic('user-sessions').publish(Buffer.from(JSON.stringify(sessionSummary)));
  }
}

// Real-time analytics pipeline
class ClickStreamAnalytics {
  private counters: Map<string, number> = new Map();

  async start(): Promise<void> {
    const subscription = pubsub.subscription('clickstream');

    subscription.on('message', async (message) => {
      const event = JSON.parse(message.data.toString());
      await this.updateMetrics(event);
      message.ack();
    });

    // Publish metrics every 10 seconds
    setInterval(() => this.publishMetrics(), 10000);
  }

  private async updateMetrics(event: any): Promise<void> {
    const key = `${event.page}:${event.action}`;
    this.counters.set(key, (this.counters.get(key) || 0) + 1);
  }

  private async publishMetrics(): Promise<void> {
    const metrics = Array.from(this.counters.entries()).map(([key, count]) => {
      const [page, action] = key.split(':');
      return { page, action, count };
    });

    await pubsub.topic('realtime-metrics').publish(
      Buffer.from(
        JSON.stringify({
          timestamp: new Date().toISOString(),
          metrics,
        }),
      ),
    );

    // Reset counters
    this.counters.clear();
  }
}

Best Practices​

  • Use Dataflow for complex stream processing
  • Implement watermarking for late data handling
  • Choose appropriate window types (tumbling, sliding, session)
  • Handle backpressure with flow control
  • Monitor processing lag

9. Cache Invalidation Pattern​

Description​

Use Pub/Sub to coordinate cache invalidation across distributed services.

Use Cases​

  • Multi-instance cache synchronization
  • CDN cache purging
  • Distributed cache updates
  • Read-through cache coordination

Architecture​

Update Service → Data Store → Cache Invalidation Topic → Cache Instance 1
                                                       → Cache Instance 2
                                                       → CDN

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';
import { createClient } from 'redis';

const pubsub = new PubSub();
const redis = createClient();

// Cache manager with Pub/Sub invalidation
class DistributedCacheManager {
  private cacheInvalidationTopic = 'cache-invalidation';

  constructor() {
    this.setupInvalidationListener();
  }

  async set(key: string, value: any, ttl: number = 3600): Promise<void> {
    // Update local cache
    await redis.setEx(key, ttl, JSON.stringify(value));

    // Notify other instances
    await this.publishInvalidation('set', key, value);
  }

  async delete(key: string): Promise<void> {
    // Delete from local cache
    await redis.del(key);

    // Notify other instances
    await this.publishInvalidation('delete', key);
  }

  async invalidatePattern(pattern: string): Promise<void> {
    // Find and delete matching keys
    const keys = await redis.keys(pattern);
    if (keys.length > 0) {
      await redis.del(keys);
    }

    // Notify other instances
    await this.publishInvalidation('invalidate-pattern', pattern);
  }

  private async publishInvalidation(operation: string, key: string, value?: any): Promise<void> {
    await pubsub.topic(this.cacheInvalidationTopic).publish(Buffer.from(JSON.stringify({ operation, key, value })), {
      operation,
      instanceId: process.env.INSTANCE_ID || 'unknown',
    });
  }

  private setupInvalidationListener(): void {
    const subscription = pubsub.subscription('cache-invalidation-sub');

    subscription.on('message', async (message) => {
      // Ignore messages from this instance
      if (message.attributes.instanceId === process.env.INSTANCE_ID) {
        message.ack();
        return;
      }

      const { operation, key, value } = JSON.parse(message.data.toString());

      try {
        switch (operation) {
          case 'set':
            await redis.setEx(key, 3600, JSON.stringify(value));
            break;
          case 'delete':
            await redis.del(key);
            break;
          case 'invalidate-pattern':
            const keys = await redis.keys(key);
            if (keys.length > 0) {
              await redis.del(keys);
            }
            break;
        }

        message.ack();
      } catch (error) {
        console.error('Cache invalidation error:', error);
        message.nack();
      }
    });
  }
}

// Application service with cache
class ProductService {

10. Circuit Breaker Pattern​

Description​

Monitor service health and automatically stop sending messages to failing services.

Use Cases​

  • Fault tolerance
  • Cascading failure prevention
  • Service degradation handling
  • Health monitoring

Architecture​

Publisher → Health Monitor → Circuit Breaker → Healthy Service
                           ↓ (on failure)
                      Fallback Service / Queue

Implementation Example​

import { PubSub } from '@google-cloud/pubsub';

const pubsub = new PubSub();

// Circuit breaker states
enum CircuitState {
  CLOSED = 'CLOSED', // Normal operation
  OPEN = 'OPEN', // Failing, reject requests
  HALF_OPEN = 'HALF_OPEN', // Testing if service recovered
}

// Circuit breaker implementation
class CircuitBreaker {
  private state: CircuitState = CircuitState.CLOSED;
  private failureCount = 0;
  private successCount = 0;
  private lastFailureTime?: number;

  constructor(
    private failureThreshold: number = 5,
    private resetTimeout: number = 60000,
    private halfOpenAttempts: number = 3,
  ) {}

  async execute<T>(operation: () => Promise<T>): Promise<T> {
    if (this.state === CircuitState.OPEN) {
      if (this.shouldAttemptReset()) {
        this.state = CircuitState.HALF_OPEN;
        this.successCount = 0;
      } else {
        throw new Error('Circuit breaker is OPEN');
      }
    }

    try {
      const result = await operation();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  private onSuccess(): void {
    this.failureCount = 0;

    if (this.state === CircuitState.HALF_OPEN) {
      this.successCount++;
      if (this.successCount >= this.halfOpenAttempts) {
        this.state = CircuitState.CLOSED;
        console.log('Circuit breaker closed - service recovered');
      }
    }
  }

  private onFailure(): void {
    this.failureCount++;
    this.lastFailureTime = Date.now();

    if (this.failureCount >= this.failureThreshold) {
      this.state = CircuitState.OPEN;
      console.error('Circuit breaker opened - service failing');

      // Publish circuit breaker event
      this.publishCircuitBreakerEvent('OPENED');
    }
  }

  private shouldAttemptReset(): boolean {
    return this.lastFailureTime ? Date.now() - this.lastFailureTime >= this.resetTimeout : false;
  }

  getState(): CircuitState {
    return this.state;
  }

  private async publishCircuitBreakerEvent(event: string): Promise<void> {
    await pubsub.topic('circuit-breaker-events').publish(
      Buffer.from(
        JSON.stringify({
          event,
          timestamp: new Date().toISOString(),
          failureCount: this.failureCount,
        }),
      ),
    );
  }
}

// Service with circuit breaker
class ResilientMessagePublisher {
  private circuitBreaker: CircuitBreaker;
  private fallbackQueue: any[] = [];

  constructor(private topicName: string, private fallbackTopicName: string) {
    this.circuitBreaker = new CircuitBreaker(5, 60000, 3);
    this.monitorCircuitBreaker();
  }

  async publish(data: any): Promise<void> {
    try {
      await this.circuitBreaker.execute(async () => {
        await pubsub.topic(this.topicName).publish(Buffer.from(JSON.stringify(data)));
      });
    } catch (error) {
      console.error('Primary publish failed:', error);

      if (this.circuitBreaker.getState() === CircuitState.OPEN) {
        // Use fallback
        await this.publishToFallback(data);
      } else {
        throw error;
      }
    }
  }

  private async publishToFallback(data: any): Promise<void> {
    console.log('Using fallback topic');
    await pubsub.topic(this.fallbackTopicName).publish(Buffer.from(JSON.stringify(data)), { fallback: 'true' });
  }

  private monitorCircuitBreaker(): void {
    const subscription = pubsub.subscription('circuit-breaker-events-sub');

    subscription.on('message', async (message) => {
      const event = JSON.parse(message.data.toString());

      if (event.event === 'OPENED') {
        // Alert operations team
        await this.sendAlert('Circuit breaker opened', event);

        // Start retry queue processor
        this.processRetryQueue();
      }

      message.ack();
    });
  }

  private async processRetryQueue(): Promise<void> {
    if (this.circuitBreaker.getState() !== CircuitState.CLOSED) {
      return;
    }

    while (this.fallbackQueue.length > 0) {
      const item = this.fallbackQueue.shift();
      try {
        await this.publish(item);
      } catch (error) {
        this.fallbackQueue.unshift(item);
        break;
      }
    }
  }

  private async sendAlert(message: string, details: any): Promise<void> {
    await pubsub.topic('alerts').publish(Buffer.from(JSON.stringify({ message, details })));
  }
}

// Health check subscriber with circuit breaker
class HealthMonitoredSubscriber {
  private circuitBreaker: CircuitBreaker;
  private metrics = {
    processed: 0,
    failed: 0,
    lastError: null as any,
  };

  constructor(private subscriptionName: string) {
    this.circuitBreaker = new CircuitBreaker();
    this.startHealthReporting();
  }

  async start(): Promise<void> {
    const subscription = pubsub.subscription(this.subscriptionName);

    subscription.on('message', async (message) => {
      try {
        await this.circuitBreaker.execute(async () => {
          await this.processMessage(message);
        });

        this.metrics.processed++;
        message.ack();
      } catch (error) {
        this.metrics.failed++;
        this.metrics.lastError = error;

        if (this.circuitBreaker.getState() === CircuitState.OPEN) {
          // Don't ack - let message retry later
          message.nack();
        } else {
          message.ack();
        }
      }
    });
  }

  private async processMessage(message: any): Promise<void> {
    const data = JSON.parse(message.data.toString());
    // Processing logic
  }

  private startHealthReporting(): void {
    setInterval(async () => {
      await pubsub.topic('health-metrics').publish(
        Buffer.from(
          JSON.stringify({
            service: this.subscriptionName,
            circuitState: this.circuitBreaker.getState(),
            metrics: this.metrics,
            timestamp: new Date().toISOString(),
          }),
        ),
      );
    }, 30000); // Report every 30 seconds
  }
}

  • Audit message access
  • Implement message validation

Conclusion​

These 10 pub/sub architecture patterns provide robust solutions for building scalable, resilient distributed systems. Choose patterns based on your specific requirements for:

  • Scalability needs: Work Queue, Fan-Out
