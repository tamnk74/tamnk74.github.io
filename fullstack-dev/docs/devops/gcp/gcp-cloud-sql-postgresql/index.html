GCP Cloud SQL PostgreSQL

Google Cloud SQL for PostgreSQL is a fully managed database service that makes it easy to set up, maintain, manage, and administer your PostgreSQL databases in the cloud. This guide covers logging configuration, monitoring, and best practices.

Overview​

Cloud SQL for PostgreSQL provides:

  • Fully Managed: Automated backups, replication, patches, and updates
  • High Availability: Built-in failover and read replicas
  • Security: Data encryption at rest and in transit
  • Scalability: Vertical and horizontal scaling options
  • Integration: Seamless integration with other GCP services

Logging Configuration​

Enabling comprehensive logging is crucial for monitoring, debugging, and security auditing.

Essential Logging Flags​

1. Query Logging​

log_statement

Controls which SQL statements are logged:

# Using gcloud CLI
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_statement=all

# Options:
# - none: No statements logged (default)
# - ddl: Only DDL statements (CREATE, ALTER, DROP)
# - mod: DDL + DML modifications (INSERT, UPDATE, DELETE)
# - all: All statements including SELECT

log_min_duration_statement

Log queries that take longer than specified milliseconds:

# Log queries taking longer than 1000ms (1 second)
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_min_duration_statement=1000

# Set to 0 to log all queries (use carefully - high overhead)
# Set to -1 to disable (default)

2. Connection Logging​

log_connections

Log all successful connections:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_connections=on

log_disconnections

Log session terminations with duration:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_disconnections=on

3. Error and Warning Logging​

log_min_messages

Sets minimum severity level to log:

# Options: DEBUG5, DEBUG4, DEBUG3, DEBUG2, DEBUG1, INFO, NOTICE, WARNING, ERROR, LOG, FATAL, PANIC
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_min_messages=WARNING

log_min_error_statement

Log statements causing errors at or above this level:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_min_error_statement=ERROR

log_error_verbosity

Controls the verbosity of logged error messages:

# Options: TERSE, DEFAULT, VERBOSE
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_error_verbosity=DEFAULT

# TERSE: Excludes DETAIL, HINT, QUERY, and CONTEXT
# DEFAULT: Includes DETAIL, HINT, QUERY (excludes CONTEXT)
# VERBOSE: Includes all fields including CONTEXT and SQLSTATE

4. Lock and Deadlock Logging​

log_lock_waits

Log long lock waits (controlled by deadlock_timeout):

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_lock_waits=on,deadlock_timeout=1000

deadlock_timeout

Time in milliseconds before checking for deadlock:

# Default: 1000ms
gcloud sql instances patch INSTANCE_NAME \
  --database-flags deadlock_timeout=1000

5. Checkpoint and Autovacuum Logging​

log_checkpoints

Log checkpoint activities:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_checkpoints=on

log_autovacuum_min_duration

Log autovacuum actions taking longer than specified time:

# Log autovacuum operations taking longer than 250ms
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_autovacuum_min_duration=250

Comprehensive Logging Setup​

For production environments, use this recommended configuration:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags \
log_connections=on,\
log_disconnections=on,\
log_duration=off,\
log_lock_waits=on,\
log_statement=ddl,\
log_min_duration_statement=1000,\
log_checkpoints=on,\
log_autovacuum_min_duration=250,\
log_min_messages=WARNING,\
log_min_error_statement=ERROR,\
log_error_verbosity=DEFAULT,\
log_temp_files=0

Additional Useful Flags​

log_duration

Log duration of every completed statement:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_duration=on

log_temp_files

Log temporary file creation above specified size (in KB):

# Log temp files larger than 0 KB (all temp files)
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_temp_files=0

log_line_prefix

Customize log line format:

# Include timestamp, user, database, PID, and client address
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_line_prefix='%t [%u@%d] [%p]: '

# Format placeholders:
# %t - timestamp
# %u - user name
# %d - database name
# %p - process ID
# %h - remote host
# %a - application name
# %i - command tag
# %v - virtual transaction ID
# %x - transaction ID
# %q - stop here in non-session processes
# %e - SQLSTATE error code
# %c - session ID
# %l - log line number
# %s - process start timestamp
# %r - remote host and port
# %m - timestamp with milliseconds

log_hostname

Resolve IP addresses to hostnames in logs:

# Enable hostname logging (may add DNS lookup overhead)
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_hostname=on

# Default: off (shows IP addresses only)

log_timezone

Set timezone for log timestamps:

# Set to specific timezone
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_timezone='UTC'

# Or use your local timezone
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_timezone='America/New_York'

6. Replication and Recovery Logging​

log_replication_commands

Log replication commands from replication connections:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_replication_commands=on

log_recovery_conflict_waits

Log standby recovery conflict waits exceeding deadlock_timeout:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_recovery_conflict_waits=on

7. Statement Statistics Logging​

log_statement_stats

Log cumulative performance statistics for each query:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_statement_stats=on

# Warning: Cannot be used with individual stats flags below

log_parser_stats

Log parser performance statistics:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_parser_stats=on

log_planner_stats

Log planner performance statistics:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_planner_stats=on

log_executor_stats

Log executor performance statistics:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_executor_stats=on

8. Transaction and Execution Context​

log_transaction_sample_rate

Fraction of transactions to log (0.0 to 1.0):

# Log 10% of all transactions
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_transaction_sample_rate=0.1

# Useful for high-traffic systems to reduce log volume

log_statement_sample_rate

Fraction of statements to log when log_statement=all:

# Log 5% of statements
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_statement_sample_rate=0.05

log_min_duration_sample

Log statements based on duration and sampling:

# Log 20% of statements taking longer than 100ms
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_min_duration_sample=100,log_statement_sample_rate=0.2

9. Advanced Error and Warning Options​

log_parameter_max_length

Maximum length of bind parameters to log (in bytes):

# Limit parameter logging to 1KB
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_parameter_max_length=1024

# Set to -1 for unlimited (default)
# Set to 0 to disable parameter logging

log_parameter_max_length_on_error

Maximum length of bind parameters logged on error:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_parameter_max_length_on_error=2048

log_truncate_on_rotation

Truncate (overwrite) existing log files on rotation:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_truncate_on_rotation=off

# Default: off (appends to existing files)

10. Btree Index Deletion Logging​

log_btree_build_stats

Log statistics about btree index builds:

gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_btree_build_stats=on

11. Prepared Statement Logging​

log_min_duration_statement with prepared statements

Track prepared statement performance:

# Combine with log_line_prefix to identify prepared statements
gcloud sql instances patch INSTANCE_NAME \
  --database-flags \
log_min_duration_statement=500,\
log_line_prefix='%t [%p] %q%a %u@%d '

Flag Compatibility Notes​

Mutually Exclusive Flags

  • Cannot use log_statement_stats=on with individual stats flags (log_parser_stats, log_planner_stats, log_executor_stats)
  • Choose either combined or individual statistics

Flag Dependencies

  • log_statement_sample_rate only applies when log_statement=all
  • log_transaction_sample_rate samples entire transactions
  • log_hostname=on adds DNS lookup latency to connections

PostgreSQL Version Considerations

Some flags require specific PostgreSQL versions:

  • log_recovery_conflict_waits - PostgreSQL 14+
  • log_transaction_sample_rate - PostgreSQL 12+
  • log_statement_sample_rate - PostgreSQL 13+
  • log_parameter_max_length - PostgreSQL 13+

Check your Cloud SQL PostgreSQL version:

gcloud sql instances describe INSTANCE_NAME \
  --format="value(databaseVersion)"

Viewing Logs​

Using Cloud Console​

  1. Navigate to Cloud SQL Instances
  2. Click on your instance
  3. Select "Logs" from the left menu
  4. Filter logs using Cloud Logging queries

Using gcloud CLI​

# View recent logs
gcloud logging read "resource.type=cloudsql_database AND \
  resource.labels.database_id=PROJECT_ID:INSTANCE_NAME" \
  --limit 50 --format json

# Filter by severity
gcloud logging read "resource.type=cloudsql_database AND \
  severity>=ERROR" --limit 50

# Tail logs in real-time
gcloud logging tail "resource.type=cloudsql_database AND \
  resource.labels.database_id=PROJECT_ID:INSTANCE_NAME"

Using Log Explorer​

resource.type="cloudsql_database"
resource.labels.database_id="PROJECT_ID:INSTANCE_NAME"
textPayload=~"ERROR"

Best Practices​

  1. Start Conservative

    • Begin with log_statement=ddl and log_min_duration_statement=1000
    • Avoid log_statement=all in production (high overhead)

  2. Monitor Log Volume

    • Excessive logging can impact performance and increase costs
    • Use Cloud Logging quotas and metrics

  3. Set Appropriate Retention

    # Create log sink with retention
    gcloud logging sinks create cloudsql-logs \
      storage.googleapis.com/BUCKET_NAME \
      --log-filter='resource.type="cloudsql_database"'

  4. Use Log-based Metrics

    # Create metric for slow queries
    gcloud logging metrics create slow_queries \
      --description="Queries taking >5 seconds" \
      --log-filter='resource.type="cloudsql_database" AND
        textPayload=~"duration: [5-9][0-9]{3}\.[0-9]+ ms"'

  5. Security Considerations

    • Be cautious with log_statement=all (may log sensitive data)
    • Restrict access to logs using IAM roles
    • Consider using Cloud Data Loss Prevention (DLP) for sensitive logs

Troubleshooting​

Problem: Flags not updating

# Verify flags are set
gcloud sql instances describe INSTANCE_NAME \
  --format="value(settings.databaseFlags)"

# Restart might be required for some flags
gcloud sql instances restart INSTANCE_NAME

Problem: Too many logs

# Reduce verbosity
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_statement=none,log_duration=off

# Focus on slow queries only
gcloud sql instances patch INSTANCE_NAME \
  --database-flags log_min_duration_statement=5000

Problem: Missing logs

# Check Cloud Logging is enabled
gcloud services enable logging.googleapis.com

# Verify IAM permissions (requires logging.logEntries.list)
gcloud projects get-iam-policy PROJECT_ID
