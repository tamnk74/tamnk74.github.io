Overview​

Observability is the ability to understand the internal state of your system by examining its outputs. Google Cloud Platform provides a comprehensive suite of tools for monitoring, logging, tracing, and debugging applications.

The Three Pillars of Observability​

  1. Metrics: Numerical data that shows system performance over time
  2. Logs: Detailed event records from applications and infrastructure
  3. Traces: End-to-end journey of requests through distributed systems

Why GCP Cloud Operations?​

  • Unified Platform: Single pane of glass for all observability data
  • Scalability: Handles petabytes of data without performance degradation
  • Integration: Native integration with all GCP services
  • Intelligence: AI-powered anomaly detection and insights
  • Cost-Effective: Pay-per-use pricing with generous free tier

Custom Metrics​

Using OpenTelemetry with NestJS​

// metrics.module.ts
import { Module } from '@nestjs/common';
import { MeterProvider } from '@opentelemetry/sdk-metrics';
import { GoogleCloudMetricExporter } from '@google-cloud/opentelemetry-cloud-monitoring-exporter';

@Module({})
export class MetricsModule {
  constructor() {
    this.setupMetrics();
  }

  private setupMetrics() {
    const exporter = new GoogleCloudMetricExporter({
      projectId: process.env.GCP_PROJECT_ID,
    });

    const meterProvider = new MeterProvider({
      readers: [
        {
          exporter,
          interval: 60000, // Export every 60 seconds
        },
      ],
    });

    global.meterProvider = meterProvider;
  }
}

Recording Custom Metrics​

// order.service.ts
import { Injectable } from '@nestjs/common';

@Injectable()
export class OrderService {
  private orderCounter: Counter;
  private orderValueHistogram: Histogram;

  constructor() {
    const meter = global.meterProvider.getMeter('ecommerce-orders');

    this.orderCounter = meter.createCounter('orders_total', {
      description: 'Total number of orders',
    });

    this.orderValueHistogram = meter.createHistogram('order_value', {
      description: 'Distribution of order values',
      unit: 'USD',
    });
  }

  async createOrder(orderData: CreateOrderDto) {
    try {
      const order = await this.saveOrder(orderData);

      // Record metrics
      this.orderCounter.add(1, {
        status: 'success',
        payment_method: orderData.paymentMethod,
      });

      this.orderValueHistogram.record(order.totalAmount, {
        currency: order.currency,
      });

      return order;
    } catch (error) {
      this.orderCounter.add(1, { status: 'failed' });
      throw error;
    }
  }
}

Example: Comprehensive Metrics for E-commerce​

// metrics.service.ts
import { Injectable } from '@nestjs/common';
import { Meter } from '@opentelemetry/api';

@Injectable()
export class MetricsService {
  private meter: Meter;

  // Counters
  private httpRequestsTotal: Counter;
  private dbQueriesTotal: Counter;
  private cacheHitsTotal: Counter;
  private cacheMissesTotal: Counter;

  // Histograms
  private httpRequestDuration: Histogram;
  private dbQueryDuration: Histogram;

  // Gauges
  private activeConnections: ObservableGauge;
  private queueSize: ObservableGauge;

  constructor() {
    this.meter = global.meterProvider.getMeter('ecommerce-api');
    this.initializeMetrics();
  }

  private initializeMetrics() {
    // HTTP Metrics
    this.httpRequestsTotal = this.meter.createCounter('http_requests_total', {
      description: 'Total HTTP requests',
    });

    this.httpRequestDuration = this.meter.createHistogram('http_request_duration_seconds', {
      description: 'HTTP request duration',
      unit: 'seconds',
    });

    // Database Metrics
    this.dbQueriesTotal = this.meter.createCounter('db_queries_total', {
      description: 'Total database queries',
    });

    this.dbQueryDuration = this.meter.createHistogram('db_query_duration_seconds', {
      description: 'Database query duration',
      unit: 'seconds',
    });

    // Cache Metrics
    this.cacheHitsTotal = this.meter.createCounter('cache_hits_total', {
      description: 'Total cache hits',
    });

    this.cacheMissesTotal = this.meter.createCounter('cache_misses_total', {
      description: 'Total cache misses',
    });

    // System Metrics
    this.activeConnections = this.meter.createObservableGauge('active_connections', {
      description: 'Number of active connections',
    });

    this.queueSize = this.meter.createObservableGauge('queue_size', {
      description: 'Number of items in queue',
    });
  }

  recordHttpRequest(method: string, path: string, statusCode: number, duration: number) {
    const attributes = {
      method,
      path,
      status: statusCode.toString(),
    };

    this.httpRequestsTotal.add(1, attributes);
    this.httpRequestDuration.record(duration / 1000, attributes);
  }

  recordDatabaseQuery(operation: string, table: string, duration: number) {
    const attributes = { operation, table };

    this.dbQueriesTotal.add(1, attributes);
    this.dbQueryDuration.record(duration / 1000, attributes);
  }

  recordCacheOperation(hit: boolean, key: string) {
    const attributes = { key_prefix: key.split(':')[0] };

    if (hit) {
      this.cacheHitsTotal.add(1, attributes);
    } else {
      this.cacheMissesTotal.add(1, attributes);
    }
  }
}

Cloud Logging​

Cloud Logging stores, searches, analyzes, and alerts on log data from GCP services and applications.

Structured Logging with NestJS​

// logger.service.ts
import { Injectable, LoggerService } from '@nestjs/common';
import { Logging } from '@google-cloud/logging';

@Injectable()
export class CloudLoggingService implements LoggerService {
  private logging: Logging;
  private log: any;

  constructor() {
    this.logging = new Logging({
      projectId: process.env.GCP_PROJECT_ID,
    });

    this.log = this.logging.log('application-logs');
  }

  private async writeLog(severity: string, message: any, context?: string) {
    const metadata = {
      resource: {
        type: 'k8s_container',
        labels: {
          project_id: process.env.GCP_PROJECT_ID,
          location: process.env.GCP_REGION,
          cluster_name: process.env.GKE_CLUSTER,
          namespace_name: process.env.K8S_NAMESPACE,
          pod_name: process.env.HOSTNAME,
          container_name: process.env.CONTAINER_NAME,
        },
      },
      severity,
    };

    const entry = this.log.entry(metadata, {
      message: typeof message === 'string' ? message : JSON.stringify(message),
      context,
      timestamp: new Date().toISOString(),
      service: process.env.SERVICE_NAME,
      version: process.env.SERVICE_VERSION,
      trace: this.getCurrentTrace(),
    });

    await this.log.write(entry);
  }

  log(message: any, context?: string) {
    this.writeLog('INFO', message, context);
  }

  error(message: any, trace?: string, context?: string) {
    this.writeLog('ERROR', { message, trace }, context);
  }

  warn(message: any, context?: string) {
    this.writeLog('WARNING', message, context);
  }

  debug(message: any, context?: string) {
    this.writeLog('DEBUG', message, context);
  }

  verbose(message: any, context?: string) {
    this.writeLog('DEBUG', message, context);
  }

  private getCurrentTrace(): string | null {
    // Extract trace from OpenTelemetry context
    const span = trace.getSpan(context.active());
    if (span) {
      const spanContext = span.spanContext();
      return `projects/${process.env.GCP_PROJECT_ID}/traces/${spanContext.traceId}`;
    }
    return null;
  }
}

Log-Based Metrics​

Create metrics from log entries:

# Create a log-based metric for 500 errors
gcloud logging metrics create http_500_errors \
  --description="Count of HTTP 500 errors" \
  --log-filter='severity="ERROR" AND httpRequest.status=500'

# Create a distribution metric for response times
gcloud logging metrics create http_response_time \
  --description="HTTP response time distribution" \
  --value-extractor='EXTRACT(httpRequest.latency)' \
  --metric-kind=DELTA \
  --value-type=DISTRIBUTION

Cloud Trace​

Cloud Trace helps you understand how long it takes your application to handle requests and identify performance bottlenecks.

Setting Up Tracing with OpenTelemetry​

// tracing.ts
import { NodeTracerProvider } from '@opentelemetry/sdk-trace-node';
import { TraceExporter } from '@google-cloud/opentelemetry-cloud-trace-exporter';
import { registerInstrumentations } from '@opentelemetry/instrumentation';
import { HttpInstrumentation } from '@opentelemetry/instrumentation-http';
import { ExpressInstrumentation } from '@opentelemetry/instrumentation-express';
import { NestInstrumentation } from '@opentelemetry/instrumentation-nestjs-core';
import { PgInstrumentation } from '@opentelemetry/instrumentation-pg';
import { RedisInstrumentation } from '@opentelemetry/instrumentation-redis-4';
import { BatchSpanProcessor } from '@opentelemetry/sdk-trace-base';

export function setupTracing() {
  const provider = new NodeTracerProvider({
    resource: new Resource({
      [SemanticResourceAttributes.SERVICE_NAME]: process.env.SERVICE_NAME,
      [SemanticResourceAttributes.SERVICE_VERSION]: process.env.SERVICE_VERSION,
    }),
  });

  const exporter = new TraceExporter({
    projectId: process.env.GCP_PROJECT_ID,
  });

  provider.addSpanProcessor(new BatchSpanProcessor(exporter));

  provider.register();

  // Register instrumentations
  registerInstrumentations({
    instrumentations: [
      new HttpInstrumentation(),
      new ExpressInstrumentation(),
      new NestInstrumentation(),
      new PgInstrumentation(),
      new RedisInstrumentation(),
    ],
  });

  return provider;
}

Custom Spans​

// order.service.ts
import { Injectable } from '@nestjs/common';
import { trace, SpanStatusCode } from '@opentelemetry/api';

@Injectable()
export class OrderService {
  private tracer = trace.getTracer('order-service');

  async processOrder(orderId: string) {
    const span = this.tracer.startSpan('processOrder', {
      attributes: {
        'order.id': orderId,
      },
    });

    try {
      // Validate order
      await this.validateOrder(orderId);

      // Process payment
      const paymentSpan = this.tracer.startSpan('processPayment', {
        parent: span,
      });
      try {
        await this.processPayment(orderId);
        paymentSpan.setStatus({ code: SpanStatusCode.OK });
      } catch (error) {
        paymentSpan.setStatus({
          code: SpanStatusCode.ERROR,
          message: error.message,
        });
        throw error;
      } finally {
        paymentSpan.end();
      }

      // Update inventory
      await this.updateInventory(orderId);

      span.setStatus({ code: SpanStatusCode.OK });
      return { success: true };
    } catch (error) {
      span.setStatus({
        code: SpanStatusCode.ERROR,
        message: error.message,
      });
      span.recordException(error);
      throw error;
    } finally {
      span.end();
    }
  }
}

Error Reporting​

Cloud Error Reporting automatically groups and displays errors from your applications.

Setting Up Error Reporting​

// error-reporting.service.ts
import { Injectable, Catch, ArgumentsHost } from '@nestjs/common';
import { BaseExceptionFilter } from '@nestjs/core';
import { ErrorReporting } from '@google-cloud/error-reporting';

@Injectable()
@Catch()
export class ErrorReportingFilter extends BaseExceptionFilter {
  private errors: ErrorReporting;

  constructor() {
    super();
    this.errors = new ErrorReporting({
      projectId: process.env.GCP_PROJECT_ID,
      reportMode: 'production',
      serviceContext: {
        service: process.env.SERVICE_NAME,
        version: process.env.SERVICE_VERSION,
      },
    });
  }

  catch(exception: any, host: ArgumentsHost) {
    // Report error to Cloud Error Reporting
    this.errors.report(exception);

    // Call the base exception filter
    super.catch(exception, host);
  }
}

Using in Application​

// main.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { ErrorReportingFilter } from './error-reporting.service';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Use global error reporting filter
  app.useGlobalFilters(new ErrorReportingFilter());

  await app.listen(3000);
}
bootstrap();

Application Performance Monitoring (APM)​

Comprehensive APM implementation combining all observability tools.

APM Middleware​

// apm.middleware.ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';
import { MetricsService } from './metrics.service';
import { trace, context } from '@opentelemetry/api';

@Injectable()
export class APMMiddleware implements NestMiddleware {
  constructor(private readonly metricsService: MetricsService) {}

  use(req: Request, res: Response, next: NextFunction) {
    const startTime = Date.now();

    // Extract trace context
    const span = trace.getSpan(context.active());

    // Add trace ID to response headers
    if (span) {
      const spanContext = span.spanContext();
      res.setHeader('X-Cloud-Trace-Context', spanContext.traceId);
    }

    // Record metrics on response finish
    res.on('finish', () => {
      const duration = Date.now() - startTime;

      this.metricsService.recordHttpRequest(req.method, req.route?.path || req.path, res.statusCode, duration);
    });

    next();
  }
}

SLOs and SLIs​

Service Level Objectives (SLOs) and Service Level Indicators (SLIs) are critical for measuring service reliability.

Defining SLOs​

# slo-config.yaml
apiVersion: monitoring.googleapis.com/v1
kind: ServiceLevelObjective
metadata:
  name: order-service-availability
spec:
  serviceLevelIndicator:
    requestBased:
      goodTotalRatio:
        goodServiceFilter: |
          resource.type="k8s_container"
          resource.labels.namespace_name="ecommerce"
          resource.labels.container_name="order-service"
          metric.type="logging.googleapis.com/user/http_requests_total"
          metric.labels.status!~"5.."
        totalServiceFilter: |
          resource.type="k8s_container"
          resource.labels.namespace_name="ecommerce"
          resource.labels.container_name="order-service"
          metric.type="logging.googleapis.com/user/http_requests_total"
  goal: 0.999 # 99.9% availability
  rollingPeriod: 2592000s # 30 days

Cost Optimization​

Log Sampling​

// log-sampler.ts
export class LogSampler {
  private sampleRate: number;

  constructor(sampleRate: number = 0.1) {
    this.sampleRate = sampleRate;
  }

  shouldSample(level: string): boolean {
    // Always log errors and warnings
    if (level === 'ERROR' || level === 'WARNING') {
      return true;
    }

    // Sample other logs
    return Math.random() < this.sampleRate;
  }
}

// Usage in logger
export class SampledLogger {
  private sampler = new LogSampler(0.1); // 10% sampling

  log(level: string, message: string) {
    if (this.sampler.shouldSample(level)) {
      // Write to Cloud Logging
      this.cloudLogger.log(level, message);
    }
  }
}

Metrics Aggregation​

// metrics-aggregator.ts
export class MetricsAggregator {
  private metrics: Map<string, number> = new Map();
  private flushInterval: NodeJS.Timeout;

  constructor() {
    // Flush aggregated metrics every 60 seconds
    this.flushInterval = setInterval(() => this.flush(), 60000);
  }

  record(metricName: string, value: number) {
    const current = this.metrics.get(metricName) || 0;
    this.metrics.set(metricName, current + value);
  }

  private async flush() {
    for (const [name, value] of this.metrics.entries()) {
      await this.sendToCloudMonitoring(name, value);
    }
    this.metrics.clear();
  }
}

Best Practices Summary​

  1. Use Structured Logging: Always log in JSON format with consistent fields
  2. Implement Distributed Tracing: Track requests across all services
  3. Define SLOs Early: Set clear reliability targets
  4. Alert on Symptoms, Not Causes: Focus on user impact
  5. Use Log Sampling: Reduce costs for high-volume logs
  6. Correlate Signals: Link logs, metrics, and traces
  7. Monitor Business Metrics: Track KPIs alongside technical metrics
  8. Set Up Dashboards: Create service-specific and system-wide views
  9. Regular Review: Continuously improve observability practices
  10. Cost Awareness: Monitor and optimize observability costs

Conclusion​

Implementing comprehensive observability on GCP provides deep insights into your microservices architecture. By combining Cloud Monitoring, Logging, Trace, and Profiler with OpenTelemetry, you can achieve end-to-end visibility across your entire system.

Key takeaways:

  • Start with the golden signals: latency, traffic, errors, saturation
  • Implement structured logging from day one
  • Use distributed tracing to understand request flow
  • Define and monitor SLOs for critical services
  • Set up intelligent alerting to reduce noise
  • Optimize costs through sampling and filtering

With proper observability in place, you can confidently deploy, scale, and maintain production microservices on Google Cloud Platform.
