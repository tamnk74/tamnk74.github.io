Cloud NAT - Network Address Translation Guide

Overview​

Network Address Translation (NAT) is a method of mapping one IP address space into another by modifying network address information in the IP header of packets while they are in transit across a traffic routing device. In cloud environments, NAT services enable resources in private subnets to access the internet while remaining unreachable from inbound internet traffic.

What is NAT?​

Basic NAT Concept​

How NAT Works​

Outbound Connection (Private → Internet):

Step 1: VM sends packet
  Source: 10.0.0.10:54321
  Destination: 142.250.185.206:443 (google.com)

Step 2: NAT translates source
  Source: 34.120.45.67:45678 (NAT public IP + ephemeral port)
  Destination: 142.250.185.206:443

Step 3: NAT records mapping
  Connection Table Entry:
    Internal: 10.0.0.10:54321
    External: 34.120.45.67:45678
    Destination: 142.250.185.206:443
    Protocol: TCP
    Timeout: 600 seconds

Inbound Response (Internet → Private):

Step 1: Response arrives at NAT
  Source: 142.250.185.206:443
  Destination: 34.120.45.67:45678

Step 2: NAT looks up connection table
  Found mapping: 34.120.45.67:45678 → 10.0.0.10:54321

Step 3: NAT translates destination
  Source: 142.250.185.206:443
  Destination: 10.0.0.10:54321 (original VM)

Types of NAT​

1. Static NAT (1:1 NAT)​

One private IP maps to one public IP permanently.

Use Cases:

  • Servers needing consistent outbound IP
  • IP whitelisting requirements
  • Dedicated resources for specific services

2. Dynamic NAT​

Pool of public IPs shared dynamically among private hosts.

Use Cases:

  • Large networks with limited public IPs
  • Cost optimization
  • Flexible IP allocation

3. PAT / NAPT (Port Address Translation)​

Multiple private IPs share a single public IP using different ports.

Use Cases:

  • Most common NAT type
  • Maximum IP conservation
  • Default for Cloud NAT

Cloud NAT Configuration​

Basic Setup with gcloud​

# Create Cloud Router
gcloud compute routers create nat-router \
    --network=my-vpc \
    --region=us-central1

# Create Cloud NAT with auto-allocated IPs
gcloud compute routers nats create my-nat \
    --router=nat-router \
    --region=us-central1 \
    --auto-allocate-nat-external-ips \
    --nat-all-subnet-ip-ranges

# Create Cloud NAT with manual IP allocation
gcloud compute addresses create nat-ip-1 nat-ip-2 \
    --region=us-central1

gcloud compute routers nats create my-nat \
    --router=nat-router \
    --region=us-central1 \
    --nat-external-ip-pool=nat-ip-1,nat-ip-2 \
    --nat-all-subnet-ip-ranges

Terraform Configuration​

# Cloud Router
resource "google_compute_router" "nat_router" {
  name    = "nat-router"
  region  = "us-central1"
  network = google_compute_network.vpc.id

  bgp {
    asn = 64514
  }
}

# Reserve static NAT IPs
resource "google_compute_address" "nat_ip" {
  count  = 2
  name   = "nat-ip-${count.index}"
  region = "us-central1"
}

# Cloud NAT
resource "google_compute_router_nat" "nat" {
  name                               = "cloud-nat"
  router                             = google_compute_router.nat_router.name
  region                             = google_compute_router.nat_router.region
  nat_ip_allocate_option             = "MANUAL_ONLY"
  nat_ips                            = google_compute_address.nat_ip[*].self_link
  source_subnetwork_ip_ranges_to_nat = "ALL_SUBNETWORKS_ALL_IP_RANGES"

  log_config {
    enable = true
    filter = "ERRORS_ONLY"
  }

  # Port allocation settings
  min_ports_per_vm                    = 64
  max_ports_per_vm                    = 65536
  enable_endpoint_independent_mapping = false

  # Timeouts
  udp_idle_timeout_sec             = 30
  icmp_idle_timeout_sec            = 30
  tcp_established_idle_timeout_sec = 1200
  tcp_transitory_idle_timeout_sec  = 30
  tcp_time_wait_timeout_sec        = 120
}

Subnet-Specific NAT​

resource "google_compute_router_nat" "nat" {
  name                               = "cloud-nat"
  router                             = google_compute_router.nat_router.name
  region                             = "us-central1"
  nat_ip_allocate_option             = "AUTO_ONLY"
  source_subnetwork_ip_ranges_to_nat = "LIST_OF_SUBNETWORKS"

  # Only NAT traffic from specific subnets
  subnetwork {
    name                    = google_compute_subnetwork.private_subnet.id
    source_ip_ranges_to_nat = ["ALL_IP_RANGES"]
  }

  subnetwork {
    name                    = google_compute_subnetwork.gke_subnet.id
    source_ip_ranges_to_nat = ["PRIMARY_IP_RANGE"]
    # Exclude secondary ranges (pod/service IPs)
  }
}

NAT Use Cases​

Use Case 1: Private GKE Clusters​

Scenario: GKE nodes need to pull container images and access external APIs without public IPs.

Configuration:

# GKE Private Cluster with Cloud NAT
# terraform/gke-private-nat.tf

resource "google_container_cluster" "private_gke" {
  name     = "private-cluster"
  location = "us-central1"

  # Private cluster configuration
  private_cluster_config {
    enable_private_nodes    = true
    enable_private_endpoint = false
    master_ipv4_cidr_block  = "172.16.0.0/28"
  }

  # IP allocation for pods and services
  ip_allocation_policy {
    cluster_secondary_range_name  = "pods"
    services_secondary_range_name = "services"
  }

  network    = google_compute_network.vpc.name
  subnetwork = google_compute_subnetwork.gke_subnet.name
}

# Cloud NAT for private nodes
resource "google_compute_router_nat" "gke_nat" {
  name                               = "gke-nat"
  router                             = google_compute_router.nat_router.name
  region                             = "us-central1"
  nat_ip_allocate_option             = "AUTO_ONLY"
  source_subnetwork_ip_ranges_to_nat = "LIST_OF_SUBNETWORKS"

  subnetwork {
    name                    = google_compute_subnetwork.gke_subnet.id
    source_ip_ranges_to_nat = ["ALL_IP_RANGES"]
  }

  # Higher port allocation for containers
  min_ports_per_vm = 4096
}

Use Case 2: Database Server Updates​

Scenario: Database servers in private subnets need to download security updates.

Cron Job for Secure Updates:

#!/bin/bash
# /etc/cron.d/security-updates

# Run security updates at 3 AM (through NAT)
0 3 * * * root apt-get update && apt-get upgrade -y --security

# Log the NAT IP being used
0 3 * * * root curl -s ifconfig.me >> /var/log/nat-ip.log

Use Case 4: CI/CD Pipeline External Access​

Scenario: Build agents need to download dependencies without public IPs.

Build Configuration:

# cloudbuild.yaml
steps:
  # All external fetches go through NAT
  - name: 'node:18'
    entrypoint: 'npm'
    args: ['ci']
    # npm install → NAT → registry.npmjs.org

  - name: 'python:3.11'
    entrypoint: 'pip'
    args: ['install', '-r', 'requirements.txt']
    # pip install → NAT → pypi.org

  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/app:$COMMIT_SHA', '.']
    # Pull base images → NAT → docker.io

options:
  # Use private pool (no public IPs)
  pool:
    name: 'projects/$PROJECT_ID/locations/us-central1/workerPools/private-pool'

Use Case 5: Microservices Egress Control​

Scenario: Control and monitor all outbound traffic from microservices.

NAT Logging Configuration:

resource "google_compute_router_nat" "microservices_nat" {
  name   = "microservices-nat"
  router = google_compute_router.nat_router.name
  region = "us-central1"

  nat_ip_allocate_option             = "AUTO_ONLY"
  source_subnetwork_ip_ranges_to_nat = "ALL_SUBNETWORKS_ALL_IP_RANGES"

  # Enable comprehensive logging
  log_config {
    enable = true
    filter = "ALL"  # Log all connections
  }
}

# Alert on suspicious outbound traffic
resource "google_monitoring_alert_policy" "nat_egress_alert" {
  display_name = "High NAT Egress"
  combiner     = "OR"

  conditions {
    display_name = "NAT bytes sent spike"
    condition_threshold {
      filter          = "resource.type=\"nat_gateway\" AND metric.type=\"router.googleapis.com/nat/sent_bytes_count\""
      duration        = "300s"
      comparison      = "COMPARISON_GT"
      threshold_value = 1073741824  # 1 GB in 5 minutes
    }
  }

  notification_channels = [google_monitoring_notification_channel.email.id]
}

Use Case 6: Compliance and Audit Requirements​

Scenario: Financial services requiring all egress traffic to be logged and from known IPs.

# Compliance Requirements

PCI-DSS Requirement 1.3.6:
  Description: 'Do not disclose private IP addresses to external networks'
  Solution: Cloud NAT masks all internal IPs

SOC 2 Type II:
  Description: 'Monitor and log all network egress'
  Solution: Cloud NAT logging with Cloud Logging export

HIPAA:
  Description: 'Control data egress from healthcare systems'
  Solution: NAT with specific subnet rules + VPC Service Controls

Audit Configuration:

# Export NAT logs to BigQuery for compliance auditing
resource "google_logging_project_sink" "nat_audit_sink" {
  name        = "nat-audit-logs"
  destination = "bigquery.googleapis.com/projects/${var.project_id}/datasets/${google_bigquery_dataset.audit_logs.dataset_id}"

  filter = <<-EOT
    resource.type="nat_gateway"
    logName="projects/${var.project_id}/logs/compute.googleapis.com%2Fnat_flows"
  EOT

  unique_writer_identity = true
}

# BigQuery dataset for long-term retention
resource "google_bigquery_dataset" "audit_logs" {
  dataset_id                  = "nat_audit_logs"
  friendly_name               = "NAT Audit Logs"
  description                 = "NAT flow logs for compliance auditing"
  location                    = "US"
  default_table_expiration_ms = 31536000000  # 1 year retention

  labels = {
    compliance = "pci-dss"
    env        = "production"
  }
}

NAT Port Allocation​

Understanding Port Exhaustion​

Port Allocation Strategies​

# Default: 64 ports per VM
resource "google_compute_router_nat" "default_nat" {
  min_ports_per_vm = 64
  # Max concurrent connections per VM: 64
}

# High-traffic applications: 4096 ports
resource "google_compute_router_nat" "high_traffic_nat" {
  min_ports_per_vm = 4096
  # Max concurrent connections per VM: 4,096
}

# Dynamic allocation for variable workloads
resource "google_compute_router_nat" "dynamic_nat" {
  min_ports_per_vm                    = 64
  max_ports_per_vm                    = 65536
  enable_dynamic_port_allocation      = true
  enable_endpoint_independent_mapping = false
}

Calculating Required Ports​

Formula:
  Required Ports = Concurrent Connections × Safety Factor

Example - GKE Node:
  Pods per node: 30
  Connections per pod: 50
  Total connections: 30 × 50 = 1,500
  Safety factor: 2x
  Required ports: 3,000 → Round to 4,096

Example - API Server:
  Concurrent users: 1,000
  Connections per user: 3
  Total connections: 3,000
  Safety factor: 2x
  Required ports: 6,000 → Round to 8,192

resource "google_compute_router_nat" "nat" {

Log Analysis Queries​

-- BigQuery: Top external destinations
SELECT
  jsonPayload.connection.dest_ip AS destination_ip,
  jsonPayload.connection.dest_port AS destination_port,
  COUNT(*) AS connection_count,
  SUM(CAST(jsonPayload.bytes_sent AS INT64)) AS total_bytes_sent
FROM
  `project_id.dataset.nat_flows_*`
WHERE
  _TABLE_SUFFIX >= FORMAT_DATE('%Y%m%d', DATE_SUB(CURRENT_DATE(), INTERVAL 7 DAY))
GROUP BY
  destination_ip, destination_port
ORDER BY
  connection_count DESC
LIMIT 100;

-- Find potential data exfiltration
SELECT
  jsonPayload.connection.src_ip AS source_vm,
  jsonPayload.connection.dest_ip AS destination,
  SUM(CAST(jsonPayload.bytes_sent AS INT64)) AS bytes_sent
FROM
  `project_id.dataset.nat_flows_*`
WHERE
  CAST(jsonPayload.bytes_sent AS INT64) > 104857600  -- > 100 MB
GROUP BY
  source_vm, destination
ORDER BY
  bytes_sent DESC;

When to Use NAT​

Use Cloud NAT when:

  • ✅ Private resources need internet access
  • ✅ You need consistent outbound IPs
  • ✅ Security requires hiding internal IPs
  • ✅ Compliance mandates egress logging
  • ✅ Running private GKE clusters

Don't use Cloud NAT when:

  • ❌ Resources need to receive inbound connections (use Load Balancer)
  • ❌ Only accessing GCP services (use Private Google Access)
  • ❌ Connecting to on-premises only (use Cloud VPN/Interconnect)

Best Practices​

1. IP Address Management​

Best Practices:
  # Use static IPs for whitelisting
  - Reserve dedicated NAT IPs
  - Document IPs for third-party whitelisting
  - Monitor IP pool utilization

  # Avoid over-allocation
  - Start with AUTO_ONLY
  - Switch to MANUAL_ONLY when IPs stabilize
  - Plan for IP changes in maintenance windows

2. Port Allocation​

Port Allocation Guidelines:
  # Default workloads
  min_ports_per_vm: 64

  # Web applications
  min_ports_per_vm: 512

  # GKE nodes (many pods)
  min_ports_per_vm: 4096

  # High-traffic services
  min_ports_per_vm: 8192
  enable_dynamic_port_allocation: true

3. Logging Strategy​

Logging Configuration:
  Development:
    filter: 'ALL'
    retention: 7 days

  Production:
    filter: 'ERRORS_ONLY' # Cost optimization
    retention: 30 days
    export_to_bigquery: true # For analysis

  Compliance (PCI/HIPAA):
    filter: 'ALL'
    retention: 1 year
    export_to_bigquery: true
    export_to_gcs: true # Long-term archive

4. High Availability​

HA Configuration:
  # Cloud NAT is regional - deploy per region
  regions:
    - us-central1
    - us-east1
    - europe-west1

  # Each region needs its own NAT
  per_region:
    - cloud_router
    - cloud_nat
    - nat_ip_pool

  # Multi-region architecture
  dns_failover: enabled
  health_checks: enabled

5. Cost Optimization​

Cost Factors:
  # NAT gateway: $0.045/hour per gateway
  # Data processing: $0.045/GB
  # NAT IPs: $0.01/hour per unused IP

Optimization Tips:
  - Use AUTO_ONLY to avoid paying for unused IPs
  - Filter logging to reduce log storage costs
  - Use VPC Service Controls to avoid NAT for GCP services
  - Consider egress costs in architecture decisions

Troubleshooting​

Common Issues​

Issue 1: NAT Not Working​

# Check NAT status
gcloud compute routers nats describe my-nat \
    --router=nat-router \
    --region=us-central1

# Verify NAT IP allocation
gcloud compute routers get-nat-ip-info nat-router \
    --region=us-central1

# Check if subnet is included
gcloud compute routers nats describe my-nat \
    --router=nat-router \
    --region=us-central1 \
    --format="yaml(sourceSubnetworkIpRangesToNat)"

Issue 2: Port Exhaustion​

# Check port usage metrics
gcloud monitoring metrics list \
    --filter="metric.type=router.googleapis.com/nat/port_usage"

# Increase port allocation
gcloud compute routers nats update my-nat \
    --router=nat-router \
    --region=us-central1 \
    --min-ports-per-vm=4096

Issue 3: Connection Timeouts​

# Check timeout settings
gcloud compute routers nats describe my-nat \
    --router=nat-router \
    --region=us-central1 \
    --format="yaml(tcpEstablishedIdleTimeoutSec,tcpTransitoryIdleTimeoutSec)"

# Increase timeouts
gcloud compute routers nats update my-nat \
    --router=nat-router \
    --region=us-central1 \
    --tcp-established-idle-timeout=1200 \
    --tcp-transitory-idle-timeout=30

Summary​

Key Takeaways​

  1. Cloud NAT enables private resources to access the internet without exposing private IPs
  2. Fully managed and auto-scaling - no infrastructure to maintain
  3. Essential for private GKE clusters and security-focused architectures
  4. Consistent outbound IPs for third-party API whitelisting
  5. Comprehensive logging for compliance and troubleshooting
  6. Regional service - deploy in each region where needed

Quick Reference​

# Create NAT (quick start)
gcloud compute routers create nat-router --network=my-vpc --region=us-central1
