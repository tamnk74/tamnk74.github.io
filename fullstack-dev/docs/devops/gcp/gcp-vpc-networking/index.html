GCP VPC Networking: Complete Guide

Overview​

Google Cloud Virtual Private Cloud (VPC) networking is the foundation of your cloud infrastructure. This comprehensive guide covers VPC concepts, subnetting, IP addressing, CIDR notation, firewall rules, network tags, Cloud NAT, Cloud VPN, and all load balancing types available in GCP.

What You'll Learn​

  1. VPC Fundamentals - Network architecture, modes, and design patterns
  2. Subnets & IP Addressing - CIDR notation, IP ranges, and subnet design
  3. Firewall Rules & Tags - Security policies, network tags, and access control
  4. Cloud NAT - Outbound internet access for private instances
  5. Cloud VPN - Secure hybrid cloud connectivity
  6. Load Balancing - All GCP load balancer types and use cases

Part 1: Virtual Private Cloud (VPC) Concepts​

What is a VPC?​

A Virtual Private Cloud (VPC) is a virtualized network within Google Cloud Platform that provides:

  • Network isolation for your resources
  • Global resource spanning multiple regions
  • Scalable infrastructure with no capacity planning
  • Built-in security with firewall rules and IAM integration
  • Private communication between resources

VPC Network Modes​

1. Auto Mode VPC​

Characteristics:

  • Automatically creates one subnet per region
  • Predefined IP ranges (10.128.0.0/9)
  • Easy to set up, limited control
  • Suitable for testing and simple deployments
# Create auto mode VPC
gcloud compute networks create auto-vpc \
  --subnet-mode=auto \
  --bgp-routing-mode=regional

# List automatically created subnets
gcloud compute networks subnets list \
  --network=auto-vpc

Auto Mode Subnet Ranges:

us-east1:        10.142.0.0/20
us-west1:        10.138.0.0/20
us-central1:     10.128.0.0/20
europe-west1:    10.132.0.0/20
asia-east1:      10.140.0.0/20
... (one per region)

2. Custom Mode VPC (Recommended)​

Characteristics:

  • Full control over subnet creation and IP ranges
  • No automatic subnet creation
  • More flexibility for production environments
  • Can create multiple subnets per region
# Create custom mode VPC
gcloud compute networks create custom-vpc \
  --subnet-mode=custom \
  --bgp-routing-mode=global

# Create custom subnets
gcloud compute networks subnets create prod-subnet-us-central1 \
  --network=custom-vpc \
  --region=us-central1 \
  --range=10.0.0.0/24 \
  --enable-private-ip-google-access \
  --enable-flow-logs

gcloud compute networks subnets create prod-subnet-europe-west1 \
  --network=custom-vpc \
  --region=europe-west1 \
  --range=10.1.0.0/24 \
  --enable-private-ip-google-access \
  --enable-flow-logs

VPC Network Properties​

BGP Routing Mode​

Regional Routing:

  • Routes learned through Cloud Router stay in region
  • Reduces cross-region traffic costs
  • Suitable for isolated regional deployments

Global Routing:

  • Routes learned through Cloud Router available globally
  • Enables multi-region connectivity
  • Required for global load balancing
# Set BGP routing mode
gcloud compute networks update custom-vpc \
  --bgp-routing-mode=global

MTU (Maximum Transmission Unit)​

# Set MTU to 1460 (default) or 8896 (jumbo frames)
gcloud compute networks update custom-vpc \
  --mtu=1460

VPC Peering​

Connect two VPC networks for private communication:

# Create VPC peering from vpc-1 to vpc-2
gcloud compute networks peerings create vpc-1-to-vpc-2 \
  --network=vpc-1 \
  --peer-network=vpc-2 \
  --peer-project=project-2

# Create reverse peering from vpc-2 to vpc-1
gcloud compute networks peerings create vpc-2-to-vpc-1 \
  --network=vpc-2 \
  --peer-network=vpc-1 \
  --peer-project=project-1

Part 2: Subnets, IP Addressing, and CIDR Notation​

Understanding CIDR Notation​

CIDR (Classless Inter-Domain Routing) is a method for allocating IP addresses and routing.

CIDR Format: IP_ADDRESS/PREFIX_LENGTH​

Example: 10.0.0.0/24

10.0.0.0    = Network address
/24         = Prefix length (subnet mask)
            = First 24 bits are network portion
            = Last 8 bits are host portion
            = 2^8 = 256 total addresses
            = 254 usable addresses (excluding network and broadcast)

Reserved IP Addresses in GCP Subnets​

GCP reserves 4 IP addresses per subnet:

Example subnet: 10.0.1.0/24

10.0.1.0    - Network address (reserved)
10.0.1.1    - Default gateway (reserved by GCP)
10.0.1.2    - Reserved by GCP for future use
10.0.1.255  - Broadcast address (reserved)

Usable range: 10.0.1.3 - 10.0.1.254 (252 addresses)

Subnet Design Best Practices​

1. Plan for Growth​

# Bad: Too small
gcloud compute networks subnets create prod-subnet \
  --network=vpc \
  --region=us-central1 \
  --range=10.0.0.0/28  # Only 14 usable IPs!

# Good: Room for growth
gcloud compute networks subnets create prod-subnet \
  --network=vpc \
  --region=us-central1 \
  --range=10.0.0.0/22  # 1,022 usable IPs

2. Organize by Environment and Tier​

# Production VPC
gcloud compute networks create prod-vpc --subnet-mode=custom

# Production subnets by tier
gcloud compute networks subnets create prod-web-us-central1 \
  --network=prod-vpc --region=us-central1 --range=10.0.0.0/24

gcloud compute networks subnets create prod-app-us-central1 \
  --network=prod-vpc --region=us-central1 --range=10.0.1.0/24

gcloud compute networks subnets create prod-data-us-central1 \
  --network=prod-vpc --region=us-central1 --range=10.0.2.0/24

# Staging VPC
gcloud compute networks create staging-vpc --subnet-mode=custom

# Staging subnets
gcloud compute networks subnets create staging-us-central1 \
  --network=staging-vpc --region=us-central1 --range=10.1.0.0/22

# Development VPC
gcloud compute networks create dev-vpc --subnet-mode=custom

# Development subnets
gcloud compute networks subnets create dev-us-central1 \
  --network=dev-vpc --region=us-central1 --range=10.2.0.0/22

Subnet Expansion​

Expand subnet range without downtime:

# Original subnet: 10.0.0.0/24 (256 IPs)
gcloud compute networks subnets expand-ip-range prod-subnet \
  --region=us-central1 \
  --prefix-length=22  # Expand to 10.0.0.0/22 (1,024 IPs)

# Note: Can only expand, cannot shrink
# New range must include original range

Secondary IP Ranges​

Add secondary IP ranges for GKE pods and services:

# Create subnet with secondary ranges for GKE
gcloud compute networks subnets create gke-subnet \
  --network=vpc \
  --region=us-central1 \
  --range=10.0.0.0/24 \
  --secondary-range pods=10.4.0.0/14 \
  --secondary-range services=10.8.0.0/20

# Add secondary range to existing subnet
gcloud compute networks subnets update gke-subnet \
  --region=us-central1 \
  --add-secondary-ranges pods-2=10.12.0.0/14

IP Aliasing​

Assign multiple IP addresses to a single VM:

# Create VM with alias IP ranges
gcloud compute instances create vm-with-aliases \
  --zone=us-central1-a \
  --subnet=gke-subnet \
  --network-interface="aliases=/32;/32;/32"

Calculating Subnet Sizes​

Python Script for CIDR Calculations​

#!/usr/bin/env python3
# cidr_calculator.py

import ipaddress

def analyze_cidr(cidr_block):
    """Analyze a CIDR block and print details"""
    network = ipaddress.ip_network(cidr_block)

    print(f"\n{'='*60}")
    print(f"CIDR Block Analysis: {cidr_block}")
    print(f"{'='*60}")
    print(f"Network Address:     {network.network_address}")
    print(f"Broadcast Address:   {network.broadcast_address}")
    print(f"Netmask:            {network.netmask}")
    print(f"Wildcard Mask:      {network.hostmask}")
    print(f"Prefix Length:      /{network.prefixlen}")
    print(f"Total IPs:          {network.num_addresses}")
    print(f"Usable IPs (GCP):   {network.num_addresses - 4}")
    print(f"First Usable IP:    {list(network.hosts())[2] if network.num_addresses > 4 else 'N/A'}")
    print(f"Last Usable IP:     {list(network.hosts())[-1] if network.num_addresses > 4 else 'N/A'}")
    print(f"\nIP Range:           {network.network_address} - {network.broadcast_address}")

    # Show subnet division examples
    print(f"\n{'Subnet Division Examples':-^60}")
    for new_prefix in [network.prefixlen + 1, network.prefixlen + 2, network.prefixlen + 3]:
        if new_prefix <= 32:
            subnets = list(network.subnets(new_prefix=new_prefix))
            print(f"  /{new_prefix}: {len(subnets)} subnets of {subnets[0].num_addresses} IPs each")
            if len(subnets) <= 8:
                for i, subnet in enumerate(subnets, 1):
                    print(f"    Subnet {i}: {subnet}")

def suggest_subnet_size(required_ips):
    """Suggest appropriate CIDR prefix for required number of IPs"""
    # Account for GCP reserved IPs
    total_needed = required_ips + 4

    # Find smallest prefix that fits
    for prefix in range(32, 7, -1):
        if 2 ** (32 - prefix) >= total_needed:
            network_size = 2 ** (32 - prefix)
            usable = network_size - 4
            print(f"\n{'='*60}")
            print(f"Subnet Size Recommendation")
            print(f"{'='*60}")
            print(f"Required IPs:       {required_ips}")
            print(f"Recommended CIDR:   /{prefix}")
            print(f"Total IPs:          {network_size}")
            print(f"Usable IPs (GCP):   {usable}")
            print(f"Overhead:           {usable - required_ips} IPs")
            print(f"Utilization:        {(required_ips/usable)*100:.1f}%")
            break

if __name__ == "__main__":
    # Example analyses
    analyze_cidr("10.0.0.0/24")
    analyze_cidr("10.0.0.0/22")
    analyze_cidr("192.168.1.0/28")

    # Suggest subnet sizes
    suggest_subnet_size(100)   # Need 100 IPs
    suggest_subnet_size(500)   # Need 500 IPs
    suggest_subnet_size(1000)  # Need 1000 IPs

Part 3: Firewall Rules and Network Tags​

Firewall Rule Fundamentals​

GCP firewall rules are stateful and control traffic to/from VM instances.

Key Concepts​

  • Stateful: Return traffic automatically allowed
  • Implicit deny: All ingress traffic denied by default
  • Implicit allow: All egress traffic allowed by default
  • Priority-based: Rules evaluated by priority (0-65535, lower is higher priority)

Firewall Rule Components​

Loading diagram...

Creating Firewall Rules​

Allow SSH Access​

# Allow SSH from anywhere (not recommended for production)
gcloud compute firewall-rules create allow-ssh-from-anywhere \
  --network=vpc \
  --allow=tcp:22 \
  --source-ranges=0.0.0.0/0 \
  --description="Allow SSH from anywhere" \
  --priority=1000

# Allow SSH from specific IP range (recommended)
gcloud compute firewall-rules create allow-ssh-from-office \
  --network=vpc \
  --allow=tcp:22 \
  --source-ranges=203.0.113.0/24 \
  --description="Allow SSH from office IP" \
  --priority=900

Allow HTTP/HTTPS Traffic​

# Allow HTTP and HTTPS
gcloud compute firewall-rules create allow-http-https \
  --network=vpc \
  --allow=tcp:80,tcp:443 \
  --source-ranges=0.0.0.0/0 \
  --target-tags=web-server \
  --description="Allow HTTP/HTTPS to web servers" \
  --priority=1000

Allow Internal Traffic​

# Allow all internal traffic within VPC
gcloud compute firewall-rules create allow-internal \
  --network=vpc \
  --allow=tcp:0-65535,udp:0-65535,icmp \
  --source-ranges=10.0.0.0/8 \
  --description="Allow all internal traffic" \
  --priority=1000

Deny Specific Traffic​

# Deny traffic from specific IP (higher priority)
gcloud compute firewall-rules create deny-blacklist \
  --network=vpc \
  --action=DENY \
  --rules=tcp,udp \
  --source-ranges=198.51.100.0/24 \
  --description="Deny traffic from blacklisted IPs" \
  --priority=100

Network Tags​

Network tags enable flexible firewall targeting:

Tag-Based Firewall Rules​

# Create firewall rule targeting specific tags
gcloud compute firewall-rules create allow-web-to-app \
  --network=vpc \
  --allow=tcp:8080 \
  --source-tags=web-tier \
  --target-tags=app-tier \
  --description="Allow web tier to access app tier" \
  --priority=1000

# Allow database access only from app tier
gcloud compute firewall-rules create allow-app-to-db \
  --network=vpc \
  --allow=tcp:5432 \
  --source-tags=app-tier \
  --target-tags=db-tier \
  --description="Allow app tier to access database" \
  --priority=1000

Assign Tags to VMs​

# Create VM with network tags
gcloud compute instances create web-server-1 \
  --zone=us-central1-a \
  --subnet=prod-web-subnet \
  --tags=web-tier,public-facing \
  --machine-type=e2-medium

# Add tags to existing VM
gcloud compute instances add-tags web-server-1 \
  --zone=us-central1-a \
  --tags=https-enabled

# Remove tags from VM
gcloud compute instances remove-tags web-server-1 \
  --zone=us-central1-a \
  --tags=public-facing

Service Account-Based Rules​

More secure than network tags:

# Create firewall rule targeting service account
gcloud compute firewall-rules create allow-app-sa \
  --network=vpc \
  --allow=tcp:8080 \
  --source-service-accounts=web-sa@project.iam.gserviceaccount.com \
  --target-service-accounts=app-sa@project.iam.gserviceaccount.com \
  --description="Allow web SA to access app SA" \
  --priority=900

Multi-Tier Application Firewall Example​

#!/bin/bash
# multi_tier_firewall.sh

PROJECT_ID="my-project"
NETWORK="prod-vpc"

# Web tier firewall rules
gcloud compute firewall-rules create allow-internet-to-web \
  --network=${NETWORK} \
  --allow=tcp:80,tcp:443 \
  --source-ranges=0.0.0.0/0 \
  --target-tags=web-tier \
  --description="Allow HTTP/HTTPS from internet to web tier"

gcloud compute firewall-rules create allow-lb-health-check \
  --network=${NETWORK} \
  --allow=tcp:80,tcp:443 \
  --source-ranges=130.211.0.0/22,35.191.0.0/16 \
  --target-tags=web-tier \
  --description="Allow health checks from GCP load balancers"

# Application tier firewall rules
gcloud compute firewall-rules create allow-web-to-app \
  --network=${NETWORK} \
  --allow=tcp:8080,tcp:8443 \
  --source-tags=web-tier \
  --target-tags=app-tier \
  --description="Allow web tier to access app tier"

# Database tier firewall rules
gcloud compute firewall-rules create allow-app-to-db \
  --network=${NETWORK} \
  --allow=tcp:5432 \
  --source-tags=app-tier \
  --target-tags=db-tier \
  --description="Allow app tier to access PostgreSQL database"

# Management access
gcloud compute firewall-rules create allow-iap-ssh \
  --network=${NETWORK} \
  --allow=tcp:22 \
  --source-ranges=35.235.240.0/20 \
  --description="Allow SSH via Identity-Aware Proxy"

# Deny all other ingress (lowest priority)
gcloud compute firewall-rules create deny-all-ingress \
  --network=${NETWORK} \
  --action=DENY \
  --rules=all \
  --source-ranges=0.0.0.0/0 \
  --priority=65534 \
  --description="Deny all other ingress traffic"

echo "✅ Firewall rules created successfully"

Part 4: Cloud NAT and Cloud VPN​

Cloud NAT (Network Address Translation)​

Cloud NAT allows VM instances without external IP addresses to access the internet.

Cloud NAT Architecture​

Loading diagram...

Cloud NAT Benefits​

  • ✅ Security: VMs don't need public IPs
  • ✅ Cost-effective: Reduced public IP usage
  • ✅ Scalability: Automatic scaling
  • ✅ Manageability: Centralized outbound access control

Setting Up Cloud NAT​

# Step 1: Create Cloud Router
gcloud compute routers create nat-router \
  --network=vpc \
  --region=us-central1

# Step 2: Create Cloud NAT configuration
gcloud compute routers nats create nat-config \
  --router=nat-router \
  --region=us-central1 \
  --nat-all-subnet-ip-ranges \
  --auto-allocate-nat-external-ips

# Verify NAT configuration
gcloud compute routers nats describe nat-config \
  --router=nat-router \
  --region=us-central1

Advanced Cloud NAT Configuration​

# Create NAT with specific IP addresses
# First, reserve static IPs
gcloud compute addresses create nat-ip-1 nat-ip-2 \
  --region=us-central1

# Create NAT with manual IPs
gcloud compute routers nats create nat-manual-ips \
  --router=nat-router \
  --region=us-central1 \
  --nat-custom-subnet-ip-ranges=subnet-1,subnet-2 \
  --nat-external-ip-pool=nat-ip-1,nat-ip-2

# Configure NAT with port reservation
gcloud compute routers nats update nat-config \
  --router=nat-router \
  --region=us-central1 \
  --min-ports-per-vm=64 \
  --max-ports-per-vm=512

# Enable Cloud NAT logging
gcloud compute routers nats update nat-config \
  --router=nat-router \
  --region=us-central1 \
  --enable-logging \
  --log-filter=ALL

Testing Cloud NAT​

# Create VM without external IP
gcloud compute instances create test-nat-vm \
  --zone=us-central1-a \
  --subnet=prod-subnet \
  --no-address \
  --tags=no-ip

# SSH via IAP
gcloud compute ssh test-nat-vm \

# Test internet access from VM
curl -s ifconfig.me  # Should return NAT gateway IP

Cloud VPN​

Cloud VPN securely connects your on-premises network to your GCP VPC network.

VPN Types​

  1. HA VPN (High Availability VPN) - Recommended

    • 99.99% SLA
    • Two interfaces for redundancy
    • Supports multiple tunnels

  2. Classic VPN (Legacy)

    • 99.9% SLA
    • Single interface
    • Being deprecated

HA VPN Architecture​

Loading diagram...

Setting Up HA VPN​

#!/bin/bash
# setup_ha_vpn.sh

PROJECT_ID="my-project"
REGION="us-central1"
NETWORK="prod-vpc"
PEER_ASN=65002  # On-premises BGP ASN
GCP_ASN=65001   # GCP BGP ASN
ON_PREM_PEER_IP="203.0.113.10"

# Step 1: Create HA VPN Gateway
gcloud compute vpn-gateways create ha-vpn-gw \
  --network=${NETWORK} \
  --region=${REGION}

# Step 2: Create Cloud Router with BGP
gcloud compute routers create vpn-router \
  --region=${REGION} \
  --network=${NETWORK} \
  --asn=${GCP_ASN}

# Step 3: Create external VPN gateway (on-premises side)
gcloud compute external-vpn-gateways create on-prem-gw \
  --interfaces=0=${ON_PREM_PEER_IP}

# Step 4: Create VPN tunnels
# Tunnel 1 to interface 0
gcloud compute vpn-tunnels create tunnel-1 \
  --peer-external-gateway=on-prem-gw \
  --peer-external-gateway-interface=0 \
  --region=${REGION} \
  --ike-version=2 \
  --shared-secret="shared_secret_1" \
  --router=vpn-router \
  --vpn-gateway=ha-vpn-gw \
  --interface=0

# Tunnel 2 to interface 1 (redundancy)
gcloud compute vpn-tunnels create tunnel-2 \
  --peer-external-gateway=on-prem-gw \
  --peer-external-gateway-interface=0 \
  --region=${REGION} \
  --ike-version=2 \
  --shared-secret="shared_secret_2" \
  --router=vpn-router \
  --vpn-gateway=ha-vpn-gw \
  --interface=1

# Step 5: Create BGP sessions
gcloud compute routers add-interface vpn-router \
  --interface-name=if-tunnel-1 \
  --ip-address=169.254.1.1 \
  --mask-length=30 \
  --vpn-tunnel=tunnel-1 \
  --region=${REGION}

gcloud compute routers add-bgp-peer vpn-router \
  --peer-name=bgp-peer-1 \
  --interface=if-tunnel-1 \
  --peer-ip-address=169.254.1.2 \
  --peer-asn=${PEER_ASN} \
  --region=${REGION}

gcloud compute routers add-interface vpn-router \
  --interface-name=if-tunnel-2 \
  --ip-address=169.254.2.1 \
  --mask-length=30 \
  --vpn-tunnel=tunnel-2 \
  --region=${REGION}

gcloud compute routers add-bgp-peer vpn-router \
  --peer-name=bgp-peer-2 \
  --interface=if-tunnel-2 \
  --peer-ip-address=169.254.2.2 \
  --peer-asn=${PEER_ASN} \
  --region=${REGION}

echo "✅ HA VPN configured successfully"

displayName: "VPN Tunnel Down Alert"

Part 5: Load Balancing Types​

GCP offers 7 types of load balancers to suit different use cases.

Load Balancer Decision Tree​

1. External HTTP(S) Load Balancer​

Use Case: Global web applications, REST APIs, mobile backends

Features:

  • Global load balancing with anycast IPs
  • SSL termination
  • URL-based routing
  • Cloud CDN integration
  • Cloud Armor (DDoS protection)

Create External HTTP(S) Load Balancer​

#!/bin/bash
# create_https_lb.sh

PROJECT_ID="my-project"
REGION="us-central1"

# Step 1: Create instance template
gcloud compute instance-templates create web-template \
  --machine-type=e2-medium \
  --network=default \
  --subnet=default \
  --tags=http-server,https-server \
  --metadata=startup-script='#!/bin/bash
    apt-get update
    apt-get install -y nginx
    echo "Hello from $(hostname)" > /var/www/html/index.html
    systemctl start nginx'

# Step 2: Create managed instance group
gcloud compute instance-groups managed create web-mig \
  --base-instance-name=web \
  --template=web-template \
  --size=3 \
  --region=${REGION}

# Step 3: Set autoscaling
gcloud compute instance-groups managed set-autoscaling web-mig \
  --region=${REGION} \
  --max-num-replicas=10 \
  --min-num-replicas=3 \
  --target-cpu-utilization=0.75 \
  --cool-down-period=90

# Step 4: Configure named port
gcloud compute instance-groups managed set-named-ports web-mig \
  --region=${REGION} \
  --named-ports=http:80

# Step 5: Create health check
gcloud compute health-checks create http http-health-check \
  --port=80 \
  --check-interval=10s \
  --timeout=5s \
  --healthy-threshold=2 \
  --unhealthy-threshold=3 \
  --request-path=/

# Step 6: Create backend service
gcloud compute backend-services create web-backend \
  --protocol=HTTP \
  --health-checks=http-health-check \
  --global \
  --enable-cdn \
  --cache-mode=CACHE_ALL_STATIC

# Step 7: Add backend (instance group) to backend service
gcloud compute backend-services add-backend web-backend \
  --instance-group=web-mig \
  --instance-group-region=${REGION} \
  --balancing-mode=UTILIZATION \
  --max-utilization=0.8 \
  --capacity-scaler=1.0 \
  --global

# Step 8: Create URL map
gcloud compute url-maps create web-url-map \
  --default-service=web-backend

# Step 9: Reserve static IP
gcloud compute addresses create lb-ip \
  --global

# Step 10: Create target HTTP proxy
gcloud compute target-http-proxies create http-proxy \
  --url-map=web-url-map

# Step 11: Create forwarding rule
gcloud compute forwarding-rules create http-forwarding-rule \
  --address=lb-ip \
  --global \
  --target-http-proxy=http-proxy \
  --ports=80

# Get the IP address
LB_IP=$(gcloud compute addresses describe lb-ip \
  --global \
  --format="get(address)")

echo "✅ Load Balancer created successfully!"
echo "Load Balancer IP: ${LB_IP}"
echo "Test with: curl http://${LB_IP}"

Best Practices Summary​

VPC Design​

✅ Do:

  • Use custom mode VPCs for production
  • Plan IP ranges carefully (avoid overlaps)
  • Enable VPC Flow Logs for troubleshooting
  • Use Shared VPC for multi-project organizations
  • Enable Private Google Access

❌ Don't:

  • Use auto mode VPCs in production
  • Create overlapping IP ranges
  • Use public IPs unnecessarily
  • Forget to plan for growth

Firewall Rules​

✅ Do:

  • Use principle of least privilege
  • Leverage network tags or service accounts
  • Enable firewall logging for critical rules
  • Document firewall rules
  • Use priority strategically

❌ Don't:

  • Allow 0.0.0.0/0 for SSH in production
  • Forget to test firewall changes
  • Use overly permissive rules
  • Neglect to review unused rules

Cloud NAT​

✅ Do:

  • Use Cloud NAT for private instances
  • Monitor NAT gateway metrics
  • Configure appropriate port limits
  • Use static IPs for whitelisting

❌ Don't:

  • Assign external IPs when not needed
  • Forget to monitor port exhaustion
  • Use single NAT for critical workloads

Cloud VPN​

✅ Do:

  • Use HA VPN for production
  • Enable BGP for dynamic routing
  • Monitor tunnel health
  • Use strong encryption
  • Document VPN configuration

❌ Don't:

  • Use Classic VPN for new deployments
  • Forget to test failover
  • Use weak encryption settings
  • Neglect monitoring

Load Balancing​

✅ Do:

  • Choose appropriate LB type for use case
  • Configure health checks properly
  • Enable Cloud CDN for static content
  • Use Cloud Armor for DDoS protection
  • Monitor backend health

❌ Don't:

  • Use wrong load balancer type
  • Configure aggressive health checks
  • Forget session affinity requirements
  • Neglect SSL certificate renewal
