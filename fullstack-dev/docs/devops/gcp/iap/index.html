Identity-Aware Proxy (IAP)

Overview​

Identity-Aware Proxy (IAP) is a Google Cloud service that provides centralized authentication and authorization for applications accessed via HTTPS. It allows you to establish a central authorization layer for applications over TLS, so you can adopt an application-level access control model instead of relying on network-level firewalls.

How IAP Works​

IAP works by verifying user identity and context of the request to determine if a user should be allowed to access an application or resource. When a user tries to access an IAP-secured resource:

  1. Authentication: IAP checks if the user is authenticated. If not, it redirects to Google's authentication system.
  2. Authorization: After authentication, IAP checks if the user is authorized to access the resource based on Cloud IAM policies.
  3. Access: If authorized, the request is forwarded to the application with identity information in headers.

Key Features​

Centralized Access Control​

  • Single point of authentication and authorization
  • Unified policy management across applications
  • Integration with Cloud IAM for fine-grained access control

Zero Trust Security Model​

  • Verify every request regardless of network location
  • No reliance on network perimeter security
  • Context-aware access decisions

Identity Information Forwarding​

  • Passes user identity to applications via headers
  • Enables application-level personalization
  • Supports audit logging and compliance

Easy Integration​

  • Works with existing applications without code changes
  • Supports both Google Cloud and on-premises applications
  • Compatible with App Engine, GKE, Compute Engine, and Cloud Run

Use Cases​

1. Securing Internal Applications​

Scenario: Your organization has internal tools and dashboards that should only be accessible to employees.

Solution: Use IAP to:

  • Authenticate users with corporate Google Workspace accounts
  • Grant access based on group membership or individual users
  • Eliminate the need for VPNs or IP whitelisting
# Example IAP Policy
members:
  - group:engineering@company.com
  - user:admin@company.com
role: roles/iap.httpsResourceAccessor

2. Partner and Vendor Access​

Scenario: External partners need access to specific applications or dashboards but shouldn't have full network access.

Solution: IAP enables:

  • Granular access control for external users
  • Time-limited access grants
  • Audit trails of partner activity
  • No need to provision VPN credentials

3. Multi-Tenant Applications​

Scenario: SaaS application serving multiple customers with different access requirements.

Solution: Use IAP to:

  • Authenticate users from different organizations
  • Implement tenant-level isolation
  • Support both Google accounts and external identity providers via Cloud Identity

4. Compliance and Audit Requirements​

Scenario: Applications handling sensitive data requiring strict access controls and audit logs.

Solution: IAP provides:

  • Detailed access logs for compliance reporting
  • Integration with Cloud Logging and Cloud Audit Logs
  • Proof of authentication and authorization decisions
  • Support for regulatory requirements (HIPAA, SOC 2, etc.)

5. Development and Staging Environments​

Scenario: Protect non-production environments from unauthorized access while allowing team collaboration.

Solution: Use IAP to:

  • Restrict access to specific teams or individuals
  • Avoid exposing development environments publicly
  • Enable secure testing without complex network configurations
  • Quick policy updates as team composition changes

6. Legacy Application Modernization​

Scenario: Legacy applications with weak or no authentication mechanisms.

Solution: IAP enables:

  • Add modern authentication without modifying application code
  • Implement OAuth 2.0 and OpenID Connect standards
  • Gradual migration to cloud-native security
  • Protect applications during modernization process

7. Microservices Security​

Scenario: Securing communication between microservices in a distributed architecture.

Solution: Use IAP with service accounts to:

  • Authenticate service-to-service requests
  • Implement zero-trust networking
  • Control which services can communicate
  • Integrate with service mesh solutions

8. Remote Work and BYOD Support​

Scenario: Employees accessing company resources from various locations and devices.

Solution: IAP provides:

  • Context-aware access based on device posture
  • No VPN required for secure access
  • Support for personal and corporate devices
  • Integration with BeyondCorp Enterprise for advanced controls

Supported Resources​

IAP can secure the following Google Cloud resources:

  • App Engine applications (standard and flexible)
  • Compute Engine VM instances
  • Google Kubernetes Engine (GKE) workloads
  • Cloud Run services
  • On-premises applications via Cloud Load Balancing

Implementation Steps​

Basic Setup​

  1. Enable IAP API

    gcloud services enable iap.googleapis.com

  2. Configure OAuth Consent Screen

    • Set up OAuth consent screen in Google Cloud Console
    • Add authorized domains

  3. Enable IAP for Resource

    gcloud iap web enable --resource-type=app-engine \
      --service=default

  4. Grant Access

    gcloud iap web add-iam-policy-binding \
      --resource-type=app-engine \
      --service=default \
      --member=user:employee@company.com \
      --role=roles/iap.httpsResourceAccessor

Application Integration​

IAP forwards user identity in request headers:

// Node.js example - Reading IAP headers
const email = req.headers['x-goog-authenticated-user-email'];
const userId = req.headers['x-goog-authenticated-user-id'];

// Verify IAP JWT token
const jwt = req.headers['x-goog-iap-jwt-assertion'];
// Validate JWT signature and claims

Best Practices​

Security​

  1. Always verify IAP headers: Don't trust headers blindly; validate JWT tokens
  2. Use signed headers: Enable signed headers to prevent header spoofing
  3. Implement defense in depth: Combine IAP with other security measures
  4. Regular access reviews: Periodically review and update IAM policies

Operations​

  1. Monitor access logs: Set up alerts for unusual access patterns
  2. Test policies: Verify policies in non-production before applying to production
  3. Document access requirements: Maintain clear documentation of who needs access
  4. Automate policy management: Use Infrastructure as Code for IAP policies

Performance​

  1. Enable CDN: Use Cloud CDN for static content
  2. Optimize origin: Ensure backend applications perform well
  3. Monitor latency: Track IAP overhead on request latency
  4. Consider caching: Implement appropriate caching strategies

Limitations​

  • IAP is designed for HTTPS traffic only; does not support other protocols
  • Additional latency due to authentication checks (typically minimal)
  • Requires Google account or Cloud Identity for users
  • OAuth consent screen configuration required for production use
  • Maximum policy size limitations

Pricing​

IAP itself is free, but you pay for:

  • Load balancing infrastructure
  • Backend compute resources
  • Cloud Logging storage
  • Network egress

Related Services​

  • BeyondCorp Enterprise: Advanced context-aware access with device posture checks
  • Cloud Armor: DDoS protection and WAF capabilities
  • Cloud Load Balancing: Required for IAP on Compute Engine and GKE
  • VPC Service Controls: Additional perimeter security
  • Access Context Manager: Define fine-grained access levels
