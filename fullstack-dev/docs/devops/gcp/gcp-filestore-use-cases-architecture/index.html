GCP Filestore: Top 10 Use Cases and Architecture Guide

Overview​

Google Cloud Filestore is a fully managed NFS (Network File System) file storage service for applications requiring a file system interface and shared file system for data. It provides high-performance file storage with a simple, scalable architecture that integrates seamlessly with Google Cloud Platform services.

Key Features​

  • Fully Managed: No infrastructure management required
  • High Performance: Up to 320,000 IOPS and 30 GB/s throughput
  • NFSv3 Compatible: Works with existing NFS-based applications
  • Scalable: From 1 TiB to 100 TiB capacity
  • Low Latency: Sub-millisecond latency for file operations
  • Integrated: Works with GCE, GKE, Cloud Run, and App Engine

Architecture Overview​

Filestore Service Tiers​

1. Basic Tier​

  • Capacity: 1 TiB to 63.9 TiB
  • Performance: Up to 16,000 IOPS, 1.2 GB/s throughput
  • Use Case: General-purpose file storage
  • Availability: Zonal (99.9% SLA)

2. High Scale Tier​

  • Capacity: 10 TiB to 100 TiB
  • Performance: Up to 320,000 IOPS, 30 GB/s throughput
  • Use Case: High-performance computing, analytics
  • Availability: Zonal (99.9% SLA)

3. Enterprise Tier​

  • Capacity: 1 TiB to 10 TiB
  • Performance: Up to 100,000 IOPS, 12 GB/s throughput
  • Use Case: Mission-critical applications
  • Availability: Regional (99.99% SLA) with automatic failover

Top 10 Use Cases​

1. Container-Native Storage for GKE​

Scenario: Kubernetes workloads requiring shared persistent storage across multiple pods.

Architecture:

Implementation:

apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: filestore-storage
provisioner: filestore.csi.storage.gke.io
parameters:
  tier: basic-hdd
  network: default
volumeBindingMode: WaitForFirstConsumer
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: shared-data
spec:
  accessModes:
    - ReadWriteMany
  storageClassName: filestore-storage
  resources:
    requests:
      storage: 1Ti
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: nginx
          image: nginx:latest
          volumeMounts:
            - name: shared-storage
              mountPath: /usr/share/nginx/html
      volumes:
        - name: shared-storage
          persistentVolumeClaim:
            claimName: shared-data

Benefits:

  • Shared storage across multiple pods
  • ReadWriteMany (RWX) access mode
  • Persistent data beyond pod lifecycle
  • Scalable storage for growing applications

2. Media Rendering and Processing​

Scenario: Video transcoding, image processing, and media asset management requiring high-throughput file access.

Architecture:

Key Configurations:

# Create High Scale Filestore for media processing
gcloud filestore instances create media-processing \
    --tier=HIGH_SCALE_SSD \
    --file-share=name=media,capacity=50TB \
    --network=name=default \
    --zone=us-central1-a

Benefits:

  • High throughput (30 GB/s) for large media files
  • Parallel processing by multiple workers
  • Low latency for random read/write operations
  • Cost-effective compared to persistent disks

3. Enterprise File Sharing and Collaboration​

Scenario: Centralized file storage for teams needing collaborative access to documents, CAD files, and project assets.

Architecture:

Directory Structure:

/filestore-share/
├── /departments/
│   ├── /engineering/
│   ├── /design/
│   └── /marketing/
├── /projects/
│   ├── /project-alpha/
│   └── /project-beta/
└── /shared/
    ├── /templates/
    └── /resources/

Access Control:

# Mount on Linux workstation
sudo mount -t nfs -o vers=3 \
  10.0.0.2:/media /mnt/filestore

# Set permissions
sudo chown -R team:team /mnt/filestore/projects
sudo chmod 770 /mnt/filestore/projects

Benefits:

  • Regional availability (99.99% SLA)
  • Automatic failover
  • Familiar file system interface
  • Integration with existing tools

4. Machine Learning Training Data Storage​

Scenario: Storing and serving training datasets for machine learning models with multiple GPUs/TPUs accessing the same data.

Architecture:

Performance Optimization:

# Python code for efficient data loading
import tensorflow as tf

# Mount path to Filestore
FILESTORE_PATH = "/mnt/filestore/datasets"

def create_dataset(file_pattern):
    """Create TensorFlow dataset from Filestore"""
    dataset = tf.data.Dataset.list_files(
        f"{FILESTORE_PATH}/{file_pattern}"
    )

    # Parallel reading with optimal buffer sizes
    dataset = dataset.interleave(
        lambda x: tf.data.TFRecordDataset(x),
        cycle_length=16,
        num_parallel_calls=tf.data.AUTOTUNE
    )

    # Prefetch for better throughput
    dataset = dataset.prefetch(tf.data.AUTOTUNE)

    return dataset

# Training script
dataset = create_dataset("train/*.tfrecord")
dataset = dataset.batch(256)

model.fit(dataset, epochs=100)

Benefits:

  • High IOPS for random data access
  • Shared storage across multiple training nodes
  • Checkpoint and model versioning
  • Cost-effective for large datasets

5. Database Backup and Recovery​

Scenario: Storing database backups with fast restore capabilities for disaster recovery.

Architecture:

Backup Scripts:

#!/bin/bash
# backup-postgres.sh

FILESTORE_MOUNT="/mnt/filestore/backups"
BACKUP_DIR="${FILESTORE_MOUNT}/postgres"
DATE=$(date +%Y%m%d_%H%M%S)

# Create backup directory
mkdir -p "${BACKUP_DIR}"

# Perform backup
pg_dump -h localhost -U postgres -F c \
  -f "${BACKUP_DIR}/db_backup_${DATE}.dump" \
  production_db

# Keep only last 30 days
find "${BACKUP_DIR}" -type f -mtime +30 -delete

# Snapshot Filestore for point-in-time recovery
gcloud filestore snapshots create "snapshot-${DATE}" \
  --instance=backup-instance \
  --zone=us-central1-a \
  --file-share=backups

Restore Process:

#!/bin/bash
# restore-postgres.sh

FILESTORE_MOUNT="/mnt/filestore/backups"
BACKUP_FILE="${FILESTORE_MOUNT}/postgres/db_backup_20250113_120000.dump"

# Restore from backup
pg_restore -h localhost -U postgres \
  -d production_db_restored \
  -c "${BACKUP_FILE}"

Benefits:

  • Fast backup writes (high throughput)
  • Quick restore times
  • Snapshot-based point-in-time recovery
  • Cost-effective medium-term storage

6. Content Management System (CMS) Storage​

Scenario: WordPress, Drupal, or custom CMS requiring shared file storage for media uploads across multiple web servers.

Architecture:

WordPress Configuration:

// wp-config.php
define('UPLOADS', '/mnt/filestore/uploads');

// .htaccess optimization
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/jpg "access plus 1 year"
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/gif "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
</IfModule>

Kubernetes Deployment:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: wordpress
spec:
  replicas: 3
  selector:
    matchLabels:
      app: wordpress
  template:
    metadata:
      labels:
        app: wordpress
    spec:
      containers:
        - name: wordpress
          image: wordpress:latest
          env:
            - name: WORDPRESS_DB_HOST
              value: cloudsql-proxy:3306
          volumeMounts:
            - name: wordpress-uploads
              mountPath: /var/www/html/wp-content/uploads
      volumes:
        - name: wordpress-uploads
          persistentVolumeClaim:
            claimName: filestore-pvc

Benefits:

  • Shared media storage across all web servers
  • No need for rsync or object storage adapters
  • Consistent file system view
  • Easy migration from traditional hosting

7. CI/CD Build Artifacts and Cache​

Scenario: Storing build artifacts, dependency caches, and compiled binaries for faster CI/CD pipelines.

Architecture:

Cloud Build Configuration:

# cloudbuild.yaml
steps:
  # Mount Filestore cache
  - name: 'gcr.io/cloud-builders/gcloud'
    args:
      - 'compute'
      - 'ssh'
      - 'build-worker'
      - '--command=sudo mount -t nfs 10.0.0.2:/cache /mnt/cache'

  # Restore dependencies from cache
  - name: 'node:18'
    entrypoint: 'bash'
    args:
      - '-c'
      - |
        if [ -d "/mnt/cache/node_modules" ]; then
          cp -r /mnt/cache/node_modules ./
        fi
        npm install
        cp -r ./node_modules /mnt/cache/
    volumes:
      - name: 'cache'
        path: '/mnt/cache'

  # Build application
  - name: 'node:18'
    args: ['npm', 'run', 'build']

  # Build Docker image
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/app:$SHORT_SHA', '.']

  # Push to registry
  - name: 'gcr.io/cloud-builders/docker'
    args: ['push', 'gcr.io/$PROJECT_ID/app:$SHORT_SHA']

options:
  machineType: 'E2_HIGHCPU_8'

Benefits:

  • Faster builds with shared dependency cache
  • Reduced network egress costs
  • Shared artifacts across build agents
  • Persistent build history

8. Electronic Design Automation (EDA) Workloads​

Scenario: Semiconductor design, circuit simulation, and VLSI workflows requiring high-performance file I/O.

Architecture:

Performance Configuration:

# Create High Scale instance with maximum performance
gcloud filestore instances create eda-storage \
    --tier=HIGH_SCALE_SSD \
    --file-share=name=designs,capacity=100TB \
    --network=name=eda-vpc \
    --zone=us-central1-a

# Mount with performance options
sudo mount -t nfs -o vers=3,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport \
  10.0.0.2:/designs /mnt/eda

Benefits:

  • Ultra-high IOPS (320,000) for small file operations
  • High throughput (30 GB/s) for large datasets
  • Low latency for iterative design workflows
  • Shared design libraries across teams

9. Genomics and Life Sciences Data Analysis​

Scenario: Processing and analyzing genomic sequencing data requiring shared access to reference genomes and research datasets.

Architecture:

Pipeline Example:

#!/bin/bash
# genomics-pipeline.sh

FILESTORE="/mnt/filestore"
REFERENCE="${FILESTORE}/references/hg38.fa"
INPUT_FASTQ="${FILESTORE}/samples/sample_001.fastq.gz"
OUTPUT_DIR="${FILESTORE}/results/sample_001"

mkdir -p "${OUTPUT_DIR}"

# Alignment
bwa mem -t 32 "${REFERENCE}" "${INPUT_FASTQ}" \
  > "${OUTPUT_DIR}/aligned.sam"

# Convert to BAM
samtools view -bS "${OUTPUT_DIR}/aligned.sam" \
  > "${OUTPUT_DIR}/aligned.bam"

# Sort BAM
samtools sort "${OUTPUT_DIR}/aligned.bam" \
  -o "${OUTPUT_DIR}/sorted.bam"

# Variant calling
gatk HaplotypeCaller \
  -R "${REFERENCE}" \
  -I "${OUTPUT_DIR}/sorted.bam" \
  -O "${OUTPUT_DIR}/variants.vcf"

Benefits:

  • Shared reference genome storage
  • High throughput for large FASTQ files
  • Concurrent access by multiple analysis pipelines
  • Compliance with data retention requirements

Scenario: Shared development environments, testing data, and sandbox environments for development teams.

Performance Best Practices​

1. Mount Options Optimization​

# Optimal NFS mount options for Filestore
sudo mount -t nfs -o vers=3,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport \
  [FILESTORE_IP]:/[FILE_SHARE_NAME] /mnt/filestore

2. Network Configuration​

# Ensure proper firewall rules
gcloud compute firewall-rules create allow-nfs \
  --direction=INGRESS \
  --priority=1000 \
  --network=default \
  --action=ALLOW \
  --rules=tcp:2049,udp:2049 \
  --source-ranges=10.0.0.0/8

3. Monitoring and Alerting​

# Cloud Monitoring alert policy
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: filestore-alerts
spec:
  groups:
    - name: filestore
      interval: 30s
      rules:
        - alert: FilestoreHighLatency
          expr: filestore_latency_ms > 10
          for: 5m
          labels:
            severity: warning
          annotations:
            summary: 'High latency on Filestore instance'

        - alert: FilestoreCapacityHigh
          expr: (filestore_used_bytes / filestore_capacity_bytes) > 0.85
          for: 10m
          labels:
            severity: critical
          annotations:
            summary: 'Filestore capacity above 85%'

Security Best Practices​

1. VPC Service Controls​

# Create VPC Service Perimeter
gcloud access-context-manager perimeters create filestore-perimeter \
  --title="Filestore Security Perimeter" \
  --resources=projects/PROJECT_NUMBER \
  --restricted-services=file.googleapis.com \
  --policy=POLICY_ID

2. IAM Permissions​

# Grant minimal required permissions
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member=serviceAccount:SERVICE_ACCOUNT@PROJECT_ID.iam.gserviceaccount.com \
  --role=roles/file.editor

3. Encryption​

  • In-transit: Automatic encryption using NFS over TLS
  • At-rest: Automatic encryption with Google-managed keys or CMEK

Migration Strategies​

From On-Premises NAS​

# Use rsync for initial migration
rsync -avz --progress /mnt/nas/ /mnt/filestore/

# Or use Transfer Service for large datasets
gcloud transfer jobs create \
  --source-posix-filesystem=/mnt/nas \
  --destination-file-system=projects/PROJECT_ID/locations/us-central1/instances/INSTANCE_ID/fileshares/SHARE_NAME

From Cloud Storage​

# Mount both and copy
gcsfuse BUCKET_NAME /mnt/gcs
rsync -avz --progress /mnt/gcs/ /mnt/filestore/

From Persistent Disks​

# Create temporary VM, attach disk, and copy
gcloud compute instances create migration-vm \
  --zone=us-central1-a \
  --disk=name=SOURCE_DISK,mode=ro

# SSH and copy
rsync -avz --progress /mnt/disk/ /mnt/filestore/

Monitoring and Observability​

Key Metrics to Monitor​

  1. Throughput: Read/write bytes per second
  2. IOPS: Input/output operations per second
  3. Latency: Average operation latency
  4. Capacity: Used vs. available capacity
  5. Mount Status: Active mounts and connection health

Troubleshooting Common Issues​

Issue 1: Mount Failures​

# Check connectivity
ping [FILESTORE_IP]

# Verify firewall rules
gcloud compute firewall-rules list --filter="name:nfs"

# Test NFS mount
showmount -e [FILESTORE_IP]

Issue 2: Performance Degradation​

# Check IOPS and throughput limits
gcloud filestore instances describe INSTANCE_NAME \
  --zone=ZONE \
  --format="value(tier,fileShares[0].capacityGb)"

# Monitor in real-time
watch -n 1 'nfsstat -c'

Issue 3: Capacity Planning​

# Check current usage
df -h /mnt/filestore

# Expand capacity
gcloud filestore instances update INSTANCE_NAME \
  --zone=ZONE \
  --file-share=name=SHARE_NAME,capacity=NEW_CAPACITY_GB

Conclusion​

Google Cloud Filestore provides a versatile, high-performance file storage solution for a wide range of use cases. Whether you're running containerized applications on GKE, processing large media files, or building machine learning pipelines, Filestore offers the scalability, performance, and reliability needed for modern cloud-native applications.

Key Takeaways​

  • Choose the right tier: Match performance and availability to workload requirements
  • Optimize network: Use proper mount options and VPC configuration
  • Monitor proactively: Set up alerts for capacity, performance, and availability
  • Secure by default: Leverage VPC Service Controls and IAM
  • Plan for growth: Start with appropriate capacity and scale as needed
