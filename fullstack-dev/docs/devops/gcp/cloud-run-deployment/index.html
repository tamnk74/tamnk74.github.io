Deploy Cloud Run with Node.js and GitHub Actions

Overview​

Google Cloud Run is a fully managed serverless platform that automatically scales your containerized applications. This guide covers deploying Node.js applications to Cloud Run with automated CI/CD pipelines using GitHub Actions.

Cloud Run Fundamentals​

What is Cloud Run?​

Cloud Run is a managed compute platform that:

  • Automatically scales from zero to N
  • Bills only for actual usage (CPU/memory/requests)
  • Supports any language via containers
  • Integrates with GCP services
  • Provides HTTPS endpoints automatically

Cloud Run vs Cloud Functions​

FeatureCloud RunCloud Functions
ContainerCustom Docker imagesManaged runtimes only
Request TimeoutUp to 60 minutesUp to 9 minutes
Concurrent RequestsUp to 1000 per instance1 per instance (2nd gen: up to 1000)
Use CaseWeb apps, APIs, long-running tasksEvent-driven, quick functions
Cold StartSlightly slowerFaster
FlexibilityFull controlLimited to runtime

Express.js Application Example​

src/index.js

const express = require('express');
const { createLogger, format, transports } = require('winston');

// Initialize logger
const logger = createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: format.combine(format.timestamp(), format.errors({ stack: true }), format.json()),
  transports: [new transports.Console()],
});

// Initialize Express app
const app = express();

// Middleware
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// CORS configuration
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', process.env.ALLOWED_ORIGINS || '*');
  res.header('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS');
  res.header('Access-Control-Allow-Headers', 'Content-Type, Authorization');

  if (req.method === 'OPTIONS') {
    return res.sendStatus(200);
  }
  next();
});

// Request logging middleware
app.use((req, res, next) => {
  const start = Date.now();

  res.on('finish', () => {
    const duration = Date.now() - start;
    logger.info('HTTP Request', {
      method: req.method,
      path: req.path,
      status: res.statusCode,
      duration: `${duration}ms`,
      userAgent: req.get('user-agent'),
    });
  });

  next();
});

// Health check endpoint
app.get('/health', (req, res) => {
  res.status(200).json({
    status: 'healthy',
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
    environment: process.env.NODE_ENV || 'development',
  });
});

// Liveness probe (for Cloud Run)
app.get('/liveness', (req, res) => {
  res.status(200).send('OK');
});

// Readiness probe
app.get('/readiness', async (req, res) => {
  // Check database connection, external services, etc.
  try {
    // Example: await database.ping();
    res.status(200).json({ ready: true });
  } catch (error) {
    logger.error('Readiness check failed', { error: error.message });
    res.status(503).json({ ready: false, error: error.message });
  }
});

// API routes
app.get('/api/v1/data', async (req, res) => {
  try {
    // Your business logic here
    const data = {
      message: 'Hello from Cloud Run!',
      timestamp: new Date().toISOString(),
      version: process.env.VERSION || '1.0.0',
    };

    res.json(data);
  } catch (error) {
    logger.error('Error fetching data', { error: error.message });
    res.status(500).json({ error: 'Internal server error' });
  }
});

// POST endpoint example
app.post('/api/v1/process', async (req, res) => {
  try {
    const { data } = req.body;

    if (!data) {
      return res.status(400).json({ error: 'Missing data parameter' });
    }

    // Process data
    const result = {
      processed: true,
      input: data,
      timestamp: new Date().toISOString(),
    };

    res.status(201).json(result);
  } catch (error) {
    logger.error('Error processing request', { error: error.message });
    res.status(500).json({ error: 'Internal server error' });
  }
});

// Error handling middleware
app.use((err, req, res, next) => {
  logger.error('Unhandled error', {
    error: err.message,
    stack: err.stack,
    path: req.path,
    method: req.method,
  });

  res.status(err.status || 500).json({
    error: process.env.NODE_ENV === 'production' ? 'Internal server error' : err.message,
  });
});

// 404 handler
app.use((req, res) => {
  res.status(404).json({ error: 'Not found' });
});

// Graceful shutdown
const gracefulShutdown = async (signal) => {
  logger.info(`${signal} received, shutting down gracefully`);

  // Close database connections, cleanup resources
  try {
    // await database.close();
    logger.info('Cleanup completed');
    process.exit(0);
  } catch (error) {
    logger.error('Error during shutdown', { error: error.message });
    process.exit(1);
  }
};

process.on('SIGTERM', () => gracefulShutdown('SIGTERM'));
process.on('SIGINT', () => gracefulShutdown('SIGINT'));

// Start server
const PORT = process.env.PORT || 8080;
const server = app.listen(PORT, '0.0.0.0', () => {
  logger.info(`Server started on port ${PORT}`, {
    environment: process.env.NODE_ENV,
    nodeVersion: process.version,
  });
});

// Handle server errors
server.on('error', (error) => {
  logger.error('Server error', { error: error.message });
  process.exit(1);
});

module.exports = app;

Containerization with Docker​

Optimized Dockerfile​

Dockerfile

# Multi-stage build for smaller image size

# Stage 1: Build stage
FROM node:18-alpine AS builder

WORKDIR /app

# Copy package files
COPY package*.json ./

# Install dependencies (including dev dependencies for build)
RUN npm ci --only=production

# Stage 2: Production stage
FROM node:18-alpine

# Install dumb-init for proper signal handling
RUN apk add --no-cache dumb-init

# Create non-root user
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001

WORKDIR /app

# Copy dependencies from builder
COPY --from=builder --chown=nodejs:nodejs /app/node_modules ./node_modules

# Copy application source
COPY --chown=nodejs:nodejs src ./src
COPY --chown=nodejs:nodejs package*.json ./

# Switch to non-root user
USER nodejs

# Expose port
EXPOSE 8080

# Health check
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD node -e "require('http').get('http://localhost:8080/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"

# Use dumb-init to handle signals properly
ENTRYPOINT ["dumb-init", "--"]

# Start application
CMD ["node", "src/index.js"]

Testing​

tests/integration/api.test.js

const request = require('supertest');
const app = require('../../src/index');

describe('API Endpoints', () => {
  describe('GET /health', () => {
    it('should return healthy status', async () => {
      const response = await request(app).get('/health').expect('Content-Type', /json/).expect(200);

      expect(response.body).toHaveProperty('status', 'healthy');
      expect(response.body).toHaveProperty('timestamp');
    });
  });

  describe('GET /api/v1/data', () => {
    it('should return data', async () => {
      const response = await request(app).get('/api/v1/data').expect('Content-Type', /json/).expect(200);

      expect(response.body).toHaveProperty('message');
      expect(response.body).toHaveProperty('timestamp');
    });
  });

  describe('POST /api/v1/process', () => {
    it('should process data successfully', async () => {
      const testData = { data: 'test' };

      const response = await request(app)
        .post('/api/v1/process')
        .send(testData)
        .expect('Content-Type', /json/)
        .expect(201);

      expect(response.body).toHaveProperty('processed', true);
      expect(response.body.input).toBe('test');
    });

    it('should return 400 for missing data', async () => {
      const response = await request(app).post('/api/v1/process').send({}).expect('Content-Type', /json/).expect(400);

      expect(response.body).toHaveProperty('error');
    });
  });
});

GitHub Actions CI/CD Pipeline​

GitHub Secrets Setup​

Add these secrets to your GitHub repository (Settings > Secrets and variables > Actions):

  • GCP_PROJECT_ID: Your GCP project ID
  • GCP_SA_KEY: Base64-encoded service account key JSON
  • GCP_REGION: Deployment region (e.g., us-central1)

Production Deployment Workflow​

.github/workflows/deploy-prod.yml

name: Deploy to Cloud Run (Production)

on:
  push:
    branches:
      - main
    tags:
      - 'v*'

env:
  PROJECT_ID: ${{ secrets.GCP_PROJECT_ID }}
  REGION: ${{ secrets.GCP_REGION }}
  SERVICE_NAME: my-app-prod
  ARTIFACT_REGISTRY: us-central1-docker.pkg.dev
  REPOSITORY: cloud-run-apps

jobs:
  test:
    name: Run Tests
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run linter
        run: npm run lint

      - name: Run tests
        run: npm test

      - name: Upload coverage reports
        uses: codecov/codecov-action@v3
        with:
          file: ./coverage/coverage-final.json
          flags: unittests

  build-and-deploy:
    name: Build and Deploy to Cloud Run
    needs: test
    runs-on: ubuntu-latest

    permissions:
      contents: read
      id-token: write

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Cloud SDK
        uses: google-github-actions/setup-gcloud@v2
        with:
          version: 'latest'

      - name: Authenticate to Google Cloud
        uses: google-github-actions/auth@v2
        with:
          credentials_json: ${{ secrets.GCP_SA_KEY }}

      - name: Configure Docker for Artifact Registry
        run: |
          gcloud auth configure-docker ${{ env.ARTIFACT_REGISTRY }}

      - name: Extract version from tag
        id: version
        run: |
          if [[ "${{ github.ref }}" == refs/tags/* ]]; then
            VERSION=${GITHUB_REF#refs/tags/}
          else
            VERSION=${GITHUB_SHA::8}
          fi
          echo "version=$VERSION" >> $GITHUB_OUTPUT
          echo "VERSION: $VERSION"

      - name: Build Docker image
        run: |
          IMAGE_NAME="${{ env.ARTIFACT_REGISTRY }}/${{ env.PROJECT_ID }}/${{ env.REPOSITORY }}/${{ env.SERVICE_NAME }}:${{ steps.version.outputs.version }}"
          docker build \
            --build-arg VERSION=${{ steps.version.outputs.version }} \
            --build-arg BUILD_DATE=$(date -u +"%Y-%m-%dT%H:%M:%SZ") \
            --build-arg VCS_REF=${{ github.sha }} \
            --tag $IMAGE_NAME \
            --tag ${{ env.ARTIFACT_REGISTRY }}/${{ env.PROJECT_ID }}/${{ env.REPOSITORY }}/${{ env.SERVICE_NAME }}:latest \
            .
          echo "IMAGE_NAME=$IMAGE_NAME" >> $GITHUB_ENV

      - name: Push Docker image to Artifact Registry
        run: |
          docker push ${{ env.IMAGE_NAME }}
          docker push ${{ env.ARTIFACT_REGISTRY }}/${{ env.PROJECT_ID }}/${{ env.REPOSITORY }}/${{ env.SERVICE_NAME }}:latest

      - name: Deploy to Cloud Run
        id: deploy
        uses: google-github-actions/deploy-cloudrun@v2
        with:
          service: ${{ env.SERVICE_NAME }}
          region: ${{ env.REGION }}
          image: ${{ env.IMAGE_NAME }}
          flags: |
            --platform=managed
            --allow-unauthenticated
            --memory=512Mi
            --cpu=1
            --min-instances=1
            --max-instances=10
            --concurrency=80
            --timeout=300
            --port=8080
            --set-env-vars=NODE_ENV=production,VERSION=${{ steps.version.outputs.version }}
            --set-secrets=DATABASE_URL=DATABASE_URL:latest,API_KEY=API_KEY:latest,JWT_SECRET=JWT_SECRET:latest
            --service-account=${{ env.PROJECT_ID }}@appspot.gserviceaccount.com
          tag: traffic

      - name: Configure traffic splitting (gradual rollout)
        run: |
          # Send 10% traffic to new revision
          gcloud run services update-traffic ${{ env.SERVICE_NAME }} \
            --region=${{ env.REGION }} \
            --to-revisions=${{ steps.deploy.outputs.revision }}=10

      - name: Run smoke tests
        run: |
          SERVICE_URL="${{ steps.deploy.outputs.url }}"
          echo "Testing $SERVICE_URL"

          # Health check
          curl -f $SERVICE_URL/health || exit 1

          # API test
          curl -f $SERVICE_URL/api/v1/data || exit 1

      - name: Promote to 100% traffic
        if: success()
        run: |
          gcloud run services update-traffic ${{ env.SERVICE_NAME }} \
            --region=${{ env.REGION }} \
            --to-latest

      - name: Rollback on failure
        if: failure()
        run: |
          echo "Deployment failed, rolling back..."
          gcloud run services update-traffic ${{ env.SERVICE_NAME }} \
            --region=${{ env.REGION }} \
            --to-revisions=PREVIOUS=100

      - name: Output deployment info
        run: |
          echo "✅ Deployment completed successfully!"
          echo "🌐 Service URL: ${{ steps.deploy.outputs.url }}"
          echo "📦 Image: ${{ env.IMAGE_NAME }}"
          echo "🏷️  Version: ${{ steps.version.outputs.version }}"
          echo "🔄 Revision: ${{ steps.deploy.outputs.revision }}"

      - name: Send Slack notification
        if: always()
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {
              "text": "${{ job.status == 'success' && '✅' || '❌' }} Cloud Run Deployment ${{ job.status }}",
              "blocks": [
                {
                  "type": "section",
                  "text": {
                    "type": "mrkdwn",
                    "text": "*Cloud Run Deployment*\n*Status:* ${{ job.status }}\n*Service:* ${{ env.SERVICE_NAME }}\n*Version:* ${{ steps.version.outputs.version }}\n*URL:* ${{ steps.deploy.outputs.url }}"
                  }
                }
              ]
            }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

Structured Logging in Application​

const { createLogger, format, transports } = require('winston');

const logger = createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: format.combine(format.timestamp(), format.errors({ stack: true }), format.json()),
  defaultMeta: {
    service: 'my-app',
    version: process.env.VERSION,
  },
  transports: [
    new transports.Console({
      format: format.combine(format.colorize(), format.simple()),
    }),
  ],
});

// Log with trace context for Cloud Trace integration
app.use((req, res, next) => {
  const traceHeader = req.header('X-Cloud-Trace-Context');
  if (traceHeader) {
    const [trace] = traceHeader.split('/');
    req.trace = `projects/${process.env.PROJECT_ID}/traces/${trace}`;
  }
  next();
});

// Example usage
logger.info('Request received', {
  method: req.method,
  path: req.path,
  trace: req.trace,
});

Cloud Monitoring Dashboards​

# Create custom metrics
# In your application:
const { MetricServiceClient } = require('@google-cloud/monitoring');
const client = new MetricServiceClient();

async function recordMetric(metricType, value) {
  const projectId = process.env.PROJECT_ID;
  const dataPoint = {
    interval: {
      endTime: {
        seconds: Date.now() / 1000,
      },
    },
    value: {
      doubleValue: value,
    },
  };

  const timeSeriesData = {
    metric: {
      type: `custom.googleapis.com/${metricType}`,
    },
    resource: {
      type: 'cloud_run_revision',
      labels: {
        project_id: projectId,
        service_name: 'my-app-prod',
      },
    },
    points: [dataPoint],
  };

  const request = {
    name: client.projectPath(projectId),
    timeSeries: [timeSeriesData],
  };

  await client.createTimeSeries(request);
}

Advanced Patterns​

Blue-Green Deployment​

# Deploy new version without traffic
gcloud run deploy my-app-prod \
  --image=NEW_IMAGE \
  --region=us-central1 \
  --no-traffic \
  --tag=blue

# Test the new version
curl https://blue---my-app-prod-HASH-uc.a.run.app/health

# Switch traffic
gcloud run services update-traffic my-app-prod \
  --region=us-central1 \
  --to-tags=blue=100

# Rollback if needed
gcloud run services update-traffic my-app-prod \
  --region=us-central1 \
  --to-tags=green=100

Canary Deployment​

# Deploy new version with tag
gcloud run deploy my-app-prod \
  --image=NEW_IMAGE \
  --region=us-central1 \
  --tag=canary \
  --no-traffic

# Gradually increase traffic
gcloud run services update-traffic my-app-prod \
  --region=us-central1 \
  --to-tags=canary=10

# Monitor metrics, then increase
gcloud run services update-traffic my-app-prod \
  --region=us-central1 \
  --to-tags=canary=50

# Full rollout
gcloud run services update-traffic my-app-prod \
  --region=us-central1 \
  --to-latest

# Create VPC connector

gcloud run deploy my-app-prod \
  --image=IMAGE_URL \
  --region=us-central1 \
  --vpc-connector=my-connector \
  --vpc-egress=all-traffic

Best Practices​

1. Container Optimization​

✅ DO:

  • Use multi-stage builds to reduce image size
  • Run as non-root user
  • Use Alpine Linux base images when possible
  • Implement proper health checks
  • Use .dockerignore to exclude unnecessary files

❌ DON'T:

  • Include secrets in the image
  • Run as root user
  • Use :latest tags in production
  • Bundle development dependencies

2. Application Design​

✅ DO:

  • Implement graceful shutdown (SIGTERM handling)
  • Use connection pooling for databases
  • Implement request timeouts
  • Log structured JSON for Cloud Logging
  • Use environment variables for configuration

❌ DON'T:

  • Store state in memory (use external storage)
  • Make assumptions about filesystem persistence
  • Hardcode configuration values
  • Ignore cold start optimization

3. Security​

✅ DO:

  • Use Secret Manager for sensitive data
  • Implement authentication/authorization
  • Use HTTPS only
  • Regularly update dependencies
  • Scan images for vulnerabilities
  • Use VPC connector for private resources

❌ DON'T:

  • Expose services publicly without authentication
  • Store secrets in environment variables
  • Use default service accounts
  • Allow unrestricted CORS

4. Cost Optimization​

✅ DO:

  • Set appropriate min/max instances
  • Optimize concurrency settings
  • Use request timeout limits
  • Implement caching strategies
  • Monitor and analyze costs

❌ DON'T:

  • Set min-instances > 0 for dev/staging
  • Over-provision CPU/memory
  • Ignore cold start penalties
  • Run expensive operations synchronously

5. Monitoring & Operations​

✅ DO:

  • Set up uptime checks
  • Configure alerts for errors and latency
  • Use distributed tracing
  • Implement structured logging
  • Monitor key metrics (CPU, memory, requests)

❌ DON'T:

  • Deploy without monitoring
  • Ignore error rates
  • Skip load testing
  • Forget about log retention costs

6. CI/CD​

✅ DO:

  • Implement automated testing
  • Use semantic versioning
  • Tag images with git SHA
  • Implement gradual rollouts
  • Have rollback procedures
  • Run smoke tests after deployment

❌ DON'T:

  • Deploy without tests
  • Skip version tagging
  • Deploy directly to production
  • Ignore failed deployments

Deployment Checklist​

Pre-Deployment​

  • Code reviewed and approved
  • All tests passing
  • Security scan completed
  • Environment variables configured
  • Secrets stored in Secret Manager
  • Resource limits set appropriately
  • Monitoring and alerts configured
  • Backup and rollback plan ready

Deployment​

  • Docker image built and tested
  • Image pushed to Artifact Registry
  • Service deployed to Cloud Run
  • Health checks passing
  • Smoke tests completed
  • Traffic gradually shifted
  • Logs reviewed for errors

Post-Deployment​

  • Monitor error rates
  • Check response times
  • Verify functionality
  • Review cost impact
  • Update documentation
  • Notify stakeholders

Troubleshooting​

Common Issues​

1. Container fails to start

# Check logs
gcloud run services logs read my-app-prod --region=us-central1 --limit=50

# Common causes:
# - Port not set to 8080
# - Missing environment variables
# - Dependencies not installed
# - Healthcheck failing

2. Cold start latency

# Solutions:
# - Set min-instances > 0
# - Optimize container size
# - Use startup CPU boost
# - Implement lazy loading

gcloud run services update my-app-prod \
  --region=us-central1 \
  --min-instances=1 \
  --cpu-boost

3. Memory limits exceeded

# Increase memory
gcloud run services update my-app-prod \
  --region=us-central1 \
  --memory=1Gi

# Or optimize application memory usage

4. Request timeout

# Increase timeout (max 60 minutes)
gcloud run services update my-app-prod \
  --region=us-central1 \
  --timeout=300

5. Connection to Cloud SQL fails

# Verify Cloud SQL instance name
gcloud sql instances describe INSTANCE_NAME

# Check service account permissions
gcloud projects get-iam-policy PROJECT_ID

# Ensure VPC connector is configured
gcloud run services describe my-app-prod --region=us-central1
