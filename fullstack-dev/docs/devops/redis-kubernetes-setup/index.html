Redis Setup with Kubernetes

Overview​

This guide covers deploying Redis on Kubernetes with various architectures including standalone, master-replica, and Redis Cluster configurations. Learn how to set up Redis for high availability, scalability, and production-ready deployments on Kubernetes.

Architecture Patterns​

1. Standalone Redis (Development/Testing)​

Simple single-node Redis deployment suitable for development and testing environments.

2. Master-Replica with Redis Sentinel (High Availability)​

Redis Sentinel for automatic failover and high availability.

3. Redis Cluster (Horizontal Scaling)​

Sharded Redis Cluster for horizontal scaling and high throughput.

Deployment Examples​

1. Standalone Redis Deployment​

ConfigMap for Redis configuration:

# redis-standalone-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config
  namespace: redis

    loglevel notice
    logfile ""

    save 300 10
    save 60 10000
    stop-writes-on-bgsave-error yes
    rdbcompression yes
    rdbchecksum yes
    dbfilename dump.rdb
    dir /data

    # Replication
    replica-serve-stale-data yes
    replica-read-only yes
    repl-diskless-sync no
    repl-diskless-sync-delay 5
    repl-disable-tcp-nodelay no
    replica-priority 100

    # Security
    # requirepass your-strong-password-here

    # Limits
    maxmemory 256mb
    maxmemory-policy allkeys-lru
    maxclients 10000

    # Append Only File
    appendonly yes
    appendfilename "appendonly.aof"
    appendfsync everysec
    no-appendfsync-on-rewrite no
    auto-aof-rewrite-percentage 100
    auto-aof-rewrite-min-size 64mb

    # Slow log
    slowlog-log-slower-than 10000
    slowlog-max-len 128

StatefulSet for Redis:

# redis-ha-statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis-ha
  namespace: redis
spec:
  serviceName: redis-ha-headless
  replicas: 3
  selector:
    matchLabels:
      app: redis-ha
  template:
    metadata:
      labels:
        app: redis-ha
    spec:
      initContainers:
        - name: init-redis
          image: redis:7.2-alpine
          command:
            - sh
            - -c
            - |
              set -ex
              # Get pod ordinal index
              ordinal=${HOSTNAME##*-}
              # Copy appropriate config
              if [ "$ordinal" -eq 0 ]; then
                cp /mnt/config/master.conf /etc/redis/redis.conf
              else
                cp /mnt/config/replica.conf /etc/redis/redis.conf
              fi
          volumeMounts:
            - name: redis-config
              mountPath: /mnt/config
            - name: config
              mountPath: /etc/redis
      containers:
        - name: redis
          image: redis:7.2-alpine
          command:
            - redis-server
            - /etc/redis/redis.conf
          ports:
            - name: redis
              containerPort: 6379
          resources:
            requests:
              cpu: 200m
              memory: 512Mi
            limits:
              cpu: 1000m
              memory: 1Gi
          volumeMounts:
            - name: data
              mountPath: /data
            - name: config
              mountPath: /etc/redis
          livenessProbe:
            tcpSocket:
              port: 6379
            initialDelaySeconds: 30
            periodSeconds: 10
          readinessProbe:
            exec:
              command:
                - sh
                - -c
                - redis-cli -a $REDIS_PASSWORD ping
            initialDelaySeconds: 10
            periodSeconds: 5
          env:
            - name: REDIS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: redis-secret
                  key: password
      volumes:
        - name: redis-config
          configMap:
            name: redis-ha-config
        - name: config
          emptyDir: {}
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ['ReadWriteOnce']
        storageClassName: standard-rwo
        resources:
          requests:
            storage: 10Gi

Cluster Initialization Job:

# redis-cluster-init-job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: redis-cluster-init
  namespace: redis
spec:
  template:
    spec:
      containers:
        - name: redis-cluster-init
          image: redis:7.2-alpine
          command:
            - sh
            - -c
            - |
              set -ex

              # Wait for all pods to be ready
              sleep 30

              # Build cluster nodes list
              NODES=""
              for i in $(seq 0 5); do
                NODES="$NODES redis-cluster-$i.redis-cluster.redis.svc.cluster.local:6379"
              done

              # Create cluster
              echo "yes" | redis-cli -a $REDIS_PASSWORD \
                --cluster create $NODES \
                --cluster-replicas 1
                
              # Verify cluster
              redis-cli -a $REDIS_PASSWORD \
                -c \
                -h redis-cluster-0.redis-cluster.redis.svc.cluster.local \
                cluster info
          env:
            - name: REDIS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: redis-secret
                  key: password
      restartPolicy: OnFailure
  backoffLimit: 5

4. Using Helm Chart (Bitnami Redis)​

The easiest way to deploy Redis with production-ready configurations:

# Add Bitnami repository
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

# Install Redis Standalone
helm install redis bitnami/redis \
  --namespace redis \
  --create-namespace \
  --set auth.enabled=true \
  --set auth.password="your-strong-password" \
  --set master.persistence.enabled=true \
  --set master.persistence.size=10Gi \
  --set replica.replicaCount=2 \
  --set replica.persistence.enabled=true \
  --set replica.persistence.size=10Gi \
  --set metrics.enabled=true

# Install Redis Cluster
helm install redis-cluster bitnami/redis-cluster \
  --namespace redis \
  --create-namespace \
  --set password="your-strong-password" \
  --set cluster.nodes=6 \
  --set cluster.replicas=1 \
  --set persistence.size=20Gi \
  --set metrics.enabled=true

# redis-network-policy.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: redis-network-policy
  namespace: redis
spec:
  podSelector:
    matchLabels:
      app: redis
  policyTypes:
    - Ingress
    - Egress
  ingress:
    # Allow from application namespace
    - from:
        - namespaceSelector:
            matchLabels:
              name: default
        - podSelector:
            matchLabels:
              app: backend
      ports:
        - protocol: TCP
          port: 6379
    # Allow from same namespace (for cluster communication)
    - from:
        - podSelector:
            matchLabels:
              app: redis
      ports:
        - protocol: TCP
          port: 6379
        - protocol: TCP
          port: 16379 # Cluster bus
  egress:
    # Allow DNS
    - to:
        - namespaceSelector:
            matchLabels:
              name: kube-system
      ports:
        - protocol: UDP
          port: 53
    # Allow cluster communication
    - to:
        - podSelector:
            matchLabels:
              app: redis
      ports:
        - protocol: TCP
          port: 6379
        - protocol: TCP
          port: 16379

apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: redis-alerts
  namespace: redis
spec:
  groups:
    - name: redis.rules
      interval: 30s
      rules:
        - alert: RedisDown
          expr: redis_up == 0
          for: 5m
          labels:
            severity: critical
          annotations:
            summary: 'Redis instance is down'
            description: 'Redis instance {{ $labels.instance }} is down'

        - alert: RedisHighMemoryUsage
          expr: redis_memory_used_bytes / redis_memory_max_bytes * 100 > 90
          for: 5m
          labels:
            severity: warning
          annotations:
            summary: 'Redis high memory usage'
            description: 'Redis instance {{ $labels.instance }} memory usage is {{ $value }}%'

        - alert: RedisHighConnections
          expr: redis_connected_clients > 1000
          for: 5m
          labels:
            severity: warning
          annotations:
            summary: 'Redis high number of connections'
            description: 'Redis instance {{ $labels.instance }} has {{ $value }} connections'

        - alert: RedisReplicationLag
          expr: redis_replication_lag_seconds > 10
          for: 5m
          labels:
            severity: warning
          annotations:
            summary: 'Redis replication lag'
            description: 'Redis replication lag on {{ $labels.instance }} is {{ $value }} seconds'

        - alert: RedisRejectedConnections
          expr: rate(redis_rejected_connections_total[5m]) > 0
          for: 5m
          labels:
            severity: warning
          annotations:
            summary: 'Redis rejected connections'
            description: 'Redis instance {{ $labels.instance }} is rejecting connections'

Backup and Restore​

1. Backup CronJob​

# redis-backup-cronjob.yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: redis-backup
  namespace: redis
spec:
  schedule: '0 2 * * *' # Daily at 2 AM
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 3
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: backup
              image: redis:7.2-alpine
              command:
                - sh
                - -c
                - |
                  set -ex

                  # Backup filename with timestamp
                  BACKUP_FILE="/backup/redis-backup-$(date +%Y%m%d-%H%M%S).rdb"

                  # Trigger BGSAVE
                  redis-cli -h redis-ha-0.redis-ha-headless.redis.svc.cluster.local \
                    -a $REDIS_PASSWORD \
                    BGSAVE

                  # Wait for BGSAVE to complete
                  while [ "$(redis-cli -h redis-ha-0.redis-ha-headless.redis.svc.cluster.local -a $REDIS_PASSWORD LASTSAVE)" = "$(date +%s)" ]; do
                    sleep 5
                  done

                  # Copy RDB file
                  kubectl exec -n redis redis-ha-0 -- cat /data/dump.rdb > $BACKUP_FILE

                  # Upload to GCS (or S3)
                  gcloud storage cp $BACKUP_FILE gs://your-backup-bucket/redis/

                  # Cleanup old backups (keep last 7 days)
                  find /backup -name "redis-backup-*.rdb" -mtime +7 -delete

                  echo "Backup completed: $BACKUP_FILE"
              env:
                - name: REDIS_PASSWORD
                  valueFrom:
                    secretKeyRef:
                      name: redis-secret
                      key: password
              volumeMounts:
                - name: backup
                  mountPath: /backup
          volumes:
            - name: backup
              persistentVolumeClaim:
                claimName: redis-backup-pvc
          restartPolicy: OnFailure

2. Restore Procedure​

# Restore from backup
#!/bin/bash

BACKUP_FILE="redis-backup-20231120-020000.rdb"
REDIS_POD="redis-ha-0"
NAMESPACE="redis"

# Download backup from GCS
gcloud storage cp gs://your-backup-bucket/redis/$BACKUP_FILE /tmp/

# Scale down replicas
kubectl scale statefulset redis-ha --replicas=1 -n $NAMESPACE

# Stop Redis
kubectl exec -n $NAMESPACE $REDIS_POD -- redis-cli -a $REDIS_PASSWORD SHUTDOWN SAVE

# Copy backup file to pod
kubectl cp /tmp/$BACKUP_FILE $NAMESPACE/$REDIS_POD:/data/dump.rdb

# Start Redis
kubectl delete pod $REDIS_POD -n $NAMESPACE

# Wait for pod to be ready
kubectl wait --for=condition=ready pod/$REDIS_POD -n $NAMESPACE --timeout=300s

# Scale back up
kubectl scale statefulset redis-ha --replicas=3 -n $NAMESPACE

echo "Restore completed"

Client Configuration​

NestJS Application Configuration​

// app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { RedisModule } from '@nestjs-modules/ioredis';

@Module({
  imports: [
    ConfigModule.forRoot(),
    RedisModule.forRootAsync({
      imports: [ConfigModule],
      useFactory: (configService: ConfigService) => {
        const isCluster = configService.get('REDIS_CLUSTER') === 'true';

        if (isCluster) {
          // Redis Cluster configuration
          return {
            type: 'cluster',
            nodes: [
              {
                host: 'redis-cluster-0.redis-cluster.redis.svc.cluster.local',
                port: 6379,
              },
              {
                host: 'redis-cluster-1.redis-cluster.redis.svc.cluster.local',
                port: 6379,
              },
              {
                host: 'redis-cluster-2.redis-cluster.redis.svc.cluster.local',
                port: 6379,
              },
            ],
            options: {
              redisOptions: {
                password: configService.get('REDIS_PASSWORD'),
                tls: {},
              },
              clusterRetryStrategy: (times) => {
                return Math.min(100 * times, 2000);
              },
            },
          };
        } else {
          // Sentinel configuration
          return {
            type: 'sentinel',
            sentinels: [
              {
                host: 'redis-sentinel-0.redis-sentinel.redis.svc.cluster.local',
                port: 26379,
              },
              {
                host: 'redis-sentinel-1.redis-sentinel.redis.svc.cluster.local',
                port: 26379,
              },
              {
                host: 'redis-sentinel-2.redis-sentinel.redis.svc.cluster.local',
                port: 26379,
              },
            ],
            name: 'mymaster',
            password: configService.get('REDIS_PASSWORD'),
            db: 0,
            retryStrategy: (times) => {
              return Math.min(times * 50, 2000);
            },
          };
        }
      },
      inject: [ConfigService],
    }),
  ],
})
export class AppModule {}

2. Persistent Volume Configuration​

  • Use SSD-backed storage classes for better performance
  • Enable volume snapshots for backup
  • Set appropriate reclaim policies
storageClassName: premium-rwo # GKE SSD storage
reclaimPolicy: Retain
volumeBindingMode: WaitForFirstConsumer

3. High Availability Checklist​

  • ✅ Use StatefulSets for stable network identities
  • ✅ Deploy across multiple availability zones
  • ✅ Configure pod anti-affinity rules
  • ✅ Enable persistence with durable storage
  • ✅ Set up automated backups
  • ✅ Configure health checks (liveness/readiness probes)
  • ✅ Use Sentinel or Cluster mode for failover
  • ✅ Monitor with Prometheus and alerts
  • ✅ Implement network policies for security
  • ✅ Use TLS for encryption in transit

4. Pod Anti-Affinity​

affinity:
  podAntiAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      - labelSelector:
          matchExpressions:
            - key: app
              operator: In
              values:
                - redis-cluster
        topologyKey: kubernetes.io/hostname
    preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchExpressions:
              - key: app
                operator: In
                values:
                  - redis-cluster
          topologyKey: topology.kubernetes.io/zone

Troubleshooting​

Common Issues and Solutions​

1. Pods not starting:

# Check pod status
kubectl get pods -n redis

# View pod logs
kubectl logs redis-ha-0 -n redis

# Describe pod for events
kubectl describe pod redis-ha-0 -n redis

# Check PVC status
kubectl get pvc -n redis

2. Cluster not forming:

# Check cluster status
kubectl exec -it redis-cluster-0 -n redis -- redis-cli -a $REDIS_PASSWORD cluster info

# Check cluster nodes
kubectl exec -it redis-cluster-0 -n redis -- redis-cli -a $REDIS_PASSWORD cluster nodes

# Re-initialize cluster if needed
kubectl delete job redis-cluster-init -n redis
kubectl apply -f redis-cluster-init-job.yaml

3. Replication issues:

# Check replication status
kubectl exec -it redis-ha-0 -n redis -- redis-cli -a $REDIS_PASSWORD INFO replication

# Force replica to resync
kubectl exec -it redis-ha-1 -n redis -- redis-cli -a $REDIS_PASSWORD REPLICAOF redis-ha-0.redis-ha-headless.redis.svc.cluster.local 6379

4. Performance issues:

# Check slow log
kubectl exec -it redis-ha-0 -n redis -- redis-cli -a $REDIS_PASSWORD SLOWLOG GET 10

# Monitor commands
kubectl exec -it redis-ha-0 -n redis -- redis-cli -a $REDIS_PASSWORD MONITOR

# Check memory usage
kubectl exec -it redis-ha-0 -n redis -- redis-cli -a $REDIS_PASSWORD INFO memory
