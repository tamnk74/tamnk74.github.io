ConfigMap for Redis Configuration in Kubernetes

Overview​

ConfigMaps in Kubernetes provide a way to externalize configuration from container images, making applications more portable and easier to manage. For Redis deployments, ConfigMaps are essential for managing redis.conf settings, sentinel configurations, and environment-specific parameters without rebuilding Docker images.

Why Use ConfigMaps for Redis?​

Benefits​

  1. Separation of Concerns: Configuration is decoupled from application code
  2. Environment-Specific Settings: Different configs for dev, staging, and production
  3. Version Control: Configuration changes tracked in Git
  4. No Image Rebuilds: Update configuration without rebuilding containers
  5. GitOps Compatible: Declarative configuration management
  6. Hot Reloading: Some settings can be updated without pod restarts

ConfigMap vs. Secrets​

AspectConfigMapSecret
PurposeNon-sensitive configurationSensitive data (passwords, keys)
EncodingPlain text (UTF-8)Base64 encoded
Storageetcd (plain text)etcd (can be encrypted at rest)
Use Caseredis.conf, sentinel.confRedis passwords, TLS certificates
Best PracticePublic configurationPrivate credentials

Basic ConfigMap Structure​

1. Simple Redis Configuration​

# redis-basic-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config
  namespace: redis
  labels:
    app: redis
    component: config
data:
  # Simple key-value configuration
  redis-port: '6379'
  max-memory: '256mb'
  max-clients: '10000'

  # Full redis.conf file
  redis.conf: |
    # Network
    bind 0.0.0.0
    protected-mode no
    port 6379
    tcp-backlog 511
    timeout 0
    tcp-keepalive 300

    # General
    daemonize no
    supervised no
    pidfile /var/run/redis_6379.pid
    loglevel notice
    logfile ""
    databases 16

    # Memory Management
    maxmemory 256mb
    maxmemory-policy allkeys-lru
    maxclients 10000

2. Using ConfigMap in Pod​

# redis-pod-with-configmap.yaml
apiVersion: v1
kind: Pod
metadata:
  name: redis
  namespace: redis
spec:
  containers:
    - name: redis
      image: redis:7.2-alpine
      command:
        - redis-server
        - /usr/local/etc/redis/redis.conf
      volumeMounts:
        # Mount entire ConfigMap as files
        - name: redis-config
          mountPath: /usr/local/etc/redis
          readOnly: true
      # Or mount individual keys as environment variables
      env:
        - name: REDIS_PORT
          valueFrom:
            configMapKeyRef:
              name: redis-config
              key: redis-port
        - name: MAX_MEMORY
          valueFrom:
            configMapKeyRef:
              name: redis-config
              key: max-memory
  volumes:
    - name: redis-config
      configMap:
        name: redis-config
        items:
          - key: redis.conf
            path: redis.conf

2. Template-Based Configuration​

# redis-config-template.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config-template
  namespace: redis
data:
  redis.conf: |
    # This will be processed by init container
    bind 0.0.0.0
    protected-mode no
    port 6379

    # Placeholders to be replaced
    maxmemory ${MAX_MEMORY}
    maxmemory-policy ${EVICTION_POLICY}

    # Replication settings
    replicaof ${MASTER_HOST} ${MASTER_PORT}
    masterauth ${MASTER_PASSWORD}

    # Cluster settings
    cluster-enabled ${CLUSTER_ENABLED}
    cluster-config-file /data/nodes-${POD_ID}.conf
    cluster-node-timeout ${CLUSTER_TIMEOUT}

Init Container for Processing:

initContainers:
  - name: config-processor
    image: busybox:1.35
    command:
      - sh
      - -c
      - |
        # Read template
        cp /tmp/config-template/redis.conf /tmp/redis.conf

        # Replace placeholders
        sed -i "s/\${MAX_MEMORY}/${MAX_MEMORY}/g" /tmp/redis.conf
        sed -i "s/\${EVICTION_POLICY}/${EVICTION_POLICY}/g" /tmp/redis.conf
        sed -i "s/\${MASTER_HOST}/${MASTER_HOST}/g" /tmp/redis.conf
        sed -i "s/\${MASTER_PORT}/${MASTER_PORT}/g" /tmp/redis.conf
        sed -i "s/\${CLUSTER_ENABLED}/${CLUSTER_ENABLED}/g" /tmp/redis.conf
        sed -i "s/\${CLUSTER_TIMEOUT}/${CLUSTER_TIMEOUT}/g" /tmp/redis.conf
        sed -i "s/\${POD_ID}/${POD_ID}/g" /tmp/redis.conf

        # Copy to final location
        cp /tmp/redis.conf /etc/redis/redis.conf

        echo "Configuration processed successfully"
        cat /etc/redis/redis.conf
    env:
      - name: MAX_MEMORY
        value: '2gb'
      - name: EVICTION_POLICY
        value: 'allkeys-lru'
      - name: MASTER_HOST
        value: 'redis-master.redis.svc.cluster.local'
      - name: MASTER_PORT
        value: '6379'
      - name: CLUSTER_ENABLED
        value: 'yes'
      - name: CLUSTER_TIMEOUT
        value: '5000'
      - name: POD_ID
        valueFrom:
          fieldRef:
            fieldPath: metadata.name
    volumeMounts:
      - name: config-template
        mountPath: /tmp/config-template
      - name: config
        mountPath: /etc/redis
volumes:
  - name: config-template
    configMap:
      name: redis-config-template
  - name: config
    emptyDir: {}

3. Master-Replica Dynamic Configuration​

# redis-ha-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-ha-config
  namespace: redis
data:
  # Base configuration shared by all
  base.conf: |
    bind 0.0.0.0
    protected-mode no
    port 6379
    tcp-backlog 511
    timeout 0
    tcp-keepalive 300

    # Logging
    loglevel notice
    logfile ""

    # Persistence
    save 900 1
    save 300 10
    save 60 10000
    dbfilename dump.rdb
    dir /data

    appendonly yes
    appendfilename "appendonly.aof"
    appendfsync everysec

    # Memory
    maxmemory 2gb
    maxmemory-policy allkeys-lru

  # Master-specific settings
  master.conf: |
    # Include base config
    include /etc/redis/base.conf

    # Master settings
    masterauth ${REDIS_PASSWORD}
    requirepass ${REDIS_PASSWORD}

    # Replication
    min-replicas-to-write 1
    min-replicas-max-lag 10

    # Persistence for master
    save 900 1
    save 300 10
    save 60 10000

  # Replica-specific settings
  replica.conf: |
    # Include base config
    include /etc/redis/base.conf

    # Replica settings
    replicaof ${MASTER_HOST} 6379
    masterauth ${REDIS_PASSWORD}
    requirepass ${REDIS_PASSWORD}

    # Replica behavior
    replica-serve-stale-data yes
    replica-read-only yes
    repl-diskless-sync no
    repl-diskless-sync-delay 5
    repl-disable-tcp-nodelay no
    replica-priority 100

  # Init script to determine role
  init.sh: |
    #!/bin/sh
    set -e

    # Get pod ordinal from hostname
    ORDINAL=${HOSTNAME##*-}

    # Pod 0 is always master
    if [ "$ORDINAL" = "0" ]; then
      echo "Initializing as MASTER"
      cp /etc/redis-config/base.conf /etc/redis/redis.conf
      cat /etc/redis-config/master.conf | grep -v "^include" >> /etc/redis/redis.conf
    else
      echo "Initializing as REPLICA of redis-ha-0"
      cp /etc/redis-config/base.conf /etc/redis/redis.conf
      cat /etc/redis-config/replica.conf | grep -v "^include" >> /etc/redis/redis.conf
      
      # Set master host dynamically
      MASTER_HOST="redis-ha-0.redis-ha-headless.redis.svc.cluster.local"
      sed -i "s/\${MASTER_HOST}/${MASTER_HOST}/g" /etc/redis/redis.conf
    fi

    # Replace password placeholder
    sed -i "s/\${REDIS_PASSWORD}/${REDIS_PASSWORD}/g" /etc/redis/redis.conf

    echo "Configuration initialized for pod ${HOSTNAME}"

4. Redis Cluster Configuration​

# redis-cluster-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-cluster-config
  namespace: redis
data:
  redis.conf: |
    # Network
    bind 0.0.0.0
    protected-mode no
    port 6379
    tcp-backlog 511

    # Cluster mode
    cluster-enabled yes
    cluster-config-file /data/nodes.conf
    cluster-node-timeout 5000
    cluster-replica-validity-factor 10
    cluster-migration-barrier 1
    cluster-require-full-coverage no
    cluster-replica-no-failover no
    cluster-allow-reads-when-down no

    # Cluster announcements (for external access)
    # cluster-announce-ip will be set dynamically
    # cluster-announce-port 6379
    # cluster-announce-bus-port 16379

    # General
    daemonize no
    supervised no
    pidfile /var/run/redis_6379.pid
    loglevel notice
    logfile ""
    databases 16

    # Persistence - RDB
    save 900 1
    save 300 10
    save 60 10000
    stop-writes-on-bgsave-error yes
    rdbcompression yes
    rdbchecksum yes
    dbfilename dump.rdb
    dir /data

    # Persistence - AOF
    appendonly yes
    appendfilename "appendonly.aof"
    appendfsync everysec
    no-appendfsync-on-rewrite no
    auto-aof-rewrite-percentage 100
    auto-aof-rewrite-min-size 64mb
    aof-load-truncated yes
    aof-use-rdb-preamble yes

    # Replication
    repl-diskless-sync no
    repl-diskless-sync-delay 5
    repl-disable-tcp-nodelay no
    replica-priority 100

    # Security
    masterauth ${REDIS_PASSWORD}
    requirepass ${REDIS_PASSWORD}

    # Memory
    maxmemory 4gb
    maxmemory-policy allkeys-lru
    maxmemory-samples 5

    # Performance
    slowlog-log-slower-than 10000
    slowlog-max-len 128
    latency-monitor-threshold 100

    # Advanced config
    hash-max-ziplist-entries 512
    hash-max-ziplist-value 64
    list-max-ziplist-size -2
    set-max-intset-entries 512
    zset-max-ziplist-entries 128
    zset-max-ziplist-value 64

  # Script to initialize cluster
  init-cluster.sh: |
    #!/bin/sh
    set -e

    # Wait for all pods to be ready
    echo "Waiting for all Redis pods to be ready..."
    sleep 30

    # Build cluster nodes list
    REDIS_NODES=""
    for i in $(seq 0 5); do
      POD_FQDN="redis-cluster-${i}.redis-cluster-headless.redis.svc.cluster.local"
      REDIS_NODES="${REDIS_NODES} ${POD_FQDN}:6379"
    done

    echo "Creating cluster with nodes: ${REDIS_NODES}"

    # Create cluster (3 masters, 3 replicas)
    echo "yes" | redis-cli \
      -a ${REDIS_PASSWORD} \
      --cluster create ${REDIS_NODES} \
      --cluster-replicas 1

    # Verify cluster
    redis-cli \
      -a ${REDIS_PASSWORD} \
      -c \
      -h redis-cluster-0.redis-cluster-headless.redis.svc.cluster.local \
      cluster info

    redis-cli \
      -a ${REDIS_PASSWORD} \
      -c \
      -h redis-cluster-0.redis-cluster-headless.redis.svc.cluster.local \
      cluster nodes

    echo "Cluster initialization completed successfully"

5. Sentinel Configuration​

# redis-sentinel-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-sentinel-config
  namespace: redis
data:
  sentinel.conf: |
    # Sentinel port
    bind 0.0.0.0
    port 26379

    # Working directory
    dir /data

    # Sentinel monitor
    # sentinel monitor <master-name> <ip> <port> <quorum>
    sentinel monitor mymaster redis-ha-0.redis-ha-headless.redis.svc.cluster.local 6379 2

    # Authentication
    sentinel auth-pass mymaster ${REDIS_PASSWORD}

    # Failure detection
    sentinel down-after-milliseconds mymaster 5000
    sentinel parallel-syncs mymaster 1
    sentinel failover-timeout mymaster 10000

    # Notification scripts (optional)
    # sentinel notification-script mymaster /path/to/notification.sh
    # sentinel client-reconfig-script mymaster /path/to/reconfig.sh

    # Sentinel logging
    logfile ""
    loglevel notice

    # Protection
    protected-mode no

    # Performance
    sentinel deny-scripts-reconfig yes

  # Init script for sentinel
  init-sentinel.sh: |
    #!/bin/sh
    set -e

    # Copy template config
    cp /etc/sentinel-config/sentinel.conf /etc/sentinel/sentinel.conf

    # Replace password
    sed -i "s/\${REDIS_PASSWORD}/${REDIS_PASSWORD}/g" /etc/sentinel/sentinel.conf

    # Detect and configure master
    MASTER_HOST="redis-ha-0.redis-ha-headless.redis.svc.cluster.local"

    # Verify master is reachable
    until redis-cli -h ${MASTER_HOST} -a ${REDIS_PASSWORD} ping; do
      echo "Waiting for Redis master to be ready..."
      sleep 2
    done

    echo "Sentinel configuration initialized"
    cat /etc/sentinel/sentinel.conf

ConfigMap Management Best Practices​

1. Immutable ConfigMaps​

# Immutable ConfigMap (Kubernetes 1.21+)
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config-v1
  namespace: redis
immutable: true # Cannot be updated, must create new version
data:
  redis.conf: |
    # Configuration content
    bind 0.0.0.0
    port 6379

Benefits of Immutable ConfigMaps:

  • Prevents accidental configuration changes
  • Improves cluster performance (less watch overhead)
  • Forces versioned configuration updates
  • Better GitOps workflow

2. Versioned ConfigMaps​

# redis-config-v1.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config-v1
  namespace: redis
  labels:
    version: v1
data:
  redis.conf: |
    maxmemory 2gb

---
# redis-config-v2.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config-v2
  namespace: redis
  labels:
    version: v2
data:
  redis.conf: |
    maxmemory 4gb  # Increased memory

Deployment strategy:

# Update Deployment to use new version
spec:
  template:
    spec:
      volumes:
        - name: redis-config
          configMap:
            name: redis-config-v2 # Update version

3. ConfigMap Size Limits​

  • Maximum size: 1 MiB per ConfigMap
  • etcd limits: Total 1.5 MiB per object
  • Best practice: Keep ConfigMaps small and focused

For large configurations:

# Split large config into multiple ConfigMaps
---
# Base configuration
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config-base
data:
  base.conf: |
    # Core settings
    bind 0.0.0.0
    port 6379

---
# Persistence configuration
apiVersion: v1

metadata:
  name: redis-config-persistence
data:
  persistence.conf: |
    # Persistence settings
    save 900 1
    appendonly yes

---
# Memory configuration
apiVersion: v1

  name: redis-config-memory
data:
  memory.conf: |
    # Memory settings
    maxmemory 4gb
    maxmemory-policy allkeys-lru

4. ConfigMap Updates and Rollouts​

Automatic update with subPath (NOT recommended):

volumeMounts:
  - name: config
    mountPath: /etc/redis/redis.conf
    subPath: redis.conf # Won't auto-update

Automatic update without subPath (Recommended):

volumeMounts:
  - name: config
    mountPath: /etc/redis # Auto-updates when ConfigMap changes

Force pod restart on ConfigMap change:

# Add checksum annotation to force restart
apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis
spec:
  template:
    metadata:
      annotations:
        checksum/config: { { include (print $.Template.BasePath "/configmap.yaml") . | sha256sum } }

Manual rollout after ConfigMap update:

# Update ConfigMap
kubectl apply -f redis-configmap.yaml

# Restart pods to pick up changes
kubectl rollout restart statefulset/redis -n redis

# Check rollout status
kubectl rollout status statefulset/redis -n redis

Configuration Validation​

1. Pre-deployment Validation​

# validation-job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: redis-config-validator
  namespace: redis
spec:
  template:
    spec:
      containers:
        - name: validator
          image: redis:7.2-alpine
          command:
            - sh
            - -c
            - |
              # Test configuration syntax
              redis-server /etc/redis/redis.conf --test-memory 1

              if [ $? -eq 0 ]; then
                echo "Configuration is valid"
                exit 0
              else
                echo "Configuration validation failed"
                exit 1
              fi
          volumeMounts:
            - name: config
              mountPath: /etc/redis
      volumes:
        - name: config
          configMap:
            name: redis-config
      restartPolicy: Never
  backoffLimit: 1

2. Runtime Configuration Check​

# config-checker sidecar
containers:
  - name: config-checker
    image: busybox:1.35
    command:
      - sh
      - -c
      - |
        while true; do
          # Check if config has changed
          CONFIG_HASH=$(md5sum /etc/redis/redis.conf | awk '{print $1}')
          
          if [ "$CONFIG_HASH" != "$LAST_HASH" ]; then
            echo "Configuration changed: $CONFIG_HASH"
            
            # Notify main container to reload
            redis-cli -h localhost -a $REDIS_PASSWORD CONFIG REWRITE
            
            LAST_HASH=$CONFIG_HASH
          fi
          
          sleep 30
        done
    volumeMounts:
      - name: redis-config
        mountPath: /etc/redis

ConfigMap from Files​

Create ConfigMap from file​

# Create ConfigMap from redis.conf file
kubectl create configmap redis-config \
  --from-file=redis.conf=/path/to/redis.conf \
  --namespace=redis

# Create from multiple files
kubectl create configmap redis-config \
  --from-file=redis.conf=/path/to/redis.conf \
  --from-file=sentinel.conf=/path/to/sentinel.conf \
  --namespace=redis

# Create from directory
kubectl create configmap redis-config \
  --from-file=/path/to/redis-configs/ \
  --namespace=redis

Generate ConfigMap YAML from file​

# Dry-run to generate YAML
kubectl create configmap redis-config \
  --from-file=redis.conf=/path/to/redis.conf \
  --dry-run=client \
  -o yaml > redis-configmap.yaml

Troubleshooting ConfigMaps​

1. Check ConfigMap contents​

# View ConfigMap
kubectl get configmap redis-config -n redis -o yaml

# Describe ConfigMap
kubectl describe configmap redis-config -n redis

# Get specific key
kubectl get configmap redis-config -n redis -o jsonpath='{.data.redis\.conf}'

2. Verify Pod is using correct ConfigMap​

# Check mounted ConfigMap in pod
kubectl exec -it redis-0 -n redis -- cat /etc/redis/redis.conf

# Compare with ConfigMap
kubectl get configmap redis-config -n redis -o jsonpath='{.data.redis\.conf}' > /tmp/configmap.conf
kubectl exec redis-0 -n redis -- cat /etc/redis/redis.conf > /tmp/pod.conf
diff /tmp/configmap.conf /tmp/pod.conf

3. Debug ConfigMap mounting issues​

# Check volume mounts
kubectl describe pod redis-0 -n redis | grep -A 5 "Mounts:"

# Check volume sources
kubectl describe pod redis-0 -n redis | grep -A 10 "Volumes:"

# Check for events
kubectl get events -n redis --field-selector involvedObject.name=redis-0

4. Common Issues​

Issue 1: Configuration not updating

# Solution: Check if using subPath (prevents auto-update)
kubectl get pod redis-0 -n redis -o yaml | grep subPath

# If using subPath, restart pod manually
kubectl delete pod redis-0 -n redis

Issue 2: ConfigMap too large

# Check ConfigMap size
kubectl get configmap redis-config -n redis -o json | jq '.data | to_entries | .[] | .key + ": " + (.value | length | tostring) + " bytes"'

# Split large ConfigMaps or use Secrets for large files

Issue 3: Permission denied errors

# Check defaultMode in ConfigMap volume
kubectl get pod redis-0 -n redis -o yaml | grep -A 5 configMap

# Set correct permissions
volumes:
- name: config
  configMap:
    name: redis-config
    defaultMode: 0644  # Read permissions

Summary​

ConfigMaps are essential for managing Redis configuration in Kubernetes:

  • Use ConfigMaps for non-sensitive configuration (redis.conf, sentinel.conf)
  • Use Secrets for sensitive data (passwords, TLS certificates)
  • Version ConfigMaps for safe rollouts and rollbacks
  • Make ConfigMaps immutable for production stability
  • Split large configs across multiple ConfigMaps
  • Validate configurations before deployment
  • Avoid subPath for automatic config updates
  • Use init containers for dynamic configuration generation
  • Monitor ConfigMap changes and trigger appropriate pod restarts

This approach enables declarative, version-controlled, and environment-specific Redis configurations in Kubernetes.
