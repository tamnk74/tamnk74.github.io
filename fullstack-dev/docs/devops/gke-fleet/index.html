GKE Fleet: Multi-Cluster Management

Google Kubernetes Engine (GKE) Fleet is a unified way to manage multiple Kubernetes clusters—across regions, projects, and even clouds—as a single logical fleet. It enables centralized policy, configuration, and workload management, supporting hybrid and multi-cloud environments.

Use Cases​

  • Centralized security and policy enforcement across clusters
  • Consistent configuration and GitOps (Config Sync)
  • Multi-cluster service discovery and load balancing
  • Workload identity and access management
  • Hybrid and multi-cloud application deployment

Architecture Overview​

Key Features​

  • Centralized Identity & Access: Manage users and permissions across clusters.
  • Config Sync: Enforce consistent configuration and policy using GitOps.
  • Multi-Cluster Services: Expose and discover services across clusters.
  • Workload Identity: Securely manage service accounts and identities.
  • Anthos Integration: Seamless integration with Anthos for hybrid/multi-cloud.

Prerequisites​

  • Google Cloud project with billing enabled
  • GKE clusters (zonal, regional, or on-prem)
  • gcloud CLI installed and authenticated

Step 1: Enable Fleet API​

gcloud services enable gkehub.googleapis.com

Step 2: Register Clusters to the Fleet​

For GKE Clusters​

gcloud container hub memberships register <CLUSTER_NAME> \
  --gke-cluster=<REGION>/<CLUSTER_NAME> \
  --project=<PROJECT_ID>

For Non-GKE (On-Prem/Other Cloud) Clusters​

gcloud container hub memberships register <CLUSTER_NAME> \
  --context=<KUBECONFIG_CONTEXT> \
  --kubeconfig=<KUBECONFIG_PATH> \
  --project=<PROJECT_ID>

See Registering non-GKE clusters for details.

Step 3: Verify Fleet Membership​

gcloud container hub memberships list

Step 4: Enable Config Sync (Optional)​

gcloud beta container hub config-management enable

Step 5: Enable Multi-Cluster Service Discovery (Optional)​

gcloud container hub multi-cluster-services enable

Multi-Project Fleet Setup​

When managing multiple GCP projects with one cluster each under a single fleet, you need to designate one project as the Fleet Host Project and register clusters from other projects as fleet members.

Architecture: Multi-Project Fleet​

Prerequisites for Multi-Project Fleet​

  1. Fleet Host Project: A dedicated project to host the fleet (recommended)
  2. Member Projects: Projects containing GKE clusters (dev, staging, prod, etc.)
  3. IAM Permissions: Proper cross-project permissions
  4. Billing: All projects must have billing enabled

Step-by-Step Setup​

1. Choose or Create a Fleet Host Project​

Designate one project as the fleet host. This can be:

  • A dedicated fleet management project (recommended for production)
  • One of your existing projects (e.g., production project)
# Set the fleet host project ID
export FLEET_HOST_PROJECT_ID="my-fleet-host-project"
export FLEET_ID="my-multi-project-fleet"

# Switch to the fleet host project
gcloud config set project ${FLEET_HOST_PROJECT_ID}

2. Enable Required APIs in Fleet Host Project​

# Enable Fleet API in the host project
gcloud services enable gkehub.googleapis.com \
  --project=${FLEET_HOST_PROJECT_ID}

# Enable additional fleet features
gcloud services enable \
  multiclusterservicediscovery.googleapis.com \
  multiclusteringress.googleapis.com \
  anthosconfigmanagement.googleapis.com \
  --project=${FLEET_HOST_PROJECT_ID}

3. Create the Fleet in Host Project​

# Create a fleet (if not using the default fleet)
gcloud container fleet create ${FLEET_ID} \
  --project=${FLEET_HOST_PROJECT_ID}

Note: Each project has a default fleet. For multi-project setups, you can either:

  • Use the default fleet of the host project
  • Create a named fleet for better organization

4. Grant Cross-Project IAM Permissions​

For each member project, grant the fleet host project permission to register clusters:

# Set member project variables
export MEMBER_PROJECT_ID="my-dev-project"

# Grant gkehub.connect permission to the fleet host project
gcloud projects add-iam-policy-binding ${MEMBER_PROJECT_ID} \
  --member="serviceAccount:service-${FLEET_HOST_PROJECT_NUMBER}@gcp-sa-gkehub.iam.gserviceaccount.com" \
  --role="roles/gkehub.connect" \
  --project=${MEMBER_PROJECT_ID}

# Grant container.viewer permission for cluster discovery
gcloud projects add-iam-policy-binding ${MEMBER_PROJECT_ID} \
  --member="serviceAccount:service-${FLEET_HOST_PROJECT_NUMBER}@gcp-sa-gkehub.iam.gserviceaccount.com" \
  --role="roles/container.viewer" \
  --project=${MEMBER_PROJECT_ID}

Get Fleet Host Project Number:

export FLEET_HOST_PROJECT_NUMBER=$(gcloud projects describe ${FLEET_HOST_PROJECT_ID} --format="value(projectNumber)")

5. Enable GKE Hub API in Member Projects​

# For each member project
gcloud services enable gkehub.googleapis.com \
  --project=${MEMBER_PROJECT_ID}

6. Register Clusters from Member Projects​

# For Project 1 (Dev)
export DEV_PROJECT_ID="my-dev-project"
export DEV_CLUSTER_NAME="dev-cluster"
export DEV_CLUSTER_REGION="us-central1"

gcloud container fleet memberships register ${DEV_CLUSTER_NAME} \
  --gke-cluster=${DEV_CLUSTER_REGION}/${DEV_CLUSTER_NAME} \
  --project=${DEV_PROJECT_ID} \
  --fleet-project=${FLEET_HOST_PROJECT_ID}

# For Project 2 (Staging)
export STAGING_PROJECT_ID="my-staging-project"
export STAGING_CLUSTER_NAME="staging-cluster"
export STAGING_CLUSTER_REGION="us-east1"

gcloud container fleet memberships register ${STAGING_CLUSTER_NAME} \
  --gke-cluster=${STAGING_CLUSTER_REGION}/${STAGING_CLUSTER_NAME} \
  --project=${STAGING_PROJECT_ID} \
  --fleet-project=${FLEET_HOST_PROJECT_ID}

# For Project 3 (Prod)
export PROD_PROJECT_ID="my-prod-project"
export PROD_CLUSTER_NAME="prod-cluster"
export PROD_CLUSTER_REGION="us-west1"

gcloud container fleet memberships register ${PROD_CLUSTER_NAME} \
  --gke-cluster=${PROD_CLUSTER_REGION}/${PROD_CLUSTER_NAME} \
  --project=${PROD_PROJECT_ID} \
  --fleet-project=${FLEET_HOST_PROJECT_ID}

7. Verify Fleet Membership​

# List all clusters in the fleet
gcloud container fleet memberships list \
  --project=${FLEET_HOST_PROJECT_ID}

# Describe a specific cluster membership
gcloud container fleet memberships describe ${DEV_CLUSTER_NAME} \
  --project=${FLEET_HOST_PROJECT_ID}

8. Enable Fleet Features (Optional)​

# Enable Config Sync for centralized configuration
gcloud container fleet config-management enable \
  --project=${FLEET_HOST_PROJECT_ID}

# Enable Multi-Cluster Services
gcloud container fleet multi-cluster-services enable \
  --project=${FLEET_HOST_PROJECT_ID}

# Enable Multi-Cluster Ingress
gcloud container fleet ingress enable \
  --config-membership=${PROD_CLUSTER_NAME} \
  --project=${FLEET_HOST_PROJECT_ID}

Complete Setup Script​

Here's a complete bash script for setting up a multi-project fleet:

#!/bin/bash
set -e

# Configuration
FLEET_HOST_PROJECT_ID="my-fleet-host"
FLEET_ID="production-fleet"

# Member projects and clusters
declare -A PROJECTS=(
  ["dev"]="my-dev-project:dev-cluster:us-central1"
  ["staging"]="my-staging-project:staging-cluster:us-east1"
  ["prod"]="my-prod-project:prod-cluster:us-west1"
)

# Get fleet host project number
FLEET_HOST_PROJECT_NUMBER=$(gcloud projects describe ${FLEET_HOST_PROJECT_ID} \
  --format="value(projectNumber)")

echo "Setting up fleet in host project: ${FLEET_HOST_PROJECT_ID}"

# Step 1: Enable APIs in fleet host
gcloud services enable gkehub.googleapis.com \
  multiclusterservicediscovery.googleapis.com \
  multiclusteringress.googleapis.com \
  anthosconfigmanagement.googleapis.com \
  --project=${FLEET_HOST_PROJECT_ID}

# Step 2: Create fleet (optional, if not using default)
# gcloud container fleet create ${FLEET_ID} --project=${FLEET_HOST_PROJECT_ID}

# Step 3: Configure member projects
for env in "${!PROJECTS[@]}"; do
  IFS=':' read -r PROJECT_ID CLUSTER_NAME REGION <<< "${PROJECTS[$env]}"

  echo "Configuring ${env} environment: ${PROJECT_ID}"

  # Enable GKE Hub API in member project
  gcloud services enable gkehub.googleapis.com --project=${PROJECT_ID}

  # Grant IAM permissions
  gcloud projects add-iam-policy-binding ${PROJECT_ID} \
    --member="serviceAccount:service-${FLEET_HOST_PROJECT_NUMBER}@gcp-sa-gkehub.iam.gserviceaccount.com" \
    --role="roles/gkehub.connect" \
    --project=${PROJECT_ID}

  gcloud projects add-iam-policy-binding ${PROJECT_ID} \
    --member="serviceAccount:service-${FLEET_HOST_PROJECT_NUMBER}@gcp-sa-gkehub.iam.gserviceaccount.com" \
    --role="roles/container.viewer" \
    --project=${PROJECT_ID}

  # Register cluster to fleet
  gcloud container fleet memberships register ${CLUSTER_NAME} \
    --gke-cluster=${REGION}/${CLUSTER_NAME} \
    --project=${PROJECT_ID} \
    --fleet-project=${FLEET_HOST_PROJECT_ID}

  echo "✓ ${env} cluster registered successfully"
done

# Step 4: Verify fleet membership
echo "Fleet membership summary:"
gcloud container fleet memberships list --project=${FLEET_HOST_PROJECT_ID}

# Step 5: Enable fleet features
echo "Enabling Config Sync..."
gcloud container fleet config-management enable \
  --project=${FLEET_HOST_PROJECT_ID}

echo "Enabling Multi-Cluster Services..."
gcloud container fleet multi-cluster-services enable \
  --project=${FLEET_HOST_PROJECT_ID}

echo "✓ Multi-project fleet setup complete!"

Managing Multi-Project Fleet​

Applying Policies Across All Projects​

Use Config Sync to apply consistent policies across all clusters:

# config-management.yaml
apiVersion: configmanagement.gke.io/v1
kind: ConfigManagement
metadata:
  name: config-management
spec:
  clusterName: CLUSTER_NAME
  git:
    syncRepo: https://github.com/your-org/fleet-config
    syncBranch: main
    secretType: none
    policyDir: 'policies'
  policyController:
    enabled: true

Apply to all clusters:

for cluster in dev-cluster staging-cluster prod-cluster; do
  kubectl apply -f config-management.yaml --context=${cluster}
done

Monitoring Fleet Health​

# View fleet status
gcloud container fleet memberships list \
  --project=${FLEET_HOST_PROJECT_ID} \
  --format="table(name,state.code,uniqueId)"

# Check Config Sync status
gcloud container fleet config-management status \
  --project=${FLEET_HOST_PROJECT_ID}

Unregistering a Cluster​

gcloud container fleet memberships unregister ${CLUSTER_NAME} \
  --project=${MEMBER_PROJECT_ID} \
  --fleet-project=${FLEET_HOST_PROJECT_ID}

Best Practices for Multi-Project Fleets​

  1. Use a Dedicated Fleet Host Project: Keep fleet management separate from workloads
  2. Consistent Naming Convention: Use clear names like {env}-{region}-cluster
  3. Label Your Clusters: Add environment labels for easy filtering 
    gcloud container fleet memberships update ${CLUSTER_NAME} \
      --update-labels=environment=dev,region=us-central1 \
      --project=${FLEET_HOST_PROJECT_ID}
  4. Implement RBAC: Use Workload Identity and IAM for secure cross-project access
  5. Centralized Logging: Send logs from all clusters to a central project
  6. GitOps for Config: Use Config Sync with a single Git repository
  7. Regular Audits: Periodically review fleet membership and permissions

Troubleshooting Multi-Project Setup​

Issue: Registration fails with permission denied

  • Solution: Verify IAM bindings for gkehub.connect role
  • Check project numbers match correctly

Issue: Cluster not appearing in fleet

  • Solution: Ensure both projects have gkehub.googleapis.com enabled
  • Verify network connectivity to GKE Hub endpoints

Issue: Config Sync not working across projects

  • Solution: Check that Config Sync is enabled at the fleet level
  • Verify Git repository access from all clusters

Common Operational Tasks​

  • Apply Policy Across Fleet:
    • Use Config Sync to push RBAC, NetworkPolicy, or other YAMLs to all clusters.
  • Workload Identity Federation:
    • Map GCP IAM to Kubernetes service accounts for secure, cross-cluster identity.
  • Monitor Fleet Health:
    • Use GKE Hub and Cloud Console for fleet-wide status and alerts.

Best Practices​

  • Use unique cluster names and labels for easy identification.
  • Regularly audit fleet membership and permissions.
  • Use Config Sync for GitOps-driven, consistent configuration.
  • Enable workload identity for secure service-to-service communication.
  • Test multi-cluster services in a staging environment before production.

Troubleshooting​

  • If a cluster does not appear in the fleet, check registration logs and IAM permissions.
  • Ensure all clusters have network connectivity to GKE Hub endpoints.
  • Use gcloud container hub memberships describe <CLUSTER_NAME> for detailed status.
