Cloud Storage Use Cases

Overview​

Cloud storage is a fundamental service in modern cloud computing that allows organizations to store and access data over the internet. This guide explores practical use cases, best practices, and implementation patterns for cloud storage across different scenarios.

Storage Types Overview​

Object Storage​

  • Examples: Amazon S3, Google Cloud Storage, Azure Blob Storage
  • Best for: Unstructured data, media files, backups
  • Characteristics: Highly scalable, cost-effective, accessible via HTTP/HTTPS

Block Storage​

  • Examples: Amazon EBS, Google Persistent Disk, Azure Disk Storage
  • Best for: Database storage, application data requiring low latency
  • Characteristics: High performance, attached to compute instances

File Storage​

  • Examples: Amazon EFS, Google Filestore, Azure Files
  • Best for: Shared file systems, legacy applications
  • Characteristics: NFS/SMB protocols, concurrent access

Common Use Cases​

1. Static Website Hosting​

Use Case: Host static websites, SPAs (Single Page Applications), or documentation sites directly from cloud storage.

Benefits:

  • ✅ Cost-effective (no server management)
  • ✅ High availability and scalability
  • ✅ Global CDN integration
  • ✅ Custom domain support

Implementation Example (GCS):

# Create a bucket
gsutil mb -c STANDARD -l us-central1 gs://my-website-bucket

# Make bucket publicly accessible
gsutil iam ch allUsers:objectViewer gs://my-website-bucket

# Configure as website
gsutil web set -m index.html -e 404.html gs://my-website-bucket

# Upload content
gsutil -m cp -r ./build/* gs://my-website-bucket

Best Practices:

  • Enable CDN for faster global access
  • Set appropriate cache headers
  • Use versioning for rollback capability
  • Implement security headers

2. Media Storage and Delivery​

Use Case: Store and serve images, videos, audio files, and other media content for applications.

Benefits:

  • ✅ Unlimited scalability
  • ✅ Global content delivery
  • ✅ On-the-fly transformations
  • ✅ Automatic format optimization

Architecture Pattern:

User Upload → API Gateway → Lambda/Cloud Function → Cloud Storage
                                                         ↓
                                                    CDN (CloudFlare/CloudFront)
                                                         ↓
                                                    End Users

Implementation Example (S3 + CloudFront):

// Node.js upload to S3
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';

const s3Client = new S3Client({ region: 'us-east-1' });

async function uploadMedia(file: Buffer, key: string) {
  const command = new PutObjectCommand({
    Bucket: 'my-media-bucket',
    Key: key,
    Body: file,
    ContentType: 'image/jpeg',
    CacheControl: 'max-age=31536000', // 1 year
    Metadata: {
      uploadedAt: new Date().toISOString(),
    },
  });

  return await s3Client.send(command);
}

Best Practices:

  • Use lifecycle policies for old content
  • Implement image optimization pipeline
  • Set up separate buckets for different media types
  • Use signed URLs for private content

3. Application Data Backup and Disaster Recovery​

Use Case: Automated backup of databases, application data, and configurations.

Benefits:

  • ✅ Durability (11 9's with S3)
  • ✅ Geographic redundancy
  • ✅ Point-in-time recovery
  • ✅ Compliance and retention policies

Implementation Example (PostgreSQL Backup):

#!/bin/bash
# Automated database backup script

DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="production_db"
BACKUP_FILE="${DB_NAME}_${DATE}.sql.gz"
BUCKET="gs://my-backup-bucket/postgres"

# Create backup
pg_dump $DB_NAME | gzip > /tmp/$BACKUP_FILE

# Upload to cloud storage
gsutil cp /tmp/$BACKUP_FILE $BUCKET/

# Clean up local file
rm /tmp/$BACKUP_FILE

# Delete backups older than 30 days
gsutil -m rm -r $(gsutil ls $BUCKET/ | grep -v $(date +%Y%m -d "30 days ago"))

Kubernetes CronJob Example:

kind: CronJob

  name: postgres-backup

4. Data Lake and Analytics​

Use Case: Store raw and processed data for analytics, machine learning, and business intelligence.

Benefits:

  • ✅ Cost-effective storage for massive datasets
  • ✅ Integration with analytics tools
  • ✅ Schema-on-read flexibility
  • ✅ Support for various data formats

Architecture Pattern:

Data Sources → Ingestion Layer → Cloud Storage (Data Lake)
                                        ↓
                              ┌─────────┼─────────┐
                              ↓         ↓         ↓
                         BigQuery  Dataflow  ML Engine

Storage Organization:

gs://company-data-lake/
├── raw/                    # Raw ingested data
│   ├── year=2024/
│   │   ├── month=01/
│   │   │   ├── day=01/
│   │   │   │   └── events.parquet
├── processed/              # Cleaned and transformed
│   ├── year=2024/
│   │   └── month=01/
│   │       └── aggregated_events.parquet
└── analytics/              # Ready for consumption
    └── year=2024/
        └── month=01/
            └── reports.parquet

Implementation Example (Data Pipeline):

from google.cloud import storage
import pandas as pd
import pyarrow.parquet as pq

def process_and_store(source_bucket, dest_bucket, file_path):
    """Process CSV and store as Parquet in data lake"""

    # Read from cloud storage
    storage_client = storage.Client()
    bucket = storage_client.bucket(source_bucket)
    blob = bucket.blob(file_path)

    # Download and process
    csv_data = blob.download_as_text()
    df = pd.read_csv(pd.StringIO(csv_data))

    # Transform data
    df['processed_at'] = pd.Timestamp.now()
    df = df.dropna()

    # Write as Parquet
    dest_bucket_obj = storage_client.bucket(dest_bucket)
    parquet_path = file_path.replace('.csv', '.parquet')

    # Upload to processed folder
    dest_blob = dest_bucket_obj.blob(f'processed/{parquet_path}')
    dest_blob.upload_from_string(
        df.to_parquet(index=False),
        content_type='application/octet-stream'
    )

E-commerce Specific Use Cases​

1. Product Image Management​

Scenario: Store and serve millions of product images with multiple resolutions.

Architecture:

Upload Service → Cloud Storage (Original) → Image Processing Pipeline
                                                    ↓
                                          Multiple Resolutions
                                          (thumbnail, medium, large)
                                                    ↓
                                          CDN Distribution

Implementation:

// Product image upload service
import { Storage } from '@google-cloud/storage';
import sharp from 'sharp';

const storage = new Storage();
const bucket = storage.bucket('product-images');

async function uploadProductImage(productId: string, imageBuffer: Buffer) {
  const sizes = {
    thumbnail: { width: 150, height: 150 },
    medium: { width: 500, height: 500 },
    large: { width: 1200, height: 1200 },
    original: null,
  };

  const uploads = [];

  for (const [size, dimensions] of Object.entries(sizes)) {
    let processedImage = imageBuffer;

    if (dimensions) {
      processedImage = await sharp(imageBuffer)
        .resize(dimensions.width, dimensions.height, { fit: 'inside' })
        .jpeg({ quality: 85 })
        .toBuffer();
    }

    const fileName = `products/${productId}/${size}.jpg`;
    const file = bucket.file(fileName);

    uploads.push(
      file.save(processedImage, {
        metadata: {
          contentType: 'image/jpeg',
          cacheControl: 'public, max-age=31536000',
        },
      }),
    );
  }

  await Promise.all(uploads);

  return {
    thumbnail: `https://cdn.example.com/products/${productId}/thumbnail.jpg`,
    medium: `https://cdn.example.com/products/${productId}/medium.jpg`,
    large: `https://cdn.example.com/products/${productId}/large.jpg`,
  };
}

2. Order Document Storage​

Scenario: Store invoices, receipts, and order-related documents.

Implementation:

// Order document storage
import { Storage } from '@google-cloud/storage';
import PDFDocument from 'pdfkit';

const storage = new Storage();
const bucket = storage.bucket('order-documents');

async function generateAndStoreInvoice(order: Order) {
  const doc = new PDFDocument();
  const chunks: Buffer[] = [];

  doc.on('data', (chunk) => chunks.push(chunk));
  doc.on('end', async () => {
    const pdfBuffer = Buffer.concat(chunks);

    const fileName = `invoices/${order.year}/${order.month}/${order.id}.pdf`;
    const file = bucket.file(fileName);

    await file.save(pdfBuffer, {
      metadata: {
        contentType: 'application/pdf',
        metadata: {
          orderId: order.id,
          customerId: order.customerId,
          generatedAt: new Date().toISOString(),
        },
      },
    });

    // Store reference in database
    await db.orders.update(order.id, {
      invoiceUrl: fileName,
    });
  });

  // Generate PDF content
  doc.fontSize(20).text('Invoice', { align: 'center' });
  doc.fontSize(12).text(`Order #${order.id}`);
  // ... add order details
  doc.end();
}

// Generate signed URL for customer download
async function getInvoiceDownloadUrl(orderId: string) {
  const [metadata] = await db.orders.findById(orderId);
  const file = bucket.file(metadata.invoiceUrl);

  const [url] = await file.getSignedUrl({
    version: 'v4',
    action: 'read',
    expires: Date.now() + 15 * 60 * 1000, // 15 minutes
  });

  return url;
}

3. Import/Export Data Files​

Scenario: Handle bulk product imports, order exports, and data migrations.

Implementation:

// Bulk product import/export
import { Storage } from '@google-cloud/storage';
import csv from 'csv-parser';
import { createObjectCsvWriter } from 'csv-writer';

const storage = new Storage();
const bucket = storage.bucket('import-export');

// Import products from CSV
async function importProducts(fileName: string) {
  const file = bucket.file(`imports/${fileName}`);
  const stream = file.createReadStream();

  const products = [];

  return new Promise((resolve, reject) => {
    stream
      .pipe(csv())
      .on('data', (row) => {
        products.push({
          sku: row.sku,
          name: row.name,
          price: parseFloat(row.price),
          stock: parseInt(row.stock),
        });
      })
      .on('end', async () => {
        // Bulk insert to database
        await db.products.insertMany(products);
        resolve(products.length);
      })
      .on('error', reject);
  });
}

// Export orders to CSV
async function exportOrders(startDate: Date, endDate: Date) {
  const orders = await db.orders.find({
    createdAt: { $gte: startDate, $lte: endDate },
  });

  const fileName = `exports/orders_${startDate.toISOString()}_to_${endDate.toISOString()}.csv`;
  const localFile = `/tmp/${Date.now()}.csv`;

  const csvWriter = createObjectCsvWriter({
    path: localFile,
    header: [
      { id: 'orderId', title: 'Order ID' },
      { id: 'customerId', title: 'Customer ID' },
      { id: 'total', title: 'Total' },
      { id: 'status', title: 'Status' },
      { id: 'createdAt', title: 'Created At' },
    ],
  });

  await csvWriter.writeRecords(orders);

  // Upload to cloud storage
  await bucket.upload(localFile, {
    destination: fileName,
    metadata: {
      contentType: 'text/csv',
    },
  });

  return fileName;
}

Scenario: Store customer reviews, product photos, and user-uploaded content.

// User-generated content storage
import { Storage } from '@google-cloud/storage';
import { v4 as uuidv4 } from 'uuid';

const storage = new Storage();
const bucket = storage.bucket('user-content');

async function uploadReviewImage(userId: string, productId: string, imageBuffer: Buffer) {
  const imageId = uuidv4();
  const fileName = `reviews/${productId}/${userId}/${imageId}.jpg`;

  // Scan for inappropriate content (pseudo-code)
  const isSafe = await moderationService.scanImage(imageBuffer);

  if (!isSafe) {
    throw new Error('Image contains inappropriate content');
  }

  // Upload to cloud storage
  const file = bucket.file(fileName);
  await file.save(imageBuffer, {
    metadata: {
      contentType: 'image/jpeg',
      metadata: {
        userId,
        productId,
        uploadedAt: new Date().toISOString(),
        moderated: 'true',
      },
    },
  });

  // Generate public URL
  await file.makePublic();
  const publicUrl = `https://storage.googleapis.com/${bucket.name}/${fileName}`;

  return publicUrl;
}

Cloud Function Implementation:

// index.ts - Cloud Function for image processing
import { Storage } from '@google-cloud/storage';
import { CloudEvent } from '@google-cloud/functions-framework';
import sharp from 'sharp';

const storage = new Storage();
const processedBucket = storage.bucket('processed-images');

interface StorageObjectData {
  name: string;
  bucket: string;
  contentType: string;
}

export async function processImage(cloudEvent: CloudEvent<StorageObjectData>) {
  const file = cloudEvent.data;

  // Skip if already processed
  if (file.name.includes('/processed/')) {
    return;
  }

  // Only process images
  if (!file.contentType?.startsWith('image/')) {
    return;
  }

  const bucket = storage.bucket(file.bucket);
  const srcFile = bucket.file(file.name);

  // Download image
  const [imageBuffer] = await srcFile.download();

  // Define sizes to generate
  const sizes = [
    { name: 'thumbnail', width: 150, height: 150 },
    { name: 'small', width: 320, height: 320 },
    { name: 'medium', width: 640, height: 640 },
    { name: 'large', width: 1280, height: 1280 },
  ];

  // Process images in parallel
  const processPromises = sizes.map(async (size) => {
    const processed = await sharp(imageBuffer)
      .resize(size.width, size.height, {
        fit: 'inside',
        withoutEnlargement: true,
      })
      .jpeg({ quality: 85, progressive: true })
      .toBuffer();

    const fileName = file.name.replace(/\.[^/.]+$/, '');
    const destFile = processedBucket.file(`processed/${fileName}_${size.name}.jpg`);

    await destFile.save(processed, {
      metadata: {
        contentType: 'image/jpeg',
        cacheControl: 'public, max-age=31536000',
        metadata: {
          originalFile: file.name,
          processedSize: size.name,
          processedAt: new Date().toISOString(),
        },
      },
    });

    console.log(`Processed ${size.name}: ${destFile.name}`);
  });

  await Promise.all(processPromises);

  // Optionally delete original or move to archive
  // await srcFile.move(`archive/${file.name}`);
}

2. Dataflow Pipeline (Python):

# dataflow_pipeline.py
import apache_beam as beam
from apache_beam.options.pipeline_options import PipelineOptions
from apache_beam.io.gcp.bigquery import WriteToBigQuery
import json

class ParseJson(beam.DoFn):
    def process(self, element):
        try:
            data = json.loads(element)
            yield {
                'timestamp': data['timestamp'],
                'user_id': data['user_id'],
                'event_type': data['event_type'],
                'properties': json.dumps(data.get('properties', {}))
            }
        except Exception as e:
            print(f"Error parsing: {e}")

def run_pipeline():
    options = PipelineOptions(
        project='my-project',
        region='us-central1',
        runner='DataflowRunner',
        temp_location='gs://company-datalake-raw/temp',
        staging_location='gs://company-datalake-raw/staging'
    )

    with beam.Pipeline(options=options) as p:
        (p
         | 'Read from Pub/Sub' >> beam.io.ReadFromPubSub(
             subscription='projects/my-project/subscriptions/events-sub'
         )
         | 'Parse JSON' >> beam.ParDo(ParseJson())
         | 'Write to GCS' >> beam.io.WriteToText(
             'gs://company-datalake-raw/events',
             file_name_suffix='.json',
             num_shards=10
         )
         | 'Write to BigQuery' >> WriteToBigQuery(
             table='my-project:analytics.events',
             schema='timestamp:TIMESTAMP,user_id:STRING,event_type:STRING,properties:STRING',
             write_disposition=beam.io.BigQueryDisposition.WRITE_APPEND
         ))

if __name__ == '__main__':
    run_pipeline()

2. Microservice Subscriber (Node.js):

// microservices/scan-service/src/index.ts
import { PubSub } from '@google-cloud/pubsub';
import { Storage } from '@google-cloud/storage';

const pubsub = new PubSub();
const storage = new Storage();

interface StorageEvent {
  kind: string;
  id: string;
  bucket: string;
  name: string;
  size: string;
  contentType: string;
  timeCreated: string;
}

async function processUpload(event: StorageEvent) {
  console.log(`Processing file: ${event.name}`);

  const bucket = storage.bucket(event.bucket);
  const file = bucket.file(event.name);

  // Download and scan file
  const [contents] = await file.download();

  // Perform virus scan, content moderation, etc.
  const scanResult = await scanFile(contents);

  if (scanResult.isSafe) {
    // Move to processed bucket
    await file.copy(`processed-${event.bucket}/${event.name}`);

    // Update metadata
    await file.setMetadata({
      metadata: {
        scanned: 'true',
        scanResult: JSON.stringify(scanResult),
        scannedAt: new Date().toISOString(),
      },
    });
  } else {
    // Quarantine suspicious file
    await file.move(`quarantine-${event.bucket}/${event.name}`);

    // Send alert
    await sendAlert({
      file: event.name,
      reason: scanResult.reason,
    });
  }
}

// Subscribe to Pub/Sub
const subscription = pubsub.subscription('scan-service-sub');

subscription.on('message', async (message) => {
  try {
    const event: StorageEvent = JSON.parse(message.data.toString());
    await processUpload(event);
    message.ack();
  } catch (error) {
    console.error('Error processing message:', error);
    message.nack();
  }
});

console.log('Scan service listening for storage events...');

Key Considerations​

Multi-Region:

  • ✅ Best for: Global user base, disaster recovery
  • ⚠️ Consider: Replication costs, consistency requirements

Serverless:

  • ✅ Best for: Automatic scaling, pay-per-use
  • ⚠️ Consider: Cold starts, execution time limits

Data Lake:

  • ✅ Best for: Large-scale analytics, data science
  • ⚠️ Consider: Query costs, data organization

Secure Enterprise:

  • ✅ Best for: Regulated industries, sensitive data
  • ⚠️ Consider: Setup complexity, access restrictions

Hybrid Cloud:

  • ✅ Best for: Gradual migration, legacy integration
  • ⚠️ Consider: Network bandwidth, latency

Event-Driven:

  • ✅ Best for: Decoupled systems, async processing
  • ⚠️ Consider: Event ordering, retry logic

Performance Considerations​

Object Storage:

  • Throughput: High (parallel downloads)
  • Latency: Medium (HTTP overhead)
  • IOPS: Not applicable
  • Best for: Large files, bulk operations

Block Storage:

  • Throughput: Very High
  • Latency: Very Low (< 1ms)
  • IOPS: Very High (thousands)
  • Best for: Databases, transactional workloads

File Storage:

  • Throughput: High
  • Latency: Low
  • IOPS: High
  • Best for: Shared access, legacy apps

Best Practices​

1. Security​

Bucket Policies and IAM:

{
  "bindings": [
    {
      "role": "roles/storage.objectViewer",
      "members": ["allUsers"],
      "condition": {
        "title": "Public read for website assets",
        "expression": "resource.name.startsWith('projects/_/buckets/my-bucket/objects/public/')"
      }
    },
    {
      "role": "roles/storage.objectCreator",
      "members": ["serviceAccount:upload-service@project.iam.gserviceaccount.com"]
    }
  ]
}

Encryption:

// Server-side encryption with customer-managed keys
await bucket.file('sensitive-data.json').save(data, {
  kmsKeyName: 'projects/my-project/locations/global/keyRings/my-keyring/cryptoKeys/my-key',
});

2. Lifecycle Management​

Automatic Archival and Deletion:

{
  "lifecycle": {
    "rule": [
      {
        "action": { "type": "SetStorageClass", "storageClass": "NEARLINE" },
        "condition": { "age": 30 }
      },
      {
        "action": { "type": "SetStorageClass", "storageClass": "COLDLINE" },
        "condition": { "age": 90 }
      },
      {
        "action": { "type": "SetStorageClass", "storageClass": "ARCHIVE" },
        "condition": { "age": 365 }
      },
      {
        "action": { "type": "Delete" },
        "condition": { "age": 730 }
      }
    ]
  }
}

Implementation:

# Apply lifecycle policy
gsutil lifecycle set lifecycle-policy.json gs://my-bucket

3. Versioning and Retention​

Enable Versioning:

# Enable object versioning
gsutil versioning set on gs://my-bucket

# Set retention policy (cannot delete for 30 days)
gsutil retention set 30d gs://my-bucket

# Lock retention policy (irreversible!)
gsutil retention lock gs://my-bucket

2. Request Optimization​

Batch Operations:

// Bad: Individual uploads
for (const file of files) {
  await bucket.upload(file);
}

// Good: Batch uploads
await Promise.all(files.map((file) => bucket.upload(file)));

Multipart Upload for Large Files:

import { Storage } from '@google-cloud/storage';

async function uploadLargeFile(filePath: string, destination: string) {
  const storage = new Storage();
  const bucket = storage.bucket('my-bucket');

  await bucket.upload(filePath, {
    destination,
    resumable: true,
    validation: 'crc32c',
    metadata: {
      contentType: 'video/mp4',
    },
  });
}

3. Data Transfer Optimization​

Use Regional Buckets:

# Create bucket in same region as compute
gsutil mb -c STANDARD -l us-central1 gs://my-regional-bucket

Compress Data:

// Compress before upload
import zlib from 'zlib';
import { Storage } from '@google-cloud/storage';

async function uploadCompressed(data: string, fileName: string) {
  const compressed = zlib.gzipSync(Buffer.from(data));
  const storage = new Storage();
  const bucket = storage.bucket('my-bucket');

  await bucket.file(fileName).save(compressed, {
    metadata: {
      contentEncoding: 'gzip',
      contentType: 'application/json',
    },
  });
}

Conclusion​

Cloud storage is a versatile service that supports numerous use cases from simple static website hosting to complex data lake architectures. By understanding the different storage types, their characteristics, and following best practices, you can build scalable, cost-effective, and secure storage solutions for your applications.

Key Takeaways​

  1. Choose the right storage type based on your access patterns and requirements
  2. Implement lifecycle policies to optimize costs automatically
  3. Use appropriate security measures including IAM, encryption, and signed URLs
  4. Monitor usage and costs to identify optimization opportunities
  5. Design for scale from the beginning with proper organization and naming conventions
  6. Leverage CDN integration for global content delivery
  7. Implement backup and disaster recovery strategies
