Setup Domain for Cloud Run with Cloudflare

Overview​

This guide walks you through the complete process of setting up a new domain (full-stack-webhook.com) and pointing it to a Google Cloud Run application. We'll use Cloudflare for DNS management and SSL/TLS termination, providing CDN, DDoS protection, and WAF capabilities.

Architecture​

Loading diagram...

Prerequisites​

  • Domain registered (e.g., full-stack-webhook.com)
  • Cloudflare account
  • Google Cloud Platform account with billing enabled
  • Cloud Run service deployed
  • gcloud CLI installed and configured

Step 1: Deploy Cloud Run Service​

Create and Deploy Cloud Run Application​

# Set project and region
export PROJECT_ID="your-project-id"
export REGION="us-central1"
export SERVICE_NAME="full-stack-webhook"

gcloud config set project $PROJECT_ID

# Deploy Cloud Run service
gcloud run deploy $SERVICE_NAME \
  --image gcr.io/${PROJECT_ID}/webhook-app:latest \
  --platform managed \
  --region $REGION \
  --allow-unauthenticated \
  --port 8080 \
  --memory 512Mi \
  --cpu 1 \
  --min-instances 0 \
  --max-instances 10 \
  --concurrency 80 \
  --timeout 300s \
  --service-account webhook-sa@${PROJECT_ID}.iam.gserviceaccount.com \
  --set-env-vars="NODE_ENV=production,LOG_LEVEL=info"

Sample Dockerfile for Cloud Run:

# Dockerfile
FROM node:18-alpine AS builder

WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

COPY . .
RUN npm run build

FROM node:18-alpine

WORKDIR /app

COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package*.json ./

# Create non-root user
RUN addgroup -g 1001 -S nodejs && adduser -S nodejs -u 1001
USER nodejs

EXPOSE 8080

ENV PORT=8080
ENV NODE_ENV=production

CMD ["node", "dist/main.js"]

Sample Express/NestJS Application:

// main.ts - NestJS
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { Logger } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  const logger = new Logger('Bootstrap');

  // Trust proxy headers from Cloudflare
  app.set('trust proxy', true);

  // Health check endpoint
  app.getHttpAdapter().get('/health', (req, res) => {
    res.json({
      status: 'ok',
      timestamp: new Date().toISOString(),
      uptime: process.uptime(),
    });
  });

  const port = process.env.PORT || 8080;
  await app.listen(port, '0.0.0.0');

  logger.log(`Application listening on port ${port}`);
}

bootstrap();

echo "Service URL: $SERVICE_URL"

Step 2: Add Domain to Cloudflare​

2.1 Add Site to Cloudflare​

  1. Go to Cloudflare Dashboard
  2. Click Add a Site
  3. Enter your domain: full-stack-webhook.com
  4. Click Add Site
  5. Select a plan (Free is sufficient for most use cases)
  6. Click Continue

2.2 Review DNS Records​

Cloudflare will scan for existing DNS records. You can skip this for a new domain.

2.3 Update Nameservers at Domain Registrar​

Cloudflare will provide you with nameservers:

ns1.cloudflare.com
ns2.cloudflare.com

Update at your domain registrar:

For example, if using Google Domains:

  1. Go to Google Domains
  2. Select your domain
  3. Click DNS → Custom name servers
  4. Add Cloudflare nameservers
  5. Save changes

For GoDaddy:

  1. Go to Domain Settings
  2. Find Nameservers section
  3. Change to Custom
  4. Add Cloudflare nameservers
  5. Save

Verification:

# Check nameservers (may take 24-48 hours to propagate)
dig NS full-stack-webhook.com +short

# Or use
nslookup -type=NS full-stack-webhook.com

Wait for Cloudflare to verify nameserver changes (usually 5 minutes to 24 hours).

Step 3: Configure DNS Records in Cloudflare​

3.1 Add DNS Records​

Once nameservers are active, configure DNS records:

Option A: Using Cloudflare Dashboard

  1. Go to DNS → Records
  2. Add the following records:
# Root domain pointing to Cloud Run
Type: CNAME
Name: @ (or full-stack-webhook.com)
Target: ghs.googlehosted.com
Proxy status: Proxied (Orange Cloud)
TTL: Auto

# WWW subdomain
Type: CNAME
Name: www
Target: full-stack-webhook.com
Proxy status: Proxied (Orange Cloud)
TTL: Auto

# Optional: API subdomain
Type: CNAME
Name: api
Target: full-stack-webhook.com
Proxy status: Proxied (Orange Cloud)
TTL: Auto

Option B: Using Cloudflare API

# Get Zone ID
ZONE_ID=$(curl -s -X GET "https://api.cloudflare.com/client/v4/zones?name=full-stack-webhook.com" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" | jq -r '.result[0].id')

echo "Zone ID: $ZONE_ID"

# Add root domain CNAME
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/dns_records" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "type": "CNAME",
    "name": "@",
    "content": "ghs.googlehosted.com",
    "ttl": 1,
    "proxied": true
  }'

# Add www subdomain
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/dns_records" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "type": "CNAME",
    "name": "www",
    "content": "full-stack-webhook.com",
    "ttl": 1,
    "proxied": true
  }'

3.2 Verify DNS Propagation​

# Check DNS resolution
dig full-stack-webhook.com +short
dig www.full-stack-webhook.com +short

# Should return Cloudflare IPs (when proxied)
# Example: 104.21.x.x or 172.67.x.x

# Check from multiple locations
curl https://dnschecker.org/all-dns-records-of-domain.php?query=full-stack-webhook.com

Step 4: Map Custom Domain to Cloud Run​

4.1 Add Domain Mapping​

# Map root domain
gcloud run domain-mappings create \
  --service $SERVICE_NAME \
  --domain full-stack-webhook.com \
  --region $REGION

# Map www subdomain
gcloud run domain-mappings create \
  --service $SERVICE_NAME \
  --domain www.full-stack-webhook.com \
  --region $REGION

# Optional: Map api subdomain
gcloud run domain-mappings create \
  --service $SERVICE_NAME \
  --domain api.full-stack-webhook.com \
  --region $REGION

4.2 Verify Domain Mapping Status​

# Check domain mapping status
gcloud run domain-mappings describe \
  --domain full-stack-webhook.com \
  --region $REGION

# List all domain mappings
gcloud run domain-mappings list \
  --region $REGION

✔ Mapping full-stack-webhook.com
✔ Creating Certificate
✔ Certificate created
✔ Domain verified

4.3 Wait for SSL Certificate​

Cloud Run automatically provisions a managed SSL certificate. This may take 15-60 minutes.

# Check certificate status
gcloud run domain-mappings describe \
  --domain full-stack-webhook.com \
  --region $REGION \
  --format="value(status.conditions)"

Step 5: Configure Cloudflare SSL/TLS Settings​

5.1 Set SSL/TLS Mode​

  1. Go to SSL/TLS tab in Cloudflare
  2. Select Full (strict) mode
    • This ensures end-to-end encryption
    • Cloudflare validates the certificate from Cloud Run
SSL/TLS Encryption Mode: Full (strict)
  - Browser → Cloudflare: Encrypted (TLS 1.3)
  - Cloudflare → Cloud Run: Encrypted (TLS 1.2+)
  - Cloud Run certificate: Google-managed (valid)

5.2 Enable Always Use HTTPS​

  1. Go to SSL/TLS → Edge Certificates
  2. Enable Always Use HTTPS
  3. Enable HTTP Strict Transport Security (HSTS)
HSTS Settings:
  Enable HSTS: ON
  Max Age: 12 months (31536000 seconds)
  Include subdomains: ON
  Preload: ON
  No-Sniff header: ON

5.3 Configure Minimum TLS Version​

  1. Go to SSL/TLS → Edge Certificates
  2. Set Minimum TLS Version: TLS 1.2
  3. Enable TLS 1.3: ON
  4. Enable Automatic HTTPS Rewrites: ON

5.4 Configure Authenticated Origin Pulls (Optional)​

For additional security, configure authenticated origin pulls:

# This ensures only Cloudflare can connect to your Cloud Run service
# However, Cloud Run with Cloudflare proxy already provides this

Step 6: Configure Cloudflare Page Rules​

Create Performance and Security Rules​

  1. Go to Rules → Page Rules
  2. Add the following rules:

Rule 1: Cache Static Assets

URL Pattern: *full-stack-webhook.com/static/*
Settings:
  - Cache Level: Cache Everything
  - Edge Cache TTL: 1 month
  - Browser Cache TTL: 1 day

Rule 2: Bypass Cache for API/Webhooks

URL Pattern: *full-stack-webhook.com/api/*
Settings:
  - Cache Level: Bypass
  - Security Level: High
  - Disable Performance

Rule 3: Bypass Cache for Webhooks

URL Pattern: *full-stack-webhook.com/webhooks/*
Settings:
  - Cache Level: Bypass
  - Disable Performance

Using Cloudflare API:​

# Create cache rule for static assets
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/pagerules" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "targets": [{
      "target": "url",
      "constraint": {
        "operator": "matches",
        "value": "*full-stack-webhook.com/static/*"
      }
    }],
    "actions": [
      {"id": "cache_level", "value": "cache_everything"},
      {"id": "edge_cache_ttl", "value": 2592000},
      {"id": "browser_cache_ttl", "value": 86400}
    ],
    "priority": 1,
    "status": "active"
  }'

# Create bypass rule for API
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/pagerules" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "targets": [{
      "target": "url",
      "constraint": {
        "operator": "matches",
        "value": "*full-stack-webhook.com/api/*"
      }
    }],
    "actions": [
      {"id": "cache_level", "value": "bypass"}
    ],
    "priority": 2,
    "status": "active"
  }'

Step 7: Configure Cloudflare WAF and Security​

7.1 Enable WAF Managed Rules​

  1. Go to Security → WAF
  2. Enable Cloudflare Managed Ruleset
  3. Enable OWASP ModSecurity Core Rule Set

7.2 Create Custom WAF Rules​

# Rule 1: Rate limiting for webhooks
Expression: (http.request.uri.path contains "/webhooks/")
Action: Block
Rate: 100 requests per minute per IP

# Rule 2: Block suspicious user agents
Expression: (http.user_agent contains "bot" or http.user_agent contains "scanner")
Action: Challenge

# Rule 3: Geographic restrictions (if needed)
Expression: (ip.geoip.country in {"CN" "RU"})
Action: Block

Using Cloudflare API:

# Create rate limiting rule
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/firewall/rules" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "filter": {
      "expression": "(http.request.uri.path contains \"/webhooks/\")",
      "paused": false
    },
    "action": "block",
    "description": "Rate limit webhooks"
  }'

7.3 Configure DDoS Protection​

  1. Go to Security → DDoS
  2. Verify HTTP DDoS Attack Protection is enabled (automatic)
  3. Enable Sensitive Mode for stricter protection

Step 8: Configure Cloudflare Transform Rules​

Add Security Headers​

  1. Go to Rules → Transform Rules → Modify Response Header
  2. Add security headers:
Rule Name: Add Security Headers
When incoming requests match: All incoming requests

Headers to add:
  - Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
  - X-Content-Type-Options: nosniff
  - X-Frame-Options: DENY
  - X-XSS-Protection: 1; mode=block
  - Referrer-Policy: strict-origin-when-cross-origin
  - Permissions-Policy: geolocation=(), microphone=(), camera=()

Using Cloudflare API:

curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/rulesets/phases/http_response_headers_transform/entrypoint" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "rules": [{
      "action": "rewrite",
      "action_parameters": {
        "headers": {
          "Strict-Transport-Security": {
            "operation": "set",
            "value": "max-age=31536000; includeSubDomains; preload"
          },
          "X-Content-Type-Options": {
            "operation": "set",
            "value": "nosniff"
          },
          "X-Frame-Options": {
            "operation": "set",
            "value": "DENY"
          }
        }
      },
      "expression": "true",
      "description": "Add security headers"
    }]
  }'

Step 9: Update Cloud Run Service Configuration​

Configure for Cloudflare​

# Update service to handle Cloudflare proxy headers
gcloud run services update $SERVICE_NAME \
  --region $REGION \
  --set-env-vars="TRUST_PROXY=true,CLOUDFLARE_PROXY=true"

Application Configuration:

// app.ts - Handle Cloudflare Headers
import express from 'express';

const app = express();

// Trust Cloudflare proxy
app.set('trust proxy', true);

// Middleware to extract real IP from Cloudflare headers
app.use((req, res, next) => {
  // CF-Connecting-IP contains the real client IP
  const realIp = req.headers['cf-connecting-ip'] || req.headers['x-forwarded-for'] || req.ip;

  req.clientIp = realIp;

  // Cloudflare country code
  req.country = req.headers['cf-ipcountry'];

  // Cloudflare ray ID for debugging
  req.cfRay = req.headers['cf-ray'];

  next();
});

// Webhook endpoint
app.post('/webhooks/payment', async (req, res) => {
  console.log('Webhook received from IP:', req.clientIp);
  console.log('Country:', req.country);
  console.log('CF-Ray:', req.cfRay);

  // Process webhook
  // ...

  res.json({ status: 'received' });
});

// Health check
app.get('/health', (req, res) => {
  res.json({
    status: 'ok',
    timestamp: new Date().toISOString(),
  });
});

const port = process.env.PORT || 8080;
app.listen(port, () => {
  console.log(`Server listening on port ${port}`);
});

Troubleshooting​

Common Issues​

1. DNS not resolving:

# Check nameservers
dig NS full-stack-webhook.com +short

# If not showing Cloudflare nameservers, wait or check registrar settings
# Clear DNS cache
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder  # macOS
sudo systemd-resolve --flush-caches  # Linux
ipconfig /flushdns  # Windows

2. SSL Certificate Errors:

# Check Cloud Run domain mapping status
gcloud run domain-mappings describe \
  --domain full-stack-webhook.com \
  --region $REGION

# If certificate is pending, wait 15-60 minutes
# If failed, delete and recreate mapping
gcloud run domain-mappings delete --domain full-stack-webhook.com --region $REGION
gcloud run domain-mappings create --service $SERVICE_NAME --domain full-stack-webhook.com --region $REGION

3. 522 Connection Timed Out:

# This means Cloudflare can't connect to Cloud Run
# Verify domain mapping exists
gcloud run domain-mappings list --region $REGION

# Check Cloud Run service is running
gcloud run services describe $SERVICE_NAME --region $REGION

# Verify Cloudflare SSL mode is "Full (strict)"

4. 502 Bad Gateway:

# Check Cloud Run logs
gcloud logging read "resource.type=cloud_run_revision AND resource.labels.service_name=$SERVICE_NAME" --limit 50

# Check for application errors
# Verify health endpoint is responding
curl https://$(gcloud run services describe $SERVICE_NAME --region $REGION --format='value(status.url)')/health

5. Cloudflare Headers Not Received:

// Verify application is reading headers correctly
app.use((req, res, next) => {
  console.log('CF-Connecting-IP:', req.headers['cf-connecting-ip']);
  console.log('CF-Ray:', req.headers['cf-ray']);
  console.log('CF-IPCountry:', req.headers['cf-ipcountry']);
  next();
});

Best Practices​

1. Security​

✓ Enable Cloudflare WAF Managed Rules
✓ Use Full (strict) SSL/TLS mode
✓ Enable HSTS with preload
✓ Implement rate limiting for sensitive endpoints
✓ Use authenticated origin pulls (optional)
✓ Enable DDoS protection
✓ Regularly review security logs
✓ Keep SSL certificates up to date

2. Performance​

✓ Enable Cloudflare CDN for static assets
✓ Use appropriate cache headers
✓ Enable Brotli compression
