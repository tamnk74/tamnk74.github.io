Akamai to Cloudflare Migration Guide

Overview​

This comprehensive guide outlines the migration strategy from Akamai (CDN, WAF, Bot Management) to Cloudflare for web applications. The migration will be executed in phases to minimize risk and ensure zero downtime.

Executive Summary​

Migration Timeline: 4-8 weeks
Risk Level: Medium
Recommended Approach: Phased migration with parallel testing

Key Benefits of Migration​

BenefitDescription
Cost ReductionCloudflare offers more competitive pricing, especially for bandwidth
Unified PlatformSingle dashboard for CDN, WAF, Bot Management, and DNS
Modern FeaturesWorkers, Pages, Stream, R2, and other edge computing capabilities
Better PerformanceLarger global network with 300+ data centers
Developer ExperienceAPI-first approach, better documentation, easier configuration

Migration Strategy​

Phase 1: Preparation (Week 1-2)​

1.1 Cloudflare Account Setup​

# Setup Cloudflare account
1. Create Cloudflare account (Enterprise recommended)
2. Add domain to Cloudflare (don't change DNS yet)
3. Configure SSL/TLS settings
4. Import SSL certificates if needed

1.2 Feature Mapping​

Create a mapping document for all Akamai features to Cloudflare equivalents:

CDN Rules Mapping:

// Example: Akamai Property Manager rule to Cloudflare Page Rule
// Akamai: Cache static assets for 7 days
{
  "name": "Cache Static Assets",
  "criteria": [
    {
      "name": "fileExtension",
      "options": {
        "values": ["jpg", "png", "css", "js"]
      }
    }
  ],
  "behaviors": [
    {
      "name": "caching",
      "options": {
        "behavior": "MAX_AGE",
        "ttl": "7d"
      }
    }
  ]
}

// Cloudflare equivalent: Page Rule or Cache Rule
// URL pattern: *example.com/*.{jpg,png,css,js}
// Cache Level: Cache Everything
// Edge Cache TTL: 7 days

WAF Rules Mapping:

// Akamai Kona WAF rule example
{
  "name": "Block SQL Injection",
  "conditions": [
    {
      "type": "requestHeader",
      "match": "contains",
      "value": "union select"
    }
  ],
  "action": "deny"
}

// Cloudflare WAF Custom Rule equivalent
(http.request.uri.query contains "union select") or 
(http.request.body contains "union select")

1.3 Cloudflare Configuration​

# Configure Cloudflare settings
1. SSL/TLS Mode: Full (Strict) recommended
2. Always Use HTTPS: Enable
3. Automatic HTTPS Rewrites: Enable
4. Minimum TLS Version: 1.2 or higher
5. TLS 1.3: Enable
6. HTTP/2: Enable
7. HTTP/3 (QUIC): Enable

Cloudflare Dashboard Configuration:

# cloudflare-config.yaml (for Terraform/API)
zone_settings:
  ssl: "strict"
  always_use_https: "on"
  min_tls_version: "1.2"
  tls_1_3: "on"
  http2: "on"
  http3: "on"
  brotli: "on"
  early_hints: "on"
  
cache_settings:
  browser_cache_ttl: 14400
  development_mode: "off"
  
security_settings:
  security_level: "medium"
  challenge_ttl: 1800
  browser_check: "on"

Performance Testing Script:

#!/bin/bash
# performance-test.sh

DOMAINS=("akamai.yourdomain.com" "cloudflare-test.yourdomain.com")

for domain in "${DOMAINS[@]}"; do
  echo "Testing $domain"
  
  # Test page load time
  curl -w "@curl-format.txt" -o /dev/null -s "https://$domain"
  
  # Test cache headers
  curl -I "https://$domain" | grep -i cache
  
  # Test compression
  curl -H "Accept-Encoding: gzip,br" -I "https://$domain" | grep -i encoding
  
  # Test SSL
  echo | openssl s_client -connect $domain:443 -servername $domain 2>/dev/null | openssl x509 -noout -text
done

Phase 3: Gradual Traffic Migration (Week 3-5)​

3.1 DNS Preparation​

# Prepare DNS changes
1. Lower TTL on DNS records (e.g., 300 seconds)
2. Wait for TTL to expire globally
3. Prepare rollback DNS configuration

3.2 Staged Rollout​

Option A: Geographic Rollout

# Week 3: Migrate 10% traffic (specific regions)
- [ ] Update DNS for Asia-Pacific region
- [ ] Monitor for 48 hours
- [ ] Validate metrics

# Week 4: Migrate 50% traffic
- [ ] Update DNS for Europe
- [ ] Monitor for 48 hours
- [ ] Validate metrics

# Week 5: Migrate 100% traffic
- [ ] Update DNS for Americas
- [ ] Monitor for 72 hours
- [ ] Validate all metrics

Option B: Percentage-Based Rollout

# Use DNS load balancing or split testing
1. Route 10% traffic to Cloudflare
2. Monitor for 48 hours
3. Increase to 25%, monitor 48 hours
4. Increase to 50%, monitor 48 hours
5. Increase to 75%, monitor 48 hours
6. Migrate 100% traffic

async function getCloudflareAnalytics(zoneId, apiToken) {

    `https://api.cloudflare.com/client/v4/zones/${zoneId}/analytics/dashboard`,
    {

Phase 4: Full Migration (Week 5-6)​

4.1 Complete DNS Cutover​

# Final DNS migration
1. Update all DNS records to Cloudflare nameservers
2. Verify propagation globally
3. Monitor for 72 hours
4. Keep Akamai active for rollback

DNS Configuration Example:

# Before (Akamai)
yourdomain.com.  IN  CNAME  yourdomain.com.edgekey.net.

# After (Cloudflare)
yourdomain.com.  IN  A      192.0.2.1  # Cloudflare Anycast IP
yourdomain.com.  IN  AAAA   2606:4700::1  # Cloudflare IPv6

Cloudflare Workers Example:

// worker-cache-optimization.js
addEventListener('fetch', event => {
  event.respondWith(handleRequest(event.request))
})

async function handleRequest(request) {
  const url = new URL(request.url)
  
  // Custom cache key based on device type
  const deviceType = request.headers.get('CF-Device-Type') || 'desktop'
  const cacheKey = new Request(url.toString(), {
    headers: request.headers,
    cf: {
      cacheKey: `${url.toString()}-${deviceType}`
    }
  })
  
  // Check cache first
  let response = await caches.default.match(cacheKey)
  
  if (!response) {
    response = await fetch(request)
    
    // Cache for 1 hour
    const headers = new Headers(response.headers)
    headers.set('Cache-Control', 'public, max-age=3600')
    
    response = new Response(response.body, {
      status: response.status,
      statusText: response.statusText,
      headers: headers
    })
    
    event.waitUntil(caches.default.put(cacheKey, response.clone()))
  }
  
  return response
}

Advanced WAF Rules:

// Cloudflare Firewall Rules
// Block known malicious IPs
(ip.geoip.country in {"CN" "RU"}) and (cf.threat_score > 10)

// Rate limit API endpoints
(http.request.uri.path contains "/api/") and 
(rate(5m) > 100)

// Block suspicious user agents
(http.user_agent contains "bot" or http.user_agent contains "crawler") and 
not (cf.client.bot)

// Protect admin panel
(http.request.uri.path contains "/admin") and 
not (ip.src in {1.2.3.4 5.6.7.8})

Rollback Procedures​

Emergency Rollback (< 5 minutes)​

# Quick DNS rollback
1. Update DNS back to Akamai nameservers
2. Verify Akamai configuration still active
3. Monitor traffic shift
4. Communicate to stakeholders

Rollback Script:

#!/bin/bash
# emergency-rollback.sh

echo "Starting emergency rollback to Akamai..."

# Update DNS via API (example using Cloudflare API)
ZONE_ID="your-zone-id"
API_TOKEN="your-api-token"

# Revert A record
curl -X PUT "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/dns_records/$RECORD_ID" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  --data '{
    "type": "CNAME",
    "name": "yourdomain.com",
    "content": "yourdomain.com.edgekey.net",
    "ttl": 300,
    "proxied": false
  }'

echo "DNS updated. Monitoring propagation..."
watch -n 5 'dig yourdomain.com +short'

Partial Rollback​

# Rollback specific features
1. Disable Cloudflare WAF, keep CDN
2. Disable Bot Management, keep WAF and CDN
3. Route specific regions back to Akamai

Configuration Management​

Infrastructure as Code (Terraform)​

# cloudflare-main.tf
terraform {
  required_providers {
    cloudflare = {
      source  = "cloudflare/cloudflare"
      version = "~> 4.0"
    }
  }
}

provider "cloudflare" {
  api_token = var.cloudflare_api_token
}

# Zone configuration
resource "cloudflare_zone" "main" {
  zone = var.domain_name
  plan = "enterprise"
}

# Zone settings
resource "cloudflare_zone_settings_override" "main" {
  zone_id = cloudflare_zone.main.id

  settings {
    ssl                      = "strict"
    always_use_https         = "on"
    min_tls_version          = "1.2"
    tls_1_3                  = "on"
    automatic_https_rewrites = "on"
    brotli                   = "on"
    http2                    = "on"
    http3                    = "on"
    zero_rtt                 = "on"
  }
}

# WAF Rules
resource "cloudflare_ruleset" "waf_custom_rules" {
  zone_id     = cloudflare_zone.main.id
  name        = "Custom WAF Rules"
  description = "Custom security rules migrated from Akamai"
  kind        = "zone"
  phase       = "http_request_firewall_custom"

  rules {
    action = "block"
    expression = "(http.request.uri.query contains \"union select\") or (http.request.uri.query contains \"<script>\")"
    description = "Block SQL injection and XSS attempts"
  }

  rules {
    action = "challenge"
    expression = "(cf.threat_score > 14)"
    description = "Challenge high threat score requests"
  }
}

# Rate limiting
resource "cloudflare_rate_limit" "api_rate_limit" {
  zone_id   = cloudflare_zone.main.id
  threshold = 100
  period    = 60
  match {
    request {
      url_pattern = "${var.domain_name}/api/*"
    }
  }
  action {
    mode    = "challenge"
    timeout = 86400
  }
}

# Page Rules
resource "cloudflare_page_rule" "cache_static_assets" {
  zone_id = cloudflare_zone.main.id
  target  = "${var.domain_name}/*.(jpg|jpeg|png|gif|css|js|woff|woff2)"
  priority = 1

  actions {
    cache_level         = "cache_everything"
    edge_cache_ttl      = 604800
    browser_cache_ttl   = 604800
  }
}

Monitoring and Alerting​

Cloudflare Analytics​

// cloudflare-monitoring.js
const { CloudflareAPI } = require('cloudflare-api');

const cf = new CloudflareAPI({
  email: process.env.CF_EMAIL,
  key: process.env.CF_API_KEY
});

async function monitorMetrics() {
  const zoneId = process.env.CF_ZONE_ID;
  
  // Get analytics
  const analytics = await cf.zones.analytics.dashboard(zoneId, {
    since: -1440, // 24 hours
    continuous: true
  });
  
  // Check thresholds
  const errorRate = (analytics.totals.requests.http_status['5xx'] / analytics.totals.requests.all) * 100;
  
  if (errorRate > 1) {
    sendAlert('High error rate detected', errorRate);
  }
  
  // Check cache hit ratio
  const cacheHitRatio = (analytics.totals.requests.cached / analytics.totals.requests.all) * 100;
  
  if (cacheHitRatio < 80) {
    sendAlert('Low cache hit ratio', cacheHitRatio);
  }
}

function sendAlert(message, value) {
  // Send to Slack, PagerDuty, etc.
  console.log(`ALERT: ${message} - ${value}`);
}

setInterval(monitorMetrics, 300000); // Every 5 minutes
