Cloudflare Rules Guide

Overview​

Cloudflare Rules is a powerful suite of features that allows you to customize how Cloudflare handles requests and responses for your domain. With Rules, you can modify URLs, headers, redirect traffic, configure settings, and much more—all without touching your origin server code.

Why Use Cloudflare Rules?​

Benefits​

  • Performance: Process requests at the edge before they reach your origin
  • Flexibility: Customize behavior without code changes
  • Security: Block, challenge, or redirect malicious traffic
  • Cost Efficiency: Reduce origin load and bandwidth costs
  • Global Deployment: Changes propagate instantly across Cloudflare's network
  • No Downtime: Update rules without restarting servers

Key Advantages​

  1. Edge Processing: Rules execute on Cloudflare's global network
  2. Real-time Updates: Changes take effect immediately
  3. Conditional Logic: Apply rules based on complex conditions
  4. Order Control: Define execution order for precise behavior
  5. Templates: Use pre-built rules for common scenarios
  6. API Support: Automate rule management via API

Prerequisites​

  • Active Cloudflare account
  • Domain proxied through Cloudflare (orange cloud enabled)
  • Appropriate plan level for advanced features

Types of Cloudflare Rules​

1. Configuration Rules​

Purpose: Customize Cloudflare configuration settings for matching requests.

Use Cases:

  • Enable/disable security features for specific paths
  • Adjust cache settings per URL pattern
  • Configure SSL/TLS settings dynamically
  • Set browser integrity checks conditionally

Example:

When incoming requests match:
  - Hostname equals: api.example.com
Then:
  - Disable security: Yes
  - Browser Integrity Check: Off
  - SSL: Full (strict)

Available Settings:

  • Auto Minify (HTML, CSS, JS)
  • Browser Cache TTL
  • Browser Integrity Check
  • Email Obfuscation
  • Hotlink Protection
  • Mirage (Image optimization)
  • Rocket Loader
  • Security Level
  • SSL/TLS Mode
  • WAF Managed Rules

Typical Examples:

Example 1: Disable Security for API Endpoints

Rule Name: API Security Configuration
When incoming requests match:
  - Hostname equals: api.example.com
  - Path starts with: /webhooks/
Then:
  - Browser Integrity Check: Off
  - Security Level: Essentially Off
  - Challenge Passage: 30 minutes
Reason: External services calling webhooks need consistent access

Example 2: Enable Performance Features for Static Content

Rule Name: Optimize Static Assets
When incoming requests match:
  - Path starts with: /static/
  - File extension is in: css, js, html
Then:
  - Auto Minify: CSS, JavaScript, HTML
  - Rocket Loader: On
  - Mirage: On
  - Polish: Lossless

Example 3: Strict Security for Admin Panel

Rule Name: Admin Area Security
When incoming requests match:
  - Path starts with: /admin
  OR Path starts with: /wp-admin
Then:
  - Security Level: High
  - Browser Integrity Check: On
  - Email Obfuscation: On
  - Hotlink Protection: On

Example 4: SSL/TLS Configuration per Subdomain

Rule Name: Flexible SSL for Legacy Subdomain
When incoming requests match:
  - Hostname equals: legacy.example.com
Then:
  - SSL: Flexible
  - Always Use HTTPS: Off
Reason: Legacy subdomain has no SSL certificate at origin

Example 5: Disable Features for Mobile App API

Rule Name: Mobile App API Config
When incoming requests match:
  - Hostname equals: api.example.com
  - User Agent contains: MyMobileApp/
Then:
  - Auto Minify: Off (all)
  - Rocket Loader: Off
  - Email Obfuscation: Off
Reason: Mobile app needs raw responses

2. Transform Rules​

Purpose: Modify HTTP headers and URLs of requests and responses.

Types:

a) URL Rewrite Rules​

Modify the URL path and query string before it reaches your origin.

Example:

Rewrite URL path:
  From: /old-api/v1/*
  To: /api/v2/$1
Before: https://example.com/old-api/v1/users
After: https://example.com/api/v2/users

b) Request Header Modification​

Add, modify, or remove HTTP request headers.

Example:

Add header:
  X-Custom-Country: ${ip.geoip.country}
  X-Original-URL: ${http.request.uri}

Remove header:
  X-Internal-Header

c) Response Header Modification​

Add, modify, or remove HTTP response headers.

Example:

Add headers:
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
  Strict-Transport-Security: max-age=31536000

Remove header:
  Server

d) Managed Transforms​

One-click transforms for common header modifications.

Available Options:

  • Add security headers
  • Remove visitor IP from headers
  • Add bot management headers
  • Add true client IP header

Typical Examples for Transform Rules:

URL Rewrite Examples:

Example 1: API Versioning

Rule Name: Default to Latest API Version
When: Path starts with /api/ AND does not contain /v
Rewrite: /api/v2${http.request.uri.path}
Before: /api/users
After: /api/v2/users

Example 2: Clean URLs (Remove .html)

Rule Name: Clean URL Extension
When: Path ends with .html
Rewrite: substring(http.request.uri.path, 0, -5)
Before: /about.html
After: /about

Example 3: Lowercase URL Paths

Rule Name: Normalize to Lowercase
When: Path contains uppercase characters
Rewrite: lower(http.request.uri.path)
Before: /Products/ITEM-123
After: /products/item-123

Request Header Modification Examples:

Example 4: Add Geolocation Headers

Rule Name: Add Geo Context
When: All requests
Add Headers:
  X-Country: ${ip.geoip.country}
  X-City: ${ip.geoip.city}
  X-Region: ${ip.geoip.region}
  X-Timezone: ${ip.geoip.timezone}

Example 5: Add True Client IP for Origin

Rule Name: Forward Real Client IP
When: All requests
Set Header:
  True-Client-IP: ${ip.src}
  CF-Connecting-IP: ${ip.src}
Remove Header: X-Forwarded-For (to replace with clean value)

Example 6: Custom User Agent Modification

Rule Name: Bot Identifier
When: Bot Management Score < 30
Set Header:
  X-Bot-Score: ${cf.bot_management.score}
  X-Bot-Verified: ${cf.bot_management.verified_bot}

Response Header Modification Examples:

Example 7: Security Headers Bundle

Rule Name: Add Security Headers
When: All responses
Add Headers:
  X-Frame-Options: SAMEORIGIN
  X-Content-Type-Options: nosniff
  X-XSS-Protection: 1; mode=block
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: geolocation=(), microphone=(), camera=()

Example 8: CORS Headers for API

Rule Name: API CORS Headers
When: Path starts with /api/
Add Headers:
  Access-Control-Allow-Origin: https://app.example.com
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
  Access-Control-Allow-Headers: Content-Type, Authorization
  Access-Control-Max-Age: 86400

Example 9: Remove Server Identification

Rule Name: Hide Server Info
When: All responses
Remove Headers: Server
  X-Powered-By
  X-AspNet-Version
  X-AspNetMvc-Version
Reason: Don't reveal technology stack

Example 10: Cache Control Override

Rule Name: Force Cache Headers
When: File extension in: jpg, png, gif, webp
Set Header:
  Cache-Control: public, max-age=31536000, immutable

3. Redirect Rules​

Purpose: Redirect visitors from source URLs to target URLs.

Types:

a) Single Redirects​

Individual redirect rules with conditions.

Example:

Rule: Redirect HTTP to HTTPS
When: Scheme equals "http"
Then: Redirect to https://${hostname}${path}
Status: 301 (Permanent)

b) Bulk Redirects​

Manage thousands of redirects using lists.

Example:

Source URL              → Target URL                 Status
/old-page              → /new-page                  301
/product-1             → /products/item-1           302
/blog/2023/post        → /blog/2024/updated-post    301

Use Cases:

  • Site migration (old → new URLs)
  • HTTP → HTTPS redirects
  • WWW → non-WWW (or vice versa)
  • Legacy URL forwarding
  • Marketing campaign URLs
  • Subdomain redirects

Typical Examples for Redirect Rules:

Single Redirect Examples:

Example 1: Force HTTPS

Rule Name: Force HTTPS
When: Scheme equals "http"
Then: Redirect to https://${hostname}${path}
Status: 301 Permanent Redirect
Preserve Query String: Yes

Example 2: Add/Remove WWW

Rule Name: Add WWW Prefix
When: Hostname equals "example.com"
Then: Redirect to https://www.example.com${path}
Status: 301 Permanent Redirect

Rule Name: Remove WWW Prefix
When: Hostname equals "www.example.com"
Then: Redirect to https://example.com${path}
Status: 301 Permanent Redirect

Example 3: Redirect Old Blog Structure

Rule Name: Blog URL Migration
When: Path matches regex "^/blog/([0-9]{4})/([0-9]{2})/(.*)$"
Then: Redirect to /articles/$1-$2-$3
Status: 301 Permanent Redirect
Before: /blog/2024/12/my-post
After: /articles/2024-12-my-post

Example 4: Mobile Subdomain Redirect

Rule Name: Mobile Site Redirect
When:
  - Hostname equals "example.com"
  - User Agent contains "Mobile"
Then: Redirect to https://m.example.com${path}
Status: 302 Temporary Redirect

Example 5: Marketing Campaign Redirect

Rule Name: Campaign Short URL
When: Path equals "/promo"
Then: Redirect to /products/special-offer?utm_source=campaign

Example 6: Country-Specific Redirect

Rule Name: Geographic Redirect
When:
  - Path equals "/"
  - Country in: DE, FR, IT, ES
Then: Redirect to https://eu.example.com/
Status: 302 Temporary Redirect

Bulk Redirect Examples:

4. Origin Rules​

Purpose: Customize where traffic goes and how it reaches your origin.

Capabilities:

  • Override Host header
  • Change destination hostname
  • Modify destination port
  • Set SNI (Server Name Indication)
  • Override DNS resolution

Example:

When incoming requests match:
  - Hostname equals: cdn.example.com
Then:
  - Host Header: origin.example.com
  - Destination Port: 8080
  - Resolve Override: origin-server-1.example.com

Use Cases:

  • Load balancing to multiple origins
  • Blue-green deployments
  • A/B testing different backends
  • Route subdomains to different servers
  • Port-based routing

Typical Examples for Origin Rules:

Example 1: Host Header Override for Multi-tenant

Rule Name: Multi-tenant Routing
When: Hostname equals "customer1.example.com"
Then:
  - Host Header: app.example.com
  - Destination Hostname: origin-1.example.com
  - SNI: origin-1.example.com
Reason: Route different customer domains to same origin app

Example 2: Blue-Green Deployment

Rule Name: Blue Environment (Production)
When: Cookie "deployment" does not equal "green"
Then:
  - Destination Hostname: blue-origin.example.com
  - Host Header: app.example.com

Rule Name: Green Environment (Testing)
When: Cookie "deployment" equals "green"
Then:
  - Destination Hostname: green-origin.example.com
  - Host Header: app.example.com

Example 3: Geographic Origin Routing

Rule Name: US Traffic to US Origin
When: Country in: US, CA, MX
Then:
  - Destination Hostname: us-origin.example.com
  - Destination Port: 443

Rule Name: EU Traffic to EU Origin
When: Country in: GB, DE, FR, IT, ES
Then:
  - Destination Hostname: eu-origin.example.com
  - Destination Port: 443

Rule Name: Asia Traffic to Asia Origin
When: Country in: JP, CN, KR, SG
Then:
  - Destination Hostname: asia-origin.example.com
  - Destination Port: 443

Example 4: Non-Standard Port Routing

Rule Name: Route to Custom Port
When: Path starts with "/api/v2/"
Then:
  - Destination Hostname: api-v2.example.com
  - Destination Port: 8443
  - Host Header: api.example.com

Example 5: A/B Test Different Backends

Rule Name: A/B Test - Variant A (50%)
When: Cookie "ab_test" equals "variant_a"
Then:
  - Destination Hostname: backend-a.example.com

Rule Name: A/B Test - Variant B (50%)
When: Cookie "ab_test" equals "variant_b"
Then:
  - Destination Hostname: backend-b.example.com

Example 6: Canary Release

Rule Name: Canary - New Version (10%)
When:
  - Header "X-Canary" equals "true"
  OR User Agent contains "CanaryTest"
Then:
  - Destination Hostname: canary-origin.example.com

Rule Name: Stable Version (90%)
When: All other requests
Then:
  - Destination Hostname: stable-origin.example.com

Rule Name: Internal Origin Resolution
When: Path starts with "/internal/"
Then:
  - Resolve Override: 10.0.1.100

Example 8: Media Server Routing

Rule Name: Route Media to Dedicated Server
When: File extension in: mp4, mp3, webm, mov, avi
Then:
  - Destination Hostname: media.example.com
  - Host Header: cdn.example.com
  - Destination Port: 443

6. Snippets​

Purpose: Execute custom JavaScript code at the edge.

Use Cases:

  • Complex header manipulation
  • Custom authentication logic
  • A/B testing logic
  • Geolocation-based logic
  • Custom rate limiting
  • Request/response transformation

Typical Examples for Snippets:

Example 1: Add Country-Based Headers

export default {
  async fetch(request) {
    const country = request.cf.country;
    const response = await fetch(request);

    const newResponse = new Response(response.body, response);
    newResponse.headers.set('X-Country-Code', country);
    newResponse.headers.set('X-Region', request.cf.region || 'unknown');

    return newResponse;
  },
};

Example 2: Custom Authentication Check

export default {
  async fetch(request) {
    const authToken = request.headers.get('Authorization');

    // Simple token validation
    if (!authToken || !authToken.startsWith('Bearer ')) {
      return new Response('Unauthorized', { status: 401 });
    }

    // Verify token (simplified example)
    const token = authToken.substring(7);
    if (token !== 'valid-token-here') {
      return new Response('Invalid token', { status: 403 });
    }

    // Add user context
    const modifiedRequest = new Request(request);
    modifiedRequest.headers.set('X-User-Id', 'user-123');

    return fetch(modifiedRequest);
  },
};

Example 3: A/B Testing with Cookie

export default {
  async fetch(request) {
    const url = new URL(request.url);
    let variant = getCookie(request, 'ab_variant');

    // Assign variant if not set
    if (!variant) {
      variant = Math.random() < 0.5 ? 'A' : 'B';
    }

    // Modify path based on variant
    if (variant === 'B') {
      url.pathname = '/variant-b' + url.pathname;
    }

    const response = await fetch(new Request(url, request));

    // Set cookie for persistence
    const newResponse = new Response(response.body, response);
    if (!getCookie(request, 'ab_variant')) {
      newResponse.headers.set('Set-Cookie', `ab_variant=${variant}; Path=/; Max-Age=2592000`);
    }

    return newResponse;
  },
};

function getCookie(request, name) {
  const cookies = request.headers.get('Cookie') || '';
  const match = cookies.match(new RegExp(`(^| )${name}=([^;]+)`));
  return match ? match[2] : null;
}

Example 4: Rate Limiting by IP

export default {
  async fetch(request, env) {
    const ip = request.headers.get('CF-Connecting-IP');
    const key = `ratelimit:${ip}`;

    // Get current count from KV
    const count = parseInt((await env.RATE_LIMIT.get(key)) || '0');

    // Check if exceeded (10 requests per minute)
    if (count >= 10) {
      return new Response('Rate limit exceeded', {
        status: 429,
        headers: {
          'Retry-After': '60',
        },
      });
    }

    // Increment counter
    await env.RATE_LIMIT.put(key, (count + 1).toString(), {
      expirationTtl: 60,
    });

    return fetch(request);
  },
};

Example 5: Redirect Based on Language

export default {
  async fetch(request) {
    const url = new URL(request.url);
    const acceptLanguage = request.headers.get('Accept-Language') || '';

    // Only redirect home page
    if (url.pathname === '/') {
      if (acceptLanguage.includes('es')) {
        return Response.redirect('https://es.example.com/', 302);
      } else if (acceptLanguage.includes('fr')) {
        return Response.redirect('https://fr.example.com/', 302);
      } else if (acceptLanguage.includes('de')) {
        return Response.redirect('https://de.example.com/', 302);
      }
    }

    return fetch(request);
  },
};

Example 6: Response Body Modification

export default {
  async fetch(request) {
    const response = await fetch(request);

    // Only modify HTML responses
    if (!response.headers.get('content-type')?.includes('text/html')) {
      return response;
    }

    // Read and modify body
    let body = await response.text();
    body = body.replace('</head>', '<script>console.log("Injected by Cloudflare Snippet");</script></head>');

    return new Response(body, {
      status: response.status,
      headers: response.headers,
    });
  },
};

Example 7: Custom Caching Logic

export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);

    // Custom cache key
    const cacheKey = new Request(url.toString(), request);
    const cache = caches.default;

    // Check cache
    let response = await cache.match(cacheKey);

    if (!response) {
      // Fetch from origin
      response = await fetch(request);

      // Cache based on custom logic
      if (response.ok && url.pathname.startsWith('/api/')) {
        const cacheResponse = response.clone();
        cacheResponse.headers.set('Cache-Control', 'public, max-age=300');
        ctx.waitUntil(cache.put(cacheKey, cacheResponse));
      }
    }

    return response;
  },
};

10. URL Normalization​

Purpose: Standardize incoming URLs to consistent format.

Features:

  • Normalize character encoding
  • Normalize query strings
  • Sort query parameters
  • Remove duplicate slashes
  • Decode unreserved characters

Typical Examples for URL Normalization:

Example 1: Query String Sorting

Setting: Sort query strings
Before: /search?category=books&sort=price&page=2
After: /search?category=books&page=2&sort=price
Benefit: Improves cache hit ratio

Example 2: Remove Duplicate Slashes

Setting: Normalize paths
Before: /products//category///item
After: /products/category/item
Benefit: Consistent URLs

Example 3: Decode Unnecessary Encoding

Setting: Decode unreserved characters
Before: /products/t%2Dshirt  (incorrectly encoded dash)
After: /products/t-shirt
Benefit: Cleaner URLs

Example 4: Normalize Encoding

Setting: Normalize character encoding
Before: /search?q=caf%C3%A9  (UTF-8)
After: /search?q=café  (normalized)
Benefit: Consistent encoding

Example 5: Remove Empty Query Parameters

Setting: Remove empty parameters
Before: /page?param1=value&param2=&param3=
After:  /page?param1=value
Benefit: Cleaner cache keys

Rule Execution Order​

Understanding execution order is crucial for predictable behavior:

1. Single Redirects
2. URL Rewrite Rules
3. Configuration Rules
4. Origin Rules
5. Bulk Redirects
6. Managed Transforms
7. Request Header Transform Rules
8. Cache Rules
9. Snippets
10. Cloud Connector
11. Response Header Transform Rules

Important Notes:

  • Rules execute in order within each type
  • Later rules can overwrite earlier rules (for non-terminating actions)
  • Terminating actions (redirect, block) stop further evaluation
  • Page Rules are overridden by newer Rules products

Rule Expressions​

Rules use Cloudflare's expression language for matching conditions.

Basic Syntax​

Field Operator Value

Common Fields​

http.host                    # Hostname
http.request.uri.path        # URL path
http.request.uri.query       # Query string
http.request.method          # HTTP method
http.request.headers         # Request headers
http.response.code           # Response status code
ip.src                       # Client IP
ip.geoip.country             # Country code
cf.bot_management.score      # Bot score

Operators​

eq           # Equals
ne           # Not equals
lt           # Less than
gt           # Greater than
in           # In list
contains     # Contains string
matches      # Regex match
starts with  # Starts with
ends with    # Ends with

Example Expressions​

# Match specific hostname
(http.host eq "www.example.com")

# Match path pattern
(http.request.uri.path matches "^/api/v[0-9]+/")

# Match multiple conditions
(http.host eq "api.example.com" and http.request.method eq "POST")

# Match country
(ip.geoip.country in {"US" "CA" "MX"})

# Match file extension
(http.request.uri.path ends with ".jpg" or http.request.uri.path ends with ".png")

# Exclude paths
(not http.request.uri.path starts with "/admin")

# Complex logic
(http.host eq "example.com" and
 (http.request.uri.path starts with "/api/" or
  http.request.uri.path starts with "/v1/"))

Common Use Cases​

1. Force HTTPS​

Rule Type: Single Redirect
When: Scheme equals "http"
Then: Redirect to https://${hostname}${path}
Status: 301 Permanent

2. WWW to Non-WWW​

Rule Type: Single Redirect
When: Hostname equals "www.example.com"
Then: Redirect to https://example.com${path}
Status: 301 Permanent

3. Add Security Headers​

Rule Type: Response Header Modification
When: All incoming requests
Then add headers:
  - X-Frame-Options: DENY
  - X-Content-Type-Options: nosniff
  - X-XSS-Protection: 1; mode=block
  - Strict-Transport-Security: max-age=31536000; includeSubDomains
  - Referrer-Policy: strict-origin-when-cross-origin

4. API Versioning​

Rule Type: URL Rewrite
When: Path starts with "/api/"
Then: Rewrite path to "/api/v2${path}"

5. Mobile Redirection​

Rule Type: Single Redirect
When: User agent contains "Mobile" AND Hostname equals "example.com"
Then: Redirect to https://m.example.com${path}
Status: 302 Temporary

6. Geographic Routing​

Rule Type: Origin Rule
When: Country is in ["US", "CA"]
Then:
  - Destination: us-origin.example.com
  - Port: 443

When: Country is in ["GB", "FR", "DE"]
Then:
  - Destination: eu-origin.example.com
  - Port: 443

7. Remove Sensitive Headers​

Rule Type: Request Header Modification
When: Path starts with "/api/"
Then remove headers:
  - X-Internal-User
  - X-Debug-Mode
  - X-Admin-Token

8. A/B Testing​

Rule Type: URL Rewrite + Cookie
When: Cookie "ab_test" equals "variant_b"
Then: Rewrite path to "/variant-b${path}"

When: Cookie "ab_test" does not exist
Then: Rewrite path based on random(0,100) < 50
  - True: "/variant-a${path}"
  - False: "/variant-b${path}"

9. Bot Management​

Rule Type: Configuration Rule
When: Bot Management Score < 30
Then:
  - Challenge Action: Managed Challenge
  - Security Level: High

10. Maintenance Mode​

Rule Type: Single Redirect
When: Path does not start with "/maintenance"
Then: Redirect to https://example.com/maintenance
Status: 302 Temporary

Best Practices​

1. Use Descriptive Names​

Good: 'Redirect old blog URLs to new structure'
Bad: 'Rule 1'

2. Test Before Deploying​

  • Use "Dry Run" mode when available
  • Test with curl or browser dev tools
  • Monitor initial traffic closely

3. Order Rules Carefully​

# Correct order
1. Specific rule: /api/v1/users/admin → /admin/users
2. General rule: /api/v1/* → /api/v2/*

# Wrong order (specific rule never matches)
1. General rule: /api/v1/* → /api/v2/*
2. Specific rule: /api/v1/users/admin → /admin/users

4. Use Comments/Descriptions​

Description: 'Temporary redirect for Black Friday campaign - Remove after 2024-11-30'

5. Avoid Rule Conflicts​

# Conflict example
Rule 1: Set header X-Custom to "value1"
Rule 2: Set header X-Custom to "value2"
Result: Last rule wins (value2)

6. Monitor Performance​

  • Check rule execution time
  • Track rule match rates
  • Review analytics regularly

7. Use Templates​

Start with Cloudflare's pre-built templates for common scenarios.

8. Consolidate Rules​

# Instead of 5 separate rules for different paths
Instead: Use one rule with OR conditions
(http.request.uri.path in {"/path1" "/path2" "/path3" "/path4" "/path5"})

9. Document Complex Rules​

Rule: Geographic routing for APIs
Purpose: Route traffic to nearest origin
Created: 2024-01-15
Dependencies: Origin Rules, Geographic IP data
Maintenance: Review quarterly

10. Version Control​

Store rule configurations in Git:

cloudflare-rules/
  ├── production/
  │   ├── cache-rules.json
  │   ├── transform-rules.json
  │   └── redirect-rules.json
  └── staging/
      ├── cache-rules.json
      ├── transform-rules.json
      └── redirect-rules.json

Testing and Debugging​

Using Cloudflare Trace​

  1. Go to Rules → Trace
  2. Enter URL to test
  3. Click Run Trace
  4. Review which rules matched

Using curl​

# Test redirect
curl -I https://example.com/old-path

# Test header modification
curl -I https://example.com/ | grep X-Custom

# Test with specific header
curl -H "X-Test: value" https://example.com/

# Test from specific country (using VPN/proxy)
curl --proxy socks5://us-proxy:1080 https://example.com/

Using Browser DevTools​

  1. Open DevTools (F12)
  2. Go to Network tab
  3. Make request
  4. Check:
    • Response headers
    • Redirects (Status 301/302)
    • Modified URLs

Common Issues​

Rules Not Triggering​

Causes:

  • DNS not proxied (gray cloud)
  • Incorrect expression syntax
  • Rule disabled
  • Plan limits exceeded

Solution:

# Check DNS proxy status
# Ensure orange cloud is enabled

# Test expression
Use Cloudflare Trace to validate

Redirect Loops​

Causes:

  • Conflicting redirect rules
  • Origin redirects conflicting with Cloudflare redirects

Solution:

# Add exception for redirect target
When: Path does not equal "/new-path"
Then: Redirect to /new-path

Headers Not Modified​

Causes:

  • Rule order issue
  • Origin headers overriding
  • Cache serving old version

Solution:

# Purge cache
# Check rule execution order
# Verify in Cloudflare Trace
