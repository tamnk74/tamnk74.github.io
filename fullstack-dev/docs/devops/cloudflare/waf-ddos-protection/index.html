Cloudflare WAF & DDoS Protection for E-Commerce

Edge-layer security for a million-user platform: Cloudflare WAF blocking OWASP Top 10, volumetric DDoS mitigation, bot management, rate limiting, and GCP Cloud Armor as a secondary defence layer.

Architecture Overview​

Defence-in-depth: Cloudflare absorbs attacks at the edge; GCP Cloud Armor provides a second layer at the load balancer before traffic enters GKE.

Cloudflare WAF — Dashboard UI Setup​

The Cloudflare dashboard is the fastest way to enable and verify WAF rules before codifying them in Terraform. All settings below map 1-to-1 to the Terraform resources in subsequent sections.

Step 1 — Enable the zone proxy (orange cloud)​

  1. Go to Cloudflare Dashboard → your domain → DNS → Records.
  2. Click the proxy toggle on your A / CNAME records so the icon shows an orange cloud. All traffic now routes through Cloudflare's edge.

Step 2 — SSL/TLS mode​

  1. SSL/TLS → Overview.
  2. Set mode to Full (strict) — requires a valid certificate at your GCP origin (e.g. managed cert on the GCP Load Balancer).
  3. SSL/TLS → Edge Certificates → Always Use HTTPS → On.
  4. SSL/TLS → Edge Certificates → Minimum TLS Version → TLS 1.2.
  5. SSL/TLS → Edge Certificates → TLS 1.3 → On.

Step 3 — Enable Managed WAF Rulesets​

  1. Security → WAF → Managed Rules.
  2. Click Deploy next to:
    • Cloudflare Managed Ruleset — Cloudflare's own threat intel rules.
    • Cloudflare OWASP Core Ruleset — OWASP CRS covering SQLi, XSS, RCE, path traversal, SSRF.
  3. After deploying OWASP CRS, click Edit and set:
    • Paranoia Level → PL1 (lowest false-positive rate — suitable for REST APIs).
    • Score threshold → Managed Challenge at 40, Block at 60. Adjust after reviewing the Security Events log.
  4. Click Save.

Tip: Start in Log mode for 24–48 hours before switching to Block. Review Security → Events to confirm no legitimate traffic is caught.

Step 4 — Custom WAF Rules​

  1. Security → WAF → Custom Rules → Create rule.
  2. Create each rule using the Expression Builder or paste the expression directly:
Rule nameExpression (simplified)Action
Block credential stuffing(http.request.uri.path eq "/auth/login") and (cf.threat_score gt 30)Block
Challenge checkout bots(http.request.uri.path contains "/checkout") and (cf.bot_management.score lt 50)Managed Challenge
Block scanners(http.user_agent contains "sqlmap") or (http.user_agent contains "nikto")Block
Block /internal paths(http.request.uri.path matches "^/internal/.*")Block
  1. Set Order: Block rules before Challenge rules.

Step 5 — Rate Limiting​

  1. Security → WAF → Rate Limiting Rules → Create rule.
  2. Configure:
Rule namePathThresholdPeriodAction
Login rate limit/auth/login (POST)5 requests15 min per IPBlock (900 s)
Checkout rate limit/checkout20 requests1 min per IPBlock (5 min)
API general/api/*1,000 requests1 min per IPManaged Challenge

Step 6 — DDoS Protection Overrides (optional, before flash sales)​

  1. Security → DDoS → HTTP DDoS Attack Protection → Deploy a DDoS override.
  2. Set Sensitivity → High and Action → Block (instead of the default Managed Challenge).
  3. Security → DDoS → Network-layer DDoS → Deploy override with sensitivity High.

Revert these to Default after the event window.

Step 7 — Bot Management​

  1. Security → Bots → Configure.
  2. Enable Bot Fight Mode (free tier) or Bot Management (Enterprise).
  3. Set:
    • Definitely Automated → Block.
    • Likely Automated → Managed Challenge.
    • Verified Bots → Allow (Googlebot, Bingbot, etc.).

Step 8 — Security Level & Under Attack Mode​

  • Security → Settings → Security Level → Medium (default). Raise to High before flash sales.
  • Under Attack Mode (I'm Under Attack!): activate via Security → Settings only during confirmed volumetric attacks. This adds a 5-second JS challenge to every request.

Step 9 — Verify in Security Events​

  1. Security → Events — real-time log of all WAF, firewall, and bot events.
  2. Filter by Action = Block to verify only malicious traffic is blocked.
  3. Click any event's Ray ID to see the full request details and which rule fired.
  4. If a legitimate request is blocked, click Create exception to add a scoped allow rule without disabling the broader rule.

Step 10 — Notifications​

  1. Notifications → Add → select:
    • Security Events Alert: triggers when WAF block rate exceeds threshold.
    • DDoS Attack Alert: triggers on L3/L4 or L7 attack detection.
  2. Set delivery to PagerDuty or Slack webhook for on-call routing.

WAF: Managed Rules (OWASP Top 10)​

Cloudflare's Managed Ruleset covers OWASP CRS (SQLi, XSS, RCE, SSRF, path traversal) and Cloudflare's own threat intelligence feeds.

Terraform: enable managed rulesets​

# terraform/modules/cloudflare/waf.tf

# Cloudflare Managed Ruleset (main — Cloudflare Core rules)
resource "cloudflare_ruleset" "waf_managed" {
  zone_id     = var.cloudflare_zone_id
  name        = "Managed WAF Rules"
  description = "Execute Cloudflare managed OWASP and core WAF rules"
  kind        = "zone"
  phase       = "http_request_firewall_managed"

  rules {
    action = "execute"
    action_parameters {
      id      = "efb7b8c949ac4650a09736fc376e9aee"  # Cloudflare Managed Ruleset
      version = "latest"
      overrides {
        # Tighten SQLi to block (default is challenge for some categories)
        categories {
          category = "wordpress"
          enabled  = false   # not running WordPress
        }
        rules {
          id              = "c2e184081120413c86c3ab7e14069605"  # SQLi rule
          action          = "block"
          enabled         = true
        }
      }
    }
    enabled    = true
    expression = "true"
  }
}

WAF: Custom Rules (Platform-Specific)​

Custom rules cover e-commerce-specific threat patterns that managed rules don't address.

# terraform/modules/cloudflare/waf-custom.tf
resource "cloudflare_ruleset" "waf_custom" {
  zone_id     = var.cloudflare_zone_id
  name        = "Custom WAF Rules — ecommerce"
  kind        = "zone"
  phase       = "http_request_firewall_custom"

  # Rule 1: Block credential stuffing on auth endpoints
  rules {
    ref         = "block-auth-stuffing"
    description = "Block rapid login attempts from same IP"
    enabled     = true
    action      = "block"
    expression  = <<-EOT
      (http.request.uri.path eq "/auth/login" and
       cf.threat_score gt 30) or
      (http.request.uri.path eq "/auth/login" and
       http.request.method eq "POST" and
       not cf.bot_management.verified_bot and
       cf.bot_management.score lt 30)
    EOT
  }

  # Rule 2: Challenge suspicious checkout traffic
  rules {
    ref         = "challenge-checkout-bots"
    description = "Managed challenge for low bot score on checkout"
    enabled     = true
    action      = "managed_challenge"
    expression  = <<-EOT
      http.request.uri.path contains "/checkout" and
      cf.bot_management.score lt 50 and
      not cf.bot_management.verified_bot
    EOT
  }

  # Rule 3: Block direct access to internal API paths from untrusted sources
  rules {
    ref         = "block-internal-api"
    description = "Block /internal/* paths from non-GCP origins"
    enabled     = true
    action      = "block"
    expression  = <<-EOT
      http.request.uri.path matches "^/internal/.*" and
      not ip.src in $gcp_origin_ips
    EOT
  }

  # Rule 4: Block requests with suspicious User-Agent (scanners, exploit tools)
  rules {
    ref         = "block-scanner-ua"
    description = "Block known vulnerability scanners"
    enabled     = true
    action      = "block"
    expression  = <<-EOT
      http.user_agent contains "sqlmap" or
      http.user_agent contains "nikto" or
      http.user_agent contains "nmap" or
      http.user_agent contains "masscan" or
      http.user_agent contains "zgrab"
    EOT
  }

  # Rule 5: Block excessively large request bodies on non-upload endpoints
  rules {
    ref         = "block-large-body"
    description = "Block requests larger than 1 MB except /upload"
    enabled     = true
    action      = "block"
    expression  = <<-EOT
      http.request.body.size gt 1048576 and
      not http.request.uri.path contains "/upload"
    EOT
  }
}

DDoS Mitigation​

L3/L4 — Volumetric (automatic)​

Cloudflare's network-level DDoS protection (Magic Transit / DDoS L3-4) is always-on and automatic — no configuration required for flows below Cloudflare's threshold. For high-profile events (flash sales), enable DDoS Override to increase sensitivity:

resource "cloudflare_ruleset" "ddos_l3_override" {
  zone_id = var.cloudflare_zone_id
  name    = "DDoS L3/L4 Sensitivity Override"
  kind    = "zone"
  phase   = "ddos_l3"

  rules {
    action = "execute"
    action_parameters {
      id = "3b64149bfa6e4220bbbc2bd6db589552"  # DDoS L3/L4 managed ruleset
      overrides {
        rules {
          id         = "3b64149bfa6e4220bbbc2bd6db589552"
          sensitivity_level = "high"   # increase before flash sales
        }
      }
    }
    expression = "true"
    enabled    = true
  }
}

Flash Sale: pre-event DDoS hardening runbook​

#!/bin/bash
# scripts/pre-flashsale-security-harden.sh
# Run 30 min before a flash sale event

ZONE_ID="${CLOUDFLARE_ZONE_ID}"
API_TOKEN="${CLOUDFLARE_API_TOKEN}"

# 1. Raise security level to "high" (Cloudflare challenges IPs with threat score > 0)
curl -s -X PATCH "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/settings/security_level" \
  -H "Authorization: Bearer ${API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"value":"high"}'

# 2. Enable Under Attack mode if already seeing traffic anomalies
# curl -s -X PATCH "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/settings/security_level" \
#   --data '{"value":"under_attack"}'  # uncomment if attack is confirmed

# 3. Activate Bot Fight Mode
curl -s -X PUT "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/bot_management" \
  -H "Authorization: Bearer ${API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"fight_mode":true}'

echo "Edge hardening applied for flash sale"

Rate Limiting (Edge)​

Edge rate limiting at Cloudflare fires before requests reach GKE — protecting against bot storms without consuming backend capacity.

# terraform/modules/cloudflare/rate-limits.tf
resource "cloudflare_ruleset" "rate_limits" {
  zone_id     = var.cloudflare_zone_id
  name        = "Rate Limiting Rules"
  kind        = "zone"
  phase       = "http_ratelimit"

  # Checkout: 20 requests per minute per IP
  rules {
    ref         = "checkout-rate-limit"
    description = "Checkout endpoint rate limit"
    enabled     = true
    action      = "block"
    action_parameters {
      response {
        status_code  = 429
        content_type = "application/json"
        content      = "{\"error\":\"Too many requests. Please try again later.\"}"
      }
    }
    ratelimit {
      characteristics      = ["ip.src"]
      period               = 60
      requests_per_period  = 20
      mitigation_timeout   = 300   # 5 min block after threshold breach
    }
    expression = "http.request.uri.path contains \"/checkout\""
  }

  # Login: 5 attempts per 15 minutes per IP
  rules {
    ref         = "login-rate-limit"
    description = "Auth login rate limit (credential stuffing)"
    enabled     = true
    action      = "block"
    ratelimit {
      characteristics     = ["ip.src"]
      period              = 900
      requests_per_period = 5
      mitigation_timeout  = 900
    }
    expression = "http.request.uri.path eq \"/auth/login\" and http.request.method eq \"POST\""
  }

  # API general: 1,000 requests per minute per IP
  rules {
    ref         = "api-general-rate-limit"
    description = "General API rate limit"
    enabled     = true
    action      = "managed_challenge"
    ratelimit {
      characteristics     = ["ip.src"]
      period              = 60
      requests_per_period = 1000
      mitigation_timeout  = 60
    }
    expression = "http.request.uri.path starts_with \"/api/\""
  }

  # Product search: 60 requests per minute per IP (prevents catalogue scraping)
  rules {
    ref         = "search-rate-limit"
    description = "Search endpoint rate limit (anti-scraping)"
    enabled     = true
    action      = "managed_challenge"
    ratelimit {
      characteristics     = ["ip.src"]
      period              = 60
      requests_per_period = 60
      mitigation_timeout  = 120
    }
    expression = "http.request.uri.path starts_with \"/api/search\""
  }
}

Custom bot challenge on checkout​

# cloudflare/page-rules/checkout-turnstile.yaml
# Enforce Cloudflare Turnstile CAPTCHA on checkout for bot scores < 50
# Configured via Cloudflare Workers (see below)
// cloudflare/workers/checkout-bot-gate.ts
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    if (!url.pathname.startsWith('/checkout')) {
      return fetch(request);
    }

    const botScore = parseInt(request.headers.get('CF-Bot-Score') ?? '100');
    const isVerifiedBot = request.headers.get('CF-Verified-Bot') === 'true';

    if (!isVerifiedBot && botScore < 30) {
      // Redirect to Turnstile challenge page
      return Response.redirect(
        `${url.origin}/challenge?redirect=${encodeURIComponent(url.pathname)}`,
        302
      );
    }

    return fetch(request);
  },
} satisfies ExportedHandler<Env>;

GCP Cloud Armor (Secondary Layer)​

Even after Cloudflare filtering, enable Cloud Armor at the GCP Global Load Balancer for defence-in-depth — this catches any traffic that bypasses Cloudflare (e.g. direct IP access, misconfigured DNS).

# terraform/modules/gcp/cloud-armor.tf
resource "google_compute_security_policy" "ecom_armor" {
  name    = "ecom-cloud-armor-${var.environment}"
  project = var.project_id

  # Rule 1: Allow only Cloudflare IP ranges at origin (block direct-to-IP attacks)
  rule {
    priority = 1000
    action   = "allow"
    match {
      versioned_expr = "SRC_IPS_V1"
      config {
        # Cloudflare IP ranges (updated periodically — automate via data source)
        src_ip_ranges = [
          "103.21.244.0/22", "103.22.200.0/22", "103.31.4.0/22",
          "104.16.0.0/13",   "104.24.0.0/14",   "108.162.192.0/18",
          "131.0.72.0/22",   "141.101.64.0/18",  "162.158.0.0/15",
          "172.64.0.0/13",   "173.245.48.0/20",  "188.114.96.0/20",
          "190.93.240.0/20", "197.234.240.0/22", "198.41.128.0/17",
        ]
      }
    }
    description = "Allow Cloudflare CDN IPs"
  }

  # Rule 2: Block all other sources (direct IP, non-Cloudflare proxies)
  rule {
    priority = 2000
    action   = "deny(403)"
    match {
      versioned_expr = "SRC_IPS_V1"
      config {
        src_ip_ranges = ["*"]
      }
    }
    description = "Block non-Cloudflare traffic reaching origin directly"
  }

  # Rule 3: SQL injection pre-configured rule (OWASP CRS)
  rule {
    priority = 900
    action   = "deny(403)"
    match {
      expr {
        expression = "evaluatePreconfiguredExpr('sqli-v33-stable')"
      }
    }
    description = "Block SQL injection (OWASP CRS — sqli)"
  }

  # Rule 4: XSS pre-configured rule
  rule {
    priority = 901
    action   = "deny(403)"
    match {
      expr {
        expression = "evaluatePreconfiguredExpr('xss-v33-stable')"
      }
    }
    description = "Block XSS (OWASP CRS — xss)"
  }

  # Rule 5: Remote File Inclusion
  rule {
    priority = 902
    action   = "deny(403)"
    match {
      expr {
        expression = "evaluatePreconfiguredExpr('rfi-v33-stable')"
      }
    }
    description = "Block Remote File Inclusion (OWASP CRS — rfi)"
  }

  adaptive_protection_config {
    layer_7_ddos_defense_config {
      enable          = true
      rule_visibility = "STANDARD"
    }
  }
}

Security Headers (Cloudflare Transform Rules)​

Apply security response headers at the edge — no origin changes needed:

resource "cloudflare_ruleset" "security_headers" {
  zone_id     = var.cloudflare_zone_id
  name        = "Security Response Headers"
  kind        = "zone"
  phase       = "http_response_headers_transform"

  rules {
    enabled     = true
    expression  = "true"
    action      = "rewrite"
    action_parameters {
      headers {
        name      = "Strict-Transport-Security"
        operation = "set"
        value     = "max-age=31536000; includeSubDomains; preload"
      }
      headers {
        name      = "X-Content-Type-Options"
        operation = "set"
        value     = "nosniff"
      }
      headers {
        name      = "X-Frame-Options"
        operation = "set"
        value     = "DENY"
      }
      headers {
        name      = "Referrer-Policy"
        operation = "set"
        value     = "strict-origin-when-cross-origin"
      }
      headers {
        name      = "Permissions-Policy"
        operation = "set"
        value     = "camera=(), microphone=(), geolocation=(self)"
      }
      headers {
        name      = "Content-Security-Policy"
        operation = "set"
        value     = "default-src 'self'; script-src 'self' 'nonce-{NONCE}' https://challenges.cloudflare.com; connect-src 'self' https://api.ecom.io; img-src 'self' data: https://cdn.ecom.io; frame-ancestors 'none'"
      }
    }
  }
}
