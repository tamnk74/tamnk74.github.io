Traffic Flow Architecture: End-to-End Request Journey

Overview​

This guide provides a detailed walkthrough of the complete traffic flow from when a user enters full-stack-dev.com in their browser until they receive a response. We'll trace the request through DNS resolution, CDN, cloud security layers, load balancing, Kubernetes cluster, and back to the user.

Complete Traffic Flow Diagram​

Detailed Traffic Flow Steps​

Phase 1: DNS Resolution (Steps 1-3)​

Step 1: User Initiates DNS Query​

# Origin Server (GCP Load Balancer): 35.190.x.x

DNS Caching Layers:

Level 1 - Browser Cache:
  Duration: 60 seconds
  Purpose: Fastest lookup for repeated requests

Level 2 - OS DNS Cache:
  Duration: 300 seconds (5 minutes)
  Location: /etc/hosts, system resolver

Level 3 - ISP DNS Resolver:
  Duration: TTL from authoritative (300s)
  Purpose: Shared cache for multiple users

Level 4 - Cloudflare Authoritative:
  Purpose: Final authority for domain resolution

Verify IAP JWT Token in Application:

// src/middleware/iap-auth.middleware.ts
import { Injectable, NestMiddleware, UnauthorizedException } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';
import { OAuth2Client } from 'google-auth-library';

@Injectable()
export class IAPAuthMiddleware implements NestMiddleware {
  private readonly oauth2Client: OAuth2Client;
  private readonly iapClientId: string;

  constructor() {
    this.iapClientId = process.env.IAP_CLIENT_ID;
    this.oauth2Client = new OAuth2Client();
  }

  async use(req: Request, res: Response, next: NextFunction) {
    // Skip IAP verification in development
    if (process.env.NODE_ENV !== 'production') {
      return next();
    }

    try {
      // Get IAP JWT from header
      const iapJwt = req.header('X-Goog-IAP-JWT-Assertion');

      if (!iapJwt) {
        throw new UnauthorizedException('No IAP JWT token provided');
      }

      // Verify the JWT token
      const ticket = await this.oauth2Client.verifyIdToken({
        idToken: iapJwt,
        audience: `/projects/PROJECT_NUMBER/global/backendServices/SERVICE_ID`,
      });

      const payload = ticket.getPayload();

      // Extract user information
      req['user'] = {
        email: payload.email,
        sub: payload.sub,
        hd: payload.hd, // Hosted domain (for G Suite)
      };

      // Add IAP headers to request
      req['iapHeaders'] = {
        email: req.header('X-Goog-Authenticated-User-Email'),
        id: req.header('X-Goog-Authenticated-User-Id'),
      };

      next();
    } catch (error) {
      throw new UnauthorizedException('Invalid IAP JWT token');
    }
  }
}

IAP Programmatic Access (for APIs):

// src/services/iap-client.service.ts
import { Injectable } from '@nestjs/common';
import { GoogleAuth } from 'google-auth-library';

@Injectable()
export class IAPClientService {
  private readonly auth: GoogleAuth;
  private readonly iapClientId: string;

  constructor() {
    this.auth = new GoogleAuth();
    this.iapClientId = process.env.IAP_CLIENT_ID;
  }

  /**
   * Make authenticated request to IAP-protected resource
   */
  async makeIAPRequest(url: string, method: string = 'GET', data?: any) {
    // Get ID token for IAP
    const client = await this.auth.getIdTokenClient(this.iapClientId);

    const headers = await client.getRequestHeaders();

    const response = await fetch(url, {
      method,
      headers: {
        ...headers,
        'Content-Type': 'application/json',
      },
      body: data ? JSON.stringify(data) : undefined,
    });

    return response.json();
  }
}

// Usage example

IAP Best Practices:

1. Authentication: ✓ Use Google Workspace accounts for centralized management
  ✓ Enable 2FA/MFA for all users
  ✓ Use service accounts for programmatic access
  ✓ Rotate OAuth client secrets regularly

2. Authorization: ✓ Follow principle of least privilege
  ✓ Use groups instead of individual users
  ✓ Implement role-based access control (RBAC)
  ✓ Regular access reviews and audits

3. Access Policies: ✓ Use Access Context Manager for device and location policies
  ✓ Require corporate devices for sensitive operations
  ✓ Implement IP allowlisting for admin access
  ✓ Set session timeout policies

4. Monitoring: ✓ Enable audit logging for all IAP access
  ✓ Set up alerts for failed authentications
  ✓ Monitor for unusual access patterns
  ✓ Review access logs regularly

5. Security: ✓ Prevent IAP bypass with firewall rules
  ✓ Verify JWT tokens in application code
  ✓ Use signed headers for additional security
  ✓ Implement defense in depth (multiple security layers)

6. Testing: ✓ Test IAP configuration in staging first
  ✓ Verify access for different user roles
  ✓ Test programmatic access with service accounts
  ✓ Validate proper error handling for denied access

// main.ts - NestJS Application Entry Point
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { Logger, ValidationPipe } from '@nestjs/common';
import helmet from 'helmet';
import compression from 'compression';

async function bootstrap() {
  const app = await NestFactory.create(AppModule, {
    logger: ['error', 'warn', 'log'],
  });

  const logger = new Logger('Bootstrap');

  // Security middleware
  app.use(helmet());

  // Compression
  app.use(compression());

  // CORS
  app.enableCors({
    origin: ['https://full-stack-dev.com', 'https://www.full-stack-dev.com'],
    credentials: true,
  });

  // Global validation pipe
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
    }),
  );

  // Graceful shutdown
  app.enableShutdownHooks();

  const port = process.env.PORT || 8080;
  await app.listen(port, '0.0.0.0');

  logger.log(`Application listening on port ${port}`);
}

bootstrap();

Health Check Endpoints:

// health.controller.ts
import { Controller, Get } from '@nestjs/common';
import { HealthCheck, HealthCheckService, TypeOrmHealthIndicator, MemoryHealthIndicator } from '@nestjs/terminus';
import { RedisHealthIndicator } from './redis-health.indicator';

@Controller('health')
export class HealthController {
  constructor(
    private health: HealthCheckService,
    private db: TypeOrmHealthIndicator,
    private redis: RedisHealthIndicator,
    private memory: MemoryHealthIndicator,
  ) {}

  @Get('live')
  @HealthCheck()
  checkLiveness() {
    // Basic liveness check - is the app running?
    return this.health.check([
      () => this.memory.checkHeap('memory_heap', 1024 * 1024 * 1024), // 1GB
    ]);
  }

  @Get('ready')
  @HealthCheck()
  checkReadiness() {
    // Readiness check - can the app serve traffic?
    return this.health.check([
      () => this.db.pingCheck('database'),
      () => this.redis.pingCheck('redis'),
      () => this.memory.checkHeap('memory_heap', 1024 * 1024 * 1024),
    ]);
  }

  @Get('startup')
  @HealthCheck()
  checkStartup() {
    // Startup check - has the app initialized?
    return this.health.check([() => this.db.pingCheck('database')]);
  }
}

    --member=user:alice@example.com \
    --role=roles/iap.httpsResourceAccessor

# Verify user has access
gcloud iap web get-iam-policy \
    --resource-type=backend-services \
    --service=full-stack-dev-backend \
    | grep alice@example.com

# Check access context conditions
gcloud access-context-manager levels list \
    --policy=POLICY_ID

# Test from user's IP address
curl -I https://full-stack-dev.com/api/users

Best Practices​

1. Caching Strategy​

Static Assets (CDN):
  - Cache-Control: public, max-age=31536000
  - Cloudflare: Cache Everything
  - Browser: Long TTL (1 year)

API Responses (Conditional):
  - Cache-Control: private, max-age=3600
  - ETag validation
  - Conditional requests (If-None-Match)

Dynamic Content:
  - Cache-Control: no-cache
  - Bypass CDN
  - Application-level caching (Redis)

2. Health Check Configuration​

Liveness Probe:
  - Purpose: Detect crashed/deadlocked pods
  - Endpoint: /health/live
  - Check: Memory, basic app health
  - Failure Action: Restart pod

Readiness Probe:
  - Purpose: Detect if pod can serve traffic
  - Endpoint: /health/ready
  - Check: Database, Redis, external dependencies
  - Failure Action: Remove from load balancer

Startup Probe:
  - Purpose: Allow slow-starting applications
  - Endpoint: /health/startup
  - Check: Application initialization
  - Failure Action: Restart pod after threshold

3. Resource Optimization​

Right-sizing:
  - Monitor actual usage
  - Set requests = typical usage
  - Set limits = max acceptable usage
  - Use VPA for recommendations

Autoscaling:
  - HPA: Based on CPU/Memory/Custom metrics
  - Cluster Autoscaler: Add nodes when needed
  - Scale down gradually (avoid flapping)

Cost Optimization:
  - Use preemptible nodes for dev/test
  - Enable bin packing
  - Use committed use discounts
  - Clean up unused resources

Summary​

This document traced the complete journey of a user request from browser to backend and back:

  1. DNS Resolution: User query → Cloudflare DNS → IP address
  2. CDN Layer: Cloudflare edge caching, WAF, DDoS protection
  3. Cloud Entry: GCP Load Balancer, Cloud Armor security
  4. Network Layer: VPC network, firewall rules, Cloud NAT
  5. Ingress: GKE cluster, Ingress controller routing
  6. Service Discovery: Kubernetes Service load balancing
  7. Application: Pod processing, business logic, database queries
  8. Response: Return through all layers with caching

Key Performance Metrics:

  • Total latency: ~150ms average
  • Throughput: 1,000-5,000 RPS (application limited)
  • Availability: 99.95%+ (multi-layer redundancy)

Security: 6 layers of protection from Cloudflare to application level
