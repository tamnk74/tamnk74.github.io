OpenTofu Guide

Overview​

OpenTofu is an open-source infrastructure as code (IaC) tool that allows you to define and manage your infrastructure using a declarative configuration language. It is a community-driven fork of Terraform, created to preserve the open-source nature of the project following Terraform's license change.

OpenTofu allows you to manage a wide variety of service providers as well as custom in-house solutions. It is drop-in compatible with Terraform configurations, making migration straightforward.

Top 10 Common Use Cases and Architectures​

  1. Multi-Cloud Deployment: Provisioning resources across AWS, GCP, and Azure simultaneously using a single configuration language.
  2. Kubernetes Cluster Provisioning: Spinning up managed Kubernetes clusters (EKS, GKE, AKS) and managing their underlying networking and node pools.
  3. Application Deployment: Deploying Helm charts or Kubernetes manifests directly via OpenTofu providers after the cluster is ready.
  4. Serverless Infrastructure: Managing Lambda functions, Cloud Functions, and their event triggers (API Gateway, Pub/Sub).
  5. Network Infrastructure: Defining VPCs, subnets, firewalls, and load balancers to ensure a consistent and secure network topology.
  6. Database Management: Provisioning managed databases (RDS, Cloud SQL) with specific configurations for backups, replication, and security.
  7. IAM & Security Policy Management: Managing users, roles, and policies to enforce least privilege access control across cloud environments.
  8. Ephemeral Environments: Creating and destroying temporary environments for testing or development (e.g., per-pull request environments).
  9. State Management & Locking: Using remote backends (S3 + DynamoDB, GCS) to share state safely among team members and prevent concurrent modifications.
  10. Drift Detection: Regularly running tofu plan to detect if the actual infrastructure state has drifted from the desired configuration.

How to Install and Use​

Installation​

macOS (Homebrew):

brew update
brew install opentofu

Linux: See the official installation guide for distribution-specific commands.

Windows (Chocolatey):

choco install opentofu

Basic Usage​

  1. Initialize: Initialize the working directory containing configuration files. This installs necessary providers.

    tofu init

  2. Plan: Create an execution plan. This shows what actions OpenTofu will take to reach the desired state.

    tofu plan

  3. Apply: Apply the changes required to reach the desired state.

    tofu apply

  4. Destroy: Destroy the infrastructure managed by OpenTofu.

    tofu destroy

Integration with Other Components​

  • CI/CD Integration (GitHub Actions): Automate your infrastructure deployment using the OpenTofu setup action.

    - name: Setup OpenTofu
      uses: opentofu/setup-opentofu@v1
    - name: Tofu Init
      run: tofu init
    - name: Tofu Plan
      run: tofu plan

  • Secret Management: Integrate with tools like Vault, AWS Secrets Manager, or GCP Secret Manager to inject sensitive data into your configurations without hardcoding them.

Best Practices​

  1. Use Remote State: Always use a remote backend (like S3, GCS, or Azure Blob Storage) with state locking (e.g., DynamoDB) for team collaboration.
  2. Modularize: Break down large configurations into reusable modules. This promotes consistency and reduces code duplication.
  3. Version Pinning: Pin provider and module versions to ensure stability and prevent unexpected breaking changes.
  4. Directory Structure: Organize your code logically (e.g., separate directories for environments like dev, staging, prod).
  5. Code Formatting: Run tofu fmt before committing to ensure consistent code style.
  6. Validation: Use tofu validate to check for syntax errors and internal consistency.
  7. Sensitive Data: Mark sensitive output variables with sensitive = true to prevent them from being shown in the CLI output.
  8. Tagging strategy: Enforce a consistent tagging strategy for all resources to help with cost allocation and management.
