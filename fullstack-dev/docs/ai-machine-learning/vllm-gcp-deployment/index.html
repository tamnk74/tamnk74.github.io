Deploying vLLM to Google Cloud Platform

This comprehensive guide shows you how to deploy the vllm/vllm-openai Docker image to Google Cloud Platform using Cloud Run with GPU support and GKE as alternatives.

🎯 Deployment Options Overview​

OptionGPU SupportComplexityCostBest For
Cloud Run with GPU✅ NVIDIA L4 (24GB)LowPay-per-useBursty workloads, auto-scaling
GKE with GPU Nodes✅ Multiple GPU typesMediumAlways-onConsistent traffic,更 control
Vertex AI✅ Managed GPUsLowHigherSimplified ML ops

Option 1: Cloud Run with GPU (Recommended for Most Cases)​

[!NOTE] Cloud Run GPU support became generally available in June 2025. It supports NVIDIA L4 GPUs (24GB VRAM) and the new RTX PRO 6000 Blackwell GPU (96GB VRAM, preview).

✅ Advantages​

  • Serverless: Scales to zero when not in use
  • Simple deployment: No Kubernetes knowledge needed
  • Fast startup: ~5 seconds with pre-installed drivers
  • Pay-per-second: Only pay for actual GPU usage
  • Fully managed: No driver or library installation needed

⚠️ Limitations​

  • GPU types: Currently limited to L4 and RTX PRO 6000 (preview)
  • Memory: Maximum 32GB RAM per container
  • Regions: Limited availability (us-central1, europe-west1, asia-southeast1, etc.)
  • Concurrent requests: Max 1000 per instance

🚀 Deploy vLLM to Cloud Run with GPU​

Prerequisites​

# Set your GCP project
export PROJECT_ID="your-gcp-project-id"
export REGION="us-central1"  # GPU-supported region

# Set GCP project
gcloud config set project $PROJECT_ID

# Enable required APIs
gcloud services enable \
  run.googleapis.com \
  artifactregistry.googleapis.com \
  cloudbuild.googleapis.com

Step 1: Create Artifact Registry Repository​

# Create Docker repository
gcloud artifacts repositories create vllm-registry \
  --repository-format=docker \
  --location=$REGION \
  --description="vLLM Docker images"

# Configure Docker authentication
gcloud auth configure-docker ${REGION}-docker.pkg.dev

Step 2: Prepare vLLM Docker Image​

You have two options:

Option A: Use Official vLLM Image (Easiest)​

# Pull official image
docker pull vllm/vllm-openai:latest

# Tag for Artifact Registry
docker tag vllm/vllm-openai:latest \
  ${REGION}-docker.pkg.dev/${PROJECT_ID}/vllm-registry/vllm-openai:latest

# Push to Artifact Registry
docker push ${REGION}-docker.pkg.dev/${PROJECT_ID}/vllm-registry/vllm-openai:latest

Option B: Build Custom Image with Your Model​

Create Dockerfile.vllm:

FROM vllm/vllm-openai:latest

# Pre-download model during build (reduces cold start time)
ENV HF_HOME=/root/.cache/huggingface
ENV MODEL_NAME=mistralai/Mistral-7B-Instruct-v0.2

# Download model at build time
RUN python -c "from huggingface_hub import snapshot_download; snapshot_download('${MODEL_NAME}')"

# Set default model
ENV VLLM_MODEL=${MODEL_NAME}

Build and push:

docker build -f Dockerfile.vllm -t ${REGION}-docker.pkg.dev/${PROJECT_ID}/vllm-registry/vllm-custom:latest .
docker push ${REGION}-docker.pkg.dev/${PROJECT_ID}/vllm-registry/vllm-custom:latest

Step 3: Deploy to Cloud Run with GPU​

gcloud run deploy vllm-service \
  --image=${REGION}-docker.pkg.dev/${PROJECT_ID}/vllm-registry/vllm-openai:latest \
  --region=$REGION \
  --platform=managed \
  --gpu=1 \
  --gpu-type=nvidia-l4 \
  --memory=16Gi \
  --cpu=4 \
  --timeout=3600 \
  --concurrency=10 \
  --min-instances=0 \
  --max-instances=3 \
  --port=8000 \
  --set-env-vars="MODEL_NAME=mistralai/Mistral-7B-Instruct-v0.2,MAX_MODEL_LEN=4096,GPU_MEMORY_UTILIZATION=0.9" \
  --command="python,-m,vllm.entrypoints.openai.api_server" \
  --args="--model,mistralai/Mistral-7B-Instruct-v0.2,--dtype,half,--max-model-len,4096,--gpu-memory-utilization,0.9" \
  --allow-unauthenticated

Parameter Breakdown:

  • --gpu=1: Number of GPUs (currently only 1 supported)
  • --gpu-type=nvidia-l4: GPU type (L4 has 24GB VRAM)
  • --memory=16Gi: Container memory
  • --cpu=4: Number of vCPUs
  • --timeout=3600: Max request timeout (1 hour)
  • --concurrency=10: Max concurrent requests per instance
  • --min-instances=0: Scale to zero when idle
  • --max-instances=3: Max autoscaling limit

Step 4: Test the Deployment​

# Get service URL
SERVICE_URL=$(gcloud run services describe vllm-service \
  --region=$REGION \
  --format='value(status.url)')

echo "Service URL: $SERVICE_URL"

# Test health endpoint
curl $SERVICE_URL/health

# Test model endpoint
curl $SERVICE_URL/v1/models

# Test completion
curl $SERVICE_URL/v1/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mistralai/Mistral-7B-Instruct-v0.2",
    "prompt": "Explain what vLLM is in one sentence:",
    "max_tokens": 50,
    "temperature": 0.7
  }'

Step 5: Cost Optimization​

# Update to scale to zero when not in use
gcloud run services update vllm-service \
  --region=$REGION \
  --min-instances=0 \
  --max-instances=3 \
  --concurrency=20

# Set CPU allocation (only during requests)
gcloud run services update vllm-service \
  --region=$REGION \
  --cpu-throttling

# Monitor costs
gcloud run services describe vllm-service \
  --region=$REGION \
  --format="value(status.traffic)"

🔐 Production Configuration​

Add Authentication​

Option 1: IAM-based Authentication​

# Deploy with authentication required
gcloud run services update vllm-service \
  --region=$REGION \
  --no-allow-unauthenticated

# Grant access to specific service account
gcloud run services add-iam-policy-binding vllm-service \
  --region=$REGION \
  --member="serviceAccount:my-app@${PROJECT_ID}.iam.gserviceaccount.com" \
  --role="roles/run.invoker"

Test with authentication:

# Get ID token
TOKEN=$(gcloud auth print-identity-token)

# Make authenticated request
curl $SERVICE_URL/v1/completions \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model": "mistralai/Mistral-7B-Instruct-v0.2", "prompt": "Hello", "max_tokens": 10}'

Option 2: API Key Authentication​

Create a wrapper service with API key validation:

# api_wrapper.py
from fastapi import FastAPI, HTTPException, Header
import httpx
import os

app = FastAPI()

VLLM_URL = os.getenv("VLLM_URL", "http://localhost:8000")
API_KEY = os.getenv("API_KEY", "secret-key")

@app.post("/v1/completions")
async def completions(
    request: dict,
    x_api_key: str = Header(None)
):
    if x_api_key != API_KEY:
        raise HTTPException(status_code=401, detail="Invalid API key")
    
    async with httpx.AsyncClient() as client:
        response = await client.post(
            f"{VLLM_URL}/v1/completions",
            json=request,
            timeout=60.0
        )
        return response.json()

Configure Secrets​

# Create secret for HuggingFace token (if using gated models)
echo -n "your-hf-token" | gcloud secrets create HF_TOKEN --data-file=-

# Grant access to Cloud Run service account
gcloud secrets add-iam-policy-binding HF_TOKEN \
  --member="serviceAccount:${PROJECT_ID}@appspot.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"

# Update Cloud Run to use secret
gcloud run services update vllm-service \
  --region=$REGION \
  --set-secrets="HF_TOKEN=HF_TOKEN:latest"

Add Health Checks and Monitoring​

# Configure startup probe (wait up to 10 minutes for model load)
gcloud run services update vllm-service \
  --region=$REGION \
  --startup-cpu-boost \
  --timeout=600

# View logs
gcloud logging read "resource.type=cloud_run_revision AND resource.labels.service_name=vllm-service" \
  --limit=50 \
  --format=json

# Set up alerts
gcloud alpha monitoring policies create \
  --notification-channels=CHANNEL_ID \
  --display-name="vLLM High Error Rate" \
  --condition-display-name="Error rate > 5%" \
  --condition-threshold-value=0.05 \
  --condition-threshold-duration=300s

💰 Cost Estimation (Cloud Run with GPU)​

NVIDIA L4 GPU Pricing (as of 2026)​

Regional Pricing (us-central1):

  • GPU: ~$0.69 per GPU-hour
  • CPU (4 vCPU): ~$0.24 per vCPU-hour
  • Memory (16GB): ~$0.03 per GB-hour
  • Requests: $0.40 per million requests

Example Monthly Cost:

Scenario: 100 hours/month of inference
- GPU (L4): 100 hours × $0.69 = $69.00
- CPU (4 vCPU): 100 hours × $0.24 × 4 = $96.00
- Memory (16GB): 100 hours × $0.03 × 16 = $48.00
- Requests (10K): ~$0.004
-----------------------------------------------
Total: ~$213/month for 100 hours of usage

Comparison to GKE:

  • GKE with n1-standard-4 + 1x NVIDIA T4 (always on): ~$400-500/month
  • Cloud Run advantage: Pay only for actual usage

Cost Optimization Tips​

  1. Scale to zero: Set --min-instances=0
  2. Use smaller models: Consider quantized models (4-bit AWQ/GPTQ)
  3. Batch requests: Higher concurrency reduces cost per request
  4. Regional selection: Prices vary by region
  5. Use committed use discounts for predictable workloads

Option 2: Deploy to GKE with GPU​

For more control and consistent traffic, use GKE:

Create GKE Cluster with GPU Nodes​

# Create GKE cluster
gcloud container clusters create vllm-cluster \
  --region=$REGION \
  --num-nodes=1 \
  --machine-type=n1-standard-4 \
  --accelerator=type=nvidia-tesla-t4,count=1 \
  --disk-size=100 \
  --enable-autoscaling \
  --min-nodes=0 \
  --max-nodes=3 \
  --addons=GcePersistentDiskCsiDriver \
  --enable-stackdriver-kubernetes

# Install NVIDIA device plugin
kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/container-engine-accelerators/master/nvidia-driver-installer/cos/daemonset-preloaded.yaml

Deploy vLLM to GKE​

Create vllm-deployment.yaml:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: vllm-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: vllm
  template:
    metadata:
      labels:
        app: vllm
    spec:
      containers:
      - name: vllm
        image: vllm/vllm-openai:latest
        command:
          - python
          - -m
          - vllm.entrypoints.openai.api_server
        args:
          - --model
          - mistralai/Mistral-7B-Instruct-v0.2
          - --dtype
          - half
          - --max-model-len
          - "4096"
          - --gpu-memory-utilization
          - "0.9"
        ports:
        - containerPort: 8000
        resources:
          limits:
            nvidia.com/gpu: 1
            memory: "16Gi"
            cpu: "4"
          requests:
            nvidia.com/gpu: 1
            memory: "12Gi"
            cpu: "2"
        env:
        - name: HF_HOME
          value: /data/huggingface
        volumeMounts:
        - name: cache-volume
          mountPath: /data/huggingface
      volumes:
      - name: cache-volume
        emptyDir: {}
      nodeSelector:
        cloud.google.com/gke-accelerator: nvidia-tesla-t4
---
apiVersion: v1
kind: Service
metadata:
  name: vllm-service
spec:
  selector:
    app: vllm
  ports:
  - port: 8000
    targetPort: 8000
  type: LoadBalancer

Deploy:

kubectl apply -f vllm-deployment.yaml

# Get external IP
kubectl get service vllm-service

GKE with Horizontal Pod Autoscaling​

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: vllm-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: vllm-deployment
  minReplicas: 1
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70

🔧 Terraform Configuration​

Cloud Run with GPU​

Create main.tf:

terraform {
  required_providers {
    google = {
      source  = "hashicorp/google"
      version = "~> 5.0"
    }
  }
}

provider "google" {
  project = var.project_id
  region  = var.region
}

variable "project_id" {
  description = "GCP Project ID"
  type        = string
}

variable "region" {
  description = "GCP Region"
  type        = string
  default     = "us-central1"
}

variable "model_name" {
  description = "HuggingFace model name"
  type        = string
  default     = "mistralai/Mistral-7B-Instruct-v0.2"
}

# Artifact Registry Repository
resource "google_artifact_registry_repository" "vllm_repo" {
  location      = var.region
  repository_id = "vllm-registry"
  format        = "DOCKER"
  description   = "vLLM Docker images"
}

# Cloud Run Service with GPU
resource "google_cloud_run_v2_service" "vllm_service" {
  name     = "vllm-service"
  location = var.region
  ingress  = "INGRESS_TRAFFIC_ALL"

  template {
    containers {
      image = "${var.region}-docker.pkg.dev/${var.project_id}/vllm-registry/vllm-openai:latest"
      
      command = ["python", "-m", "vllm.entrypoints.openai.api_server"]
      args = [
        "--model", var.model_name,
        "--dtype", "half",
        "--max-model-len", "4096",
        "--gpu-memory-utilization", "0.9"
      ]

      ports {
        container_port = 8000
      }

      resources {
        limits = {
          cpu    = "4"
          memory = "16Gi"
        }
        
        # GPU configuration
        gpu {
          type  = "nvidia-l4"
          count = 1
        }
      }

      env {
        name  = "MODEL_NAME"
        value = var.model_name
      }
    }

    scaling {
      min_instance_count = 0
      max_instance_count = 3
    }

    timeout = "3600s"
    
    max_instance_request_concurrency = 10
  }

  traffic {
    type    = "TRAFFIC_TARGET_ALLOCATION_TYPE_LATEST"
    percent = 100
  }
}

# IAM policy for public access (remove for production)
resource "google_cloud_run_service_iam_member" "public_access" {
  service  = google_cloud_run_v2_service.vllm_service.name
  location = google_cloud_run_v2_service.vllm_service.location
  role     = "roles/run.invoker"
  member   = "allUsers"
}

output "service_url" {
  value       = google_cloud_run_v2_service.vllm_service.uri
  description = "vLLM service URL"
}

Deploy with Terraform:

terraform init
terraform plan -var="project_id=your-project-id"
terraform apply -var="project_id=your-project-id"

🐛 Troubleshooting​

Issue: Cold Start is Slow (>60 seconds)​

Cause: Model download during container startup

Solutions:

  1. Pre-bake model in Docker image (recommended):

    FROM vllm/vllm-openai:latest
    RUN python -c "from huggingface_hub import snapshot_download; snapshot_download('mistralai/Mistral-7B-Instruct-v0.2')"

  2. Use minimum instances:

    --min-instances=1

  3. Enable startup CPU boost:

    --startup-cpu-boost

Issue: GPU Out of Memory​

Solutions:

  1. Reduce model length:

    --max-model-len=2048

  2. Lower GPU memory utilization:

    --gpu-memory-utilization=0.8

  3. Use quantized models:

    --model=TheBloke/Mistral-7B-Instruct-v0.2-AWQ --quantization=awq

Issue: High Costs​

Solutions:

  1. Set aggressive scale-to-zero
  2. Use smaller models or quantization
  3. Implement request batching
  4. Consider GKE for consistent workloads

🎯 Decision Matrix​

Choose Cloud Run with GPU if:

  • ✅ Traffic is bursty or unpredictable
  • ✅ You want minimal operational overhead
  • ✅ Pay-per-use pricing aligns with your usage
  • ✅ L4 GPU (24GB) is sufficient for your model

Choose GKE with GPU if:

  • ✅ You need consistent, high-volume traffic
  • ✅ You require specific GPU types (A100, V100)
  • ✅ You need fine-grained control over infrastructure
  • ✅ You have existing Kubernetes expertise
