Completing Item 6: Implement Code Style Tools

Item: 6 | Architecture Definition | Architecture & Coding Guidance | SETUP | 1 | "There is a tools will be used to check code style (lint, ESlint, PHPcs, stylecopaalyzers, etc)." | Configure the CI pipeline to run flutter analyze on every PR. Integrate SonarQube/SonarCloud for static analysis. | |

This guide details how to set up and enforce automated code style and static analysis checks for your Flutter project.

Tools​

  1. flutter analyze (Dart Analyzer & Linter):

    • Purpose: Checks for Dart language errors, warnings, and stylistic issues based on rules defined in analysis_options.yaml. This is the primary tool for enforcing Dart/Flutter best practices.
    • Setup:
      • Ensure you have a well-defined analysis_options.yaml file (see Item 3).
      • Developers should run flutter analyze locally or rely on IDE integration (VS Code shows issues automatically).
    • CI Integration:
      • Add a step to your CI pipeline (e.g., GitHub Actions workflow) that runs on every Pull Request: 
        - name: Analyze code
          run: flutter analyze --fatal-infos --fatal-warnings .
      • The --fatal-infos and --fatal-warnings flags ensure the CI job fails if any issues are found, preventing merging of non-compliant code.

  2. dart format (Code Formatter):

    • Purpose: Automatically formats Dart code according to official Dart style guidelines (handling whitespace, indentation, line wrapping, etc.). Ensures visual consistency.
    • Setup:
      • Developers should configure their IDE (VS Code) to "Format on Save" for Dart files.
      • Line length can be configured in analysis_options.yaml (though sticking to the default of 80 is often recommended).
    • CI Integration (Optional but Recommended):
      • Add a step to check formatting in the CI pipeline: 
        - name: Check formatting
          run: dart format --output=none --set-exit-if-changed .
      • This command checks if any files would be changed by the formatter. If so, it exits with an error code, failing the build and indicating that the developer forgot to format their code before committing.

  3. SonarQube / SonarCloud (Static Analysis Platform):

    • Purpose: Provides a more comprehensive analysis beyond basic linting. It tracks code smells, security vulnerabilities, code duplication, complexity (Cyclomatic Complexity), and test coverage over time. Offers dashboards and quality gates.

    • Setup:

      • Choose between self-hosted SonarQube or cloud-based SonarCloud.
      • Configure a SonarQube project for your repository.
      • Generate a sonar-project.properties file in your project root (example below).
      • Generate test coverage reports (lcov.info) using flutter test --coverage.

    • CI Integration:

      • Add steps to your CI pipeline (run after tests):

        # Example sonar-project.properties
        sonar.projectKey=your_project_key
        sonar.projectName=Your Project Name
        sonar.sources=lib
        sonar.tests=test
        sonar.language=dart
        sonar.coverage.exclusions=**/*.g.dart,**/*.freezed.dart # Exclude generated
        # Path to the lcov report generated by flutter test --coverage
        sonar.dart.coverage.reportPath=coverage/lcov.info
        # Path to the analysis report (optional, can help SonarQube)
        # sonar.dart.analysis.reportPath=analysis_report.json
        # Example CI Steps (GitHub Actions)
        - name: Run tests and generate coverage
          run: flutter test --coverage

        # Download and run SonarScanner CLI (or use dedicated actions)
        - name: SonarCloud Scan
          uses: SonarSource/sonarcloud-github-action@master
          env:
            GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} # Needed to decorate PRs
            SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }} # Set in GitHub secrets
          # Add with: args: '-Dsonar.verbose=true' for debugging

    • Quality Gates: Configure Quality Gates in SonarQube/SonarCloud (e.g., "Coverage on New Code < 80%", "New Blocker Issues > 0") to fail the CI build if quality degrades.

Summary​

By implementing these tools, especially flutter analyze and dart format enforced in CI, you establish a strong baseline for code quality and consistency. SonarQube adds deeper insights and tracking over time.
