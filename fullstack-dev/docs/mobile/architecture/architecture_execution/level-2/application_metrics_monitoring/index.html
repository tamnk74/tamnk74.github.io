Completing Item 85: Monitor Application Metrics

Item: 85 | Architecture Execution | Continuous Monitoring | RELEASE | 2 | "The application monitoring tools are measuring API availability, key functionalities, background jobs, etc. If <br>there is an issue with any of those application metrics the team will get notified." | In Firebase, monitor "Crash-free users." In Datadog, set up alerts for "P90 API response time > 1s" and "Error rate > 2%." | |

This guide focuses on monitoring key application-level metrics for both your Flutter app and its supporting backend, ensuring you can track performance, reliability, and functionality from the user's perspective and get notified of issues.

Why Monitor Application Metrics?​

  • User Experience Insight: Measures what the user actually experiences (app crashes, screen load times, API slowness) rather than just underlying infrastructure health.
  • Performance Tracking: Identifies performance bottlenecks within the app or backend APIs.
  • Reliability Measurement: Tracks application stability (crash rates, error rates).
  • Feature Health: Monitors the success/failure rates of key user interactions or background processes.
  • Faster Troubleshooting: Helps pinpoint whether issues originate in the frontend (Flutter app), backend API, or infrastructure.

Key Application Metrics to Monitor​

Flutter Mobile App:

  • Crash Rate / Crash-Free Users: Percentage of users who did not experience a crash in a given period. (Critical)
  • App Startup Time: Time from app launch to the first screen being interactive (Cold/Warm starts).
  • Screen Load/Render Time: Time taken for specific, important screens to become fully loaded and interactive.
  • ANRs (Application Not Responding - Android): Occurrences where the app UI thread is blocked for too long.
  • (Custom) Key User Interaction Success/Failure Rates: (Requires custom instrumentation) e.g., Login success rate, Payment completion rate.
  • (Custom) Network Request Performance: Latency and error rates for calls made from the app to the backend.

Backend API:

  • API Availability / Uptime: Percentage of time the API endpoints are reachable and responding successfully (often measured via synthetic checks). (Critical)
  • Request Latency (Response Time): Time taken for the API to process and respond to requests (e.g., Average, P90, P95, P99 percentiles). (Critical)
  • Request Throughput: Number of requests per second/minute.
  • Error Rate: Percentage of requests resulting in errors (especially 5xx server errors, but also 4xx client errors). (Critical)
  • Background Job Status: Success/failure rates and execution times of asynchronous tasks (e.g., sending emails, processing data).
  • (Custom) Business Transaction Metrics: e.g., Orders processed per minute, User signups per hour.

Implementation Steps​

  1. Choose Monitoring Tools:

    • Flutter App:
      • Firebase Crashlytics: Essential for crash reporting and stability tracking.
      • Firebase Performance Monitoring: Good for automatic and custom tracing of app startup, screen loads, and network requests.
      • Datadog RUM, Sentry, New Relic Mobile: More advanced Real User Monitoring (RUM) platforms.
    • Backend API:
      • APM (Application Performance Management) Tools: Datadog APM, Dynatrace, New Relic APM, Elastic APM. Provide deep insights into request traces, database queries, and errors within the backend code.
      • Cloud Provider Tools: AWS CloudWatch, Google Cloud Monitoring, Azure Monitor (can cover basic metrics like latency, error rates, especially for managed services like Load Balancers, API Gateways, Serverless Functions).
      • Logging Platforms: Datadog Logs, Splunk, Elastic Stack (can derive metrics like error rates from logs).
      • Synthetic Monitoring: Tools like Datadog Synthetics, Checkly, UptimeRobot periodically ping API endpoints to check availability and basic functionality.

  2. Integrate SDKs / Configure Agents:

    • Flutter: Integrate the Firebase Crashlytics and Performance Monitoring SDKs into your app. Add custom traces for important screen loads or flows.
    • Backend: Instrument your backend code with the chosen APM tool's agent/library. Configure cloud provider integrations or log shipping. Set up synthetic checks.

  3. Create Dashboards:

    • Flutter Dashboard: In Firebase (or other tool), create a dashboard showing: Crash-free user rate trend, App startup time trend, Key screen load time trends, ANR rates.
    • Backend Dashboard: In your APM/monitoring tool (e.g., Datadog), create a dashboard showing: API Availability (Synthetic Check), P90/P95 Request Latency, Error Rate (4xx, 5xx), Request Throughput, Background Job health. [Image of API performance monitoring dashboard]

  4. Set Up Alerts:

    • Configure alerts for critical deviations from normal behavior.
    • Essential Alerts:
      • High Crash Rate Spike (Flutter): e.g., Crash-free users drop below 99.5% shortly after a release (Firebase alert).
      • Significant Regression in Startup/Screen Load Time (Flutter): e.g., P90 App Start Time increases by >20% (Firebase alert).
      • API Availability Failure (Backend): Synthetic check fails multiple times consecutively (Datadog/UptimeRobot alert). (Critical)
      • High API Latency (Backend): e.g., P95 latency > 1 second sustained for 5 minutes (Datadog APM alert). (Critical)
      • High API Error Rate (Backend): e.g., 5xx error rate > 2% sustained for 5 minutes (Datadog APM/LB alert). (Critical)
      • Background Job Failures (Backend): Alert if a critical background job fails repeatedly.
    • Notification Channels: Send alerts to PagerDuty/Opsgenie (critical), #alerts-prod chat channel (Item 17), email.

  5. Document:

    • Document the monitoring tools used for both frontend and backend.
    • Link to the key application monitoring dashboards.
    • Outline the critical alerts configured.

By monitoring application-level metrics alongside infrastructure metrics (Item 84), you gain a comprehensive view of your system's health and user experience, enabling faster detection and resolution of issues.
