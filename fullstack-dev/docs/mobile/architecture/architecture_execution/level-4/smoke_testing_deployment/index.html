smoke_testing_deployment

Maturity Level 4: Continuous Deployment

Area: Architecture Execution Practice: Continuous Deployment Phase: DEVELOPMENT (Sprint 1-N) Index: 136

Criteria

"It is possible to check the deployment status through smoking test scripts."

E-commerce App Context (Flutter)

A "smoke test" is a basic, automated test that runs after deployment to ensure the app isn't fundamentally broken. It answers the question, "Did the deployment work?" For an e-commerce app, a good smoke test would be: "Can the app start, log in, and load the home screen?" If it fails, the build is marked as "bad" immediately.

How to Achieve This (Flutter/E-commerce)

  1. Required Tooling

UI Testing Framework: Patrol (recommended) or flutter_driver + integration_test.

CI/CD Server: GitHub Actions, Codemagic, etc.

Device Farm (Optional but best): Firebase Test Lab, AWS Device Farm, or BrowserStack.

  1. Implementation Steps

Step 1: Write the Smoke Test Script

Using Patrol, create a new test file (e.g., test/smoke_test.dart).

This test should be simple and fast. It should not test business logic, only that the core app flow is functional.

// Example using Patrol framework
import 'package:flutter_test/flutter_test.dart';
import 'package:patrol/patrol.dart';
import 'package:my_ecommerce_app/main.dart' as app; // Your app's entry

void main() {
patrolTest(
'Smoke Test: App Login and Home Screen',
(PatrolIntegrationTester $) async {
await app.main(); // Start the app
await $.pumpAndSettle(); // Wait for app to load

      // 1. Find and tap the "Login" button
      await $(#loginButton).tap();
      await $.pumpAndSettle();

      // 2. Enter credentials (use environment variables)
      await $(#emailField).enterText(PatrolTester.env['TEST_USER_EMAIL']);
      await $(#passwordField).enterText(PatrolTester.env['TEST_USER_PASS']);
      await $(#submitLoginButton).tap();
      await $.pumpAndSettle(timeout: Duration(seconds: 10)); // Wait for network

      // 3. Verify we are on the Home Screen
      // This confirms login worked and the home screen loaded.
      expect($(#homeScreenTitle), findsOneWidget);
      expect($(#productCarousel), findsOneWidget);
    },

);
}

Step 2: Integrate into CI/CD Pipeline

This test should run as a post-deploy step.

Flow:

CI/CD builds and deploys the "Dev" app to Firebase App Distribution (from Item 135).

New Step: The CI/CD job then triggers the smoke test.

Option A (Device Farm - Recommended):

Your CI/CD job uses the Firebase CLI to upload your test script and the newly-built APK/IPA to Firebase Test Lab.

Test Lab runs your smoke_test.dart on a real, physical device.

The CI/CD job waits for Test Lab to return "PASS" or "FAIL".

Option B (Emulator - Good):

Your CI/CD job starts an Android emulator.

It runs patrol_cli test --target=test/smoke_test.dart (or the flutter_driver equivalent) inside the emulator.

It waits for the test to pass or fail.

Step 3: Alert on Failure

If the smoke test fails, the CI/CD job must:

Mark the entire build/deployment as "FAILED".

Send an urgent alert to the team's Slack channel: "Smoke test failed for build 1.2.4. App may be broken."

(Advanced) Automatically roll back the deployment or mark it as "bad".
