Completing Item 104: Set Up Business Monitoring Tools

Item: 104 | Architecture Execution | Continuous Monitoring | RELEASE | 4 | There are business monitoring tools for production and there is a team in charge of following up. | (Business) Work with the PO to set up a dashboard (e.g., Looker/Data Studio) showing key business KPIs (e.g., "Daily Active Users," "Signups"). | |

This guide outlines the process of establishing tools and dashboards for monitoring key business metrics (KPIs - Key Performance Indicators) related to the Flutter mobile application, and ensuring someone is responsible for tracking them.

Why Monitor Business Metrics?​

  • Measure Success: Tracks whether the application is achieving its intended business goals (e.g., user growth, engagement, conversion).
  • Data-Driven Decisions: Provides objective data to inform product strategy, feature prioritization, and marketing efforts.
  • Identify Problems/Opportunities: Sudden drops or unexpected trends in KPIs can indicate underlying technical issues, usability problems, or market shifts.
  • Connect Tech to Business: Helps the development team understand the business impact of the features they build.

Key Business Metrics for Mobile Apps (Examples)​

The specific KPIs depend heavily on the app's purpose, but common examples include:

  • Acquisition: Downloads, Sign-ups/Registrations, Installation Source.
  • Activation: Onboarding completion rate, First key action taken (e.g., first purchase, first post).
  • Engagement: Daily Active Users (DAU), Monthly Active Users (MAU), Session duration, Session frequency, Key feature usage rates (e.g., searches performed, items added to cart).
  • Retention: Day 1/7/30 retention rates, Churn rate.
  • Revenue (if applicable): Average Revenue Per User (ARPU), Conversion Rate (e.g., view-to-purchase), Subscription renewals.
  • App Store Ratings/Reviews.

Steps​

  1. Define Key Performance Indicators (KPIs) with PO/Stakeholders:

    • Crucial Step: Work closely with the Product Owner and key business stakeholders to identify the most important metrics that define success for this specific application.
    • Ask: "How do we know if this app is successful?", "What user behaviors drive business value?", "What are our growth/engagement goals?"
    • Focus on a manageable number of primary KPIs (e.g., 5-10) rather than trying to track everything.
    • Ensure each KPI is SMART (Specific, Measurable, Achievable, Relevant, Time-bound).

  2. Implement Analytics Tracking in the App:

    • Ensure an analytics platform is integrated into the Flutter app to capture the raw data needed for the KPIs. Common choices:
      • Firebase Analytics: Good general-purpose tool, integrates well with other Firebase services, often sufficient.
      • Mixpanel, Amplitude: More advanced product analytics platforms.
      • Google Analytics for Firebase.
    • Event Tracking: Instrument the app code to log relevant events corresponding to the KPIs (e.g., analytics.logEvent(name: 'sign_up'), analytics.logEvent(name: 'add_to_cart', parameters: {...}), analytics.logScreenView(...)).
    • User Properties: Set user properties (e.g., user role, subscription status) where appropriate (respecting privacy).

  3. Choose and Configure a Business Intelligence (BI) / Dashboarding Tool:

    • While Firebase Analytics has its own dashboard, a dedicated BI tool often provides more flexibility for visualizing KPIs and combining data sources. Options:
      • Google Looker Studio (formerly Data Studio): Free, integrates well with Google Analytics/Firebase, BigQuery. Good starting point.
      • Tableau, Power BI, Looker (Google Cloud): More powerful, enterprise-grade BI tools.
      • Mixpanel, Amplitude Dashboards: If using these platforms, their built-in dashboards are often sufficient.
    • Connect Data Sources: Configure the BI tool to connect to your analytics data source (e.g., Firebase via BigQuery export, direct integration).
    • Build the Dashboard: Create a dashboard specifically for the defined KPIs. Use clear visualizations (line charts for trends, scorecards for current values, bar charts for comparisons). Organize it logically.

  4. Assign Ownership for Monitoring:

    • Designate who is primarily responsible for regularly reviewing the business monitoring dashboard and reporting on trends or anomalies. This is often the Product Owner or a dedicated Data Analyst.
    • The development team lead should also be aware of major trends, but day-to-day monitoring usually falls to the product/business side.

  5. Establish Reporting/Review Cadence:

    • Define how often the KPIs will be reviewed and discussed (e.g., weekly check-in, monthly business review).
    • Incorporate KPI review into relevant team meetings (e.g., Sprint Review).

  6. Document and Share:

    • Document the defined KPIs, their meaning, and how they are calculated on the project wiki.
    • Share the link to the primary business monitoring dashboard widely with the team and stakeholders (Item 105).

Setting up business monitoring closes the loop, allowing the team and stakeholders to see the real-world outcomes of the application's development and usage.
