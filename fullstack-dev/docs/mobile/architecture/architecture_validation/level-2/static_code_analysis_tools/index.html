Completing Item 96: Use Static Code Analysis Tools

Item: 96 | Architecture Validation | Architecture Evaluation | PREPARATION (Sprint 0) | 2 | The code quality is measured through static code analysis tools. | Configure flutter analyzewith strict rules inanalysis_options.yaml and run it on every PR. | |

(Note: This item is foundational and closely related to Item 6, "Implement Code Style Tools," and Item 25, "Align on Static Analysis Metrics Goal." This focuses on the existence and basic configuration of the tool during setup.)

This guide covers the initial setup and integration of static code analysis tools to automatically measure and check code quality in your Flutter project.

Why Use Static Code Analysis?​

  • Automated Quality Checks: Automatically detects potential bugs, style inconsistencies, performance issues, and deviations from best practices without needing to run the code.
  • Early Feedback: Provides immediate feedback to developers as they code (via IDE integration) or when they submit a Pull Request (via CI).
  • Consistency: Enforces coding standards and conventions uniformly across the entire team and codebase.
  • Bug Prevention: Catches common error patterns (e.g., potential null issues, incorrect async usage) before they reach testing or production.
  • Improved Maintainability: Encourages cleaner, more readable, and less complex code.

Core Tool: Dart Analyzer (flutter analyze)​

The primary static analysis tool for Flutter/Dart is built into the Dart SDK and run via flutter analyze.

Implementation Steps​

  1. Configure Analysis Rules (analysis_options.yaml - Crucial Step):

    • This file, placed in the root of your Flutter project, controls which rules the Dart Analyzer enforces. Do not skip this step.

    • Create/Edit analysis_options.yaml:

      • Include Base Rules: Start by including a standard set of recommended rules:

        # Use the recommended Flutter lint set
        include: package:flutter_lints/flutter.yaml
        # Optionally, include stricter sets like package:lints/recommended.yaml or effective_dart

      • Customize Rules: Enable additional lints or customize existing ones based on team preferences and project needs. Refer to the Dart Linter Rules documentation for available rules.

        analyzer:
          # Treat certain issues as errors instead of warnings/infos
          errors:
            missing_required_param: error
            # Promote infos/warnings to errors if desired
            # avoid_print: error
          exclude:
            # Exclude generated files from analysis
            - '**/*.g.dart'
            - '**/*.freezed.dart'

        linter:
          rules:
            # Enable specific rules not in the base set
            always_declare_return_types: true
            avoid_redundant_argument_values: true
            prefer_final_locals: true
            # Disable rules if necessary (use with caution)
            # avoid_catches_without_on_clauses: false

    • Commit the File: Commit analysis_options.yaml to your Git repository so the rules are shared and versioned.

  2. Integrate with IDE:

    • Modern IDEs like VS Code (with the Dart/Flutter extensions) automatically use the analysis_options.yaml file.
    • They provide real-time feedback by highlighting analysis issues directly in the code editor.
    • Ensure developers have the necessary extensions installed and enabled.

  3. Integrate with CI Pipeline:

    • Add a step to your CI workflow (e.g., GitHub Actions) that runs on every Pull Request.
    • Use the flutter analyze command. Crucially, use flags to fail the CI build if any issues are found. 
      # Example GitHub Actions step
      - name: Analyze code
        run: flutter analyze --fatal-infos --fatal-warnings .
        # --fatal-infos: Treat info-level issues as errors
        # --fatal-warnings: Treat warning-level issues as errors
    • This prevents merging code that violates the defined quality standards.

  4. Consider Additional Tools (Optional - Relates to Item 6 & 25):

    • While flutter analyze is the core, consider tools like SonarQube/SonarCloud for deeper analysis (complexity, duplication, security hotspots) and tracking quality trends over time. SonarQube often incorporates the results from the Dart Analyzer.

  5. Document and Communicate:

    • Briefly document the use of flutter analyze and the location of the analysis_options.yaml file in your project's README or onboarding guide.
    • Explain the importance of adhering to the analysis rules during team onboarding and code reviews.

By setting up and enforcing static analysis early using flutter analyze and a well-configured analysis_options.yaml, you establish a foundational layer of automated code quality assurance for your project.
